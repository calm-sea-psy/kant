1. GridSearchCV vs RandomizedSearchCV
둘 다 하이퍼파라미터 튜닝을 위한 scikit-learn 도구예요. 모델 성능을 좌우하는 하이퍼파라미터(예: max_depth, C, n_estimators 등)의 최적 조합을 교차검증(CV)으로 찾아줍니다.

ㄱ) GridSearchCV — 전수 탐색
지정한 하이퍼파라미터 후보값들의 모든 조합을 하나씩 다 시도
각 조합마다 K-fold 교차검증으로 성능 평가 → 가장 좋은 조합 선택

장점: 후보 범위 내에서 최적해를 놓치지 않음 (완전 탐색)
단점: 조합 수가 파라미터 개수·값 범위에 따라 폭발적으로 늘어남 → 느림 (차원의 저주)

ㄴ) RandomizedSearchCV — 무작위 샘플링
전체 조합을 다 보지 않고, 지정한 분포/범위에서 무작위로 n번만 샘플링해서 시도
연속형 분포(uniform, randint 등)를 지정할 수 있어 그리드보다 탐색 공간이 유연함.

장점: 시도 횟수(n_iter)를 직접 제어 → 빠름, 파라미터가 많거나 범위가 넓을 때 유리
단점: 운이 나쁘면 최적 조합을 못 찾을 수 있음 (확률적)

상황	                                                                추천
파라미터 개수 적고(2~3개) 후보값도 적음	                                GridSearchCV
파라미터 많거나 연속형 범위가 넓음	                                RandomizedSearchCV
계산 자원/시간이 제한적	                                            RandomizedSearchCV
최적해를 정밀하게 찾아야 함	                                GridSearchCV (또는 좁힌 범위로 2단계 탐색)

RandomizedSearchCV로 대략적인 좋은 영역을 찾은 뒤, 그 근처 범위로 GridSearchCV를 좁혀 정밀 탐색하는 2단계 방식이 흔히 쓰입니다.

2. ColumnTransformer
서로 다른 컬럼(특성)에 다른 전처리를 각각 적용하고 그 결과를 하나로 합쳐주는 도구예요. 실제 데이터는 수치형/범주형이 섞여 있는데, 수치형엔 스케일링을, 범주형엔 인코딩을 해야 하니까 필요합니다.

# 이렇게 컬럼마다 따로 처리하면 번거롭고 실수하기 쉬움
df['age'] = StandardScaler().fit_transform(df[['age']])
df['gender'] = OneHotEncoder().fit_transform(df[['gender']])
# ... 컬럼이 많아지면 관리 힘듦

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

numeric_features = ['age', 'income']
categorical_features = ['gender', 'city']

preprocessor = ColumnTransformer(
    transformers=[
        ('num', StandardScaler(), numeric_features),
        ('cat', OneHotEncoder(handle_unknown='ignore'), categorical_features)
    ]
)

X_transformed = preprocessor.fit_transform(X)

각 (이름, 변환기, 적용할 컬럼목록) 튜플을 지정
지정 안 된 컬럼은 기본적으로 버려짐 (remainder='passthrough'로 유지 가능)
결과는 모든 변환 결과를 가로로 이어붙인 하나의 행렬

3. Pipeline (sklearn) vs imblearn Pipeline

일반 sklearn Pipeline
전처리 → 모델 학습을 하나의 객체로 묶어서, fit/predict 한 번 호출로 전체 과정을 실행합니다.
핵심 장점: 교차검증(CV) 시 전처리(스케일링 등)의 fit이 매 fold마다 train 데이터에서만 이루어짐 → data leakage 방지. GridSearchCV와도 그대로 결합 가능.

imblearn Pipeline이 다른 점
sklearn의 Pipeline은 각 단계가 .transform()만 지원해서 샘플 개수를 바꾸는 단계(오버샘플링/언더샘플링)를 못 넣습니다. 클래스 불균형 데이터(예: 사기 탐지, 희귀질환 예측)에서 SMOTE 같은 리샘플링을 파이프라인에 끼워 넣으려면 imblearn.pipeline.Pipeline이 필요해요.

CV의 각 fold를 나누기 전에 SMOTE로 전체 데이터를 부풀리면, 검증 세트에도 합성 샘플의 "형제 데이터"가 원본 train 세트에 남아있게 되어 성능이 과대평가돼요. imblearn.Pipeline을 쓰면 CV의 각 fold마다 train 부분에만 SMOTE가 적용되고 validation 부분은 원본 그대로 유지되어 이 문제를 막아줍니다.

4. Sampler (imblearn)
클래스 불균형(class imbalance) 데이터에서 클래스별 샘플 개수를 조정해주는 도구예요. 예를 들어 사기 탐지 데이터에서 정상 99%, 사기 1%처럼 한쪽 클래스가 압도적으로 적으면, 모델이 다수 클래스만 예측해도 정확도가 99%가 나와버려서 소수 클래스를 제대로 못 배웁니다. Sampler는 이 비율을 학습 전에 조정해줍니다.

ㄱ) Over-sampling (소수 클래스를 늘림)

Sampler	                                    방식
RandomOverSampler	            소수 클래스 샘플을 단순 복제
SMOTE	                소수 클래스 샘플들 사이를 보간(interpolation)해서 새로운 합성 샘플 생성
ADASYN	                SMOTE와 비슷하지만, 분류가 어려운(경계에 가까운) 소수 샘플 주변에 더 많이 생성
BorderlineSMOTE	             결정 경계 근처의 소수 샘플 위주로 합성

ㄴ) Under-sampling (다수 클래스를 줄임)

Sampler	                                            방식
RandomUnderSampler	                    다수 클래스 샘플을 무작위로 제거
TomekLinks	                서로 다른 클래스인데 가장 가까운 이웃 쌍(경계에 애매하게 걸친 샘플)을 제거해 경계를 명확히 함
EditedNearestNeighbours (ENN)	이웃 대부분이 다른 클래스인 샘플을 제거 (노이즈 제거 효과)
NearMiss	                        소수 클래스와 가까운 다수 클래스 샘플만 선택적으로 남김

ㄷ) Combination (오버+언더 결합)

Sampler	                    방식
SMOTEENN	SMOTE로 늘린 뒤 ENN으로 노이즈성 샘플 정리
SMOTETomek	SMOTE로 늘린 뒤 TomekLinks로 경계 정리

노이즈가 많은 데이터에서 SMOTE만 쓰면 합성 샘플이 오히려 경계를 흐릴 수 있는데, 언더샘플링을 뒤에 붙여 정리해줍니다.

- 주의할 점
 -Sampler는 train 데이터에만 적용 — test/validation 데이터는 절대 리샘플링하면 안 됨 (실제 운영 환경의 분포를 반영해야 하니까)
 -sampling_strategy 파라미터로 목표 비율 조정 가능 (예: 'auto'는 소수=다수와 같아지도록, 0.5는 소수/다수 비율을 0.5로)
 -어떤 sampler가 최선인지는 데이터마다 다르므로, GridSearchCV로 sampler 종류·파라미터까지 함께 튜닝하는 경우도 많음

5. Classifier(분류기)
분류(classification) 문제를 푸는 모델이에요. 지금까지 얘기한 것들(X_train/y_train, ColumnTransformer, sampler)은 전부 데이터를 classifier에 넣기 위한 준비 과정이었고, classifier가 실제로 "이 데이터는 어떤 클래스에 속하는가"를 예측하는 역할을 합니다.

즉 y(타겟)가 범주형(카테고리)일 때 쓰는 모델이에요. (반대로 y가 연속값이면 회귀 모델, regressor를 씁니다.)

Classifier	                                                    특징
LogisticRegression	                    선형 결정 경계, 해석 쉬움, 빠름. 이름은 회귀지만 실제로는 분류
DecisionTreeClassifier	                규칙 기반 트리, 해석 쉬움, 과적합 잘 됨
RandomForestClassifier	                여러 트리를 앙상블(배깅), 과적합에 강함, 성능 준수
GradientBoostingClassifier 
/ XGBClassifier / LGBMClassifier	    부스팅 앙상블, 성능 우수, 캐글 등에서 많이 씀
SVC	                                    서포트벡터머신, 마진 최대화, 커널로 비선형 경계 가능
KNeighborsClassifier	                가까운 이웃들의 다수결로 예측, 단순하지만 느림(대용량 시)
GaussianNB	                            나이브 베이즈, 텍스트 분류 등에서 빠르고 가벼움

즉 전처리(ColumnTransformer) → 불균형 보정(sampler) → 분류(classifier) 순서로 이어지는 흐름에서, classifier는 이 파이프라인의 마지막 단계이자 실제 예측을 담당하는 핵심 모델이라고 보시면 됩니다.

분류 성능 평가 지표 (참고)
정확도(accuracy)만 보면 불균형 데이터에서 오해가 생기기 쉬워서, 보통 이런 지표를 같이 봅니다.

Precision/Recall/F1: 소수 클래스를 얼마나 잘 잡아내는지
ROC-AUC: 임계값에 무관한 전체적인 분류 성능
Confusion Matrix: 어떤 클래스를 어떤 클래스로 오분류했는지 직접 확인

6. AP(Average Precision) 최종 확인
불균형 데이터에서는 accuracy보다 AP(Average Precision, PR-AUC)가 더 신뢰할 수 있는 지표예요. Precision-Recall 곡선 아래 면적으로, 소수 클래스를 얼마나 잘 잡아내는지 보여줍니다.

7. 새 요청(new request) 예측
best_model이 파이프라인 전체(ColumnTransformer 전처리 포함)라서, 원본 raw 데이터를 그대로 넣어도 내부에서 전처리 → sampler(예측 시엔 자동 skip) → classifier 순으로 알아서 처리해준다는 점이에요

8. 모델 저장
학습된 파이프라인 객체를 파일로 저장해서, 나중에 다시 학습시키지 않고도 재사용할 수 있게 합니다
저장되는 건 전처리기+sampler+classifier가 합쳐진 파이프라인 전체 (학습된 파라미터 포함)

9. Reload 후 결과 동일성 확인
저장한 모델을 다시 불러와서, 저장 전과 동일한 예측 결과가 나오는지 검증하는 단계예요. 이건 "저장/직렬화 과정에서 뭔가 깨지지 않았는지" 확인하는 무결성 체크입니다.

10. TPE (Tree-structured Parzen Estimator)
Optuna가 기본으로 쓰는 하이퍼파라미터 탐색 알고리즘이에요. 앞서 설명한 GridSearchCV(전수 탐색)나 RandomizedSearchCV(무작위 샘플링)와 달리, 과거 시도 결과를 학습해서 다음에 시도할 지점을 똑똑하게 고르는 베이지안 최적화 계열 방법입니다.

GridSearchCV와 RandomizedSearchCV는 둘 다 "지금까지의 결과를 전혀 참고하지 않고" 후보를 고릅니다. 그리드는 정해진 모든 조합을, 랜덤은 그냥 무작위로 뽑을 뿐이죠. 그래서 이미 성능이 안 좋았던 영역 근처를 계속 낭비적으로 탐색할 수 있습니다.

TPE는 반대로 "지금까지 좋았던 시도들은 어떤 패턴이었는가"를 보고, 다음 후보를 그 패턴에 가깝게 뽑습니다.

일반적인 베이지안 최적화(예: Gaussian Process 기반)는 p(성능 | 하이퍼파라미터)를 직접 모델링하는데, TPE는 이걸 뒤집어서 접근합니다.

    - 지금까지 시도한 하이퍼파라미터 조합들을 성능 기준으로 정렬합니다.
    - 상위 일정 비율(예: 상위 25%)을 "좋은 그룹", 나머지를 "나쁜 그룹"으로 나눕니다.
    - 각 그룹의 하이퍼파라미터 분포를 별도로 추정합니다 — 좋은 그룹의 분포를 l(x), 나쁜 그룹의 분포를 g(x)라 부릅니다. 이 분포 추정에 커널 밀도 추정(Parzen window)을 쓰기 때문에 이름에 "Parzen Estimator"가 들어갑니다.
    - 다음 시도할 후보는 l(x)/g(x) 비율이 큰 지점, 즉 "나쁜 그룹보다 좋은 그룹에 훨씬 더 흔했던" 조합을 고릅니다. (이게 통계적으로 Expected Improvement를 최대화하는 것과 동치임이 알려져 있습니다.)
    - 그 지점에서 실제로 모델을 학습·평가해 결과를 관측값에 추가하고, 1~4를 반복합니다.

즉 "좋았던 조합들이 밀집된 영역"과 "나빴던 조합들이 밀집된 영역"을 비교해서, 좋은 쪽에는 흔하고 나쁜 쪽에는 드문 지점을 계속 찾아가는 방식이에요.    

11. Tree-structured
하이퍼파라미터들이 서로 조건부 관계를 가질 때가 많습니다. 예를 들어 "optimizer가 Adam이면 beta1·beta2를 튜닝하지만, SGD면 momentum을 튜닝한다"처럼요. 이런 하이퍼파라미터 공간은 평평한 격자가 아니라 트리 구조를 이룹니다. TPE는 각 파라미터의 밀도를 독립적으로(트리를 따라가며) 추정하기 때문에, 이런 조건부·계층적 탐색 공간을 자연스럽게 다룰 수 있습니다. Gaussian Process 기반 베이지안 최적화는 이런 비정형 공간을 다루기 어려운데, TPE는 상대적으로 잘 처리합니다.

import optuna
from sklearn.model_selection import cross_val_score

def objective(trial):
    n_estimators = trial.suggest_int('n_estimators', 50, 300)
    max_depth = trial.suggest_int('max_depth', 3, 15)
    
    pipe.set_params(
        classifier__n_estimators=n_estimators,
        classifier__max_depth=max_depth
    )
    score = cross_val_score(pipe, X_train, y_train, cv=5, scoring='average_precision').mean()
    return score

study = optuna.create_study(direction='maximize')  # 기본 sampler가 TPESampler
study.fit = study.optimize(objective, n_trials=50)

print(study.best_params)

suggest_int/suggest_float/suggest_categorical로 탐색 공간을 정의하면, TPE가 매 trial마다 이전 결과들을 참고해 다음 후보를 제안합니다. 명시적으로 지정하려면 optuna.create_study(sampler=optuna.samplers.TPESampler())처럼 쓸 수 있습니다.

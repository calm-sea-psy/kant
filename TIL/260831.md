1. RNN (Recurrent Neural Network, 순환 신경망)
일반 신경망(MLP, CNN)은 입력 크기가 고정이고, 각 입력을 독립적으로 처리한다. 하지만 문장, 음성, 주가, 센서 로그처럼 순서가 의미를 갖는 데이터(sequence)는
    - 길이가 가변적이다
    - 앞의 내용이 뒤의 해석에 영향을 준다 ("나는 밥을 __" → "먹었다")
RNN은 이전 시점의 정보를 기억(hidden state)해서 다음 시점 계산에 넘겨주는 구조로 이 문제를 다룬다.

ㄱ) 은닉 상태(hidden state)    
RNN은 시퀀스를 한 시점씩 순서대로 훑어간다. 각 시점에서 하는 일은 늘 똑같다.

a. 두 가지를 입력으로 받는다
    - 지금 이 시점의 새 입력 (예: 문장의 이번 단어)
    - 바로 직전 시점에서 만들어 둔 "기억" — 지금까지 읽은 내용을 하나의 벡터로 압축해 놓은 요약본

b. 둘을 섞는다.    
    - 새 입력에 한 종류의 변환을 걸고, 직전 기억에 또 다른 종류의 변환을 걸어서 둘을 더한다. 여기에 비선형 함수(tanh 같은)를 통과시켜 값의 범위를 눌러준다. 이렇게 나온 결과가 갱신된 기억, 즉 이번 시점의 은닉 상태다. "이전까지의 맥락 + 방금 들어온 정보"를 다시 하나의 요약본으로 만든 것이다.

c. 필요하면 출력을 뽑는다
    - 갱신된 기억에 또 하나의 변환을 걸면 이번 시점의 출력이 된다 (예: 다음 단어 예측, 이 시점의 품사). 매 시점 출력이 필요 없는 문제(문장 전체 감정 분류 등)라면 마지막 시점의 기억만 쓰기도 한다.

d. 다음 시점으로 넘어간다
    - 이번에 만든 기억이 다음 시점에서 "직전 기억"으로 다시 들어간다. 이 되먹임이 반복되면서 정보가 시간축을 따라 계속 전달된다.    

ㄴ) 가중치를 공유한다
입력을 변환하는 규칙, 이전 기억을 변환하는 규칙, 출력을 뽑는 규칙 — 이 세 가지 규칙(가중치)은 모든 시점에서 완전히 동일한 것을 재사용한다. 시점마다 새로 만들지 않는다.

    - 길이에 상관없이 처리 가능: 규칙이 고정이므로 시퀀스가 5개든 500개든 같은 규칙을 그만큼 더 반복하면 된다. 학습해야 할 파라미터 수는 시퀀스 길이와 무관하게 일정하다.

    - 위치와 무관한 패턴 학습: "이런 입력이 들어오면 기억을 이렇게 바꿔라"라는 규칙이 문장 앞이든 뒤든 똑같이 적용된다. CNN이 이미지의 어느 위치에서든 같은 필터로 특징을 잡아내는 것과 같은 발상이다.

ㄷ) BPTT
Backpropagation Through Time. 시퀀스를 펼친 뒤 일반 역전파를 적용한다. 긴 시퀀스는 계산·메모리 부담이 커서 보통 일정 길이로 잘라서 학습한다(truncated BPTT).

ㄹ) 기울기 소실/폭발
같은 W_hh를 반복해서 곱하며 역전파하기 때문에
    - W_hh의 영향이 1보다 작으면 → 기울기가 지수적으로 소실 → 먼 과거를 학습 못함 (장기 의존성 문제)
    - 1보다 크면 → 기울기 폭발 → 발산 (gradient clipping으로 완화)
즉 바닐라 RNN은 실제로 "10~20 스텝 전"쯤부터 기억을 (거의) 못 한다.    

W_hh : RNN이 한 시점에서 기억을 갱신할 때 세 가지 변환 규칙을 사용한다. 그중 하나가 "직전 시점의 은닉 상태(기억)를 받아서 이번 시점 기억에 얼마나, 어떻게 반영할지"를 정하는 규칙이다.

ㅁ) 개선
    - LSTM : cell state와 3개의 게이트(input/forget/output)로 정보를 더하고 지우며 장기 기억을 유지. 덧셈 기반 경로 덕에 기울기가 잘 흐른다.
    - GRU : LSTM 간소화판. 게이트 2개(update/reset), cell state 없음. 파라미터 적고 학습 빠름, 성능은 대체로 비슷.
    - 양방향(Bi-RNN) : 앞→뒤, 뒤→앞 두 방향 은닉 상태를 결합. 전체 문장이 주어진 분류·태깅에 유리 (실시간 생성엔 불가).
    - 다층(stacked) RNN : 은닉 상태를 다음 층 입력으로 쌓아 표현력 확대.

2. LSTM (Long Short-Term Memory, 장단기 메모리)
RNN의 문제: 기억이 매 시점 무조건 W_hh를 통과하며 변형되고, 역전파 때 그게 연쇄로 곱해져 먼 과거의 학습 신호가 소실된다. 짧은 의존성(단기 기억)은 잡지만 긴 의존성(장기 기억)은 못 잡는다.

ㄱ) LSTM의 해법은 두 가지다.
    - 정보를 실어 나르는 별도의 고속도로를 만든다 — cell state
    - 그 고속도로에서 무엇을 지우고, 더하고, 내보낼지를 학습된 스위치로 조절한다 — 게이트

ㄴ) RNN은 시점마다 넘기는 게 은닉 상태 하나였다. LSTM은 두 개를 넘긴다.
    - cell state (셀 상태, c_t) : 장기 기억. 시간축을 따라 흐르는 컨베이어 벨트. 매 시점 큰 변형 없이, 곱셈과 덧셈이라는 가벼운 연산만 거쳐 지나간다. 여기가 기울기가 잘 흐르는 경로다.
    - hidden state (은닉 상태, h_t) : 단기 기억이자 이번 시점의 출력. cell state를 필터링해서 "지금 당장 밖으로 내보낼 부분"만 뽑아낸 것.

ㄷ) 세 개의 게이트
게이트는 0~1 사이 값을 내놓는 작은 신경망이다. 0이면 "완전히 차단", 1이면 "완전히 통과", 그 사이면 부분 통과. 이 값을 정보 벡터에 원소별로 곱해서 흐름을 조절한다. 게이트가 몇을 낼지는 현재 입력과 직전 은닉 상태를 함께 보고 매 시점 스스로 결정한다.

a. forget gate (망각 게이트)
컨베이어 벨트 위의 기존 기억 중 무엇을 버릴지 정한다. "새 문단이 시작됐으니 앞 문단의 주어는 이제 잊자" 같은 판단. 게이트가 0을 내면 그 자리의 기억이 지워지고, 1을 내면 그대로 유지된다.

b. input gate (입력 게이트)
이번 시점의 새 정보 중 무엇을 벨트에 새로 실을지 정한다. 먼저 후보 정보(새로 기억할 만한 내용)를 만들고, 입력 게이트가 그중 실제로 저장할 부분을 골라낸다.
    - 이 두 게이트를 거쳐 cell state가 갱신된다: (기존 기억 × forget) + (새 후보 × input). 삭제와 추가가 명시적으로 분리돼 있다.

c. output gate (출력 게이트)
갱신된 cell state 중 이번 시점에 은닉 상태로 내보낼 부분을 정한다. 장기 기억 전체를 매번 노출하지 않고, 지금 필요한 만큼만 꺼낸다.

d. 결론
cell state 갱신이 덧셈 중심이라는 점이다. 바닐라 RNN은 이전 상태에 W_hh를 곱해서 다음 상태를 만들었지만(곱셈 연쇄 → 지수적 소실/폭발), LSTM의 cell state는 "이전 값에 forget 게이트를 곱하고, 거기에 새 정보를 더하는" 형태다.

forget 게이트가 1에 가까우면 이전 cell state가 거의 손실 없이 다음으로 넘어가고, 역전파 때도 기울기가 감쇠 없이 그 경로를 타고 먼 과거까지 흘러간다. 모델이 "이 정보는 오래 유지해야 한다"고 판단하면 forget 게이트를 1 근처로 열어서 사실상 기울기 고속도로를 스스로 뚫는 셈이다. 

3. RNN 과 LSTM 비교

| 항목 | 바닐라 RNN | LSTM |
|---|---|---|
| 시점 간 전달 상태 | 은닉 상태 1개 | cell state + hidden state 2개 |
| 기억 갱신 방식 | 곱셈 연쇄 (W_hh 반복) | forget로 지우고 input로 더함 (덧셈 경로) |
| 장기 의존성 | 취약 (수십 스텝에서 소실) | 상대적으로 강함 (수백 스텝) |
| 게이트 | 없음 | forget / input / output 3개 |
| 파라미터 수 | 기준 | 약 4배 (게이트마다 가중치 세트) |

    - GRU와 비교: GRU는 게이트 2개, cell state 없이 은닉 상태 하나로 합침. 파라미터가 적고 빠르며 성능은 대체로 비슷 — 데이터가 적거나 모델을 가볍게 하고 싶으면 GRU, 큰 데이터·긴 의존성이면 LSTM을 먼저 시도하는 경우가 많다.
    - 양방향 LSTM (BiLSTM) : 문장 전체가 주어지는 분류·개체명 인식·품사 태깅에서 오래 표준이었다.
    - 한계 : 여전히 순차 계산이라 병렬화가 안 되고, 아주 긴 문맥에서는 Transformer의 어텐션에 밀린다. 2018년 이후 NLP 주류는 넘어갔지만, 저지연 스트리밍·소형 모델·짧은 시계열에서는 지금도 현역이다.

4. RNN·LSTM 계열의 한계

ㄱ) 구조적 한계
a. 순차 계산 — 병렬화가 안 된다
    - GPU는 수천 개 연산을 동시에 처리할 때 진가를 발휘하는데, RNN은 시간축으로 이 병렬성을 못 쓴다. (배치 안의 여러 문장은 병렬 처리되지만, 한 문장 안 토큰들은 순차적.)
    - 학습 속도가 시퀀스 길이에 거의 비례해서 느려진다. Transformer는 문장 전체 토큰을 한 번에 처리한다 — 이 차이가 대규모 사전학습 시대에 RNN이 밀려난 결정적 이유다.
    - 추론(생성)에서는 어차피 한 토큰씩 뽑아야 해서 Transformer도 순차적이지만, 학습 단계의 병렬성 차이가 워낙 크다.

b. 고정 크기 은닉 상태 = 정보 병목    
    - 지금까지 읽은 내용 전부를 고정 길이 벡터 하나(예: 512차원)에 욱여넣어야 한다.
    - 문장이 길어질수록 이 벡터에 담아야 할 정보량은 늘어나는데 용량은 그대로다. 결국 오래된 정보가 새 정보에 밀려 덮어써진다(정보 감쇠).
    - seq2seq 번역에서 특히 심했다: 인코더가 원문 전체를 벡터 하나로 압축 → 디코더가 그것만 보고 번역. 긴 문장에서 성능이 급락했고, 이걸 뚫으려고 나온 게 어텐션이다(디코더가 매 스텝 원문의 모든 위치를 직접 참조). 어텐션이 너무 잘 돼서, 결국 "RNN 없이 어텐션만" 쓴 게 Transformer다.

c. 먼 거리 상호작용의 경로가 길다
    - 토큰 1과 토큰 100이 관계를 맺으려면 정보가 99개의 중간 스텝을 순서대로 통과해야 한다. 매 스텝 게이트·비선형을 거치며 조금씩 희석된다.
    - Transformer에서는 어떤 두 토큰이든 어텐션으로 한 번에 직접 연결된다(경로 길이 1).
    - LSTM이 forget 게이트로 장기 경로를 열 수 있다지만, 그건 "이 정보를 유지하라"고 미리 판단됐을 때 얘기다. 나중에야 중요해지는 정보는 그 사이에 이미 희석돼 있다.    

d. 단방향성
    - 기본 RNN은 왼쪽에서 오른쪽으로만 읽는다.    
    - BiLSTM이 양방향을 붙였지만 전체 시퀀스가 미리 주어질 때만 가능하다. 실시간 생성·스트리밍에서는 못 쓴다.
    - 또 양방향은 두 방향을 마지막에 이어붙이는(concat) 식이라, 진짜 양방향 상호작용이 아니라 두 단방향의 조합에 가깝다.

ㄴ) 학습상의 한계

a. 기울기 문제가 완화됐을 뿐 사라지진 않았다
    - 수백 스텝을 넘어가면 여전히 학습이 어렵다. "장기"라는 게 무한이 아니다.
    - 기울기 폭발은 오히려 LSTM에서도 흔해서 gradient clipping이 거의 필수다.
    - forget 게이트가 학습 초기에 잘못 닫히면 기억을 계속 잃는 방향으로 수렴하기도 한다(그래서 bias를 1로 초기화하는 요령).

b. 시간·메모리 비용 (BPTT)
    - 역전파를 하려면 시퀀스를 펼친 뒤 모든 중간 시점의 활성값을 저장해야 한다. 길이에 비례해 메모리가 늘어난다
    - 긴 문서는 통째로 학습 못 하고 일정 길이로 잘라서(truncated BPTT) 학습 → 자른 경계를 넘는 의존성은 애초에 학습 불가.

c. 생성 시 노출 편향 (exposure bias)
    - 학습 때는 각 시점에 정답 토큰을 다음 입력으로 넣어준다(teacher forcing). 하지만 실제 생성 때는 자기가 만든(틀릴 수 있는) 토큰을 넣는다.
    - 한 번 틀리면 그 틀린 상태가 은닉 상태에 남아 다음 예측을 더 망치고, 오류가 눈덩이처럼 커진다.
    - 이건 Transformer 디코더도 공유하는 문제이긴 하지만, RNN은 상태가 한 벡터로 이어져서 회복이 더 어렵다.

d. 계층적·구조적 정보를 명시적으로 못 담는다    
언어에는 중첩된 구(句) 구조, 괄호 짝, 들여쓰기 같은 계층이 있는데 RNN은 평평한 순차열로만 본다. 깊게 중첩된 구조나 아주 긴 범위의 문법적 일치(주어-동사 수 일치가 긴 삽입절을 사이에 두고 있을 때 등)에서 자주 틀린다.

5. RNN/LSTM이 남아 있는 곳
한계가 곧 퇴출은 아니다. Transformer의 약점(문맥 길이에 대해 계산량이 제곱으로 증가, 상태를 계속 들고 있어야 함)이 부담인 자리에서는 여전히 유리하다.
    - 저지연 스트리밍 : 음성 인식, 실시간 번역 — 토큰 하나 들어올 때마다 상태만 갱신하면 됨 (Transformer는 매번 전체 재계산 경향)
    - 임베디드·모바일 : 파라미터·메모리 적음
    - 짧은 시계열 예측 : 센서, 수요 예측 등 — 굳이 큰 모델이 필요 없음
    - 온라인 학습 : 데이터가 순차적으로 도착하는 상황

최근에는 이 "상태를 순차적으로 들고 가되 병렬 학습도 되게" 만든 계열(S4, Mamba 같은 state space model, 선형 어텐션류)이 RNN의 발상을 되살려 긴 문맥에서 Transformer의 대안으로 연구되고 있다.

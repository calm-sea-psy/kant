1. ReLU
ReLU(Rectified Linear Unit)는 딥러닝에서 가장 널리 쓰이는 비선형 활성화함수입니다.
::ReLU(x) = max(0, x)
입력이 0보다 크면 그대로 통과시키고, 0 이하면 전부 0으로 만듭니다. 그래프로 보면 x<0 구간은 완전히 평평한 0, x≥0 구간은 기울기 1인 직선입니다.

    nn.ReLU()
    # 또는 함수형으로 사용가능 
    torch.relu(x)

ㄱ) 사용하는 이유     
Linear만 계속 쌓으면 아무리 층을 늘려도 결국 하나의 선형 변환과 수학적으로 동일해집니다. 층과 층 사이에 ReLU 같은 비선형 함수를 끼워 넣어야만 "선형 변환 → 비선형 변환"이 반복되면서 곡선 형태의 복잡한 함수를 표현할 수 있습니다.

ㄴ) 단점 — Dying ReLU
입력이 음수인 뉴런은 출력도 gradient도 항상 0이 됩니다. 학습 중 특정 뉴런의 가중치가 안 좋게 업데이트되어 계속 음수 입력만 받게 되면, 그 뉴런은 영영 gradient가 0이라 다시는 업데이트되지 않고 "죽어버리는" 현상이 발생할 수 있습니다. 이를 보완하기 위해 음수 구간에도 작은 기울기를 주는 변형들(Leaky ReLU, PReLU, ELU, GELU 등)이 나왔습니다.

ㄷ) 사용위치
MLP에서는 보통 은닉층 사이(nn.Linear → nn.ReLU() → nn.Linear)에 넣고, 출력층에는 잘 쓰지 않습니다 — 회귀는 출력에 제약이 없어야 하고, 분류는 Sigmoid/Softmax가 loss 함수 안에 이미 내장되어 있기 때문입니다.

2. Sigmoid 와 BCEWithLogitsLoss

ㄱ) Sigmoid는 임의의 실수를 0~1 사이 값으로 압축하는 함수입니다.
    - x → +∞이면 결과는 1에 가까워지고, x → -∞이면 0에 가까워집니다.
    - x = 0일 때 결과는 정확히 0.5입니다.
    - 출력이 0~1 사이라서 확률로 해석하기 좋습니다 — 이진분류에서 "이 샘플이 클래스 1일 확률"로 자연스럽게 쓰입니다.

ReLU와 마찬가지로 계단함수를 대체하는 활성화함수 중 하나지만 Sigmoid는 입력값이 크거나 작을 때(양 끝으로 갈수록) 기울기가 거의 0으로 눌리는 gradient vanishing 문제가 있어서, 요즘은 은닉층 활성화함수로는 잘 안 쓰고 주로 이진분류의 출력을 확률로 바꾸는 용도로만 씁니다.    

ㄴ) BCE(Binary Cross Entropy)는 이진분류에서 "예측 확률이 정답과 얼마나 다른가"를 측정하는 손실함수입니다.
BCEWithLogitsLoss는 이 BCE 계산 앞에 Sigmoid를 내부적으로 합쳐놓은 버전입니다

    loss_fn = nn.BCEWithLogitsLoss()
    loss = loss_fn(logits, targets)

    # 위 한 줄은 개념적으로 아래와 동일합니다
    probs = torch.sigmoid(logits)
    loss = -(targets*torch.log(probs) + (1-targets)*torch.log(1-probs)).mean()

a.수치 안정성
Sigmoid와 BCE를 따로 계산하면 극단적인 logit 값에서 문제가 생깁니다.
    - logit이 아주 큰 음수(예: -100)면 sigmoid(-100)이 부동소수점 오차로 정확히 0.0이 되어버리고, 그다음 log(0)은 -inf가 되어 loss가 깨집니다.
    - BCEWithLogitsLoss는 Sigmoid와 log를 수학적으로 미리 정리한 형태(log-sum-exp 트릭)로 한 번에 계산해서, 이런 극단값에서도 오버플로/언더플로 없이 안정적인 값을 냅니다.
그래서 "Sigmoid 붙이고 → BCELoss" 조합 대신 BCEWithLogitsLoss 하나만 쓰는 것이 PyTorch의 표준 관례입니다.    

    model = nn.Sequential(
        nn.Linear(4, 16),
        nn.ReLU(),
        nn.Linear(16, 1),   # Sigmoid 없이 raw logit 그대로 출력!
    )

    loss_fn = nn.BCEWithLogitsLoss()
    logits = model(x)              # shape: (batch, 1), sigmoid 안 거친 raw 점수
    loss = loss_fn(logits, targets)  # targets: 0.0/1.0 float, shape 동일

b.주의할 점    
    - 모델 마지막 레이어에 nn.Sigmoid()를 직접 붙이면 안 됩니다 — loss 함수 안에 이미 포함되어 있어서, 붙이면 Sigmoid가 두 번 적용되는 셈이 됩니다.
    - 확률 값 자체가 필요한 추론 시점(예: p > 0.5로 클래스 판정)에만 별도로 torch.sigmoid(logits)를 호출합니다.
    - targets는 nn.MSELoss처럼 float(0.0/1.0)이어야 하고, logits와 shape이 정확히 맞아야 합니다
    브로드캐스팅 실수 가 여기서도 흔히 발생합니다.

c.이진분류에서 추론(inference) 시점에 logit → 확률 → label 변환하는 용도로는 Sigmoid를 거의 항상 씁니다
    - 학습 시: BCEWithLogitsLoss가 Sigmoid를 내부적으로 이미 포함하고 있어서, 모델은 raw logit만 출력하고 loss 계산에 Sigmoid를 따로 안 붙입니다(붙이면 이중 적용 버그).
    - 추론 시: loss 계산이 필요 없고, 사람이 보거나 판정에 쓸 확률/label이 필요하므로 이때 명시적으로 Sigmoid를 적용합니다.

    model.eval()
    with torch.no_grad():
        logits = model(x)                    # raw score, shape (batch, 1)
        probs = torch.sigmoid(logits)        # 0~1 확률로 변환
        labels = (probs > 0.5).long()        # threshold로 0/1 label 결정

d.기타사항
    - threshold 조정: 0.5가 기본이지만, 클래스 불균형이 심하거나(사기 탐지, 스팸 필터 등) recall/precision 트레이드오프가 중요하면 0.3, 0.7 같은 값으로 threshold를 튜닝하는 경우가 많습니다. 이때 확률(probs)이 필요하지 label(0.5 고정 판정)만으로는 안 되니 Sigmoid가 꼭 필요합니다.

    - logit과 threshold 0.5 비교는 사실 logits > 0과 동일: sigmoid(x) > 0.5는 수학적으로 x > 0과 같기 때문에, threshold가 0.5로 고정이라면 Sigmoid 없이 logits > 0으로 바로 label만 뽑아도 결과는 같습니다. 다만 실제 확률값(신뢰도 점수, ROC-AUC 계산 등)이 필요하면 결국 Sigmoid를 거쳐야 합니다.

3. Softmax 와 CrossEntropyLoss 그리고 argmax

ㄱ) Softmax는 여러 개의 raw score(logit)를 받아서 총합이 1인 확률 분포로 바꿔주는 함수입니다. 다중분류(클래스가 3개 이상)에서 Sigmoid의 역할을 하는 함수라고 보면 됩니다.

각 클래스의 logit을 지수함수에 넣고, 전체 합으로 나눠서 정규화합니다. 결과는:
    - 모든 값이 0~1 사이
    - 전체 합이 정확히 1
    - logit이 클수록 지수함수 특성상 확률도 비대칭적으로 더 커짐(가장 큰 logit이 확률도 압도적으로 커지는 경향)

    logits = torch.tensor([2.0, 1.0, 0.1])   # 클래스 3개짜리 raw score
    probs = torch.softmax(logits, dim=-1)     # tensor([0.659, 0.242, 0.099]) — 합 1.0

dim=-1은 마지막 차원(클래스 차원)을 기준으로 정규화하라는 뜻입니다. (batch, num_classes) shape에서 배치별로 각각 정규화되도록 항상 dim=-1을 지정합니다.

ㄴ) nn.CrossEntropyLoss()는 Softmax + Negative Log Likelihood(NLL)를 내부적으로 합쳐놓은 손실함수입니다 CEWithLogitsLoss와 정확히 같은 이유(수치 안정성)로 Softmax를 분리하지 않고 하나로 결합해서 계산합니다.

    loss_fn = nn.CrossEntropyLoss()

    logits = model(x)          # shape: (batch, num_classes), raw score
    targets = torch.tensor([0, 2, 1])   # shape: (batch,), 정수 클래스 인덱스!

    loss = loss_fn(logits, targets)

a.BCEWithLogitsLoss와 가장 다른 점 — targets의 형태    

                            BCEWithLogitsLoss	            CrossEntropyLoss
targets dtype	            float (0.0/1.0)	                   long (정수)
targets shape	        logits와 동일 (batch, 1)	    클래스 차원 없이 (batch,)
의미	                    각 샘플의 정답 확률	         각 샘플의 정답 클래스 인덱스

    - targets를 원-핫 벡터로 넣는 실수를 자주 하는데, CrossEntropyLoss는 원-핫이 아니라 정수 인덱스(0, 1, 2, ...)를 그대로 받습니다. 여기서 shape/dtype 실수가 제일 많이 난다고 앞서 언급한 부분입니다.
    - 마지막에 nn.Softmax()를 직접 붙이면 안 됩니다 — BCEWithLogitsLoss에서 Sigmoid를 따로 안 붙이는 것과 똑같은 이유로, loss 안에 이미 포함되어 있습니다.

ㄷ) argmax는 텐서에서 가장 큰 값의 인덱스를 반환하는 함수입니다. 값 자체가 아니라 "몇 번째 위치에 있었는가"를 돌려줍니다. 

    probs = torch.tensor([0.1, 0.7, 0.2])
    torch.argmax(probs)          # tensor(1)  -- 0.7이 인덱스 1에 있으므로   

ㄹ) 추론 파이프라인

    model.eval()
    with torch.no_grad():
        logits = model(x)                          # (batch, num_classes)
        probs = torch.softmax(logits, dim=-1)       # 확률 분포로 변환
        preds = torch.argmax(probs, dim=-1)         # 확률이 가장 큰 클래스 인덱스 = 예측 label

Softmax는 순서를 보존하는 단조증가 함수라서, "어떤 클래스의 확률이 가장 큰가"는 Softmax를 적용하기 전 logit에서 봐도 결과가 같습니다. 즉 torch.argmax(logits, dim=-1)과 torch.argmax(probs, dim=-1)은 항상 동일한 결과를 냅니다. 그래서 label만 필요하면(확률값 자체는 필요 없으면) Softmax 없이 logit에서 바로 argmax를 뽑아도 되고, 확률 수치(신뢰도, top-k 확률 등)가 필요할 때만 Softmax를 거치면 됩니다.  

a. 신뢰도(confidence)가 필요한 경우
    - 불확실한 예측 걸러내기: 예를 들어 이미지 분류 서비스에서 confidence가 0.55밖에 안 되면 "애매하니 사람이 재검토" 또는 "모른다고 답변"으로 처리하고, 0.95 이상일 때만 자동 처리하는 식의 threshold 기반 라우팅이 흔합니다. label 하나만 알면 이 구분이 불가능합니다.
    - 다운스트림 로직의 입력값: 추천 시스템, 광고 클릭률 예측(CTR) 등은 애초에 label이 아니라 확률값 자체가 최종 산출물입니다("이 유저가 클릭할 확률 0.03"). 순위를 매기거나(ranking), 여러 모델의 점수를 조합할 때도 확률이 필요합니다.
    - Calibration 검증: 모델이 "90% 확신"이라고 한 예측들이 실제로 90% 맞는지 점검하는 것(calibration)은 정확도 평가와 별개로 중요한 신뢰성 지표입니다.

b. Top-k 확률이 필요한 경우    
    - 후보 여러 개 보여주기: 검색 자동완성, 이미지 태깅, OCR 오탈자 후보처럼 "1등만" 아니라 "1~5등 후보와 각각의 점수"를 함께 보여주는 UX가 많습니다.
    - Beam search / 샘플링: 텍스트 생성(LLM 포함)에서 다음 토큰을 고를 때 top-1만 고정으로 뽑지 않고, top-k 확률 분포에서 샘플링하거나 여러 경로를 동시에 탐색(beam search)합니다.

c. label(argmax)만으로 충분한 경우
    이미 정해진 자동화 파이프라인에서 "맞다/틀리다"만 판정하면 끝나는 단순 분류(예: 스팸 최종 차단 여부가 이미 확정된 threshold로 결정된 경우)라면 굳이 확률을 안 봐도 됩니다.

결론적으로, 프로덕션에서 정확도(accuracy) 계산이나 단순 자동화만 목적이면 argmax(label)로 충분하지만, 사용자에게 신뢰도를 보여주거나 threshold를 조정 가능하게 하거나 다른 시스템과 점수를 조합해야 하면 확률(softmax 출력) 자체를 보존해서 넘기는 게 좋습니다.    

4. Sigmoid 와 Softmax의 차이점

                    Sigmoid	                                    Softmax
계산 단위	    원소 하나 (독립적)	                   지정한 축(axis) 전체 (서로 의존)
필요한 정보	    자기 자신 값만	                       "같은 그룹"이 뭔지 (= dim)
출력 특성	    각 값이 개별적으로 0~1	               지정한 축 기준 합이 1
용도	        이진분류(클래스 1개당 독립 확률)	    다중분류(클래스들 간 상대적 확률 분포)

이진분류에서 Sigmoid는 "이 클래스일 확률"과 "아닐 확률"을 계산 없이 암묵적으로 처리하는 반면(출력 뉴런 1개면 충분), 
다중분류의 Softmax는 "클래스 A일 확률"이 "클래스 B, C일 확률"과 서로 상대적으로 결정되는 구조라서, 어떤 원소들이 서로 "경쟁"하는 그룹인지를 dim으로 명시해줘야 하는 것입니다.

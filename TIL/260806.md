1. 선형 변환
행렬 데이터를 선형 변환할 수 있고 대표적으로 스케일링, 반사, 투영, 회전이 있다.

ㄱ) 스케일링
서로 다른 단위/크기를 가진 데이터를 맞출 때, 또는 특정 축의 중요도를 조정할 때.

| 분야 | 사용 예 |
|---|---|
| 데이터 전처리 | StandardScaler, MinMaxScaler — 특성마다 단위가 다를 때(나이 vs 소득) 스케일을 맞춤 |
| 이미지 처리 | 이미지 확대/축소(리사이즈) |
| class4 실습 | 리스크 모델에서 "연체 이력" 비중을 10배로 키우는 것 (대각행렬 D) |

ㄴ) 반사
데이터를 뒤집어서 대칭성을 만들거나, 좌우/상하 반전이 필요할 때.

| 분야 | 사용 예 |
|---|---|
| 이미지 증강(Data Augmentation) | 이미지를 좌우 반전시켜 학습 데이터를 늘림 (개 사진을 뒤집어도 여전히 "개") |
| 컴퓨터 그래픽스 | 거울 반사 효과, 대칭 도형 그리기 |
| 신호 처리 | 파형을 뒤집어 위상을 반전 |

ㄷ) 투영
고차원 데이터를 저차원으로 "눌러서" 요약하거나, 불필요한 정보를 버릴 때.

| 분야 | 사용 예 |
|---|---|
| PCA(주성분분석) | 가장 중요한 몇 개 축으로 고차원 데이터를 투영해 차원 축소 — 오늘 얘기했던 PCA가 바로 "투영"의 대표 사례 |
| 그림자/그래프 | 3D 물체를 2D 화면에 투영해서 렌더링 |
| 추천 시스템 | 고차원 임베딩 벡터를 낮은 차원으로 압축해 유사도 계산 속도 향상 |

ㄹ) 회전
방향(각도)을 바꾸되 형태나 크기는 그대로 유지해야 할 때.

| 분야 | 사용 예 |
|---|---|
| 이미지 증강 | 사진을 몇 도 회전시켜 학습 데이터 다양성 확보 |
| 로봇공학/게임 | 캐릭터·카메라·팔의 방향 제어 |
| PCA와 연결 | 오늘 배운 것처럼, PCA는 "데이터를 회전시켜서 축들이 서로 무관해지게(공분산행렬을 대각행렬로) 만드는" 과정 — 회전이 핵심 메커니즘 |

| 변환 | 데이터 분석/딥러닝에서의 역할 |
|---|---|
| 스케일링 | 전처리(정규화), 특성 중요도 조정 |
| 반사 | 데이터 증강(이미지) |
| 투영 | 차원 축소(PCA), 정보 압축 |
| 회전 | 데이터 증강, PCA의 핵심 연산, 좌표계 정렬 |

    - CNN의 데이터 증강 파이프라인(반사+회전으로 이미지 데이터를 늘림)
    - PCA(회전+투영으로 차원 축소)

2. 선형변환의 3가지 조건
ㄱ) 가산성(T(u+v)=T(u)+T(v))
    - 두 벡터를 미리 합친 뒤 변환 = 각각 변환한 뒤 나중에 합침

ㄴ) 동차성(T(cu)=cT(u))
    - 입력을 c배로 늘리면, 출력도 정확히 c배로 늘어나야 함

ㄷ) 원점보존(T(0)=0)
    - 원점은 항상 원점으로 남아 있어야 함

3. span & rank

ㄱ) span
    - span은 벡터 여러 개를 계수 곱해서 더해 만들 수 있는 모든 점들의 집합

ㄴ) rank
    - 독립적인 방향의 개수
    - rank = 열 개수 - (다른 열들의 조합으로 만들어지는 열의 개수)
    - 가우스 소거법으로 행들을 서로 빼서(소거해서) 정리한 뒤, 완전히 0으로 사라지지 않고 남은 행(row)의 개수

rank = span의 "차원(dimension)"
span이 "직선"이면 → rank는 1
span이 "평면"이면 → rank는 2
span이 "3차원 공간"이면 → rank는 3
span은 "만들 수 있는 공간 자체"(도형)이고, rank는 그 공간이 "몇 차원짜리인지"를 나타내는 숫자

| 도구 | 알 수 있는 것 |
|---|---|
| Rank | "중복이 있는가?", "몇 개나 중복인가?" (개수만) |
| 영공간(Null Space) | "정확히 어떤 컬럼이, 어떤 조합으로 중복인가?" (구체적 관계) |
| Span | 그 벡터들이 도달 가능한 공간 자체 (rank는 이 공간의 차원) |

Rank    = "이 7개 열쇠 중 진짜 필요한 건 5개뿐이야" (개수만 앎)
영공간   = "3번 열쇠는 사실 1번 열쇠를 복사한 거고, 4번은 2번+3번을 합친 거야" (누가 누구인지 특정)

4. 조건수

어떤 행렬(또는 그 행렬이 표현하는 연립방정식)이 "입력값의 작은 변화에 얼마나 민감하게 반응하는가"를 나타내는 숫자다.
조건수는 "계산 결과를 실제로 믿고 써도 되는지"를 미리 점검하는 안전장치

가장 큰 특이값 = "안 짜부라진 방향"의 크기
가장 작은 특이값 = "거의 짜부라진 방향"의 크기 (0에 매우 가까움)

조건수 = 큰 값 / 아주 작은 값 = 엄청나게 큰 숫자

5. 유일해와 무한해의 차이점

| 구분 | rank(A) | 변수 수 | 비교 결과 | 판정 |
|---|---|---|---|---|
| 유일해 | 2 | 2 | rank(A) == 변수 수 | 유일해 |
| 무한해 | 1 | 2 | rank(A) < 변수 수 | 무한해 |

유일해 케이스: A1=[[2,1],[1,3]]
    - 미지수 2개(x,y), 독립적인 식도 2개(rank=2)
    - "조건 2개로 미지수 2개를 딱 맞게 고정" -> 답이 정확히 하나로 정해짐

무한해 케이스: A2=[[2,1],[4,2]]
    - 미지수는 2개인데, 두 번째 식이 첫 번째 식의 배수라 실질적으로 "같은 조건"
    - 즉 독립적인 식은 1개(rank=1)뿐인데 미지수는 2개
    - "조건 1개로 미지수 2개를 못 다 고정" -> x를 아무렇게나 정해도 y가 그에 맞춰 정해짐 -> 무수히 많은 (x,y) 쌍이 답이 됨

기하학적으로 확인하면 더 쉽게 이해가 됨

유일해: 기울기가 다른 두 직선 -> 딱 한 점에서 만남 (변수 2개를 조건 2개가 완전히 고정)
무한해: 완전히 겹치는 두 직선 -> 그 직선 위의 모든 점이 답 (조건이 1개뿐이라 나머지 1개 자유도가 남음)

6. 정리

조건수 = 가장 큰 특이값 / 가장 작은 특이값

무한해 -> 행렬이 특이 -> 가장 작은 특이값 = 정확히 0
       -> 조건수 = 큰 값 / 0 = 무한대(∞)

| 상황 | 문제의 성격 |
|---|---|
| 조건수 높음(불안정) | 계산은 가능하지만 그 답을 못 믿음 (신뢰도 문제) |
| 무한해(rank 부족) | 답이 여러 개라 애초에 "하나로 못 정함" (정보 부족 문제) |

| 조합 | 실제로 성립하는가 | 의미 |
|---|---|---|
| 조건수 높음 + 유일해 | ✅ 성립 | 정답은 있지만 신뢰도는 낮음 |
| 조건수 낮음 + 유일해 | ✅ 성립(가장 이상적) | 정답도 있고 신뢰도도 높음 |
| 조건수 ∞ + 무한해 | ✅ 성립(항상 이렇게 됨) | 정답이 여러 개, "신뢰도"라는 개념 자체가 적용 안 됨 |
| 조건수 낮음 + 무한해 | ❌ 성립 불가 | 무한해는 특이행렬을 의미하므로 조건수는 항상 무한대 |

| 도구 | 알려주는 것 | 정확한 표현 |
|---|---|---|
| rank vs 변수 수 | 해가 몇 개인가 (0개/1개/무한개) | 존재성·유일성 판단 |
| 조건수 | 그 해를 얼마나 믿을 수 있는가 | 신뢰도·안정성 판단 |

7. 대각화

정사각행렬 A를 "고유벡터 행렬(P) × 대각행렬(D) × P의 역행렬"로 분해하는 것

P: 고유벡터들을 열로 쌓은 행렬
D: 고유값들을 대각선에 놓은 대각행렬
조건: A가 정사각행렬이고, 서로 독립인 고유벡터를 n개(행렬 크기만큼) 가져야 함 (rank(P)=n)

A =     P       ×   D       ×  P⁻¹
        ↑           ↑           ↑
    좌표축을    그 축마다   원래 좌표축으로
    고유벡터    독립적으로    되돌림
    방향으로    배율만 조정
    바꿈

| 이유 | 요약 |
|---|---|
| 계산 효율 | 거듭제곱·반복 변환을 대각원소만 다루는 것으로 극단적으로 단순화 |
| 해석 가능성 | 복잡한 변환을 "축별 독립적인 배율 조정"으로 분해해 이해 쉽게 만듦 |
| PCA의 근간 | 공분산행렬을 대각화하는 것이 곧 PCA — 오늘 배운 모든 개념의 최종 목적지 |

rank(고유벡터 행렬 P) == n(행렬 크기)  ->  대각화 가능
rank(고유벡터 행렬 P) <  n(행렬 크기)  ->  대각화 불가능

8. 회귀계수
각 특성을 얼마나 반영해야 실제 결과값(y)에 가장 가깝게 예측할 수 있다.
(XᵀX)⁻¹Xᵀy라는 공식으로 계산되고, 그 결과는 예측 오차가 입력 데이터의 모든 방향과 직교하는 지점과 같다

9. 잔차
실제값(y)과 예측값(ŷ)의 차이 즉, "모델이 못 맞춘 만큼의 오차" 이다.

    pred = Xd @ coef_lstsq   # 모델이 예측한 값
    resid = y - pred          # 실제값 - 예측값 = 잔차

잔차가 0에 가까울수록 모델이 그 샘플을 잘 맞췄다는 뜻
잔차가 크면 모델이 그 샘플에서 많이 틀렸다는 뜻

| 항목 | 내용 |
|---|---|
| 정의 | 실제값과 예측값의 차이 (y - ŷ) |
| 역할 | 모델이 얼마나 틀렸는지 재는 지표, 최소제곱법의 최적화 대상 |
| 최적 상태 | 잔차가 설계행렬의 모든 열과 직교할 때 (더 이상 줄일 수 없는 최소 오차) |
| 오차제곱합 | 잔차들을 제곱해서 더한 값 — 이게 RMSE 계산의 기초 |

10. 직교성

ㄱ) 정의
두 벡터의 내적이 0이면 서로 직교(수직)
u·v = 0  ->  직교

ㄴ) 직교행렬
모든 열이 서로 직교 + 각각 길이 1인 행렬
AᵀA = I

ㄷ) 직교행렬의 장점
    - 역행렬을 따로 계산할 필요 없이 전치만 하면 됨: A⁻¹ = Aᵀ
    - 변환 전후 길이·각도가 보존됨 (노름이 그대로 유지)
    - 서로 정보가 안 겹치는 독립적인 축을 만들어줌

ㄹ) 두 가지 다른 종류의 "직교성 확인"
    - 변환/행렬 자체의 정합성 확인: "이 행렬이 진짜 직교 성질을 갖췄나?"
    - 최적화 결과의 정합성 확인: "이 회귀계수가 진짜 최적해가 맞나?"

주의: 두 확인은 같은 도구(내적=0)를 쓰지만 검증 대상이 다르다.
첫 번째는 행렬 자체의 속성을 확인하는 것이고, 두 번째는 풀이 결과(회귀계수)가 최적인지를 확인하는 것.
잔차 직교성은 "모델이 신뢰할 만한가"가 아니라 "이 계수가 수학적 최적해인가"만 확인한다.

1. TorchVision의 transform
데이터를 모델에 넣기 전에 전처리·가공하는 함수(또는 함수들의 묶음) 를 말해요. 특히 Dataset의 __getitem__에서 파일을 읽어온 직후에 적용되는 걸 자주 보게 됩니다.

ㄱ) 사용하는 이유 
이미지 파일을 그냥 읽으면 PIL Image 객체일 뿐, 모델이 바로 쓸 수 있는 텐서가 아니에요. 게다가 크기도 제각각이고 픽셀 값 범위(0~255)도 정규화가 안 돼 있죠. transform이 이 격차를 메워줍니다
    - PIL Image → Tensor 변환
    - 이미지 크기를 모델 입력 크기로 통일 (Resize)
    - 픽셀 값을 정규화 (Normalize) — 학습 안정성에 중요
    - 데이터 증강(augmentation) — RandomCrop, RandomHorizontalFlip 등으로 학습 데이터를 다양화해 과적합 방지

ㄴ) 실행
Dataset은 생성자에서 transform을 인자로 받아 저장만 해두고, 실제 적용은 __getitem__이 호출되는 순간(=DataLoader가 배치를 만들려고 샘플을 하나씩 꺼낼 때)에 일어납니다.

        class ImageDataset(Dataset):
            def __init__(self, file_paths, labels, transform=None):
                self.file_paths = file_paths
                self.labels = labels
                self.transform = transform

            def __getitem__(self, idx):
                img = Image.open(self.file_paths[idx])   # 이 시점에 파일에서 읽음
                if self.transform:
                    img = self.transform(img)             # 리사이즈, 정규화 등
                return img, self.labels[idx]

1000장을 미리 다 변환해서 메모리에 올려두는 대신, "필요할 때마다 하나씩" 지연 처리(lazy)하는 구조라 메모리를 절약할 수 있어요.

    - 실제 사용은 torchvision.transforms를 이용해 여러 단계를 Compose로 묶습니다.

        from torchvision import transforms

        transform = transforms.Compose([
            transforms.Resize((224, 224)),
            transforms.ToTensor(),                      # PIL/ndarray -> Tensor, 0~1로 스케일
            transforms.Normalize(mean=[0.485, 0.456, 0.406],
                                std=[0.229, 0.224, 0.225]),
        ])

이렇게 만든 transform 객체를 Dataset(..., transform=transform)처럼 넘기면, 위 코드의 self.transform(img)가 이 파이프라인을 순서대로 실행하는 방식입니다.        

2. ToTensor와 shape 변화
PIL Image(또는 numpy 배열)를 PyTorch 텐서로 바꾸면서 두 가지가 동시에 바뀝니다.

    ㄱ) 값의 범위: uint8 0~255 → float32 0.0~1.0로 스케일링 (255로 나눔)
    ㄴ) 축(shape)의 순서: (H, W, C) → (C, H, W)

    원본 이미지 (PIL/numpy):  (Height, Width, Channel)   예) (224, 224, 3)
    ToTensor 이후:            (Channel, Height, Width)   예) (3, 224, 224)

이미지 라이브러리(PIL, OpenCV, matplotlib 등)는 픽셀을 화면에 그리는 관점이라 "가로 x 세로 x 채널" 순서가 자연스러운 반면, PyTorch의 nn.Conv2d는 채널을 먼저 오는 (C, H, W) 순서를 기대하도록 설계돼 있기 때문이에요. 그래서 ToTensor가 이 변환(HWC → CHW, permute)까지 같이 처리해줍니다.
DataLoader가 배치로 묶으면 여기에 batch 차원이 하나 더 붙어서 최종적으로 (batch, C, H, W)가 됩니다.

3. Normalize(mean, std)
ToTensor가 끝낸 [0,1] 범위의 텐서를 채널별로 다시 이렇게 바꿉니다.

    output = (input - mean) / std     # 채널마다 각각 적용

예를 들어 Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])면 R/G/B 채널 각각 자기 평균을 빼고 표준편차로 나눠서, 대략 평균 0, 표준편차 1 근처 분포로 만드는 거예요.

    - 의미와 이유

        a. 픽셀 값이 [0,1]처럼 항상 양수면 활성화값·그래디언트가 한쪽으로 치우치기 쉬운데, 평균을 0 근처로 옮기면 학습이 더 안정적이고 빠르게 수렴합니다.
        b. 위 숫자(0.485, 0.456, 0.406 / 0.229, 0.224, 0.225)는 임의의 값이 아니라 ImageNet 데이터셋 전체의 채널별 평균/표준편차예요. ImageNet으로 사전학습(pretrained)된 모델(ResNet, VGG 등)을 쓸 거면 그 모델이 학습될 때 봤던 것과 같은 분포로 입력을 맞춰줘야 성능이 제대로 나옵니다.
        c. 직접 처음부터 학습하는 모델이면 꼭 이 값일 필요는 없고, 본인 데이터셋의 mean/std를 계산해서 써도 됩니다.

ToTensor는 "이미지 형식을 PyTorch가 쓸 수 있는 텐서 shape/스케일로 변환", Normalize는 "그 텐서의 분포를 모델이 학습하기 좋은 형태(평균 0 근처)로 조정" — 역할이 다른 별개의 전처리 단계이고, 그래서 Compose로 항상 순서대로(ToTensor → Normalize) 묶어 씁니다.

    - mean/std
    "이 데이터셋 전체에서, 각 채널(R/G/B)의 픽셀 값들이 평균적으로 얼마이고 얼마나 퍼져있는가" 를 나타내는 통계값이에요.
    
        mean[c] = (모든 이미지, 모든 위치의 채널 c 픽셀값)의 평균
        std[c]  = (모든 이미지, 모든 위치의 채널 c 픽셀값)의 표준편차

    이미지 하나의 shape이 (3, H, W)라면, R 채널만 떼어내 모든 이미지·모든 픽셀 위치 값을 다 모은 다음 그 값들의 평균/표준편차를 낸 게 mean[0], std[0]인 거죠.        

4. Data Augmentation(데이터 증강)
학습 데이터가 부족하거나 다양성이 떨어질 때, 원본 이미지에 무작위 변형을 가해서 매 epoch마다 조금씩 다른 버전을 모델에게 보여주는 기법입니다. 실제로 새 데이터를 모으는 게 아니라, 가진 데이터를 "여러 번 다르게 보여주는" 방식이에요.

ㄱ) 필요한 이유
모델이 학습 데이터의 사소한 특징(배경, 각도, 밝기 등)까지 외워버리면 과적합(overfitting)이 생깁니다. 예를 들어 고양이 사진이 전부 정면을 보고 있으면, 모델이 "고양이 = 정면 얼굴"로 잘못 학습할 수 있어요. Augmentation으로 좌우 반전·회전·크롭된 버전을 섞어 보여주면, 모델이 "이런 변형에도 여전히 고양이"라는 좀 더 본질적인 특징을 배우게 됩니다. 즉 일반화 성능(generalization)을 올리는 정규화(regularization) 기법의 일종이에요.

ㄴ) 적용시점
transform 파이프라인 안에 그냥 하나의 단계로 들어갑니다. 다만 학습(train)용과 검증/테스트(val/test)용 transform을 다르게 만드는 게 핵심이에요.

        train_transform = transforms.Compose([
            transforms.RandomResizedCrop(224),      # 무작위 위치/크기로 잘라 리사이즈
            transforms.RandomHorizontalFlip(p=0.5), # 50% 확률로 좌우 반전
            transforms.ColorJitter(brightness=0.2, contrast=0.2),  # 밝기/대비 랜덤 변화
            transforms.ToTensor(),
            transforms.Normalize(mean=[...], std=[...]),
        ])

        val_transform = transforms.Compose([
            transforms.Resize(256),
            transforms.CenterCrop(224),   # 검증은 항상 같은 결과가 나와야 하므로 랜덤 요소 없음
            transforms.ToTensor(),
            transforms.Normalize(mean=[...], std=[...]),
        ])

검증/테스트 데이터에 무작위 변형을 넣으면 매번 다른 이미지로 평가하는 셈이 돼서 성능 측정이 불안정해지고, 애초에 "실제 배포 환경에서 볼 입력"을 평가해야 하므로 여기서는 리사이즈·크롭 정도의 결정적(deterministic) 전처리만 씁니다.        

ㄷ) 자주 쓰는 종류
종류	                                    예시
기하학적 변형	            RandomHorizontalFlip, RandomRotation, RandomResizedCrop
색상 변형	                ColorJitter(밝기/대비/채도/색조)
노이즈/가림	RandomErasing(일부 영역을 지움)
혼합 기법(고급)	            Mixup, CutMix — 두 이미지·라벨을 섞음

ㄹ) 실행시점
앞서 본 __getitem__이 호출될 때마다 self.transform(img)가 실행되므로, 같은 이미지라도 epoch마다 랜덤 시드가 달라 매번 다르게 변형된 버전이 모델에 들어갑니다. 그래서 원본 데이터셋 크기는 그대로지만, 실질적으로 모델이 보는 데이터의 다양성은 훨씬 커지는 효과가 있어요.

5. Batch Size
한 번의 학습 스텝(forward → loss → backward → update)에서 한꺼번에 처리할 이미지(샘플) 개수예요. 앞선 예시에서 이미지 1200장, batch_size=4면 한 스텝마다 4장씩 묶어서 모델에 넣고, 그 4장의 평균 loss로 한 번 파라미터를 업데이트합니다.
    
    - GPU는 여러 샘플을 동시에 행렬 연산으로 처리하는 데 최적화돼 있어서, 묶어서 처리하는 게 훨씬 빠릅니다 (병렬 연산 활용).
    - 한 장씩(batch_size=1)이면 그 한 장의 특이한 노이즈에 파라미터가 휘둘려서 학습이 불안정해요. 여러 장을 평균 내면 그래디언트가 더 안정적입니다.

ㄱ) 크기에 따른 트레이드오프
                    작은 batch (예: 8)	                        큰 batch (예: 256)
메모리 사용	            적음	                            많음 (GPU 메모리 한계에 잘 걸림)
학습 안정성	            노이즈 많음(때론 일반화에 도움)	                안정적
속도(step당)	        느림(병렬성 덜 활용)	                        빠름
1 epoch당 스텝 수	    많음 (1200/8=150)	                    적음 (1200/256≈5)    

6. Shuffle
매 epoch 시작 시 데이터셋의 순서를 무작위로 섞는 것이에요. DataLoader(dataset, batch_size=4, shuffle=True)처럼 설정합니다.

셔플을 안 하면 매 epoch마다 이미지가 항상 같은 순서로, 같은 조합으로 배치가 묶입니다. 예를 들어 데이터가 "고양이 600장 다음에 강아지 600장" 순으로 정렬돼 있다면, 셔플 없이는 초반 배치들은 전부 고양이만, 후반은 전부 강아지만 보게 되어 모델이 학습 중간에 급격히 편향될 수 있어요. 셔플하면 매 epoch 배치 구성이 달라져서 이런 순서 편향을 없애고, 더 일반화된 학습이 됩니다.
    
    - 학습(train): 항상 shuffle=True — 순서 편향 방지
    - 검증/테스트(val/test): 보통 shuffle=False — 평가는 순서가 결과에 영향 없어야 하고, 굳이 섞을 이유가 없음 (결과 확인·디버깅 시 순서 유지가 편함)

7. Train / Valid / Test Split
전체 데이터셋을 용도가 다른 세 그룹으로 나누는 것이에요.

그룹	                    역할	                                 모델이 직접 학습(파라미터 갱신)에 쓰나?
Train	        실제 파라미터를 갱신하는 데 사용	                                ✅
Validation	  학습 중간중간 "지금 잘 되고 있나" 확인, 
              하이퍼파라미터 튜닝·조기종료(early stopping) 판단용	                ❌ (평가만, 갱신 X)
Test	      학습·튜닝이 전부 끝난 뒤 딱 한 번 최종 성능을 확인	                 ❌ (평가만, 갱신 X)

    - Train만으로 평가하면 "외운 건지 진짜 이해한 건지" 구분이 안 됩니다(과적합 여부 확인 불가).
    - Validation 없이 Test만 있으면, 모델 구조나 하이퍼파라미터(learning rate, batch size 등)를 튜닝할 때마다 Test 결과를 들여다보게 되고, 그러다 보면 결국 Test 데이터에도 "간접적으로 맞춰서" 튜닝하게 됩니다 — 이러면 Test가 더 이상 "본 적 없는 데이터"가 아니게 돼서 최종 성능 평가가 왜곡돼요.
    - Validation은 "튜닝하면서 계속 들여다봐도 되는 시험지", Test는 "모든 게 끝난 후 딱 한 번만 채점하는 진짜 시험지" 역할로 분리합니다.

    비율 :: 데이터가 많으면 대략 70/15/15 또는 80/10/10, 데이터가 매우 크면(수백만 장) 98/1/1 처럼 validation·test 비율을 훨씬 작게 잡기도 해요.

    train_dataset, val_dataset, test_dataset = split(full_dataset, ratios=[0.7, 0.15, 0.15])

    train_loader = DataLoader(train_dataset, batch_size=4, shuffle=True)   # 학습용: 섞음
    val_loader   = DataLoader(val_dataset,   batch_size=4, shuffle=False)  # 검증용: 안 섞음
    test_loader  = DataLoader(test_dataset,  batch_size=4, shuffle=False)  # 테스트용: 안 섞음

    for epoch in range(num_epochs):
        train(model, train_loader, ...)      # 파라미터 갱신
        val_loss = evaluate(model, val_loader, ...)  # 갱신 없이 성능만 확인
        # val_loss 기준으로 early stopping, 모델 저장 등 결정

    test_acc = evaluate(model, test_loader, ...)   # 학습 다 끝난 후 마지막에 딱 1번

Validation·Test에는 앞서 얘기한 augmentation(랜덤 crop, flip 등)을 넣지 않는 게 원칙이에요 — 항상 같은 조건으로 평가해야 결과를 신뢰할 수 있기 때문입니다

8. random_split
random_split은 PyTorch(torch.utils.data.random_split)에서 제공하는 함수로, 앞서 얘기한 train/valid/test 분할을 실제 코드로 구현할 때 가장 많이 쓰는 방법이에요. 하나의 Dataset을 무작위로 여러 개의 작은 Dataset(정확히는 Subset)으로 쪼개줍니다.

    ㄱ) 기본 사용법

        from torch.utils.data import random_split

        full_dataset = ImageDataset(file_paths, labels, transform=transform)  # 전체 1200장

        train_dataset, val_dataset, test_dataset = random_split(
            full_dataset,
            lengths=[840, 180, 180],   # 70% / 15% / 15% (개수로 지정)
        )    
        
        또는 비율(합이 1이 되는 실수)로도 지정 가능해요.     

            train_dataset, val_dataset, test_dataset = random_split(
            full_dataset,
            lengths=[0.7, 0.15, 0.15],
        )

    ㄴ) 내부적으로 하는 일        
        a. len(full_dataset)개의 인덱스(0, 1, 2, ..., 1199)를 만들고
        b. 그 인덱스들을 무작위로 섞은 뒤
        c. lengths에 지정한 개수만큼 잘라서 각각 Subset 객체로 반환합니다

    즉 실제 데이터를 복사하는 게 아니라, "원본 데이터셋 + 이 인덱스들만 쓴다"는 정보만 가진 얇은 래퍼(Subset) 를 만드는 거예요. 그래서 메모리를 거의 추가로 안 씁니다.

    ㄷ) 재현성(reproducibility) — generator
    기본적으로 매번 실행할 때마다 다르게 섞입니다. 같은 분할을 재현하고 싶다면 시드를 고정한 generator를 넘겨줘야 해요.

        import torch
        g = torch.Generator().manual_seed(42)
        train_dataset, val_dataset, test_dataset = random_split(
            full_dataset, lengths=[0.7, 0.15, 0.15], generator=g
        )

    이렇게 하면 코드를 다시 돌려도 항상 같은 이미지들이 train/val/test로 나뉘어서, 실험을 여러 번 비교할 때 조건을 동일하게 유지할 수 있습니다.        

    ㄹ) DataLoader와 연결
    Subset도 Dataset이라서 그대로 DataLoader에 넣을 수 있어요. 이전 답변에서 본 구조 그대로예요
    
        train_loader = DataLoader(train_dataset, batch_size=4, shuffle=True)
        val_loader   = DataLoader(val_dataset,   batch_size=4, shuffle=False)
        test_loader  = DataLoader(test_dataset,  batch_size=4, shuffle=False)
    
    ㅁ) 주의할 점
        
        - 클래스 비율을 보장하지 않음: 단순히 인덱스를 무작위로 섞어서 자르기 때문에, 예를 들어 고양이/강아지 데이터가 불균형하면 train에는 고양이가 많고 val에는 강아지가 많이 몰리는 등 우연히 클래스 비율이 안 맞을 수 있어요. 클래스 비율까지 맞추고(stratified split) 싶다면 sklearn.model_selection.train_test_split(..., stratify=labels)처럼 별도 방법을 써야 합니다.
        
        - transform 공유 문제: random_split은 원본 full_dataset에 이미 지정된 transform을 그대로 물려받는 Subset을 만들기 때문에, train은 augmentation을 쓰고 val/test는 안 쓰고 싶다면(이전에 설명한 train_transform vs val_transform처럼) 이렇게 나눈 뒤 직접 val_dataset의 transform을 바꿔주는 추가 처리가 필요해요. (보통은 Dataset을 2개 따로 만들고 각각 다른 transform으로 초기화한 뒤, 같은 인덱스 리스트를 양쪽에 적용하는 방식으로 우회합니다.)

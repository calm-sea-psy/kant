1. Dropout
학습 중에 각 뉴런의 출력을 확률 p로 0으로 만든다(끈다). 매 미니배치마다 랜덤하게 다른 부분망(sub-network)을 학습시키는 셈.

ㄱ) 사용하는 이유
특정 뉴런들의 "공적응(co-adaptation)"을 막는다. 어떤 뉴런이 옆 뉴런의 존재에 의존해서 오류를 보정하는 걸 방해 → 각 뉴런이 독립적으로 유용한 특징을 학습.
앙상블 효과: 지수적으로 많은 얇은 네트워크들을 평균낸 것과 비슷.

ㄴ) 학습 vs 추론
학습: 확률 p로 드롭, 살아남은 값을 1/(1-p)로 스케일(inverted dropout). 이렇게 하면 추론 때 아무 조정도 필요 없음.
추론: 드롭 안 함. 전체 네트워크 사용.
그래서 model.eval() / training=False 전환이 중요.

보통 값: 은닉층 p=0.5, 입력층 p=0.1~0.2. CNN의 conv층엔 잘 안 쓰고(공간적 상관 때문), FC층에 주로 사용.


2. Batch Normalization
각 층의 입력(activation)을 미니배치 단위로 정규화. 채널(또는 feature)별로 평균 0, 분산 1로 만든 뒤, 학습 가능한 파라미터 γ(스케일), β(시프트)로 다시 조정.

ㄱ) 사용하는 이유
원 논문은 "internal covariate shift 감소"라고 설명했지만, 이후 연구(Santurkar et al.)는 손실 표면(loss landscape)을 매끄럽게 만들어 그래디언트가 안정되는 것이 진짜 이유라고 본다.
더 큰 learning rate 사용 가능 → 학습 속도 향상.
가중치 초기화에 덜 민감.
약한 정규화 효과(미니배치 통계의 노이즈 때문).

ㄴ) 학습 vs 추론
학습: 현재 미니배치의 μ, σ² 사용. 동시에 이동평균(running mean/var)을 누적.
추론: 배치 통계 대신 학습 때 누적한 running 통계 사용. 배치 크기 1이나 배치 구성에 결과가 흔들리지 않도록.
여기서도 eval() 전환 필수. 안 하면 추론 결과가 배치에 따라 달라짐.

ㄷ) 약점
배치 크기가 작으면(예: 2~4) 통계 추정이 부정확 → 성능 저하. 이때 LayerNorm, GroupNorm, InstanceNorm 등 대안 사용.
RNN/시퀀스에는 적용이 까다로움(→ LayerNorm이 표준, Transformer도 LayerNorm).

보통 Linear/Conv → BN → 활성화(ReLU) 순서. BN이 bias 역할을 하므로 앞 층의 bias는 생략 가능.

| 구분 | Dropout | BatchNorm |
|---|---|---|
| 목적 | 정규화(과적합 방지) | 최적화 안정화 + 약한 정규화 |
| 노이즈 원천 | 랜덤 마스킹 | 미니배치 통계 |
| 배치 크기 의존 | 없음 | 큼 |
| 추론 시 | 끔 | running 통계로 전환 |

    - 함께 쓰면 충돌할 수 있음: Dropout이 분산을 바꿔서 BN의 통계 추정을 교란(train/test 불일치, "variance shift"). 그래서 ResNet 계열은 BN만 쓰고 Dropout은 안 쓰는 경우가 많다.
    - 함께 쓴다면 순서는 ... → BN → ReLU → Dropout 으로, BN 뒤에 Dropout을 두는 게 일반적.
    - 현대 CNN: BN 위주. Transformer: LayerNorm + Dropout 조합이 표준.


3. Early Stopping
학습을 정해진 epoch 수만큼 끝까지 돌리지 않고, 검증(validation) 성능이 더 이상 좋아지지 않는 시점에 멈춘다. 과적합이 본격화되기 전에 학습을 중단하는 정규화 기법.

ㄱ) 사용하는 이유
validation loss가 최저점을 찍고 올라가기 시작하는 구간 = 모델이 train 데이터의 노이즈까지 외우기 시작하는 지점. 그 최저점 근처의 가중치가 일반화 성능이 가장 좋다. Early stopping은 그 지점을 잡아낸다.

ㄴ) 동작 방식
    - 매 epoch(또는 일정 step)마다 validation 지표를 측정.
    - 지금까지의 best 지표보다 개선되면 → best 갱신하고 그 시점 가중치를 저장(checkpoint).
    - 개선이 없으면 → "인내 카운터(patience counter)" 증가.
    - 카운터가 patience 값에 도달하면 → 학습 중단.
    - 저장해둔 best 가중치를 최종 모델로 복원.

ㄷ) 주요 하이퍼파라미터

| 파라미터 | 의미 | 흔한 값 |
|---|---|---|
| patience | 개선 없이 몇 번 참을지 | 5~20 epoch |
| min_delta | "개선"으로 인정할 최소 변화량 | 0 ~ 1e-4 |
| monitor | 감시할 지표 | val_loss, val_accuracy 등 |
| mode | min(손실) / max(정확도) | 지표에 따라 |
| restore_best_weights | 멈춘 뒤 best 가중치로 되돌릴지 | True 권장 |

    - patience가 너무 작으면: validation 곡선의 일시적 출렁임(noise)에 속아 너무 일찍 멈춤(underfitting).
    - patience가 너무 크면: 이미 과적합된 뒤에도 계속 돌아 시간 낭비. 다만 restore_best_weights=True면 최종 모델 품질은 보호됨.

ㄹ) 장점
    - 사실상 공짜인 정규화. 추가 연산 거의 없음.
    - epoch 수를 미리 정확히 맞출 필요가 없어짐 → 넉넉하게 잡고 알아서 멈추게.
    - 학습 시간 절약.

ㅁ) 주의점 / 함정
    - 반드시 validation set 기준으로. train loss로 하면 의미 없고, test set으로 하면 test 정보가 새어들어감(데이터 누수).
    - validation 곡선이 한 번 올라갔다가 다시 내려오는 경우가 있음(특히 learning rate schedule, double descent). patience를 지나치게 짧게 잡으면 이걸 놓침.
    - cosine/step LR 스케줄과 함께 쓸 때 주의: LR이 떨어지는 마지막 구간에서 성능이 확 좋아지는 일이 많아서, 스케줄이 끝나기 전에 멈추면 손해. 이럴 땐 스케줄 완주를 우선하기도 함.
    - best checkpoint를 저장하는 로직과 결합하는 게 정석. 멈춘 순간의 가중치 ≠ 가장 좋았던 가중치.
    - mini-batch 노이즈가 큰 소규모 데이터에서는 validation 지표도 출렁여서 신뢰도가 낮음 → k-fold나 EMA 등 병행 고려.

ㅂ) 다른 정규화와의 관계
    - weight decay, dropout 등이 "학습 곡선 자체를 완만하게" 만든다면, early stopping은 "언제 멈출지"를 정한다 → 서로 보완적이고 대부분 같이 씀.
    - L2 정규화와 이론적 연관: 적절한 조건에서 early stopping은 L2 weight decay와 비슷한 효과를 낸다고 알려져 있음(gradient descent가 작은 norm 해부터 탐색하기 때문).


4. CNN 기초

ㄱ) Convolution, Kernel, Filter

a. Convolution (합성곱 연산)
입력 위에서 작은 가중치 창을 한 칸씩 미끄러뜨리며, 겹친 부분끼리 원소별 곱 → 전부 합해서 값 하나를 만든다. 이 값을 창 위치마다 기록하면 출력 격자(feature map)가 된다.

    입력의 한 패치 (3×3)   ⊙  kernel (3×3)   →  9개 곱   →  합 → 스칼라 1개
    창을 오른쪽으로 한 칸 이동 → 다음 스칼라 …

딥러닝에서 말하는 convolution은 엄밀히는 cross-correlation이다(수학의 convolution은 kernel을 뒤집지만, 학습으로 가중치를 정하므로 뒤집든 말든 차이가 없어 관행적으로 안 뒤집는다).

MLP의 Linear가 "모든 입력 × 모든 출력"을 연결한다면, convolution은 국소 연결 + 가중치 공유다
    - 국소 연결: 출력 한 점은 입력의 좁은 영역(창 크기)만 본다.
    - 가중치 공유: 같은 kernel을 이미지 전체 위치에 재사용한다. → 파라미터 수가 입력 크기와 무관하게 작다.

사용하는 이유
    - 파라미터 급감: 224×224 이미지를 Linear로 받으면 가중치가 수천만 개, 3×3 conv는 9개(×채널).
    - 평행이동 등변성(translation equivariance): 고양이가 왼쪽에 있든 오른쪽에 있든 같은 kernel이 같은 특징을 잡아낸다.
    - 계층적 특징: 앞쪽 층은 에지·색 대비 같은 저수준 패턴, 뒤로 갈수록 질감 → 부품 → 물체로 조합된다.

b. Kernel (커널)
convolution에서 미끄러지는 2D 가중치 격자 하나. 보통 3×3, 5×5, 7×7. 이 숫자들이 loss.backward() → optimizer.step()으로 갱신되는 학습 대상이다.
    - kernel 하나는 한 개의 입력 채널에 대해서만 작동한다.
    - 크기가 클수록 한 번에 넓은 영역을 보지만 파라미터·연산이 제곱으로 증가. 그래서 3×3을 여러 층 쌓아 넓은 시야를 얻는 게 현대 CNN의 표준(3×3 두 층 ≈ 5×5 한 층의 시야, 파라미터는 더 적음).

c. Filter (필터)
입력 채널 수만큼의 kernel을 쌓은 3D 묶음 + 편향 1개. filter 하나가 출력 채널(feature map) 하나를 만든다.
컬러 이미지(RGB, 3채널)에 3×3 conv를 한다면

    filter 1개 = kernel(3×3) for R
        + kernel(3×3) for G      →  shape (3, 3, 3) = (in_channels, kH, kW)
        + kernel(3×3) for B
        + bias 1개

    - 세 채널 각각에서 convolution한 결과를 채널 방향으로 더하고 bias를 얹어 → 출력 feature map 한 장.

출력 채널을 16개 원하면 이런 filter를 16개 둔다. → conv 층 하나의 전체 가중치 shape

    (out_channels, in_channels, kH, kW)  =  (16, 3, 3, 3)

PyTorch nn.Conv2d(3, 16, kernel_size=3)의 .weight가 정확히 이 shape이다.

Convolution = 작은 가중치 창을 훑으며 국소 곱-합으로 feature map을 만드는 연산.
Kernel = 그 창의 2D 가중치 격자(입력 채널 1개 담당).
Filter = 입력 채널 수만큼의 kernel 묶음 + bias, 출력 채널 1장을 생산.
conv 층 = filter를 out_channels개 모아둔 것, 가중치 shape (out_channels, in_channels, kH, kW).

ㄴ) Padding과 Stride

a. Padding (패딩)
convolution을 하기 전에 입력의 가장자리에 값을 덧대는 것. 보통 0을 두르는 zero-padding.
    - 출력 크기 유지: padding 없이 3×3 kernel로 convolution하면 매 층마다 가로·세로가 2씩 줄어든다. 층을 깊게 쌓으면 feature map이 금세 사라진다. 가장자리에 한 겹 두르면(padding=1 + 3×3) 입출력 크기가 같아진다.
    - 가장자리 정보 손실 방지: padding이 없으면 모서리 픽셀은 창의 중심에 한 번도 오지 못한다 → 중앙 픽셀보다 훨씬 적게 반영됨. padding은 이 불균형을 완화한다.
    - 크기 설계 자유도: "conv는 크기 유지, 다운샘플링은 stride나 pooling이 전담"으로 역할을 분리할 수 있어 아키텍처 설계가 깔끔해진다(ResNet 등이 이 방식).
    - zero padding: 0으로 채움. 압도적으로 표준.
    - reflect / replicate: 가장자리 픽셀을 거울반사/복제. 경계에서 인위적인 0 에지가 생기는 걸 싫어하는 경우(일부 이미지 생성·복원).
    - valid(=padding 없음) vs same(출력=입력 크기가 되도록 자동 계산). 프레임워크 옵션 이름.

b. Stride
convolution 창을 미끄러뜨릴 때 몇 칸씩 건너뛸지. 기본값 1(한 칸씩). 2면 한 칸 걸러 계산.
    - stride=1: 모든 위치에서 계산 → 출력 크기 ≈ 입력 크기(padding 있을 때).
    - stride=2: 위치를 절반만 계산 → 출력 가로·세로가 약 1/2, 픽셀 수는 약 1/4로 줄어듦. → 다운샘플링.
다운샘플링을 하는 이유
    - 연산량·메모리 절감: 뒤쪽 층이 다뤄야 할 feature map이 작아진다.
    - receptive field 확대: 같은 3×3 kernel이라도 stride로 줄어든 map 위에서는 원본 기준 더 넓은 영역을 커버한다 → 층을 덜 쌓고도 넓은 시야 확보.
    - pooling 대체: 예전엔 conv(stride=1) → maxpool(stride=2) 조합이 표준이었으나, 요즘은 conv(stride=2) 하나로 합쳐 학습 가능한 다운샘플링을 하는 설계도 많다(strided convolution).
단점
위치를 건너뛰므로 정보 손실이 있다. 미세한 위치 정보가 중요한 작업(segmentation, keypoint)에서는 stride를 남발하면 성능이 떨어져, dilation이나 낮은 stride를 쓰기도 한다.

| 구분 | Padding | Stride |
|---|---|---|
| 조절 대상 | 출력 크기를 늘림(줄어드는 것 방지) | 출력 크기를 줄임(다운샘플링) |
| 파라미터 수 영향 | 없음 | 없음 |
| 연산량 영향 | 약간 증가 | 크게 감소 |
| 전형적 조합 | P=(K−1)/2로 크기 보존 | 크기 유지 층은 S=1, 줄이는 층만 S=2 |
| 정보 손실 | 방지함 | 유발함(위치 건너뜀) |

CNN의 전형적 패턴: conv(K=3, P=1, S=1)로 특징을 뽑으며 크기를 유지하다가, 단계가 바뀌는 지점에서만 conv(S=2) 또는 pooling으로 크기를 절반씩 줄이고 채널 수는 두 배로 늘린다. 이렇게 "해상도↓ + 채널(특징 종류)↑"를 반복하며 저수준 픽셀 정보를 고수준 의미 정보로 압축해 간다.

ㄷ) Pooling 연산
feature map 위에서 작은 창을 훑으며 그 안의 값들을 하나의 대표값으로 요약해 크기를 줄이는 연산. convolution과 창을 미끄러뜨리는 동작은 같지만, 곱-합 대신 max나 average 같은 고정 연산을 쓴다.

a. Max Pooling
창 안에서 가장 큰 값 하나만 남긴다. 가장 널리 쓰임.

    [[1, 3],   →  4
     [2, 4]]

    - "이 영역에 해당 특징이 강하게 나타난 곳이 있는가"만 남기고 정확한 위치·약한 반응은 버린다.
    - feature map은 "특정 패턴 검출기의 반응 지도"이므로, 최댓값 = 그 패턴이 가장 뚜렷한 지점.
    - backward: 최댓값이었던 위치로만 gradient가 흐르고 나머지는 0.

b. 사용하는 이유
    - 다운샘플링: feature map 크기를 줄여 이후 층의 연산량·메모리 절감. stride와 같은 목적.
    - 평행이동 불변성(translation invariance) 강화: 특징이 창 안에서 한두 픽셀 움직여도 max/average 결과는 거의 그대로 → "정확히 어디"보다 "있느냐"에 강건해짐.
        - convolution의 등변성(equivariance, 위치가 같이 이동)과 구별. pooling은 위치 정보를 의도적으로 흐리게 해서 불변성(invariance)에 가깝게 만든다.
    - receptive field 확대: 크기가 줄어든 map 위에서 같은 kernel이 원본 기준 더 넓은 영역을 커버.

ㄹ) Feature map
convolution filter 하나가 입력 위를 훑고 나온 2D 격자 출력. "이 filter가 반응하는 패턴이 입력의 어느 위치에 얼마나 강하게 있는가"를 나타내는 지도다.

filter 하나 → feature map 한 장. conv 층이 filter를 out_channels개 가지므로, 층 하나의 출력은 feature map out_channels장을 채널 방향으로 쌓은 3D 텐서다.

    conv 층 출력 shape = (batch, C_out, H_out, W_out)
                            ↑        ↑      ↑
                        feature map  세로   가로
                        몇 장인가    (공간 위치)

a. 채널(C) = "특징의 종류"
    - 채널 하나 = filter 하나의 반응 결과 = 하나의 특징 검출기.
    - 입력 이미지의 채널은 RGB라는 물리적 의미였지만, 중간 층부터는 "학습으로 만들어진 패턴 검출기 N개"다.
    - 예: 어떤 층의 32번 채널은 "45도 대각선 에지", 57번 채널은 "빨강-초록 경계"에 반응하도록 학습될 수 있다.

b. 공간(H×W) = "그 특징이 어디에 있는가"
    - feature map의 (i, j) 위치 값이 크다 = 원본 이미지에서 그 위치에 대응하는 영역에 해당 특징이 뚜렷하다.
    - convolution의 평행이동 등변성 때문에, 입력에서 특징이 이동하면 feature map에서도 같은 방향으로 이동한다.
    - 각 위치가 대응하는 원본 영역의 크기가 receptive field. 층이 깊어질수록 커진다.

c. 만들어지는 방법

    입력 (C_in, H, W)
    → filter 1개 = kernel C_in장 묶음이 각 입력 채널과 convolution
    → 채널 방향으로 합산 + bias
    → feature map 1장 (H_out, W_out)
    → 여기에 BatchNorm → ReLU 적용 (보통 이 상태를 activation map이라 부름)

CNN의 전형적 흐름은 "해상도↓ + 채널↑"의 반복

    - 공간 해상도는 줄어든다: stride나 pooling으로. 위치의 정밀도를 희생하는 대신 넓은 문맥을 본다.
    - 채널 수는 늘어난다: 저수준 특징은 몇 종류면 충분하지만, 고수준 특징(눈, 바퀴, 글자…)은 종류가 많아야 한다.
    - 결과적으로 앞쪽 feature map은 "픽셀에 가깝고 해석 가능한 무늬", 뒤쪽은 "사람 눈엔 안 보이지만 의미를 담은 추상적 채널".

Feature map = filter 하나가 만든 2D 반응 지도. 채널 축은 "어떤 특징인가", 공간 축은 "그 특징이 이미지의 어디에 있는가"를 나타낸다. CNN은 이 feature map의 해상도를 줄이고 채널 수를 늘려 가며 픽셀을 의미로 압축하고, 마지막 conv 층의 feature map은 Grad-CAM 같은 해석의 핵심 재료가 된다.

ㅁ) CNN classifier
CNN 조각들(convolution, filter, padding/stride, pooling, feature map)과 앞서 정리한 MLP·손실함수·train/eval을 하나로 조립하면 이미지 분류기가 된다.

    이미지  →  [특징 추출부 (backbone)]  →  [분류 헤드 (classifier head)]  →  클래스 logit
            conv/pool 반복, 공간 구조 유지        Linear, 벡터 처리(Flatten/GAP)

    - 특징 추출부: (C, H, W) feature map을 다루며 "픽셀 → 의미"로 압축. CNN 고유 부분.
    - 분류 헤드: feature map을 벡터로 바꿔 클래스 점수를 내는 부분. 사실상 MLP다 — 앞서 정리한 MLP 흐름이 여기 그대로 들어온다.

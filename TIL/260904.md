1. Transformer 아키텍처
ㄱ) 정의
Transformer는 순환(RNN)이나 합성곱(CNN) 없이 어텐션과 순방향 신경망만으로 시퀀스를 처리하는 신경망 아키텍처다.
    - 동일한 블록의 반복 stack — 각 블록 = 멀티헤드 셀프 어텐션 + 위치별 FFN
    - 잔차 연결(residual) 과 레이어 정규화(layer norm) 가 각 서브층을 감쌈
    - 위치 인코딩: 어텐션은 순서를 모르므로(순열에 대해 등변) 위치 정보를 따로 주입
    - 입력 임베딩 + 출력 projection(LM head)
    - 원조 버전은 인코더–디코더 구조 + 그 사이를 잇는 교차 어텐션

ㄴ) Self-Attention과 Transformer의 차이 — 범주가 다름

| 구분 | Self-Attention | Transformer |
|---|---|---|
| 정체 | 연산 / 메커니즘 (서브층 하나) | 완결된 아키텍처 / 모델 |
| 하는 일 | 토큰들끼리 정보를 섞음(라우팅) | 임베딩 → N개 블록 → 출력까지 전체 파이프라인 |
| 학습 파라미터 | W_Q/W_K/W_V/W_O 정도 (적음) | + FFN(대부분) + 임베딩 + head + LayerNorm |
| 순서 개념 | 없음 (그 자체로는 위치 구분 못 함) | 위치 인코딩으로 해결 |
| 비유 | 엔진 | 엔진 + 변속기 + 섀시 + 바퀴 = 자동차 전체 |

가장 중요한 포인트: 셀프 어텐션은 토큰 사이에서 정보를 "옮기고 섞을" 뿐, 내용을 거의 가공하지 않는다(연산 자체엔 파라미터가 거의 없음). 실제로 각 토큰의 표현을 "가공/연산"하는 건 FFN이다.

Transformer는 토큰끼리 섞기(어텐션) → 토큰별로 가공하기(FFN), 이 한 쌍을 N번 반복.

셀프 어텐션만으로는 모델이 아니다. Transformer는 그 어텐션을 여러 겹으로 쌓고, FFN·잔차·정규화·위치정보·입출력층을 붙여 학습 가능한 완성품으로 만든 것이다.

ㄷ) Encoder–Decoder 흐름
인코더가 원문 전체를 한 번에 읽어 표현을 만들고, 디코더가 번역문을 한 토큰씩 왼쪽에서 오른쪽으로 생성한다. 디코더는 매 스텝마다 (a) 지금까지 자기가 만든 번역문과 (b) 인코더가 만든 원문 표현을 둘 다 참조한다.

a. 인코더 (원문 처리, 병렬)
    - 원문 토큰화 → ID → 토큰 임베딩 + 위치 인코딩 → [B, L_src, D]
    - 인코더 층 N개 통과. 각 층:
        - 멀티헤드 셀프 어텐션 (양방향 — 모든 토큰이 모든 토큰을 봄, 마스크 없음)
        - Add & Norm
        - 위치별 FFN
        - Add & Norm
    - 출력: 원문 토큰마다 하나씩, 문맥이 반영된 벡터열 = 인코더 메모리. 교차 어텐션에서 K·V로 쓰이며, 한 번 계산해 모든 디코딩 스텝에서 재사용.

| 기호 | 이름 | 뜻 | 예시 값 |
|---|---|---|---|
| B | batch size | 한 번에 묶어 처리하는 문장 개수 | 32 |
| L_src | source sequence length | 원문(source) 한 문장의 토큰 개수. 배치 안에서 가장 긴 문장에 맞춰 패딩 | 20 |
| D | model dimension (d_model) | 토큰 하나를 나타내는 벡터의 길이 | 512 |

    - 읽는 법: "B개의 문장이 있고, 각 문장은 L_src개의 토큰으로 되어 있고, 각 토큰은 D개의 숫자로 된 벡터다."
    - 즉 이 텐서 안의 한 점 [b, i, :]은 b번째 문장의 i번째 토큰의 D차원 벡터 하나다.

b. 디코더 (번역문 생성, 자기회귀)
    - 지금까지 생성된 번역문 토큰 → 임베딩 + 위치 인코딩
    - 디코더 층 N개 통과. 각 층:
        - 마스크드 멀티헤드 셀프 어텐션 (causal mask — 토큰 i는 i 이하만 봄, 아직 안 만든 미래 토큰을 못 훔쳐봄)
        - Add & Norm
        - 교차 어텐션 (encoder–decoder attention): Q는 디코더, K·V는 인코더 출력. 번역문 쪽이 원문을 "골라 보는" 지점
        - Add & Norm
        - 위치별 FFN
        - Add & Norm
    - 마지막 디코더 출력 → 선형층(D → vocab 크기) → softmax → 다음 토큰 확률분포
    - 토큰 하나 선택(greedy/beam/샘플링) → 뒤에 붙임 → EOS 나올 때까지 2~4 반복

c. 어텐션 3종류 정리

| 위치 | Q 출처 | K·V 출처 | 마스크 |
|---|---|---|---|
| 인코더 셀프 어텐션 | 인코더 | 인코더 | 없음(양방향) |
| 디코더 셀프 어텐션 | 디코더 | 디코더 | causal(미래 가림) |
| 교차 어텐션 | 디코더 | 인코더 | 없음 |

    - 인코더 전용(BERT): 이해·분류·임베딩. 양방향 셀프 어텐션만.
    - 디코더 전용(GPT, Llama 등 대부분의 LLM): 마스크드 셀프 어텐션만, 교차 어텐션 없음. 생성에 특화.
    - 인코더–디코더(T5, BART, 원조): 번역·요약 같은 seq2seq.

ㄹ) 입력준비 / 문맥화 / 표현가공 / Task 출력
디코더 전용 LM 기준으로 설명한다.

a. 입력 준비 — 이산 기호를 벡터 공간으로
    - 토큰 임베딩: 각 ID를 임베딩 행렬에서 룩업 → D차원 벡터 ("이 토큰이 무엇인가")
    - 위치 인코딩: 위치 정보를 더함 ("이 토큰이 몇 번째인가"). 어텐션은 순서를 모르므로 필수. 방식: sinusoidal(원조) / 학습형(BERT·GPT-2) / RoPE·ALiBi(현대)
    - 결과: [B, L, D] — 각 토큰 = "정체성 + 위치"가 담긴 벡터
    - 핵심: 아직 토큰들은 서로 독립. 문맥이 전혀 안 섞인 상태.

b. 문맥화 — 토큰끼리 정보를 섞음
    - 각 블록의 멀티헤드 셀프 어텐션 서브층 (+ 잔차·정규화)
    - 이미 공부한 Q·Kᵀ → scale → softmax → ×V 과정. 각 토큰이 관련도에 따라 다른 토큰의 정보를 끌어와 자기 표현을 갱신
    - "혼자 있는 토큰 표현 → 문맥 속의 토큰 표현". "눈이 내린다" vs "눈이 아프다"의 "눈"이 갈라지는 지점
    - Transformer에서 토큰 간 정보가 이동하는 유일한 곳. 나머지는 전부 토큰별 독립 연산
    - 인코더면 양방향, 디코더면 causal 마스크로 볼 수 있는 문맥 범위가 정해짐

c. 표현 가공 — 토큰별로 "생각"
    - 각 블록의 위치별 FFN 서브층 (+ 잔차·정규화)
    - 선형 → 비선형(ReLU/GELU/SwiGLU) → 선형. 보통 D → 4D → D로 부풀렸다 줄임
    - 모든 토큰에 똑같이, 각각 독립적으로 적용 (토큰 간 이동 없음)
    - 파라미터의 대부분(약 2/3)과 사실적 지식이 여기 저장됨. "key-value 메모리"로 해석하는 연구가 많음
    - 어텐션이 "방 안을 돌며 필요한 메모를 모아오는" 단계라면, FFN은 "앉아서 모아온 걸 곱씹는" 단계
    - 문맥화·표현 가공 한 쌍 = Transformer 블록 1개. 이걸 N번(12·24·96...) 반복. 앞쪽 층은 표면·구문 특징, 뒤쪽 층은 의미·추상 특징

d. Task 출력 — 표현을 과제 형태로 변환
    - 마지막 블록의 [B, L, D] 표현을 과제가 요구하는 형태로 매핑하는 head
    - 언어 모델링(GPT): 선형층 D → vocab → softmax, 모든 위치에서 다음 토큰 예측. 보통 임베딩 행렬과 가중치 공유(weight tying)
    - 분류(BERT): [CLS] 토큰의 마지막 벡터 → 작은 MLP → 클래스 logits
    - 토큰 레이블링(NER·POS): 토큰마다 선형층 → 태그 logits
    - 문장 임베딩: 마지막 벡터들을 pooling(평균/CLS) → 벡터 하나
    - a~c 몸통은 과제 무관하게 사전학습되고, Task 출력의 head만 과제별로 갈아끼움. 사전학습 → 파인튜닝의 경계

| 구간 | 컴포넌트 | 토큰 간 정보 이동 | 파라미터 비중 | 텐서 변화 |
|---|---|---|---|---|
| 입력 준비 | 토큰 임베딩 + 위치 인코딩 | 없음 | 큼 (V×D 행렬) | [B,L] → [B,L,D] |
| 문맥화 | 멀티헤드 셀프 어텐션 (+잔차·정규화) | 있음 (유일) | 작음 (W_Q/K/V/O) | [B,L,D] → [B,L,D] |
| 표현 가공 | 위치별 FFN (+잔차·정규화) | 없음 (토큰 독립) | 큼 (~2/3) | [B,L,D] → [B,L,D] |
| Task 출력 | head (LM head / 분류기 등) | 과제에 따라 | 보통 작음 | [B,L,D] → 과제별 |

참고: 잔차·정규화 배치는 원조가 post-norm(서브층 → Add → Norm), 현대(GPT-2 이후)는 pre-norm(Norm → 서브층 → Add)으로 바뀌어 깊은 모델 학습이 안정화됐다.

2. Positional Encoding
셀프 어텐션은 순서를 모른다. 토큰을 뒤섞어도 각 토큰이 받는 표현이 똑같다(순열 등변). Q·Kᵀ는 벡터 내적일 뿐 "몇 번째 토큰"이라는 개념이 없다. 그래서 "고양이가 개를 쫓는다"와 "개가 고양이를 쫓는다"를 구분 못 한다.
그래서 위치 정보를 벡터로 만들어 토큰 임베딩에 더한다. x = token_embedding + positional_encoding (둘 다 D차원이라 합산 가능)

ㄱ) Sinusoidal Positional Encoding (고정 사인파 방식)
학습하지 않는 고정 함수로 위치 벡터를 만든다.

ㄴ) Learned Position Embedding (학습형 위치 임베딩)
위치 벡터를 역전파로 학습한다.

| 특징 | 범위 | 설명 |
|---|---|---|
| 짝수/홀수 차원에 sin/cos | Sinusoidal 전용 | 학습형(Learned)에는 sin/cos가 없음. 그냥 학습된 실수 값 |
| 차원마다 주기가 다름 | Sinusoidal 전용 | 파형이라서 "주기" 개념이 있음. 학습형은 주기라는 게 없음 |
| 결과가 D차원 | 절대 위치 인코딩 공통 | Sinusoidal·Learned 둘 다. 더하려면 D차원이어야 하니 당연 |
| Token Embedding에 더함 | 절대 위치 인코딩 공통 | Sinusoidal·Learned 둘 다 맨 아래서 1회 더함 |

3. Encoder-only
원조 Transformer의 인코더 스택만 떼어낸 것이다. 디코더 없음, 교차 어텐션 없음, causal mask 없음.
핵심은 어텐션이 양방향(bidirectional)이라는 것 — 모든 토큰이 왼쪽·오른쪽 전부 본다.

| 구분 | 하는 일 | 못 하는 일 |
|---|---|---|
| Encoder-only | 시퀀스 → 문맥이 반영된 토큰 벡터열 (이해·분류·검색·추출) | 자기회귀 생성 (다음 토큰 예측 구조가 아님) |

출력은 각 토큰의 문맥 표현이고, 여기에 task head를 붙여 쓴다.

ㄱ) Encoder Block 구조
전체 파이프라인

    input_ids                              [B, L]
    → 토큰 임베딩 + 위치 임베딩 + 세그먼트 임베딩   [B, L, D]   ← 입력 준비
    → Encoder Block × N
    → 각 토큰의 문맥 표현                     [B, L, D]
    → task head                                          ← Task 출력

4. Decoder-only
원조 Transformer의 디코더에서 교차 어텐션을 뺀 것이다. 인코더가 없으니 참조할 인코더 메모리도 없고, 남는 건 마스크드 셀프 어텐션 + FFN 뿐이다.

| 구분 | 원조 디코더 블록 | Decoder-only 블록 |
|---|---|---|
| 마스크드 셀프 어텐션 | O | O |
| 교차 어텐션 (Q=디코더, K·V=인코더) | O | X (인코더 자체가 없음) |
| 위치별 FFN | O | O |
| 서브층 수 | 3 | 2 |

하는 일은 언어 모델링 하나다. 입력도 출력도 같은 시퀀스이고, 정답은 입력을 한 칸 민 것("나는 밥을" → "밥을 먹었다"). 각 위치에서 다음 토큰의 확률분포를 내놓는다.

ㄱ) Decoder-only Block 구조
전체 파이프라인

    input_ids                       [B, L]
    → 토큰 임베딩 + 위치정보           [B, L, D]      ← 입력 준비
    → Decoder Block × N
    → 최종 LayerNorm
    → LM head (선형 D → vocab)        [B, L, vocab]  ← Task 출력
    → 각 위치에서 다음 토큰 확률분포

5. Causal Mask
언어 모델은 "위치 i에서 i+1을 맞춰라"로 학습한다. 그런데 셀프 어텐션은 기본적으로 모든 토큰을 본다. 위치 i가 i+1, i+2...를 보면 맞춰야 할 정답을 훔쳐보는 것(label leakage)이라 학습이 무의미해진다 — 그냥 다음 토큰을 복사하면 되니까.
Causal mask는 위치 i가 자기 자신과 그 이전 토큰만 보도록 강제한다.

scores [L, L]에서 j > i 인 자리(미래)에 매우 큰 음수를 더한다.

            j=0    j=1    j=2    j=3
    i=0      0    -1e9   -1e9   -1e9     ← 토큰 0은 0만 봄
    i=1      0     0     -1e9   -1e9     ← 토큰 1은 0,1 봄
    i=2      0     0      0     -1e9     ← 토큰 2는 0,1,2 봄
    i=3      0     0      0      0       ← 토큰 3은 다 봄

대각선 위(상삼각)를 가림 → softmax 후 그 자리 가중치 = 0.
    - 곱이 아니라 더하기: softmax 전 logit에 더해야 exp(-1e9) ≈ 0. 곱하면 exp(0)=1이라 안 가려짐
    - -∞ 대신 -1e9: 실제 구현은 큰 음수 상수. -∞는 0 × ∞ 이나 한 행이 전부 -∞일 때 NaN을 유발

ㄱ) 마스크 종류

| 마스크 | 목적 | 모양 |
|---|---|---|
| causal mask | 미래 토큰 가림 | 상삼각 |
| padding mask | 배치 정렬용 <pad> 위치 가림 | 열 단위 |

최종 마스크 = 미래도 아니고 pad도 아닌 자리만 통과.

ㄴ) 학습 시 — causal mask가 병렬 학습을 가능하게 함 (핵심)
"나는 밥을 먹었다"를 통째로 넣으면, 마스크가 각 위치의 시야를 제한하므로 한 번의 forward로 L개의 예측을 동시에 학습한다.

    위치 0 ("나는")    → "밥을"   예측   (0만 보고)
    위치 1 ("밥을")    → "먹었다" 예측   (0,1 보고)
    위치 2 ("먹었다")  → <eos>    예측   (0,1,2 보고)

이것이 teacher forcing이다. 학습 때는 실제 정답 시퀀스를 통째로 넣고 마스크로 시야만 제한하므로, RNN처럼 한 스텝씩 돌 필요가 없다. Transformer 학습이 빠른 근본 이유다.

ㄷ) 추론 시
한 토큰씩 자기회귀 생성. 생성한 토큰을 뒤에 붙이고 다시 forward. 이미 과거만 보므로 과거 토큰의 K·V는 변하지 않고, 이를 저장해 재사용하는 것이 KV 캐시다.

ㄹ) causal mask가 만드는 성질
    - 위치 i의 표현은 0..i에만 의존 → i+1이 추가돼도 앞쪽 표현 불변 → KV 캐시 성립
    - 정보가 왼→오 단방향으로만 흐름
    - BERT와의 근본 차이: BERT는 마스크 없이 양방향이라 문맥을 다 보지만 생성엔 못 씀. decoder-only는 단방향이라 생성 가능

6. FFN, Residual Connection, LayerNorm
어텐션 외에 모든 Transformer 블록을 이루는 세 부품이다. 위에서 정리한 "문맥화(어텐션) → 표현가공(FFN)"에서 FFN이 c를 담당하고, Residual·LayerNorm이 두 서브층을 감싸는 뼈대다.

ㄱ) FFN (Feed-Forward Network, position-wise)
a. 정의
각 블록의 두 번째 서브층. 선형층 → 비선형 활성화 → 선형층.

b. 역할
    - 어텐션은 Value들의 가중 평균이라 본질적으로 선형에 가까움. 비선형 변환력이 약함
    - FFN이 비선형성과 표현력을 담당. 어텐션이 모아온 문맥을 받아 "이 토큰이 이 문맥에서 무엇을 뜻하는지" 계산
    - 파라미터의 약 2/3이 여기. 어텐션 = 4D²(W_Q/K/V/O), FFN = 8D²(D×4D 두 개) → FFN이 2배
    - 지식 저장소 해석(Geva et al. 2021): 첫 선형층이 "어떤 패턴에 반응할지"(key), 둘째가 "무엇을 출력할지"(value). 사전학습으로 얻은 사실적 지식이 주로 FFN에 저장된다는 해석
    - 왜 4배 팽창? 넓은 중간 공간에서 특징을 더 잘 분리·조합. 실증적으로 2~8배가 좋음

ㄴ) Residual Connection (잔차 연결)
a. 정의
서브층 출력에 입력을 그대로 더함.

    output = x + Sublayer(x)

Transformer의 모든 서브층(어텐션, FFN 각각)에 적용된다.

b. 필요한 이유
    - 깊은 망의 gradient 소실. 층이 깊어지면 역전파 중 gradient가 계속 곱해지며 사라진다.
    - 아무리 깊어도 아래층까지 도달한다(gradient highway).
    - 서브층이 아무것도 안 하는 게 최선이면 Sublayer(x) → 0만 학습하면 된다. 잔차가 없으면 여러 층을 조합해 항등을 재현해야 해서 어렵다. 덕분에 12층, 96층까지 쌓아도 학습된다.

ㄷ) LayerNorm (계층 정규화)
a. BatchNorm 대신 LayerNorm을 쓰는 이유

| 구분 | BatchNorm | LayerNorm |
|---|---|---|
| 정규화 축 | 배치 방향(같은 특징끼리) | 특징 방향(한 토큰 안에서) |
| 배치 크기 의존 | 큼 (작으면 불안정) | 없음 |
| 가변 시퀀스 길이 | 취약 | 무관 |
| 학습/추론 차이 | 있음 (이동평균 통계) | 없음 |

    - NLP는 배치 내 문장 길이가 제각각이고 배치도 작을 수 있어 BatchNorm이 안 맞는다. LayerNorm은 토큰 하나만 보므로 이런 것과 무관하다.

b. 역할
    - 각 층의 입력 분포를 안정적으로 유지 → 학습 안정화, 수렴 가속
    - 잔차로 값이 계속 더해지며 스케일이 커지는 걸 매 서브층에서 재조정
    - gradient 스케일도 안정화

c. Pre-norm vs Post-norm

| 구분 | 수식 | 특징 |
|---|---|---|
| Post-norm (원조 2017) | x = LN(x + Sublayer(x)) | 잔차 경로에도 norm이 걸림. 깊으면 불안정, learning-rate warmup 필수 |
| Pre-norm (GPT-2 이후 표준) | x = x + Sublayer(LN(x)) | 잔차 스트림은 norm을 안 거침 → gradient 깨끗, 깊은 모델 안정 |

Pre-norm은 스트림이 한 번도 정규화되지 않으므로 마지막 블록 뒤에 final LayerNorm 하나를 추가한다.

ㄹ) 요약

| 컴포넌트 | 한 줄 | 토큰 간 이동 | 역할 |
|---|---|---|---|
| FFN | 선형→비선형→선형, D→4D→D | 없음 | 비선형 표현력, 지식 저장, 파라미터 2/3 |
| Residual | x + Sublayer(x) | — | gradient 통로, 깊은 학습 가능, 잔차 스트림 |
| LayerNorm | 토큰 벡터를 평균0·분산1로 | 없음 | 분포 안정화, 학습 가속 |

7. Prefill과 Decode
LLM 추론은 크게 Prefill과 Decode 두 단계로 나눌 수 있다.

| 단계 | 입력 | 주요 동작 | 특징 |
|---|---|---|---|
| Prefill | 전체 Prompt | Prompt 토큰들의 hidden state와 각 Layer의 K·V 계산 | 여러 Prompt 위치를 병렬 처리할 수 있음 |
| Decode | 직전에 생성한 새 토큰 | 다음 토큰 logits 계산 후 토큰 하나 선택 | 한 Token Step씩 순차 반복 |

    - Prefill에서는 길이 L_prompt인 입력 전체를 처리한다. Standard Self-Attention이라면 Prompt 내부의 Query-Key 조합 때문에 길이가 길수록 Attention 계산량이 빠르게 증가한다.
    - Decode에서는 매 Step마다 새 토큰 하나의 Query를 계산하고, 지금까지의 Prompt와 생성 토큰 전체를 참고해 다음 토큰을 만든다.

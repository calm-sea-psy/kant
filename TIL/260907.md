1. 사전학습 언어모델(PLM)
ㄱ) Pretraining 과 Task 적용 (2단계 패러다임)
PLM은 "먼저 일반 능력을 키우고, 나중에 특정 일에 맞춘다"는 2단계 구조로 이뤄져 있다.

| 단계 | 데이터 | 목적 |
|---|---|---|
| Pretraining | 대규모 레이블 없는 텍스트 (위키, 웹 등) | 문법·상식·세계지식·언어의 통계적 구조를 파라미터에 압축 |
| Task 적용 | 소규모 레이블 있는 task 데이터 | 사전학습된 표현을 실제 풀고 싶은 문제에 맞게 조정 |

ㄴ) Task 적용 방식
    - Fine-tuning: task 데이터로 파라미터를 추가 업데이트 (BERT의 기본 방식)
    - Feature extraction: 표현 벡터만 뽑아서 별도 분류기에 넣음 (파라미터 고정)
    - Prompting / In-context learning: 파라미터를 안 바꾸고 프롬프트에 예시만 제공 (GPT-3 이후)

pretraining에서 "언어를 이해하는 능력"을 이미 배웠기 때문에, downstream task는 적은 데이터로도 빠르게 학습된다.

ㄷ) LM Objective (언어모델 학습 목표)
언어모델의 근본 목표는 텍스트의 확률분포 P(문장)을 모델링하는 것이다. 시퀀스 확률을 어떻게 분해하느냐에 따라 objective가 갈린다.

| Objective | 개념 | 문맥 | 대표 모델 |
|---|---|---|---|
| Causal LM (autoregressive) | 이전 토큰들로 다음 토큰을 예측, 왼쪽→오른쪽 순차 분해 | 왼쪽만 | GPT |
| Masked LM (denoising) | 일부 토큰을 가리고 나머지 문맥으로 복원 | 양방향 | BERT |
| Span corruption (참고) | 연속 구간을 통째로 가리고 복원 | 양방향 | T5 |

Causal LM은 문장 확률을 각 위치의 조건부 확률(앞 토큰들이 주어졌을 때 다음 토큰)의 곱으로 분해한다.

a. 공통점
    - 손실함수는 cross-entropy (정답 토큰의 −log 확률). "정답을 얼마나 높은 확률로 맞혔나"를 측정
    - Self-supervised: 정답이 원문 안에 이미 있음 → 사람이 레이블링할 필요 없음 → 인터넷 규모 데이터 사용 가능. 이게 PLM이 강력한 근본 이유

ㄹ) Downstream Task
Pretraining "이후에" 실제로 풀고 싶은 구체적 과제.
"Downstream(하류)"이라는 이름은 pretraining이 상류(upstream)에 있고, 그 결과물을 받아 쓴다는 의미다.
Pretraining 자체가 목적이 아니라 downstream 성능을 위한 수단이다.

| 유형 | 예시 |
|---|---|
| 문장 분류 | 감성분석, 스팸 분류, 자연어추론(NLI) |
| 토큰 분류 | 개체명 인식(NER), 품사 태깅 |
| 문장쌍 | 문장 유사도, 질의응답(QA) |
| 생성 | 요약, 번역, 대화 |

a. 적용 패턴
    - BERT류: [CLS] 토큰의 표현 위에 작은 분류 head를 붙여 fine-tune
    - GPT류: 태스크를 "텍스트 생성 문제"로 바꿔서 프롬프트로 처리

ㅁ) Masked Language Modeling
a. BERT: Encoder-only
    - Transformer의 인코더 스택만 사용
    - 모든 토큰이 서로를 다 볼 수 있음 → 양방향(bidirectional) self-attention, 미래 마스킹 없음
    - 문맥을 양쪽에서 종합 → 이해(understanding) 태스크에 강함 (분류, 추출, NER)
    - 단점: autoregressive 구조가 아니라서 자연스러운 텍스트 생성은 못 함

b. BERT 입력 표현의 세 구성요소
입력 임베딩 = 아래 세 임베딩을 element-wise로 더한 것 (모두 같은 차원)

| 구성요소 | 역할 | 특징 |
|---|---|---|
| Token Embedding | 각 토큰(WordPiece 조각)의 의미 벡터 | 어휘사전 크기 × hidden dim 테이블에서 조회 |
| Position Embedding | 토큰의 위치 정보 | BERT는 학습되는 위치 임베딩(사인함수 아님), 최대 길이 512 |
| Token Type Embedding (=Segment) | 문장 A인지 문장 B인지 구분 | 문장쌍 입력(QA, NLI)용, 보통 0/1 두 종류 |

특수 토큰: [CLS](맨 앞, 문장 전체를 대표하는 표현), [SEP](문장 경계·끝 표시)

c. Masked LM Head와 출력
학습 과정
    - 입력 토큰의 약 15%를 선택
    - 선택된 것 중
        - 80% → [MASK] 토큰으로 교체
        - 10% → 랜덤 토큰으로 교체
        - 10% → 그대로 둠
        - 이렇게 섞는 이유: fine-tuning 때는 [MASK]가 안 나오므로 학습/실전 불일치를 완화
    - 인코더 통과 후, 마스킹된 위치의 최종 hidden 벡터만 MLM Head에 통과
        - Linear → GELU → LayerNorm → output projection(vocab 크기) → logits
        - output projection은 보통 token embedding 테이블과 가중치를 공유
    - Softmax
    - 손실은 마스킹된 위치에서만 cross-entropy 계산

ㅂ) Causal Language Modeling
a. GPT: Decoder-only
    - Transformer의 디코더 스택만 사용 (단, cross-attention은 없음 — self-attention + FFN만)
    - 왼쪽→오른쪽 단방향
    - "다음 토큰 예측"으로 학습 → 학습 목표가 곧 생성 방식이라 자연스럽게 생성 가능

b. Causal Self-Attention
    - Self-attention에서 미래 토큰을 못 보게 마스킹 (causal mask / look-ahead mask)
    - 위치 t의 토큰은 1..t만 attend, t+1 이후는 attention score를 −∞로 만든 뒤 softmax → 가중치 0
    - 이렇게 해야 "다음 토큰 예측"이 정직한 학습이 됨 (안 하면 정답을 미리 보는 커닝)
    - 이 마스크 덕분에 이전에 계산한 K/V가 바뀌지 않음 → KV Cache가 가능한 이유

c. Autoregressive Generation
    - 생성 절차: 프롬프트 입력 → 다음 토큰 1개 예측 → 그 토큰을 입력 끝에 이어붙임 → 반복
    - 한 번에 한 토큰만 생성 (그래서 느리고, KV 캐시로 가속)
    - 디코딩 전략: greedy / beam search / top-k / top-p(nucleus) / temperature

| 전략 | 종류 | 특징 | 잘 맞는 곳 |
|---|---|---|---|
| Greedy | 결정적 | 1위만, 반복 취약 | 짧은 사실 답변 |
| Beam search | 결정적(탐색) | k개 시퀀스 병렬 탐색 | 번역, 요약 |
| Temperature | 분포 조절 | 뾰족함 조절, 단독 아님 | (다른 것과 병용) |
| Top-k | 샘플링 | 상위 k개로 자름 (고정) | 일반 생성 |
| Top-p | 샘플링 | 누적확률 p로 자름 (가변) | 대화, 창작 (기본값) |

d. GPT 입력과 출력

| 구분 | 내용 |
|---|---|
| 입력 | 토큰 시퀀스 (token embedding + position embedding) |
| 각 위치의 출력 | 바로 다음 토큰에 대한 vocab 크기 logits |
| 학습 타겟 | 입력을 한 칸 shift한 것 (위치 t의 예측 타겟 = 위치 t+1의 실제 토큰) |
| 손실 | 모든 위치에서 동시에 cross-entropy (teacher forcing) |

BERT와 달리 마스킹된 일부가 아니라 모든 위치에서 손실을 계산하는 게 특징이다 — 매 토큰이 학습 신호를 준다.

ㅅ) BERT (MLM)과 GPT (CLM)의 비교

| 구분 | BERT (MLM) | GPT (CLM) |
|---|---|---|
| 구조 | Encoder-only | Decoder-only |
| Attention | 양방향 | Causal (단방향) |
| 학습 목표 | 가려진 토큰 복원 | 다음 토큰 예측 |
| 손실 계산 위치 | 마스킹된 ~15%만 | 모든 위치 |
| 위치 임베딩 | 학습된 absolute | (원조는) 학습된 absolute, 최신 GPT류는 RoPE |
| 강점 | 이해·분류·추출 | 생성 |
| Task 적용 | [CLS] 위에 head 붙여 fine-tune | 프롬프트로 생성 문제화 |

2. Hugging Face Transformers 기본 활용
ㄱ) Hugging Face Hub
모델·데이터셋·데모를 호스팅하는 git 기반 플랫폼이다 (GitHub과 비슷하지만 머신러닝 자산에 특화).
각 모델은 하나의 git 저장소이고, 대용량 weight는 git-LFS로 관리한다.

a. 모델 repo의 표준 구성

| 파일 | 내용 |
|---|---|
| config.json | 아키텍처·하이퍼파라미터 (레이어 수, hidden dim, model_type 등) |
| model.safetensors (또는 pytorch_model.bin) | 학습된 가중치 |
| tokenizer.json, vocab.txt, tokenizer_config.json | 토크나이저 |
| README.md | Model Card (설명 문서) |

    - from_pretrained("조직명/모델명") 하면 로컬 캐시(~/.cache/huggingface/hub)로 자동 다운로드
    - 접근 유형: 공개 / gated(라이선스 동의 필요, 예: Llama) / private
    - 버전 관리: 커밋 해시·태그·브랜치 → revision="커밋해시" 인자로 특정 시점 고정 가능

ㄴ) Hub 탐색 흐름
검색어 입력 → 필터링 → 정렬 → 모델 페이지 → Model Card 정독 → Files 탭 확인 → repo id를 코드에 사용

    - 필터: Task(text-classification, text-generation 등), 라이브러리(transformers), 언어, 라이선스, 파라미터 크기
    - 정렬: Trending / Most downloads / Most likes
    - 모델 페이지: Model Card 본문, "Use this model" 버튼(예제 코드 스니펫), Files and versions 탭(실제 파일 확인), Community 탭(이슈·토론)
    - 확인이 끝나면 repo id("조직명/모델명")를 코드에 그대로 사용

ㄷ) Model Card
README.md 파일 = 상단 YAML 프론트매터(메타데이터) + 본문(설명).

    ---
    license: apache-2.0
    language: ko
    tags: [text-classification]
    datasets: [nsmc]
    metrics: [accuracy]
    ---

| 순서 | 항목 | 확인할 것 |
|---|---|---|
| 1 | 프론트매터 / 태그 | 라이선스(상업적 사용 가능?), task, 언어 |
| 2 | 모델 요약 | 무슨 모델인지, 베이스 모델, 크기, 아키텍처 |
| 3 | Intended uses / 범위 밖 용도 | 내 목적에 맞는가 |
| 4 | 학습 데이터 | 어떤 데이터로 배웠나 (도메인 편향 파악) |
| 5 | 평가 결과 | 벤치마크 점수, 비교 대상 |
| 6 | Limitations & Bias | 알려진 약점·편향 |
| 7 | 사용 예제 코드 | 복붙해서 바로 실행 |
| 8 | Citation / License 세부 | 인용 형식, 제약 조건 |

ㄹ) pipeline() — 가장 쉬운 진입점
토크나이즈 → 모델 추론 → 후처리를 한 줄로 묶는 고수준 API. task 이름만 주면 기본 모델을 자동으로 골라 내려받는다.

    from transformers import pipeline

    clf = pipeline("sentiment-analysis")
    clf("이 영화 정말 최고였다")
    # [{'label': 'POSITIVE', 'score': 0.99}]

    - task 이름이 동작을 결정: sentiment-analysis, text-generation, ner, question-answering, summarization, fill-mask 등
    - model= 인자로 특정 모델 지정 가능 (생략하면 task별 기본 모델)
    - 입력은 문자열 하나 또는 리스트(배치), 출력은 후처리까지 끝난 파이썬 객체(라벨·점수·생성문)
    - 내부적으로 AutoTokenizer + AutoModelFor* 를 조합해 실행. pipeline은 그 위를 감싼 편의 계층

추상화 계층: pipeline (제일 쉬움, 제어 약함) → AutoClass (토크나이저·모델을 직접 다룸) → 커스텀 head·학습 루프 (완전 제어)

ㅁ) AutoClass
모델 아키텍처를 몰라도 알아서 올바른 클래스를 골라주는 팩토리다.

a. 주요 AutoClass

| 클래스 | 역할 |
|---|---|
| AutoConfig | 설정만 로드 |
| AutoTokenizer | 토크나이저 |
| AutoModel | 베이스 모델 (head 없음) |
| AutoModelForSequenceClassification 등 | 베이스 + task head |

ㅂ) Base Model vs Task-specific Model

| 구분 | Base Model (AutoModel) | Task-specific Model (AutoModelFor*) |
|---|---|---|
| 구성 | 트랜스포머 본체만 | 본체 + task head |
| 출력 | hidden states (표현 벡터) | task logits (분류 점수, 어휘 점수 등) |
| 용도 | 표현 추출, 커스텀 head 직접 붙이기 | 바로 task 수행 / fine-tune |

ㅅ) AutoTokenizer와 AutoModel Base Output
a. AutoTokenizer 출력

    tokenizer("안녕하세요", return_tensors="pt", padding=True, truncation=True)

    {
      'input_ids':      tensor([[101, 9521, ..., 102]]),   # 토큰 → 정수 id
      'attention_mask': tensor([[1, 1, ..., 1, 0, 0]]),    # 실제 토큰=1, 패딩=0
      'token_type_ids': tensor([[0, 0, ..., 0]])           # 문장 A/B 구분 (BERT 계열만)
    }

b. AutoModel Base Output (BaseModelOutputWithPooling)

| 필드 | shape | 의미 |
|---|---|---|
| last_hidden_state | (batch, seq_len, hidden) | 마지막 레이어의 모든 토큰 표현 (주로 이걸 씀) |
| pooler_output | (batch, hidden) | [CLS] 벡터를 Linear+tanh 통과시킨 것 (BERT 계열, 신뢰도 낮아 잘 안 씀) |
| hidden_states | tuple | 각 레이어별 출력 (output_hidden_states=True 필요) |
| attentions | tuple | 각 레이어 attention 가중치 (output_attentions=True 필요) |

ㅇ) last_hidden_state 해석
shape = (B, T, H) = (배치 크기, 시퀀스 길이, hidden 차원)
[b, t, :] 벡터 = b번째 문장에서 t번째 토큰이 전체 문맥 속에서 갖는 의미 (문맥화된 임베딩). 같은 단어라도 문장이 다르면 벡터가 다르다.

a. 용도별 사용법

| 목적 | 어떻게 |
|---|---|
| 토큰 분류 (NER, 품사) | 각 위치 벡터 [b, t, :]를 그대로 사용 |
| 문장 임베딩 (BERT) | [CLS] 위치 = last_hidden_state[:, 0, :] |
| 문장 임베딩 (권장) | mean pooling — attention_mask로 패딩 제외하고 토큰 벡터 평균 |
| 다음 토큰 예측 (GPT) | 마지막 실제 토큰 위치 벡터 |

ㅈ) Task Head
베이스 모델 위에 얹는 작은 신경망(보통 Linear 1~2층). 표현(hidden) → task 출력(logits)으로 변환한다.

| Head 종류 | 입력 | 출력 | 사용 클래스 |
|---|---|---|---|
| Sequence Classification | pooled 표현 (1개 벡터) | num_labels 점수 | ...ForSequenceClassification |
| Token Classification | 각 위치 벡터 | 위치마다 num_labels | ...ForTokenClassification |
| Question Answering | 각 위치 벡터 | 위치마다 start/end 점수 2개 | ...ForQuestionAnswering |
| Language Modeling | 각 위치 벡터 | 위치마다 vocab_size 점수 | ...ForCausalLM / ...ForMaskedLM |

    - LM head는 보통 입력 token embedding과 가중치를 공유(weight tying) → 파라미터 절약
    - head는 downstream 데이터로 학습되는 부분

ㅊ) AutoModelForSequenceClassification vs AutoModelForCausalLM

| 구분 | ForSequenceClassification | ForCausalLM |
|---|---|---|
| 목적 | 문장/문서 분류 | 텍스트 생성 |
| 대표 모델 | BERT, RoBERTa | GPT-2, Llama, Qwen |
| head | 분류 head (pooled → num_labels) | LM head (hidden → vocab) |
| 출력 logits shape | (batch, num_labels) | (batch, seq_len, vocab_size) |
| 로드 시 추가 인자 | num_labels, id2label, label2id | 보통 없음 |
| generate() | 불가 | 가능 |

ㅋ) classification logits vs vocabulary logits — 축 의미
a. classification logits: (batch, num_labels)

| 축 | 의미 | 처리 |
|---|---|---|
| axis 0 | 배치 내 각 샘플 | — |
| axis 1 | 각 클래스 (예: 부정=0, 긍정=1) | argmax(dim=1) → 예측 클래스, softmax → 확률 |

b. vocabulary logits: (batch, seq_len, vocab_size)

| 축 | 의미 | 처리 |
|---|---|---|
| axis 0 | 배치 | — |
| axis 1 | 시퀀스 위치 t | 각 위치는 "그 다음에 올 토큰"을 예측 |
| axis 2 | 어휘사전 전체 토큰 각각의 점수 (5만~15만) | argmax(dim=-1) → 다음 토큰 id |

    - 학습 시: 모든 위치의 logits를 다 사용 (각 위치 예측 vs 실제 다음 토큰)
    - 생성 시: 마지막 위치만 필요 → logits[:, -1, :]

ㅌ) Model·Tokenizer 저장/재로드와 재현성 메타데이터
모델과 토크나이저는 같은 경로에서 쌍으로 로드해야 한다. 토크나이저의 vocab과 모델의 embedding 테이블 인덱스가 1:1로 대응하기 때문이다 — 짝이 어긋나면 조용히 틀린 결과가 나온다.

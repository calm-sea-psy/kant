1. device
device는 텐서(또는 모델)가 실제로 어느 하드웨어에 올라가서 연산되는지를 나타내는 속성입니다. PyTorch에서 가장 흔한 값은 cpu와 cuda(NVIDIA GPU) 두 가지입니다.
텐서는 만들어질 때 기본적으로 CPU 메모리에 올라갑니다. GPU가 있고 그쪽에서 연산하고 싶으면 명시적으로 옮겨줘야 합니다.

ㄱ) device 개념이 필요한가
GPU는 앞서 얘기한 batch 연산(대량의 행렬곱)을 CPU보다 훨씬 빠르게 병렬 처리할 수 있습니다. 그래서 딥러닝에서는 가능하면 모델과 데이터를 GPU로 옮겨서 학습·추론합니다. 하지만 CPU 메모리와 GPU 메모리는 물리적으로 분리되어 있어서, 같은 연산에 참여하는 텐서들은 반드시 같은 device에 있어야 합니다.

    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

    model = model.to(device)          # 모델 파라미터를 device로 이동
    batch_x = batch_x.to(device)      # 입력 텐서도 같은 device로 이동
    batch_y = batch_y.to(device)

torch.cuda.is_available()로 GPU 유무를 확인해서, GPU가 있으면 cuda, 없으면 cpu로 자동 분기하는 게 표준 패턴입니다. 이렇게 하면 같은 코드가 GPU 있는 환경/없는 환경 어디서든 그대로 동작합니다.

ㄴ) 자주 쓰는 관련 메서드
    - tensor.to(device): 지정한 device로 복사본을 반환 (원본 유지, 새 텐서 할당)
    - tensor.cuda() / tensor.cpu(): .to("cuda") / .to("cpu")의 축약형(구식 스타일, 요즘은 .to(device)가 더 권장됨 — GPU 유무에 따라 분기하는 코드를 짤 필요 없이 하나로 통일 가능)
    - model.to(device)는 모델 안의 모든 파라미터·버퍼를 한 번에 이동시켜줌


2. 퍼셉트론과 선형 결정 경계
퍼셉트론(Perceptron)은 신경망의 가장 기본 단위를 모델링한, 인공 뉴런의 원형입니다. 1958년 프랑크 로젠블랫이 제안한 개념으로, 활성화함수 구조의 뿌리라고 보면 됩니다.

퍼셉트론은 여러 개의 입력값을 받아서, 각 입력에 가중치(weight)를 곱해 다 더하고, 편향(bias)을 더한 뒤, 그 결과가 특정 기준(보통 0)을 넘으면 1, 안 넘으면 0(또는 -1)을 출력하는 아주 단순한 구조입니다.

"입력들을 가중합해서, 임계값을 넘으면 활성화(발화)하고 안 넘으면 안 한다"는 것이 핵심입니다. 실제 뉴런이 여러 신호를 받아 일정 자극 이상이면 전기 신호를 발화하는 방식을 단순화해서 흉내 낸 것입니다.

ㄱ) 한계 — XOR 문제
단일 퍼셉트론(단층)은 선형으로 분리 가능한 문제만 풀 수 있습니다. 즉 하나의 직선(또는 초평면)으로 두 클래스를 나눌 수 있는 문제만 학습 가능합니다. XOR처럼 하나의 직선으로 절대 나눌 수 없는 문제는 단일 퍼셉트론으로는 원리적으로 풀 수 없다는 것이 1969년에 증명되면서, 한동안 신경망 연구가 침체되는 계기가 됐습니다(1차 AI 겨울의 원인 중 하나).


3. MLP
MLP(Multi-Layer Perceptron, 다층 퍼셉트론)는 여러 개의 완전연결층(Linear layer)을 활성화함수로 이어붙인, 가장 기본적인 신경망 구조입니다.

    nn.Sequential(
        nn.Linear(4, 16),   # 입력층 -> 은닉층 (16개 뉴런)
        nn.ReLU(),          # 은닉층 결과에 비선형 활성화
        nn.Linear(16, 1),   # 은닉층 -> 출력층
    )

    - 입력층: 데이터가 들어오는 자리(층이라기보다 그냥 입력 벡터 자체)
    - 은닉층(hidden layer): 입력층과 출력층 사이에 있는 층. 몇 개를 두든, 각 층의 뉴런(unit) 수를 몇 개로 하든 자유(둘 다 하이퍼파라미터)
    - 출력층: 최종 예측값을 내는 층

각 층은 "이전 층의 출력 전체 → 다음 층의 모든 뉴런"으로 완전히 연결되어 있어서 완전연결층(Fully Connected Layer)이라고도 부릅니다. nn.Linear가 정확히 이 연산(가중합+편향)을 수행합니다.

ㄱ) 퍼셉트론 한계의 해결
단일 퍼셉트론(층 하나)은 선형 분리 가능한 문제만 풉니다. MLP는 층과 층 사이에 비선형 활성화함수(ReLU, Sigmoid, Tanh 등)를 끼워 넣는데, 이게 핵심입니다.

만약 활성화함수 없이 Linear만 계속 쌓으면 행렬곱을 아무리 여러 번 이어붙여도 결국 하나의 선형 변환으로 합쳐지기 때문에, 층을 쌓는 의미가 없어집니다. 층 사이에 비선형 함수를 넣어야만 "선형 변환 → 비선형 변환 → 선형 변환 → ..."이 반복되면서 곡선·곡면 같은 복잡한 형태의 결정경계나 함수를 표현할 수 있게 됩니다.

ㄴ) 보편 근사 정리(Universal Approximation Theorem)
은닉층이 하나만 있어도(폭이 충분히 넓다면) MLP는 이론적으로 임의의 연속함수를 원하는 정밀도로 근사할 수 있다는 것이 수학적으로 증명되어 있습니다. 다만 "이론적으로 가능"과 "실제로 학습이 잘 된다"는 다른 문제라서, 실무에서는 넓고 얕은 층 하나보다 좁고 깊은 여러 층을 쌓는 쪽이 더 효율적으로 학습되는 경우가 많습니다.

X(200,4) → true_w로 만든 데이터는 사실 완전한 선형 관계였는데도 예제 모델은 굳이 은닉층(16)+ReLU를 넣었습니다. 이런 경우 MLP는 결국 거의 선형에 가까운 함수로 수렴하지만, 실제 문제(이미지, 텍스트, 복잡한 비선형 패턴)에서는 은닉층 수와 폭이 늘어날수록 더 복잡한 패턴을 표현할 수 있다는 게 MLP의 강점입니다.

ㄷ) 한계와 이후 발전
MLP는 입력의 순서나 공간적 구조(이미지의 픽셀 배치, 문장의 단어 순서)를 전혀 고려하지 않고 모든 입력을 그냥 평평한 벡터로 취급합니다. 그래서 이미지에는 CNN(합성곱), 시퀀스에는 RNN/Transformer처럼 구조에 맞는 특화된 아키텍처가 따로 발전했지만, 이들 내부에도 결국 MLP(완전연결층)가 부분적으로 들어가는 경우가 대부분입니다.

| 구성요소 | 역할 |
|---|---|
| Linear layer | 가중합 + 편향 (선형 변환) |
| 활성화함수 | 비선형성 부여 (없으면 여러 층이 의미 없어짐) |
| 은닉층 수/폭 | 모델의 표현력을 결정하는 하이퍼파라미터 |
| 학습 | forward → loss → backward → update, 모든 층이 한 번에 gradient로 갱신 |

4. nn.Linear
nn.Linear는 PyTorch에서 가중합 + 편향 연산(완전연결층)을 수행하는 기본 레이어입니다.

ㄱ) 정의와 연산

    layer = nn.Linear(in_features=4, out_features=16)

입력 벡터의 각 원소에 가중치를 곱해서 다 더하고, 편향을 더하는 연산을 합니다. 입력이 4차원이면, 출력의 각 원소 하나하나는 "입력 4개 값 × 각자의 가중치를 더한 값 + 편향 하나"로 계산됩니다. 이 계산을 출력 차원(16개) 수만큼 각각 독립적으로 반복합니다. 앞서 설명드린 퍼셉트론의 "가중합+편향" 연산을 16개 병렬로 쌓아놓은 것과 같습니다.

ㄴ) 내부 파라미터

    layer.weight   # shape: (out_features, in_features) = (16, 4)
    layer.bias     # shape: (out_features,) = (16,)

    - weight: 학습되는 가중치 행렬. 출력마다 입력 각각에 곱해질 계수들
    - bias: 학습되는 편향 벡터. 출력마다 하나씩

이 둘이 model.parameters()로 옵티마이저에 전달되는 실제 학습 대상이고, loss.backward() → optimizer.step()으로 값이 갱신되는 대상이 바로 이 weight, bias입니다.

ㄷ) batch dimension과의 관계
nn.Linear는 입력의 마지막 차원만 in_features와 맞으면 되고, 그 앞의 모든 차원(batch 등)은 그대로 유지됩니다.

    x = torch.randn(32, 4)     # (batch=32, in_features=4)
    layer = nn.Linear(4, 16)
    layer(x).shape               # (32, 16)  -- batch는 그대로, feature만 4->16

그래서 배치 크기가 몇이든 같은 레이어 정의 하나로 처리할 수 있습니다.

ㄹ) "Linear"라는 이름의 의미
이 연산 자체는 선형 변환입니다(입력에 대해 곱셈과 덧셈만 있고, 꺾임이나 곡률이 없음). 그래서 MLP 설명에서 말씀드렸듯이, nn.Linear만 여러 개 이어붙이면 결국 하나의 nn.Linear와 수학적으로 동일해져 버립니다. 이 레이어가 표현력을 가지려면 반드시 사이사이에 nn.ReLU() 같은 비선형 활성화함수가 있어야 합니다.
nn.Linear 자체는 "이 층이 무엇을 비선형적으로 학습하는가"가 아니라 "각 뉴런이 입력을 어떻게 가중합하는가"만 담당하는 조각입니다.

| 속성 | 의미 |
|---|---|
| in_features | 입력 벡터의 차원 수 |
| out_features | 출력 벡터의 차원 수 (= 이 층의 뉴런 개수) |
| .weight | 학습되는 가중치, shape (out_features, in_features) |
| .bias | 학습되는 편향, shape (out_features,) |
| 연산 | output = input @ weight.T + bias |
| 비선형성 | 없음 — 활성화함수와 반드시 같이 써야 함 |

5. flatten
flatten은 다차원 텐서를 더 낮은 차원(보통 1차원)으로 펼치는 연산입니다. 이미지처럼 여러 차원을 가진 데이터를 nn.Linear(입력이 1차원 벡터여야 함)에 넣기 전에 형태를 맞춰주는 용도로 가장 많이 씁니다.

ㄱ) 기본 동작

    x = torch.tensor([[1, 2, 3],
                    [4, 5, 6]])   # shape: (2, 3)
    torch.flatten(x)                 # shape: (6,)  -> tensor([1, 2, 3, 4, 5, 6])

모든 차원을 하나로 합쳐서 완전히 1차원 벡터로 만들어버립니다.

ㄴ) batch dimension은 보통 남겨야 함
이미지 배치처럼 batch 차원이 있는 텐서에 torch.flatten을 그냥 쓰면, batch 차원까지 뭉개져서 서로 다른 샘플이 하나로 섞여버리는 사고가 납니다.

    imgs = torch.randn(32, 3, 28, 28)   # (batch=32, channel=3, h=28, w=28)
    torch.flatten(imgs)                  # shape: (75264,)  -- 배치 32개가 전부 한 줄로 뭉개짐! 잘못됨

그래서 실제로는 batch 차원(0번째)은 그대로 두고, 그 뒤의 차원들만 펼치도록 start_dim을 지정합니다.

    torch.flatten(imgs, start_dim=1)     # shape: (32, 2352)  -- batch는 유지, 나머지만 3*28*28=2352로 펼침

즉 각 샘플이 "batch, 나머지 전부 펼친 벡터" 형태가 되어, nn.Linear(2352, ...)에 그대로 넣을 수 있습니다.

ㄷ) nn.Flatten() — 모델 안에서 레이어처럼 쓰는 버전

    model = nn.Sequential(
        nn.Flatten(),          # 기본값이 start_dim=1 -> batch 차원은 자동으로 보존
        nn.Linear(2352, 128),
        nn.ReLU(),
        nn.Linear(128, 10),
    )

nn.Flatten()은 start_dim 기본값이 이미 1이라서, Sequential 안에 그냥 넣기만 하면 batch 차원을 안전하게 보존하면서 나머지를 펼쳐줍니다. CNN(합성곱층) 뒤에 완전연결층을 붙일 때 거의 항상 등장하는 패턴입니다.

    model = nn.Sequential(
        nn.Conv2d(3, 16, 3),   # (batch, 3, H, W) -> (batch, 16, H', W')
        nn.ReLU(),
        nn.Flatten(),           # (batch, 16, H', W') -> (batch, 16*H'*W')
        nn.Linear(16*H_*W_, 10) # 완전연결층은 벡터 입력만 받으므로 반드시 필요
    )

ㄹ) squeeze/unsqueeze와의 차이
squeeze/unsqueeze는 크기가 1인 차원만 없애거나 추가하는 반면, flatten은 크기와 상관없이 여러 차원을 하나로 합쳐버립니다. 목적이 다릅니다. squeeze/unsqueeze는 "불필요한 자리 차원 정리", flatten은 "다차원 구조를 벡터로 변환".

| 기능 | 의미 |
|---|---|
| torch.flatten(x) | 모든 차원을 1차원으로 통합 |
| torch.flatten(x, start_dim=1) | 0번(batch) 차원은 보존, 나머지만 통합 |
| nn.Flatten() | 모델 레이어 버전, 기본적으로 batch 차원 보존 |
| 주 용도 | CNN 출력 → 완전연결층(Linear) 입력으로 넘기기 전 형태 변환 |
| 흔한 실수 | start_dim 안 주고 그냥 torch.flatten(x) 써서 batch까지 뭉개버리는 것 |

6. view, reshape, flatten 차이점
세 함수 모두 텐서의 shape을 바꾸는 데 쓰이지만, "메모리를 공유하느냐, 언제 쓸 수 있느냐, 얼마나 유연하냐"에서 차이가 있습니다.

| 구분 | view | reshape | flatten |
|---|---|---|---|
| 목적 | shape을 임의로 변경 | shape을 임의로 변경 | 여러 차원을 하나로 합침(펼치기 전용) |
| 메모리 | 항상 공유(뷰) | 가능하면 공유, 안 되면 복사 | 가능하면 공유, 안 되면 복사(내부적으로 reshape) |
| 사용 편의성 | 까다로움(연속성 신경 써야) | 더 안전함(항상 성공) | 가장 제한적(펼치기만 가능, 임의 shape 불가) |

원본 텐서가 아닐 때,
view는 메모리가 연속(contiguous)이어야 함 — 아니면 에러
reshape는 안 되면 자동으로 복사해서라도 처리
flatten는 안 되면 복사(내부적으로 reshape)

ㄱ) 사용 목적
    - shape을 자유롭게 재배열(전치 후 합치기 등 복잡한 변형) → reshape (안전), 성능이 중요하고 연속성 확신 있으면 view
    - 다차원을 벡터로 펼치기만(batch 차원 보존) → flatten 또는 nn.Flatten() — 의도가 코드에 가장 명확하게 드러남
    - 연속성 에러(view 실패)를 만났을 때 → .contiguous().view(...) 또는 그냥 reshape(...)으로 바꾸면 해결

ㄴ) -1의 의미
세 함수 모두 shape 인자에 -1을 하나 넣으면 "나머지 차원 크기로 미루어 자동 계산"해줍니다.

    x.reshape(32, -1)   # 두 번째 차원은 전체 원소 수 / 32로 자동 계산

전체 크기를 일일이 계산할 필요 없이 batch만 고정하고 나머지를 펼칠 때 자주 씁니다.

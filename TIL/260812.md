1. 부트스트랩 

- 개념
원본 데이터셋에서 복원추출(sampling with replacement) 로 같은 크기의 새로운 데이터셋을 여러 개 만드는 통계 기법
원래는 통계학에서 표본 분포를 추정하기 위해 고안된 방법 (모집단 전체를 알 수 없을 때, 가진 표본만으로 추정치의 불확실성을 근사)

- 작동 방식
원본 데이터가 $n$개 있을 때, 그중에서 무작위로 하나씩 $n$번 뽑되 뽑은 것을 다시 넣고 뽑음(복원추출)
결과적으로:
    - 어떤 데이터는 여러 번 뽑힘
    - 어떤 데이터는 한 번도 안 뽑힘

한 번도 안 뽑힐 확률    
    - 평균적으로 원본 데이터의 약 63.2%만 각 부트스트랩 샘플에 포함되고, 나머지 약 36.8%는 빠짐
    - 이 빠진 데이터를 OOB(Out-Of-Bag) 샘플이라 부르며, 별도의 검증셋 없이 모델 성능을 평가하는 데 활용 가능 
      (교차검증과 유사한 효과를 공짜로 얻음)

왜 유용한가
    - 데이터가 하나뿐이어도, 부트스트랩으로 여러 개의 "가상의 다른 데이터셋"을 만들어낼 수 있음
    - 이를 통해 추정치(평균, 분산 등)의 신뢰구간을 계산하거나, 모델의 불안정성을 줄이는 데 활용


2. 배깅(Bagging) — Bootstrap Aggregating

- 개념
부트스트랩으로 만든 여러 데이터셋 각각에 모델을 학습시킨 뒤, 그 예측을 집계(aggregating) 해 최종 예측을 만드는 앙상블 기법
이름 자체가 Bootstrap Aggregating의 줄임말

- 알고리즘
원본 데이터 $D$ 에서 부트스트랩으로 $B$개의 데이터셋 $D_1, D_2, D_B$ 생성
각 $D_b$로 독립적으로 모델(주로 결정트리) 학습 
예측 시 결과를 집계
    - 회귀: 평균
    - 분류: 다수결(투표)

왜 효과가 있는가 — 분산 감소의 원리    
    - Decision Tree에서 언급했듯, 단일 결정트리는 분산(variance)이 매우 큼 (데이터가 조금만 바뀌어도 트리 구조가 확 달라짐)
    - 여러 개의 서로 다른(부트스트랩 샘플로 학습된) 트리를 평균 내면, 개별 모델의 노이즈가 상쇄되어 전체 분산이 줄어듦
    - 통계적으로, $B$개의 독립적이고 동일한 분산을 가진 예측을 평균하면 분산은 감소 (단, 완전히 독립적일 때 이상적인 경우)
    - 편향(bias)은 크게 변하지 않음 → 배깅은 편향-분산 트레이드오프에서 분산만 선택적으로 줄이는 기법

배깅에 적합한 모델    
    - 분산이 큰(불안정한) 모델일수록 배깅 효과가 큼: 결정트리가 대표적
    - 반대로 선형회귀처럼 원래 분산이 작고 안정적인 모델은 배깅해도 효과가 미미함

배깅 → 랜덤포레스트로 확장    
K-means와 PCA 에서 언급했던 랜덤포레스트는 배깅에 한 가지를 더한 것
    - 배깅: 데이터만 부트스트랩으로 다양화
    - 랜덤포레스트: 데이터(부트스트랩) + 특징(feature)도 각 분할마다 무작위 부분집합만 사용

트리들 간의 상관관계를 낮춰 앙상블 효과를 극대화 (개별 트리가 서로 덜 비슷해질수록 평균의 분산 감소 효과가 커짐)

부트스트랩은 "하나의 데이터셋에서 복원추출로 여러 가짜 데이터셋을 만드는 리샘플링 기법"이고, 
배깅은 "그렇게 만든 여러 데이터셋 각각에 모델을 학습시켜 평균/투표로 합치는 방법"입니다. 
핵심은 Decision Tree처럼 불안정한(분산 큰) 모델을 여러 개 만들어 평균 냄으로써 분산을 줄이는 것이며, 
이것이 랜덤포레스트의 직접적인 기반이 됩니다.

2. 랜덤포레스트의 두 무작위성(Two Sources of Randomness)
랜덤포레스트라는 이름 자체가 이 이중 무작위화(double randomization)에서 나온 것입니다.

ㄱ) 무작위성 ①: 데이터 샘플링 (Bagging)

방식
    - 원본 학습 데이터 $D$ 에서 복원추출로 $B$개의 데이터셋 생성
    - 각 트리 $f_b$는 서로 다른 부트스트랩 샘플 $D_b$로 학습됨
    - 트리마다 보지 못한 데이터(OOB, 약 36.8%)가 생김 → 별도 검증셋 없이 OOB 데이터로 성능 검증 가능

목적
    - 트리마다 조금씩 다른 데이터를 보게 해 트리 간 다양성 확보
    - 하지만 이것만으로는 부족함 — 데이터셋들이 원본과 비슷하다 보니(63% 이상 겹침), 
    트리들이 여전히 서로 비슷한 구조로 자랄 수 있음 (특히 하나의 강력한 특징이 있으면 대부분의 트리가 그 특징으로 첫 분할을 함)

ㄴ) 무작위성 ②: 특징 샘플링 (Feature Randomness)

방식
    - Decision Tree는 매 노드마다 모든 특징을 검토해 지니 불순도/엔트로피 감소가 가장 큰 분할을 선택했음
    - 랜덤포레스트는 각 노드에서 분할을 결정할 때, 전체 특징 중 무작위로 뽑은 일부만 후보로 검토

목적 — 트리 간 상관관계 낮추기

    - 데이터 샘플링만으로는 지배적인 특징(예: 예측력이 매우 강한 하나의 변수)이 있으면 거의 모든 트리가 똑같이 그 특징으로 루트를 분할 → 트리들이 서로 비슷해짐(높은 상관관계)
    - 상관관계가 높은 예측들을 평균 내면 분산 감소 효과가 제한적임 트리 간 상관관계를 낮추는 것이 분산 감소의 핵심
    - 매 분할마다 사용 가능한 특징을 제한하면, 강한 특징이 없을 때는 다른 특징들도 분할에 참여할 기회를 얻음 → 트리들이 서로 다른 구조로 자람 → 앙상블 분산 추가 감소

무작위성만 적용 시	                                    효과
데이터 샘플링만 (=배깅)	        트리 간 다양성 확보하지만, 강한 특징 때문에 여전히 트리들이 유사(상관관계 높음)
특징 샘플링만	                같은 데이터를 계속 보므로 다양성 제한적
둘 다 (랜덤포레스트)	        데이터도 다르고 분할 후보 특징도 다름 → 트리 간 상관관계 최소화 → 분산 감소 극대화    

분산 감소 공식이 이상적으로 성립하려면 트리들이 독립적(상관관계 낮음) 이어야 하는데, 
데이터 샘플링만으론 이 독립성이 부족하고, 특징 샘플링을 더해야 실질적인 독립성에 가까워짐

단일 Decision Tree 에서는 가지치기로 과적합을 막아야 했지만, 
랜덤포레스트에서는 오히려 개별 트리를 깊게(과적합 상태로) 키우는 것이 전략입니다 — 어차피 이중 무작위성으로 다양화된 트리들을 평균 내면서 분산이 상쇄되기 때문입니다.

랜덤포레스트는 
① 부트스트랩으로 각 트리가 다른 데이터를 보게 하고, 
② 매 분할마다 무작위 특징 부분집합만 고려하게 해 트리 간 상관관계를 최소화함으로써, 단순 배깅보다 더 강력하게 분산을 줄이는 앙상블 기법입니다.

3. OOB Score (Out-of-Bag Score)

- 왜 생기는가
    각 트리는 부트스트랩(복원추출)으로 만든 데이터셋으로 학습
    각 부트스트랩 샘플에는 원본 데이터의 평균 약 63.2%만 포함되고, 나머지 약 36.8%는 그 트리 학습에 전혀 쓰이지 않음
    이 "안 쓰인" 데이터를 OOB(Out-Of-Bag) 샘플이라 부름

- 계산 방식
    각 데이터 포인트에 대해, 부트스트랩 샘플에 포함되지 않은 트리들만 모음 (평균적으로 전체 트리의 약 36.8%가 여기 해당)
    그 트리들만으로 예측 (다수결/평균)
    모든 데이터 포인트에 대해 이 과정을 반복해 예측값을 모음
    실제값과 비교해 정확도(분류) 또는 $R^2$/MSE(회귀) 계산 → 이게 OOB Score

- 의미와 장점
    별도의 검증셋(validation set)이나 교차검증 없이도, 학습에 쓰지 않은 데이터로 검증한 것과 동일한 효과를 얻음
    데이터가 적을 때 특히 유용 — 데이터를 학습/검증으로 나눠 낭비할 필요 없이 전체를 학습에 쓰면서도 검증 지표를 얻음
    이론적으로 K-fold 교차검증과 비슷한 신뢰도를 가짐 (트리 개수가 충분히 많을 때)    

- 한계
    트리 개수가 적으면 OOB 샘플이 부족해 추정이 불안정할 수 있음
    시계열 데이터처럼 데이터 간 독립성이 깨진 경우엔 부트스트랩 자체가 부적절 → OOB도 신뢰도 낮아짐

4. 두 가지 특징 중요도(Feature Importance)
Decision Tree 에서 언급했던 "특징 중요도"를 랜덤포레스트에서는 두 가지 다른 방식으로 계산할 수 있습니다.

ㄱ) MDI (Mean Decrease in Impurity) — 불순도 감소 기반

- 원리
    각 트리에서 특정 특징이 분할에 사용될 때마다, 그 분할로 인한 지니 불순도(또는 엔트로피/MSE) 감소량을 기록
    해당 특징이 관여한 모든 분할에서의 감소량을, 그 분할이 담당하는 샘플 비율로 가중해 합산
    이를 전체 트리에 대해 평균

- 특징
    계산이 빠름 (학습 과정에서 이미 나온 값을 재활용, 추가 연산 거의 없음)
    scikit-learn의 feature_importances_가 기본으로 제공하는 값이 바로 이것

- 한계 — 편향 문제

    카디널리티(고유값 개수)가 높은 특징일수록 과대평가되는 경향 — 연속형 변수나 범주가 많은 변수는 분할 후보가 많아 우연히도 좋은 분할을 찾을 기회가 많음
    예: 순수 노이즈인 "고객 ID" 같은 특징도 값이 다양하다는 이유만으로 중요도가 높게 나올 수 있음    
    학습 데이터 자체의 불순도 감소를 측정하는 것이라, 학습 데이터에 대한 과적합된 중요도일 수 있음 (테스트 성능과 괴리 가능)

ㄴ) Permutation Importance — 순열(뒤섞기) 기반

- 원리
"이 특징이 정말 중요하다면, 그 값을 무작위로 뒤섞었을 때 모델 성능이 크게 떨어져야 한다"는 직관
    - 학습된 모델의 기준 성능 측정 (보통 OOB Score 사용)
    - 특정 특징 $x_j$의 값들을 데이터 전체에서 무작위로 섞음(다른 특징들은 그대로 둠)
    - 섞인 데이터로 다시 예측 → 성능 재계산
    - 성능 하락폭이 클수록 그 특징이 중요

OOB 샘플로 이 과정을 수행하면 별도 검증셋 없이 계산 가능 (OOB + Permutation이 랜덤포레스트에서 흔히 쓰이는 조합)    

- 특징
    실제 예측 성능에 미치는 영향을 직접 측정하므로 더 신뢰할 수 있는 중요도
    카디널리티 편향 문제 없음 (MDI와 대조적)
    모델에 구애받지 않음(model-agnostic) — 랜덤포레스트뿐 아니라 어떤 모델에도 적용 가능

- 한계

    계산 비용 큼 (특징마다 재예측 필요, 특징 수 많으면 느림)
    상관관계가 높은 특징들이 있으면 왜곡될 수 있음 — 특징 A, B가 서로 강한 상관관계면 A를 셔플해도 B가 비슷한 정보를 담고 있어 성능이 별로 안 떨어짐 → 둘 다 과소평가될 수 있음    

구분	                MDI (불순도 감소)	                    Permutation Importance
계산 시점	            학습 중 자동 계산	                        학습 후 별도 계산
계산 비용	                낮음	                                    높음
카디널리티 편향	            있음 (연속/다범주 변수 과대평가)	            없음
상관 특징 처리	           비교적 안정적	                        왜곡 가능 (과소평가)
일반화 성능과의 연관성	     약함 (학습 데이터 기준)	             강함 (검증 성능 기준)
모델 종속성	            트리 기반 모델 전용	                        모델 무관(model-agnostic)

OOB Score는 부트스트랩 과정에서 "우연히 빠진 데이터"를 검증셋처럼 재활용해 별도 검증 없이 성능을 추정하는 방법이고, 

두 가지 특징 중요도는 "학습 중 불순도가 얼마나 줄었는가(MDI, 빠르지만 편향 있음)"와 "실제로 흔들어보면 성능이 얼마나 떨어지는가(Permutation, 느리지만 더 신뢰할 만함)"라는 서로 다른 관점에서 특징의 영향력을 측정하는 방법입니다.

배깅/랜덤포레스트에서 여러 트리를 평균 내도 분산이 완전히 0으로 사라지지 않는 이유는, 
트리들이 같은 데이터에서 파생되어 서로 상관관계를 가지기 때문이며, 그 상관관계가 만드는 바닥값이 트리 개수와 
무관하게 남아있기 때문입니다 — 이것이 랜덤포레스트가 배깅에 특징 무작위성을 더해 자체를 낮추려는 근본적인 이유입니다

5. 랜덤포레스트가 강해지려면 각 나무가 가져야 할 두 조건은 무엇일까요?
랜덤포레스트가 강해지려면 
    ① 각 트리는 개별적으로 충분히 정확해야 하고(강도, low bias), 
    ② 트리들끼리는 서로 최대한 달라야 합니다 
    
    — [랜덤포레스트의 두 무작위성]은 조건 ②를 위한 장치이고, 트리를 가지치기 없이 깊게 키우는 것은 조건 ①을 지키기 위한 선택이며, 둘 사이의 균형이 하이퍼파라미터 튜닝의 본질입니다.


6. 부스팅(Boosting)
부트스트랩과 배깅 에서 예고했던 "배깅 vs 부스팅" 비교의 반대편 축입니다. 
배깅이 병렬로 독립적인 트리를 평균내 분산을 줄이는 전략이라면, 
부스팅은 순차적으로 약한 모델을 개선해나가며 편향을 줄이는 전략입니다.   

- 기본 개념
    여러 개의 약한 학습기(weak learner) — 개별로는 성능이 그저 그런 모델(랜덤 추측보다 약간 나은 수준, 주로 얕은 결정트리) — 를 순차적으로 학습
    각 모델은 이전 모델이 잘 못 맞춘 부분을 집중적으로 보완하도록 학습됨
    최종 예측은 모든 모델의 가중 합

ㄱ) AdaBoost (Adaptive Boosting)
    - 원리 
    틀린샘플에 가중치 부여
    "이전 모델이 헷갈려한 문제"에 다음 모델이 더 신경 쓰도록 데이터의 가중치를 계속 조정 — 마치 오답노트를 계속 갱신하며 공부하는 것과 비슷    

ㄴ) Gradient Boosting — 더 일반화된 관점
    - 원리 
    잔차(residual)를 학습

    선형모델에서 손실을 줄이기 위해 파라미터를 경사 방향으로 갱신했다면, Gradient Boosting은 모델(함수) 자체를 경사 방향으로 갱신
    손실함수가 MSE면 그래디언트가 곧 잔차이므로 "잔차를 학습"하는 것과 동일해짐
    손실함수를 바꾸면(로그손실, Huber loss 등) 분류·이상치에 강건한 회귀 등 다양한 문제에 적용 가능 — AdaBoost보다 훨씬 유연한 프레임워크

구분	            AdaBoost	                                            Gradient Boosting
보완 대상	    틀린 샘플의 가중치	                                           잔차(그래디언트)
손실함수	지수 손실(exponential loss)에 암묵적으로 대응	            임의의 미분 가능한 손실함수 사용 가능
유연성	        상대적으로 제한적	                                        회귀/분류/랭킹 등 범용적    


Gradient Boosting을 공학적으로 최적화·정규화한 라이브러리들이 실무 표준

XGBoost: 손실함수에 정규화 항(트리 복잡도 페널티) 추가로 과적합 억제, 2차 근사(뉴턴 방법)로 더 정확한 최적화, 병렬 처리로 속도 개선

LightGBM: 리프 중심(leaf-wise) 트리 성장 + 히스토그램 기반 분할로 대용량 데이터에 빠름

CatBoost: 범주형 변수를 자동으로 잘 처리, 순서 기반 부스팅으로 과적합(target leakage) 방지


	                    랜덤포레스트(배깅 계열)	                                부스팅
개별 트리 깊이	깊게 (과적합 상태, low bias/high variance)	얕게 (stump~depth 3~8, high bias/low variance)
앙상블의 역할	평균으로 분산 상쇄	                        순차적으로 편향 감소
개별 모델 성격	강한 모델(strong learner)에 가까움	        약한 모델(weak learner)

배깅은 분산을 줄이는 것이 목적이므로 개별 모델이 강해도 됨(오히려 강해야 함, 조건①)
부스팅은 약한 모델들을 더해가며 편향을 줄이는 것이 목적이므로, 각 모델은 얕고 약해도 됨(오히려 너무 강하면 과적합 위험)

- 과적합 위험과 대응
    배깅은 트리를 늘려도 과적합이 잘 안 늘어나지만, 부스팅은 모델을 계속 더할수록 학습 데이터에 점점 더 맞춰짐 → 과적합 위험 존재    
    대응책:
            learning_rate(학습률) 낮추기 — 한 번에 조금씩만 개선, 대신 트리 개수(n_estimators)를 늘려 보완
            max_depth 제한 — 개별 트리를 얕게 유지
            조기 종료(Early Stopping) — 검증셋 성능이 더 이상 개선 안 되면 학습 중단
            정규화 항 튜닝 (XGBoost)

- 정형 데이터에서의 위상            
이미지·텍스트 등 비정형 데이터는 딥러닝이 강세지만, 테이블 형태의 정형 데이터에서는 지금도 XGBoost/LightGBM 계열이 신경망보다 우수한 성능을 내는 경우가 많음

정리 한 줄
부스팅은 배깅과 반대로 병렬이 아닌 순차적 학습을 통해, 얕고 약한 모델들이 이전 모델의 오차(또는 그래디언트)를 하나씩 보완해나가며 편향을 줄여나가는 앙상블 기법이며, XGBoost/LightGBM 같은 구현체가 여기에 정규화·최적화를 더해 정형 데이터에서 가장 강력한 실무 알고리즘군으로 자리잡고 있습니다.

7. XGBoost · LightGBM · CatBoost 비교
셋 다 Gradient Boosting의 구현체지만, 트리를 어떻게 키우는지, 분할을 어떻게 찾는지, 범주형 변수를 어떻게 다루는지에서 철학이 갈립니다.

ㄱ) XGBoost (eXtreme Gradient Boosting)

- 핵심 특징
    Gradient Boosting을 최초로 공학적으로 정교화한 라이브러리 (2014년, 캐글 대회 석권으로 유명해짐)
    2차 테일러 근사(뉴턴 방법) 사용 — 1차 그래디언트뿐 아니라 2차 미분(헤시안)까지 활용해 더 정확하게 손실 최소화
    명시적 정규화 항을 목적함수에 포함 (트리 복잡도 페널티):
        - 선형모델의 L2 정규화(Ridge)와 같은 아이디어를 트리 구조에 적용

- 트리 성장 방식
    레벨 단위(Level-wise) 성장: 같은 깊이의 모든 노드를 동시에 분할 (균형 잡힌 트리 형태)
- 결측치 처리
    결측값을 만나면 왼쪽/오른쪽 어느 쪽으로 보낼지 학습 중 자동으로 최적 방향 결정 (Sparsity-aware Split Finding)
- 장단점
    장점: 정확도 높음, 검증된 안정성, 방대한 커뮤니티·문서
    단점: 레벨 단위 성장이라 LightGBM보다 느리고 메모리 더 씀 (특히 대용량 데이터)        

ㄴ) LightGBM (Light Gradient Boosting Machine)
- 핵심 특징 — "가볍고 빠르게"
    Microsoft에서 개발, 속도와 메모리 효율에 초점

- 트리 성장 방식 
    리프 단위(Leaf-wise) 성장: 모든 노드를 동시에 키우지 않고, 손실 감소가 가장 큰 리프 하나만 골라 그 리프를 분할
    같은 리프 수 기준으로 레벨 단위보다 손실을 더 빠르게 줄임 (더 효율적인 트리 형태)
    단, 깊이 제한 없이 두면 한쪽으로만 깊어져 과적합 위험이 큼 → max_depth, num_leaves로 반드시 제어 필요

- 속도 최적화 기법
    히스토그램 기반 분할(Histogram-based): 연속값을 구간(bin)으로 이산화해 분할 후보를 줄임 → 분할 탐색이 훨씬 빠름 (XGBoost도 이후 버전에서 채택)
    GOSS (Gradient-based One-Side Sampling): 그래디언트가 큰(=아직 잘 못 맞추는) 샘플은 그대로 두고, 그래디언트가 작은(=이미 잘 맞추는) 샘플은 일부만 샘플링 → 데이터 양을 줄이면서도 정보 손실 최소화
    EFB (Exclusive Feature Bundling): 동시에 0이 아닌 값을 거의 갖지 않는 희소(sparse) 특징들을 하나로 묶어 차원 축소 효과 → 차원 축소 와는 다른 결의 압축이지만 계산량을 줄인다는 목적은 유사

- 장단점
    장점: XGBoost보다 훨씬 빠름, 메모리 적게 씀, 대용량 데이터에 강함
    단점: 리프 단위 성장 특성상 소규모 데이터에서는 과적합되기 쉬움 (num_leaves 튜닝 민감)


ㄷ)  CatBoost (Categorical Boosting)
- 핵심 특징 — "범주형 변수를 잘 다루자"
    Yandex에서 개발, 이름 그대로 범주형(categorical) 변수 처리에 특화    

- 범주형 변수 처리 — 가장 큰 차이점
    XGBoost/LightGBM은 기본적으로 범주형 변수를 수치로 변환(원-핫 인코딩, 레이블 인코딩 등 사용자가 전처리)해야 함
    CatBoost는 Ordered Target Statistics라는 기법으로 범주형 변수를 자동 인코딩:
        단순히 "해당 범주의 평균 타겟값"으로 치환하면 타겟 누수(target leakage) 발생 (자기 자신의 타겟 정보가 인코딩에 섞여 들어감 → 학습 데이터에 과적합)        
        CatBoost는 데이터를 무작위 순서로 배열한 뒤, 각 샘플 이전에 등장한 데이터만 사용해 평균을 계산 (마치 온라인 학습처럼) → 누수 방지    

- Ordered Boosting
    일반 Gradient Boosting도 사실 미묘한 타겟 누수 문제가 있음(잔차 계산 시 자기 자신의 정보가 간접적으로 섞임)
    CatBoost는 이를 방지하기 위해 순서를 두고 각 단계에서 그 이전 데이터로만 학습하는 Ordered Boosting 기법 사용 → 과적합에 더 강건        

- 트리 성장 방식
    대칭 트리(Oblivious/Symmetric Tree): 같은 깊이의 모든 노드가 동일한 분할 조건(같은 특징, 같은 임계값) 을 사용
    균형 잡히고 정규화 효과가 자연스럽게 생김, 예측 속도가 매우 빠름(CPU에서도), 다만 유연성은 XGBoost/LightGBM보다 낮을 수 있음    

- 장단점
    장점: 범주형 변수 많은 데이터에 최상, 하이퍼파라미터 튜닝 없이도 기본값으로 준수한 성능, 과적합에 강건
    단점: 학습 속도가 LightGBM보다 느릴 수 있음, 수치형 변수 위주 데이터에서는 이점이 덜 뚜렷    

구분	            XGBoost	                LightGBM	                        CatBoost
트리 성장	        레벨 단위	              리프 단위	                        대칭 트리
속도	              중간	                 가장 빠름	                        느림~중간
메모리	            중간~높음	              가장 적음	                            중간
범주형 변수	        수동 인코딩 필요	정수 인코딩 지원(제한적)	            자동·정교하게 처리
과적합 방지	        정규화 항	        num_leaves 신중히 튜닝 필요	        Ordered Boosting으로 강건
소규모 데이터	    안정적	                    과적합 위험 (튜닝 민감)	                안정적
대규모 데이터	 가능하지만 상대적으로 느림	       최적	                             가능
기본값 성능	        튜닝 필요	                튜닝 필요	                    튜닝 없이도 우수
GPU 지원	        지원	                    지원	                   지원 (범주형 변수도 GPU 가속)    

- 언제 무엇을 쓸까
    범주형 변수가 많고(예: 고객 등급, 지역, 카테고리), 빠르게 좋은 결과를 얻고 싶다 → CatBoost
    데이터가 매우 크고(수백만 행 이상) 속도·메모리가 중요하다 → LightGBM
    검증된 안정성, 풍부한 문서·커뮤니티 지원, 정교한 정규화 제어가 필요하다(예: 프로덕션에 이미 XGBoost 파이프라인이 있음) → XGBoost

실무에서는 셋 다 성능이 비슷한 경우가 많아, 셋 다 시도해보고 교차검증으로 비교하는 것이 일반적 (앙상블로 셋을 합치기도 함)

공통점 — 결국 같은 뼈대

셋 다 잔차/그래디언트를 순차적으로 보완하는 Gradient Boosting 프레임워크 위에 서 있고, 
차이는 "트리를 어떤 모양으로 키우느냐"와 "범주형 변수를 어떻게 다루느냐"라는 공학적 최적화 지점에 있습니다. 
근본 원리(약한 학습기 + 순차적 보완 + 편향 감소)는 동일합니다.

8. 학습률(Learning Rate) · 반복 수(n_estimators) · Early Stopping
"과적합 위험과 대응"으로 짧게 언급했던 세 가지 핵심 하이퍼파라미터 
이 셋은 서로 얽혀 있어서 하나만 떼어놓고 튜닝할 수 없는 삼각관계입니다.

ㄱ) 학습률
새로 학습된 트리의 기여분을 얼마나 반영할지 조절하는 축소 계수(shrinkage)

- 왜 작게 설정하는가
    학습률이 크면 몇 번의 반복만으로도 학습 데이터에 급격히 맞춰짐 → 빠르게 과적합
    학습률을 작게 하면 한 트리가 실수해도 전체 예측에 미치는 영향이 작음 → 더 매끄럽고 안정적인 학습 경로, 노이즈에 덜 민감
    선형모델의 경사하강법에서 학습률이 너무 크면 손실이 발산하거나 진동하는 것과 같은 원리 — 여기서도 "너무 큰 보폭으로 걷다가 최적점을 지나쳐버리는" 문제 방지

ㄴ) 반복 수
부스팅 라운드 수, 즉 순차적으로 몇 개의 약한 학습기를 더할 것인가

- 배깅과의 결정적 차이
    배깅/랜덤포레스트는 트리를 늘려도 과적합이 거의 늘지 않음 (평균을 낼 뿐이므로) → 트리 개수는 "많을수록 안정적, 계산 비용만 증가"
    반면 부스팅은 트리를 늘릴수록 학습 데이터에 점점 더 정교하게 맞춰짐 → 어느 지점을 넘으면 검증 성능이 오히려 나빠지는 명확한 과적합 지점이 존재
    학습 손실은 반복할수록 계속 감소(결국 0에 수렴 가능)
    검증 손실은 어느 지점까지 감소하다가 반등 → 이 반등 시작점이 최적 반복 수

ㄷ) Early Stopping
매 반복(트리 추가)마다 별도의 검증셋(validation set) 성능을 함께 측정
검증 성능이 일정 횟수(patience, 예: 50라운드) 동안 개선되지 않으면 학습을 중단하고, 검증 성능이 가장 좋았던 시점의 모델을 최종 모델로 채택

- 알고리즘
    학습 데이터와 별도로 검증 데이터를 분리 (부스팅은 순차적 의존성 때문에 보통 별도의 hold-out 검증셋 사용)
    매 라운드마다 새 트리 추가 후 검증 손실 계산
    검증 손실이 최근 $k$라운드 동안 갱신되지 않으면 중단
    최적 시점(best_iteration)의 모델 반환

- 장점
    반복 수(M)를 직접 튜닝할 필요가 없어짐 — 충분히 큰 $M$(예: 10,000)을 설정해두고 Early Stopping이 알아서 최적 지점에서 멈추게 함
    학습 시간도 절약됨 (불필요한 반복을 하지 않음)
    사실상 정규화(regularization)의 한 형태 — 모델이 너무 복잡해지기 전에 학습을 멈추는 것    

권장 워크플로우
    학습률을 작게 고정 (예: $\eta = 0.05$ 또는 $0.01$) — 너무 크면 성능 상한이 낮아짐
    n_estimators를 매우 크게 설정 (예: 5,000~10,000) — 어차피 Early Stopping이 멈춰줄 것이므로 "너무 많으면 어쩌지" 걱정할 필요 없음
    Early Stopping 활성화, eval_set(검증셋)과 early_stopping_rounds(patience) 설정
    나머지 하이퍼파라미터(max_depth, [[XGBoost·LightGBM·CatBoost|num_leaves]], 정규화 항 등)를 교차검증으로 튜닝   


	                    랜덤포레스트(배깅)	                                부스팅
트리 개수 늘리면	성능 안정적으로 수렴, 과적합 거의 안 늘어남	        과적합 위험 증가 (Early Stopping 필수급)
"학습률" 개념	    없음 (모든 트리 동등하게 평균)	                   있음 (각 트리 기여도 조절, [[부스팅]]과 직결)
튜닝 시 우선순위	트리 개수는 크게 걱정 안 해도 됨	        학습률·반복수·Early Stopping이 가장 먼저 잡아야 할 삼각형     

학습률은 "매 트리의 기여도를 얼마나 작게 눌러서 안정적으로 학습할지"를, 
반복 수는 "그 작은 기여를 몇 번 쌓아올릴지"를 결정하며, 
Early Stopping은 검증 성능을 실시간 관찰해 "언제 멈춰야 과적합 직전에서 최적점을 잡을 수 있는지"를 자동으로 찾아주는 안전장치 

이 셋을 (낮은 학습률 + 충분히 큰 반복수 상한 + Early Stopping)의 조합으로 함께 설정하는 것이 
부스팅 모델의 표준 튜닝 전략입니다.

- 배깅
    같은 문제를 여러 명이 각자 풀고 다수결/평균으로 답 정함
    개인별 실수(노이즈)가 상쇄됨
    애초에 모두가 같은 맹점(체계적 오류)을 가지면 평균 내도 못 고침

- 부스팅    
    한 사람이 풀고, 다음 사람이 그 사람이 틀린 부분만 이어서 품
    아무도 못 풀었던 부분이 누적으로 채워짐
    이론상 계속 이어 풀면 결국 정답에 근접 (단, 과적합 위험 상승)

편향-분산이 "트레이드오프"인가
    부스팅이 편향을 줄이는 대가로 분산이 커짐: 매 라운드가 이전 라운드에 의존(순차적)하므로, 학습 데이터의 작은 변화가 초기 트리부터 전체 사슬에 영향을 미쳐 뒤로 갈수록 증폭될 수 있음
    그래서 학습률을 낮추고 트리를 얕게 유지하며 조기 종료로 편향은 줄이되 분산이 과도하게 커지기 전에 멈추는 균형점을 찾아야 함

    반대로 랜덤포레스트는 애초에 편향이 낮은(깊은) 트리를 쓰고 평균으로 분산만 잡는 전략이므로 이런 위험이 적음 

배깅은 같은 표현력을 가진 모델들을 평균내므로 흔들림(분산)만 줄일 뿐 모델이 원래 가진 체계적 오차(편향)는 그대로 남지만, 부스팅은 이전 모델이 놓친 잔차를 다음 모델이 계속 더해가며 채우는 구조이기 때문에 앙상블 전체의 표현력이 라운드를 거듭할수록 커지고, 이것이 편향을 점진적으로 줄이는 근본 원리입니다.    

9. fold·전처리 경계·AP·계산 조건

ㄱ) 같은 Fold (동일한 교차검증 분할)

- 문제 상황
    모델 A는 5-fold 교차검증을 임의의 시드로 나눠 평가하고, 모델 B는 다른 시드로 나눠 평가하면 → 두 모델이 서로 다른 학습/검증 데이터를 본 것
    데이터 분할 자체에 우연성(어떤 분할은 쉬운 샘플이 검증셋에 몰림)이 존재하므로, 성능 차이가 모델 차이인지 운 좋은 분할 때문인지 구분 불가
- 해결
    모든 모델이 완전히 동일한 fold 인덱스(같은 random_state로 만든 동일한 train/validation 분할)를 사용해야 함
    교차검증을 비교 대상 모델 전체에 대해 같은 KFold 객체(같은 분할) 로 고정해서 적용

ㄴ) 전처리 경계 (Preprocessing Boundary)        

- 문제 상황 — 데이터 누수(Data Leakage)
    스케일링(표준화), 결측치 대체, 인코딩 같은 전처리를 train/validation 분할 전체 데이터에 미리 적용하면, validation 데이터의 정보(평균, 분산 등)가 학습 과정에 스며듦
    이렇게 되면 검증 성능이 실제보다 부풀려짐(낙관적으로 왜곡)
    만약 모델 A는 이 실수를 하고 모델 B는 안 했다면, A가 실제보다 좋아 보이는 불공정한 비교가 됨

- 경계의 의미
    전처리를 fit(학습)하는 시점과 transform(적용)하는 시점 사이에 명확한 경계선을 그어야 함:

    [학습 fold] → 전처리 파라미터 계산(fit) ──┐
                                          ├→ 두 fold 모두에 적용(transform)
    [검증 fold] → 절대 fit에 관여 안 함 ──────┘

    CatBoost의 Ordered Target Statistics 가 정확히 이 경계를 지키기 위해 고안된 기법 — 타겟 인코딩 시 "자기 자신보다 이전 데이터만" 사용해 누수 방지
    비교 대상 모델들이 같은 전처리 파이프라인, 같은 fit/transform 경계를 지키는지 확인해야 순수하게 모델 알고리즘의 차이만 비교 가능

ㄷ) AP (Average Precision, 평균 정밀도)

- 왜 "같은 지표"를 써야 하는가
    평가 지표는 Accuracy, Precision, Recall, F1, ROC-AUC, AP 등 여러 가지가 있고, 어떤 지표를 쓰느냐에 따라 "더 나은 모델"의 순위가 바뀔 수 있음
    특히 클래스 불균형 상황에서는 Accuracy는 왜곡되기 쉽고, ROC-AUC도 다수 클래스에 유리하게 낙관적으로 보일 수 있음

- 비교 시 통제해야 할 이유
    모델 A는 F1으로, 모델 B는 AP로 평가해서 비교하면 애초에 다른 잣대로 잰 것이라 비교 자체가 성립하지 않음    
    결정 임계값(threshold)에 따라 달라지는 지표(F1, Accuracy 등)와 달리 AP는 모든 임계값에 걸친 성능을 종합하므로, 임계값 선택이라는 또 다른 변수까지 통제해주는 효과도 있음

ㄹ) 계산 조건 (Computational Conditions)

- 문제 상황
    LightGBM은 히스토그램 기반이라 근본적으로 더 빠름 → 같은 시간 안에 훨씬 많은 하이퍼파라미터 탐색이나 더 많은 부스팅 라운드를 돌릴 수 있음
    만약 "각자 1시간씩 준다"는 조건으로 튜닝했다면, LightGBM은 그 시간에 100번 탐색하고 XGBoost는 20번밖에 못했을 수 있음 → 성능 차이가 알고리즘의 본질적 우월함이 아니라 단지 더 많이 탐색해봤기 때문일 수 있음

- 통제해야 할 요소들
    같은 트리 개수/라운드 수 (또는 같은 학습률·반복 수·Early Stopping|Early Stopping 조건)
    같은 하이퍼파라미터 탐색 횟수(트라이얼 수) — "동일한 탐색 예산"
    같은 하드웨어(CPU/GPU), 같은 병렬화 수준
    같은 랜덤 시드 (트리의 무작위성, [[랜덤포레스트의 두 무작위성]]에서 다룬 것처럼 특징/데이터 샘플링에 난수가 관여하므로, 시드가 다르면 우연에 의한 차이가 섞임)

- 왜 중요한가
    "속도가 빠른 것 자체도 실무적 장점"이라는 관점이라면 계산 조건을 다르게 줘도 되지만, "알고리즘 자체의 예측력 차이"를 순수하게 비교하고 싶다면 계산 자원을 동일하게 맞춰야 함
    논문/벤치마크에서 "같은 시간 예산 내 최고 성능" vs "같은 반복 수에서의 성능"을 구분해서 명시하는 것도 이 때문

네 조건 모두 "모델 외의 다른 변수를 고정해서, 성능 차이의 원인을 모델 자체로 좁히자" 는 하나의 원칙에서 나옵니다:

조건	                        통제하지 않으면 생기는 혼입변수(confound)
같은 fold	                            데이터 분할의 우연성
전처리 경계	                        데이터 누수로 인한 성능 왜곡
같은 AP(지표)	                    서로 다른 잣대로 비교하는 오류
같은 계산 조건	                    탐색량/자원 차이가 성능 차이로 둔갑

즉, 네 가지를 고정하지 않은 상태에서 "모델 A가 B보다 좋다"고 결론 내리면, 사실은 모델의 우월함이 아니라 실험 설계의 편향을 관측한 것일 수 있습니다.

10. MDI·Permutation Importance·SHAP
"어떤 특징이 예측에 얼마나 기여하는가"를 답하려 하지만, 어느 수준에서, 어떤 원리로 답하는지가 다릅니다.

ㄱ) MDI (Mean Decrease in Impurity) 

트리 학습 중 각 특징이 분할에 쓰일 때마다 불순도(지니/엔트로피/MSE) 감소량을 누적
장점: 계산 빠름(학습 중 자동 산출) / 단점: 카디널리티 높은 변수 과대평가, 학습 데이터 기준이라 일반화 성능과 괴리 가능

ㄴ) Permutation Importance

특징 값을 무작위로 섞어 성능 하락폭을 측정
장점: 모델 무관(model-agnostic), 실제 예측 성능과 직결 / 단점: 계산 비용 큼, 상관된 특징들 간 과소평가 가능

ㄷ) SHAP (SHapley Additive exPlanations)
- 기본 아이디어 — 게임이론에서 빌려온 개념
    MDI와 Permutation은 "이 특징이 전체적으로 얼마나 중요한가" 라는 전역적(global) 질문에 답함
    SHAP은 여기서 한 걸음 더 나아가, "이 특정 샘플의 이 예측값에, 이 특징이 정확히 얼마를 기여했는가" 라는 개별 예측(local) 단위의 질문에 답함
    협력 게임이론의 섀플리 값(Shapley Value) 을 차용 — "여러 참가자가 협력해 만든 보상(payoff)을, 각자의 기여도에 따라 어떻게 공정하게 나눌 것인가"라는 문제의 해법을 특징 기여도 분배에 적용

예시) 
    집값 예측에서 "역세권 여부"라는 특징의 SHAP 값이 +5000만원이라면 → "다른 특징들은 이미 고려된 상태에서, 역세권이라는 정보를 추가로 알려줬을 때 예측 가격이 평균적으로 5000만원 올라간다"는 의미    

- "공정성"의 수학적 보장
섀플리 값은 게임이론에서 다음 네 가지 공리를 동시에 만족하는 유일한 배분 방법으로 증명되어 있습니다
    효율성(Efficiency): 모든 특징의 기여도 합 = 전체 예측값 - 기준값
    대칭성(Symmetry): 두 특징이 항상 동일한 기여를 한다면 같은 값을 받음
    더미(Dummy): 예측에 전혀 영향 없는 특징은 0을 받음
    가산성(Additivity): 여러 모델을 합친 앙상블의 기여도 = 각 모델 기여도의 합

MDI나 Permutation Importance는 이런 공리적 보장이 없는 휴리스틱인 반면, SHAP은 "이렇게 나누는 게 수학적으로 유일하게 공정하다"는 근거를 가짐    

- 언제 무엇을 쓸까
    빠르게 대략적인 감을 잡고 싶다 → MDI (단, 카디널리티 편향 주의)
    모델 무관하게 신뢰할 수 있는 전역 중요도가 필요하다 → Permutation Importance
    개별 예측의 근거를 설명해야 한다(규제 준수, 고객 응대 등), 또는 방향성(어느 쪽으로 영향을 미쳤는지)까지 알아야 한다 → SHAP

셋 중 하나만 정답인 게 아니라, MDI로 빠르게 스크리닝 → Permutation으로 신뢰도 검증 → SHAP으로 개별 사례 설명처럼 단계적으로 함께 쓰는 경우가 많다.

MDI와 Permutation Importance는 "특징이 전체적으로 얼마나 중요한가"를 각각 학습 과정 부산물과 성능 민감도로 답하는 전역 지표인 반면, SHAP은 게임이론의 섀플리 값을 빌려 "이 특정 예측에 이 특징이 정확히 얼마를 더하거나 뺐는가" 를 공리적으로 유일하게 공정한 방식으로 계산하는, 개별 예측 수준까지 설명 가능한 더 정교한 도구입니다.

11. TreeSHAP 전역 해석과 지역 해석

- 일반 SHAP의 문제
정확한 섀플리 값 계산은 조합을 다 봐야 해서 특징이 많으면 사실상 불가능
Kernel SHAP(모델 무관 근사법)은 샘플링으로 근사하지만 느리고 근사 오차 존재

- TreeSHAP의 해법
Decision Tree의 구조(분할 조건, 리프값)를 직접 활용해 정확한 섀플리 값을 다항 시간에 계산
핵심 아이디어: 트리를 따라 내려가는 경로(path)마다, 특정 특징의 값을 "알 때"와 "모를 때"(모르면 여러 자식 노드로 가중 분기)의 기댓값 차이를 재귀적으로 추적
랜덤포레스트나 XGBoost·LightGBM·CatBoost 같은 트리 앙상블에도 그대로 확장(각 트리의 SHAP 값을 더하면 됨 — 섀플리 값의 가산성(Additivity) 공리 덕분)

ㄱ) 지역 해석(Local Interpretation)

- 정의
하나의 개별 샘플에 대해, 각 특징이 그 샘플의 예측값을 기준선(baseline)에서 얼마나 밀어 올리거나 내렸는지 계산
전체 학습 데이터의 평균 예측값(baseline)
샘플 $i$에서 특징 $j$의 기여도 (양수면 예측을 올림, 음수면 내림)

baseline(평균 예측) = 3억원
  + 역세권(O)         : +4000만원
  + 방 개수(3개)       : +1500만원
  + 지어진 연도(1998)  : -2000만원
  + 학군(보통)         : -500만원
  ─────────────────────────────
  = 최종 예측값        : 3억 3000만원

  각 막대가 "baseline에서 최종 예측까지 어떤 특징이 얼마나 밀고 당겼는지"를 누적으로 보여줌 → 왜 이 샘플에 대해 모델이 이런 예측을 냈는지 스토리텔링 가능

- 활용 사례
개별 의사결정 설명: "이 환자는 왜 고위험군으로 분류됐는가?", "이 대출 신청은 왜 거절됐는가?" — 규제 산업(의료, 금융)에서 설명 책임(accountability) 이 요구될 때 필수
이상 사례 디버깅: 모델이 이상하게 예측한 특정 샘플을 골라 SHAP 값을 보면, 어떤 특징이 예상 밖의 기여를 했는지 원인 추적 가능
이상치 탐지 에서 탐지된 이상 거래에 대해 "왜 이상하다고 판단했는가"를 SHAP으로 설명하는 것도 흔한 응용

ㄴ) 전역 해석(Global Interpretation)

- 핵심 관점 — MDI/Permutation과의 근본적 차이
MDI와 Permutation Importance는 처음부터 전역 지표로만 계산됨 (개별 샘플 단위로 분해가 안 됨)
SHAP은 반대 방향: 개별 샘플 단위 지역 해석을 먼저 계산한 뒤, 이를 모든 샘플에 대해 집계해서 전역 해석을 얻음 — "전역은 지역의 평균"이라는 구조

방법 ① — 평균 절대값으로 전역 중요도 산출
모든 샘플에서 특징 $j$의 기여도 크기(절댓값)를 평균 → MDI/Permutation과 비슷한 형태의 "특징 중요도 순위"를 얻되, 섀플리 값 기반이라 카디널리티 편향 없음

방법 ② — Summary Plot (분포까지 보여주는 시각화)
각 특징마다 모든 샘플의 SHAP 값을 점으로 흩뿌려 표시, 점의 색깔로 그 샘플에서의 실제 특징값 크기(높음/낮음)를 표현
단순히 "중요하다"는 순위뿐 아니라, "높은 값일 때 예측을 올리는지 내리는지" 방향성까지 한눈에 파악 — MDI/Permutation은 이 정보를 못 줌

방법 ③ — Dependence Plot
특정 특징의 실제 값(x축) vs 그 특징의 SHAP 값(y축)을 산점도로 그림 → 특징과 예측 사이의 비선형 관계를 시각적으로 드러냄
예: "면적이 커질수록 SHAP 기여도가 증가하지만, 어느 지점 이후로는 기여도 증가폭이 둔화된다" 같은 패턴 발견 가능
색상으로 다른 특징과의 상호작용도 함께 표현 가능(SHAP interaction values)

구분	            지역 해석(Local)	                    전역 해석(Global)
단위	                샘플 1개	                        전체 데이터셋
질문	        "왜 이 샘플은 이렇게 예측됐나?"	            "전반적으로 어떤 특징이 중요한가?"
산출 방식	    TreeSHAP으로 직접 계산	                    지역 SHAP 값들을 평균/집계
시각화	        Waterfall Plot, Force Plot	               Summary Plot, Dependence Plot
방향성 정보	    있음(그 샘플에서 +/-)	                    있음(Summary Plot의 색상으로)
용도	        개별 의사결정 설명, 디버깅	                특징 선택, 모델 전반 이해, 도메인 지식 검증

MDI/Permutation은 "숲을 보되 나무는 못 본다" — 전체적으로 어떤 특징이 중요한지는 알려주지만, 특정 개별 사례를 설명할 수 없음
TreeSHAP은 "나무를 먼저 정확히 보고, 그것들을 모아 숲을 그린다" — 지역 해석이라는 더 세밀한 단위에서 출발해 일관된 수학적 원리(섀플리 값의 가산성)로 전역 해석까지 자연스럽게 이어짐

TreeSHAP은 트리 구조를 활용해 각 개별 샘플의 예측에 대한 특징별 정확한 기여도(지역 해석)를 다항 시간에 계산하고, 이 지역 값들을 평균·집계함으로써 전체 데이터셋 차원의 특징 중요도와 방향성(전역 해석)까지 하나의 일관된 수학적 틀(섀플리 값) 안에서 얻어낼 수 있다는 점이 MDI·Permutation Importance 와 구별되는 가장 큰 강점입니다.

ㄷ) RAG 품질 SHAP 값으로 본 bar·beeswarm·waterfall
구분	            Bar	                    Beeswarm	                            Waterfall
단위	        전체 데이터셋	            전체 데이터셋	                            샘플 1개
축의 의미	        평균 크기	        개별 SHAP 값(부호) + 특징값(색)	        누적 기여(baseline→예측)
방향성	            없음	                    있음	                                있음
질문	"전반적으로 뭐가 중요한가?"	"그 중요도가 어느 방향이고 얼마나 퍼져 있나?"	"이 특정 RAG 응답은 왜 이 점수가 나왔나?"

뿌리는 같은 SHAP 행렬이고, bar는 그 행렬을 열(특징)별로 평균 절댓값 한 줄로 압축한 것, beeswarm은 열별로 행(샘플) 전체를 펼쳐서 방향성까지 보여준 것, waterfall은 반대로 행(샘플) 하나만 골라 열(특징) 전체를 펼쳐서 그 샘플의 예측이 조립되는 과정을 보여준 것이라고 이해하시면 됩니다.

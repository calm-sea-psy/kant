1. 대형 언어 모델(LLM)을 조정하는 일반적인 정렬(Alignment) 파이프라인

    - LLM 정렬의 기본 흐름은 방대한 텍스트로 Base Model을 사전학습하는 것에서 시작합니다. 
    - 이후 고품질의 지시어-응답 쌍으로 지도 학습(SFT)을 진행하여 Instruction Model을 만듭니다. 
    - 그 다음 인간의 선호도 데이터를 바탕으로 보상 모델(Reward Model)을 학습시키고, 
    - 마지막으로 PPO와 같은 강화학습 알고리즘을 사용해 보상 모델의 점수를 극대화하는 방향으로 LLM을 최적화(RLHF)합니다.

2. Base Model을 Instruction Model로 변환하기 위해 지도 학습 기반 미세조정(SFT, Supervised Fine-Tuning)

    - Base Model은 단순히 다음 단어를 예측하도록 학습되어 있어 사용자의 질문에 답변하기보다는 텍스트를 이어쓰는 경향이 있습니다. 
    - SFT는 고품질의 지시어와 정답 쌍 데이터를 통해 모델이 사용자의 의도를 이해하고 지시를 수행하는 방식(Instruction Model)으로 동작하도록 행동을 교정하는 역할을 합니다.

3. RLHF(Reinforcement Learning from Human Feedback) 과정에서 보상 모델(Reward Model)

    - 보상 모델은 인간의 선호도를 모방하여 점수를 매기도록 학습되는 모델입니다. 
    이를 위해 동일한 질문에 대한 여러 개의 답변을 생성한 뒤, 사람이 더 유용하고 안전한 답변에 높은 순위를 매긴 선호도 데이터(Preference Data)를 학습에 사용합니다. 
    - 이를 통해 보상 모델은 사람의 가치관과 일치하는 답변에 높은 점수를 주게 됩니다.


4. LLM Alignment의 마지막 단계에서 주로 사용되는 PPO(Proximal Policy Optimization) 

    - PPO는 강화학습 기법 중 하나로, 모델(Policy)이 보상 모델로부터 높은 보상을 받도록 가중치를 조정하는 역할을 합니다. 
    이때 모델이 점수만 높이기 위해 문법이 파괴된 이상한 텍스트를 생성하는 것(Reward Hacking)을 방지하기 위해, 원본 SFT 모델의 출력 분포에서 너무 멀어지지 않도록 KL Divergence 페널티를 적용하는 것이 핵심입니다.

5. LLM API에 대화 이력을 전달할 때 사용되는 메시지 구조(role/content) 중, 각 역할(role)

    - 'assistant'는 모델이 이전에 생성한 답변을 의미하며 대화의 이력을 구성하는 데 사용됩니다. 
    - 'system'은 모델의 전반적인 행동 지침을 설정합니다. 
    - 'user'는 사용자의 요청을 담습니다. 
    - 대화를 하나의 긴 텍스트로 묶기보다는 역할이 명시된 리스트 구조로 전달하는 것이 안전합니다.

6. Few-shot 프롬프팅

    - Few-shot 프롬프팅은 지시문과 함께 소수의 '입력-출력 예시'를 제공하여 모델이 출력 패턴을 학습하게 하는 기법입니다. 


7. 생각의 사슬(Chain-of-Thought, CoT)

    - 복잡한 수학적 계산이나 다중 조건 논리 퍼즐을 풀 때, 모델이 논리적 비약을 일으켜 오답을 내는 현상을 방지하기 위해 
    사용하는 기법
    - Chain-of-Thought (CoT) 기법은 모델이 최종 결론을 내리기 전에 문제를 여러 단계로 나누어 중간 풀이 과정(추론)을 생성하도록 유도하는 방법입니다. 
    - 이전에 생성된 논리적 풀이 텍스트가 후속 예측의 탄탄한 맥락으로 작용해 복잡한 문제의 정답률을 크게 끌어올립니다.

8. System Prompt(또는 Developer Prompt)를 작성할 때 부여하는 명시적 페르소나(Role)

    - LLM에 명확한 페르소나를 부여하면, 방대한 데이터 중 해당 분야와 연관성이 높은 전문 지식 및 어휘의 출력 확률이 우선적으로 높아져 답변의 질과 해상도가 상승합니다. 
    - 이는 통신 채널 개방이나 지식 컷오프 극복과는 무관한 확률적 텍스트 생성 메커니즘입니다.

9. tokenizer의 apply_chat_template() 함수

    messages = [
        {"role": "system", "content": "친절한 AI 튜터입니다."},
        {"role": "user", "content": "Chat Template이 무엇인가요?"}
    ]
    formatted_text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)

    - Chat 모델들은 각기 고유한 대화 형식(예: <|system|> 토큰 사용, [INST] 태그 사용 등)으로 학습되었습니다. apply_chat_template()은 딕셔너리로 구성된 role/content 리스트를 해당 모델이 기대하는 정확한 텍스트 포맷으로 변환하여, 포맷 불일치로 인한 성능 저하와 에러를 방지합니다.

10. Tool/Function Calling

    - 사용자의 질문을 받은 LLM이 자체 지식만으로 답변하기 어려울 때, 사내 데이터베이스를 검색하거나 실시간 날씨 API 등 외부 시스템을 직접 트리거(Trigger)하도록 만들고 싶습니다. 이를 구현하기 위해 사용해야 하는 핵심 LLM 기능

    - Tool/Function Calling은 LLM이 사용자 의도를 분석한 뒤, 미리 정의된 외부 도구(API, 데이터베이스 조회 등)를 실행하는 데 필요한 매개변수(Parameter)를 생성하도록 하는 기능입니다. 이를 통해 LLM은 단순한 텍스트 생성기를 넘어, 실세계의 시스템과 능동적으로 상호작용하는 에이전트(Agent)로 동작할 수 있습니다.

11. 멀티모달 프롬프팅

    - 고객 센터 챗봇을 기획 중입니다. 사용자가 고장 난 제품의 '사진'과 증상을 설명하는 '음성 파일'을 동시에 업로드하면, AI가 이를 종합적으로 분석하여 해결책을 제시하게 하려 할때 사용되는 생성형 AI의 핵심 특성

    - 멀티모달 프롬프팅은 텍스트뿐만 아니라 이미지, 오디오, 비디오 등 다양한 형태(모달리티)의 데이터를 동시에 입력받아 상호 연관성을 유기적으로 추론하는 기능입니다. 이를 통해 텍스트만으로 파악하기 힘든 상황(예: 기기 파손 상태, 음성 억양 등)을 종합적으로 이해하여 더 정확하고 입체적인 서비스를 제공할 수 있습니다.

1. Attention
Attention은 시퀀스의 각 위치가 다른 모든 위치를 직접 참조해서, "관련도"에 따라 정보를 가중 평균으로 뽑아오는 연산이다.
한 토큰의 표현(representation)을 만들 때 나머지 토큰 중 무엇이 중요한지를 동적으로(입력에 따라 매번 다르게) 결정한다는 게 핵심이다. 고정된 가중치가 아니라, 입력 내용에 따라 "어디를 볼지"가 계산된다.

ㄱ) 기본형 (Scaled Dot-Product Attention)

    Attention(Q, K, V) = softmax(Q Kᵀ / √d_k) V

    - Q Kᵀ — 쿼리와 각 키의 내적으로 유사도 점수 계산
    - / √d_k — 차원이 커지면 내적값이 커져 softmax가 포화(gradient 소실)되므로 스케일 조정
    - softmax — 점수를 합이 1인 확률분포(attention weight)로 변환
    - × V — 그 가중치로 value들을 가중합 → 출력

ㄴ) 사용하는 이유
RNN/LSTM 기반 seq2seq의 한계를 풀기 위해 나왔다.

a. 장거리 의존성 (long-range dependency)
RNN은 정보를 순차적으로 옆으로 전달하므로, 50토큰 떨어진 단어의 정보는 여러 스텝을 거치며 희석된다(vanishing gradient). Attention은 거리에 상관없이 두 토큰을 한 번에 직접 연결한다(경로 길이 O(1)).

b. 고정 크기 context vector 병목 제거
초기 seq2seq는 인코더가 문장 전체를 벡터 하나로 압축해 디코더에 넘겼다. 문장이 길수록 정보 손실이 크다. Attention(Bahdanau, 2014)은 디코더가 매 스텝마다 인코더의 모든 위치를 다시 골라볼 수 있게 해서 이 병목을 없앴다.

c. 문맥 의존적 의미
"눈이 내린다" vs "눈이 아프다"에서 "눈"의 표현은 달라야 한다. Attention은 주변 토큰을 참조해 표현을 문맥에 맞게 조정한다.

d. 병렬 처리
RNN은 t-1을 계산해야 t를 계산할 수 있어 본질적으로 순차적이다. Attention은 모든 위치의 Q·K를 한 번의 행렬곱으로 동시에 계산 → GPU에서 훨씬 효율적. Transformer가 대규모 학습을 가능하게 한 이유 중 하나다.

2. Query / Key / Value
검색 시스템 비유가 가장 잘 맞는다. 도서관에서 자료를 찾는다고 하면 아래와 같다.

| 요소 | 역할 | 비유 |
|---|---|---|
| Query (Q) | 지금 내가 찾고 있는 정보가 무엇인가 | 검색어 |
| Key (K) | 나는 어떤 정보를 담고 있는가 (매칭용 라벨) | 책 제목·색인 |
| Value (V) | 매칭되면 실제로 전달할 내용 | 책의 본문 |

ㄱ) Query
현재 토큰이 "나는 지금 이런 정보가 필요하다"라고 내보내는 벡터다. 이걸 모든 Key와 비교해서 어디에 주목할지 점수를 매긴다.

ㄴ) Key
각 토큰이 "나를 참조하려면 이런 조건에 맞아야 한다"라고 내거는 광고판이다. Query와의 내적이 클수록 그 토큰이 선택된다.

ㄷ) Value
매칭이 끝난 뒤 실제로 꺼내와 가중합되는 내용물이다. attention weight가 높은 토큰의 Value가 출력에 많이 반영된다.

ㄹ) 계산 흐름
입력 X에서 학습 가능한 가중치 행렬로 세 벡터를 만든다.

    Q = X W_Q,   K = X W_K,   V = X W_V

    - Self-attention: Q, K, V 모두 같은 입력 X에서 나옴 (문장이 자기 자신을 참조)
    - Cross-attention: Q는 디코더에서, K·V는 인코더에서 (번역에서 출력이 입력을 참조)

ㅁ) Q와 K를 분리하는 이유
"무엇을 찾는가"와 "무엇을 제공하는가"를 서로 다른 공간에서 표현할 수 있다. 덕분에 비대칭 관계를 학습한다 — "형용사가 자기가 꾸미는 명사를 찾는" 정도와 "명사가 형용사를 찾는" 정도가 다를 수 있다.

ㅂ) K와 V를 분리하는 이유
매칭에 쓰는 표현과 실제로 전달할 내용을 따로 둘 수 있다. 표면적 특징으로 매칭하되, 전달은 훨씬 풍부한 정보로 할 수 있다.

ㅅ) Multi-head
Q/K/V 세트를 여러 개(head) 병렬로 두면, 각 head가 서로 다른 종류의 관계(구문적 의존, 의미적 유사, 위치적 패턴 등)를 동시에 포착한다. 마지막에 concat 후 다시 선형변환한다.

3. Transformer 안에서 선형 계층
ㄱ) Q / K / V projection
어텐션에 들어가기 전, 입력 X를 세 방향으로 사영한다.

    Q = X W_Q    (d_model → d_k)
    K = X W_K    (d_model → d_k)
    V = X W_V    (d_model → d_v)

어텐션 연산 자체(내적·softmax·가중합)에는 학습 파라미터가 거의 없다. 학습은 대부분 이 W_Q / W_K / W_V에서 일어난다. "무엇을 기준으로 토큰을 매칭할지"를 이 행렬들이 결정한다.

4. 어텐션 계산 4단계
softmax(Q Kᵀ / √d_k) V 를 네 동작으로 쪼개서 보면 이렇게 된다.

| 단계 | 연산 | 한 줄 요약 |
|---|---|---|
| 1. 비교 | Q Kᵀ | 쿼리와 모든 키의 내적 → 관련도 점수 |
| 2. 조절 | ÷ √d_k | 점수 크기를 눌러 softmax가 포화되지 않게 |
| 3. 비율 | softmax | 점수를 합이 1인 배분 비율로 변환 |
| 4. 섞기 | × V | 그 비율로 value들을 가중합 → 새 표현 |

ㄱ) 비교 (Q · Kᵀ)
각 쿼리 벡터를 모든 키 벡터와 내적한다.

    Q : (n, d_k)      n개 쿼리
    K : (m, d_k)      m개 키
    scores = Q Kᵀ  →  (n, m)

    - scores[i][j] = "토큰 i의 질문"이 "토큰 j의 라벨"과 얼마나 맞는가
    - 내적이 크다 = 두 벡터가 같은 방향 = 관련도 높음
    - self-attention이면 n = m (문장이 자기 자신을 비교), cross-attention이면 다를 수 있음

예: "그 고양이가 피곤해서 그것이 잤다"에서 "그것이"의 쿼리는 "고양이"의 키와 내적값이 크게 나오도록 학습된다(대명사 해소).

ㄴ) 조절 (÷ √d_k)
내적값을 √d_k로 나눈다.
    - 내적은 d_k개 항의 합이다. 각 항이 평균 0, 분산 1이라면 합의 분산은 d_k, 표준편차는 √d_k
    - d_k = 64면 점수가 대략 ±8 범위로 퍼짐 → softmax에 넣으면 한 곳으로 확 쏠려(포화) 나머지는 거의 0
    - 포화되면 그 지점의 gradient도 거의 0 → 학습이 멈춤
    - √d_k로 나누면 분산이 다시 1 수준 → softmax가 적당히 부드러운 분포

마스킹도 이 단계에서 적용한다. Causal(디코더) 어텐션은 미래 토큰 위치의 점수에 -∞를 더해서, 다음 softmax에서 그 자리 비율이 0이 되게 만든다.

ㄷ) 비율 (softmax)
각 행(하나의 쿼리)에 대해 점수를 확률분포로 바꾼다.
    - a[i][j] = 토큰 i가 토큰 j에 주는 주목 비율(attention weight)
    - 핵심은 총량이 1로 고정된 경쟁 구조다. 한 토큰에 0.8을 주면 나머지 전부 합쳐서 0.2밖에 못 줌
    - 2단계의 스케일은 사실상 온도(temperature) 역할을 한다. 많이 나누면 → 점수 차이가 줄어 분포가 평평(여러 곳을 골고루), 적게 나누면 → 뾰족(한 곳에 집중)

ㄹ) 섞기 (× V)
주목 비율로 value 벡터들을 가중 평균한다.
    - 결과 output[i]는 토큰 i의 새 표현이다 — 관련 있는 토큰들의 내용(value)을 관련도만큼 끌어와 합친 벡터. "그것이"의 출력에는 "고양이"의 value가 많이 섞여 들어간다.

1·4단계는 학습 파라미터가 없는 순수 행렬곱이고, 2·3단계는 파라미터가 없는 고정 연산이다. 학습되는 건 앞뒤의 projection(W_Q/W_K/W_V/W_O)뿐이다.

ㅁ) 숫자 예시 (4단계 전체)
문장 "그 고양이가 잤다" — 토큰 3개, d_k = 4, d_v = 2. 쿼리는 "잤다"(자기 주어를 찾는다).

    Q(잤다) = [1, 1, 0, 0]

    K(그) = [1,0,0,0]      K(고양이가) = [2,2,0,0]      K(잤다) = [0,1,0,0]
    V(그) = [0,0]          V(고양이가) = [1,0]          V(잤다) = [0,1]

    1. 비교   Q·K 내적          →  scores = [1, 4, 1]
    2. 조절   ÷ √d_k = ÷ 2       →  [0.5, 2.0, 0.5]
    3. 비율   softmax            →  [0.15, 0.69, 0.15]   (합 ≈ 1, 반올림)
    4. 섞기   비율로 V 가중합     →  0.15·[0,0] + 0.69·[1,0] + 0.15·[0,1] = [0.69, 0.15]

"잤다"의 새 표현이 주어 "고양이가"의 V([1,0]) 쪽으로 크게 쏠렸다 — 비율 0.69가 거기 몰렸기 때문.

ㅂ) shape
아래는 single-head 기준(H 생략). 멀티헤드 shape는 5절.

| 시점 | shape | 마지막 축이 뜻하는 것 |
|---|---|---|
| 입력 | [B, L, D] | 각 토큰의 특징 벡터 (D개 숫자) |
| 비교 후 (scores) | [B, L, L] | 토큰 i가 토큰 j를 보는 원점수 (합 제약 없음) |
| 비율 후 (weights) | [B, L, L] | 각 쿼리의 참고 비율 분포 (L개 토큰에 대한 가중치, 합=1) |
| 혼합 후 | [B, L, D] | 문맥이 섞인 특징 벡터 (다시 D개 숫자) |

비교 단계에서 D가 소거됨: Q @ Kᵀ 는 내적이다. 토큰 i의 D차원 벡터와 토큰 j의 D차원 벡터를 곱해 숫자 하나(관련도)로 만든다. D개 값이 1개로 압축되면서 사라지고, 그 자리에 "상대 토큰 j" 축(길이 L)이 들어온다.

혼합 단계에서 D가 부활: weights @ V 는 V 벡터들(각 D차원)을 가중합한다. 두 번째 L축(어떤 토큰을 볼지)이 합산되어 사라지고, V가 가진 D축이 결과에 남는다.

가운데 [B, L, L] 에는 특징(D) 정보가 전혀 없다. 순수하게 "토큰 L개가 서로를 얼마나 참고하는가" 표만 남는다. 그 표로 원래 특징 벡터들을 다시 섞어서 [B, L, D] 로 복원하는 게 어텐션이다.

ㅅ) Attention scores
Attention scores는 Q · Kᵀ 로 나온, softmax를 거치기 전의 원점수 행렬이다. attention logits라고도 부른다.
마스킹도 이 단계에서 scores에 마스크를 더한다 (곱이 아님).

    scores_masked[i][j] = scores[i][j] + mask[i][j]

    mask[i][j] =  0       (j ≤ i 일 때  — 봐도 되는 자리)
    mask[i][j] = -1e9     (j > i  일 때  — 미래라서 가려야 하는 자리)

실제 행렬로 보기

    key        j=0    j=1    j=2    j=3
    query
    i=0          0   -1e9   -1e9   -1e9     ← 토큰 0은 자기(0)만 봄
    i=1          0      0   -1e9   -1e9     ← 토큰 1은 0,1 봄
    i=2          0      0      0   -1e9     ← 토큰 2는 0,1,2 봄
    i=3          0      0      0      0     ← 토큰 3은 다 봄

    - causal mask (디코더): j > i 인 자리를 가림 → 토큰 i는 미래를 못 봄. L_q × L_k 평면의 상삼각 부분
    - padding mask: 배치 정렬용으로 채운 <pad> 토큰 위치를 가림

ㅇ) Attention weight (주목 가중치)
softmax를 거친 참고 비율. "쿼리 i가 키 j를 얼마나 볼지"
    - 동적 가중치: 학습되는 파라미터가 아니다. 입력이 들어올 때마다 매번 새로 계산된다. (학습되는 건 뒤에 있는 W_Q/W_K/W_V)
    - 확률분포: 각 쿼리 행이 "1.0이라는 예산을 어느 키에 나눠줄지" 정한 것. 경쟁 구조 — 한 곳에 몰아주면 나머지는 적어짐
    - 해석에 사용: [L_q, L_k] 행렬을 히트맵으로 그리면 "어떤 토큰이 어떤 토큰을 봤는지" 시각화됨 (attention map). 단, 이게 곧 모델의 근거라고 단정하긴 어렵다는 논쟁도 있음

ㅈ) Context vector
그 비율로 V를 가중합한 결과. "문맥이 반영된 토큰 표현"
토큰 i의 새 표현이다. 관련 있는 토큰들의 정보(V)를 관련도(a)만큼 끌어와 합친 벡터.
    - 원래 입력 X_i 는 "토큰 i 혼자"의 표현이었다면, c_i 는 "문맥 속의 토큰 i"
    - self-attention이면 토큰마다 context vector가 하나씩 → [B, L, D]
    - 멀티헤드면 head별로 c_i 가 나오고, concat 후 W_O 로 합쳐서 최종 [B, L, D]

ㅊ) 정리

| 이름 | 시점 |
|---|---|
| attention scores / raw scores | Q @ Kᵀ 직후 |
| scaled scores / attention logits | ÷ √d_k (+ mask) 후, softmax 직전 |
| attention weights / probabilities / 참고 비율 | softmax 후 |
| context vector | weights @ V 후 |

    - softmax 전: attention scores / attention logits / (스케일 후) similarity
    - softmax 후: attention weights / attention probabilities / 참고 비율

5. Multi-Head Attention
단일 어텐션은 하나의 가중 평균만 계산한다. 즉 토큰 사이의 관계를 한 종류만 포착할 수 있다. 게다가 softmax 가중합은 평균화라서, 여러 관계가 섞이면 서로 뭉개진다.

Multi-Head Attention은 어텐션을 H개 병렬로 돌린다. 각 head는 D차원 전체가 아니라 d = D/H 차원의 작은 부분공간(subspace)에서 독립적으로 Q/K/V를 만들고 어텐션한다.

결과적으로 head마다 다른 관계를 담게 된다 — 예: 한 head는 "바로 다음 토큰", 한 head는 대명사-선행사(coreference), 한 head는 주어-동사, 한 head는 구두점 등. (BERT 분석 연구들에서 실제로 관찰됨)

ㄱ) 구조
D = 512, H = 8 → d = 64 예시.

| 기호 | 뜻 | 값 |
|---|---|---|
| D | d_model, 모델 차원 (토큰 벡터 길이) | 512 |
| H | head 개수 (병렬 어텐션 수) | 8 |
| d | head 차원 (d_head, d_k), D / H | 64 |

    X                                   [B, L, D]      (1, 10, 512)

    ── projection (W_Q, W_K, W_V : D×D) ──
    Q = X W_Q,  K = X W_K,  V = X W_V    [B, L, D]      (1, 10, 512)

    ── head로 쪼개기 ──
    reshape   [B, L, H, d]                              (1, 10, 8, 64)
    transpose [B, H, L, d]                              (1, 8, 10, 64)

여기서 W_Q 하나가 사실상 head별 작은 행렬 H개를 이어붙인 것이다. reshape는 그걸 다시 head 축으로 분리하는 것뿐 — 실제 연산은 큰 행렬곱 한 번이다.

ㄴ) 계산 (head 축을 배치처럼 취급)

| 단계 | 연산 | shape |
|---|---|---|
| 1. 비교 | Q @ Kᵀ | [B, H, L, L] |
| 2. 조절 | ÷ √d (+ mask) | [B, H, L, L] |
| 3. 비율 | softmax(dim=-1) | [B, H, L, L] |
| 4. 섞기 | A @ V | [B, H, L, d] |

스케일이 √D 가 아니라 √d(head 차원)다. 각 head가 d차원에서 내적하기 때문.

ㄷ) 합치기 (concat + output projection)

    head 출력   [B, H, L, d]                (1, 8, 10, 64)
    └ transpose → [B, L, H, d]             (1, 10, 8, 64)
    └ reshape   → [B, L, D]                (1, 10, 512)     ← head들을 이어붙임(concat)
    └ @ W_O   (D×D)  →  [B, L, D]          (1, 10, 512)

W_O 는 단순 이어붙이기로 끝내지 않고, head들의 정보를 다시 섞어서 최종 표현을 만든다. 이게 없으면 head별 출력이 그냥 512차원 안에 64칸씩 따로 놓인 상태로 끝난다.

ㄹ) 파라미터 / 연산량
head를 나눠도 파라미터·연산량은 그대로다. H · d = D 이므로 "512차원 어텐션 1개"나 "64차원 어텐션 8개"나 총량이 같다. head 수를 바꿔도 모델 크기는 거의 안 변한다.

ㅁ) head 수 선택
    - 너무 적으면: 관계 다양성 부족
    - 너무 많으면: 각 head의 d가 작아져(예: d=8) 표현력 저하
    - 관행: d = 64~128 유지. BERT·GPT-2 계열은 d=64 (D=768→H=12, D=1024→H=16), 최근 대형 모델은 d=128 (Llama-2 7B는 D=4096→H=32)
    - 연구(Are Sixteen Heads Really Better than One?): 학습 후 상당수 head를 pruning해도 성능이 유지됨 → head 간 중복이 꽤 있음

1. 손실 함수(Loss Function)의 역할
손실 함수는 모델의 예측값과 실제 정답(레이블) 사이의 차이(오차)를 하나의 숫자로 계산하는 함수입니다. 딥러닝 학습 과정에서 다음과 같은 핵심 역할을 합니다.

ㄱ) "얼마나 틀렸는지"를 정량화
모델이 아무리 복잡해도 결국 학습이 되려면 "지금 예측이 얼마나 나쁜가"를 숫자(스칼라)로 표현해야 합니다. 이 숫자가 작을수록 예측이 정답에 가깝다는 뜻입니다.

ㄴ) 학습(최적화)의 목표 설정
경사하강법(gradient descent)은 결국 손실 함수 값을 최소화하는 방향으로 파라미터(가중치)를 조정하는 과정입니다. 손실 함수가 없으면 "어느 방향으로 가중치를 바꿔야 더 나아지는지" 판단할 기준 자체가 없습니다.

ㄷ) 역전파(backpropagation)의 시작점
손실 값에 대해 각 파라미터의 gradient(미분값)를 계산하는 게 역전파인데, 이 gradient 계산이 시작되는 지점이 바로 손실 함수입니다. loss.backward()를 호출하면 손실값에서부터 거꾸로 각 레이어의 가중치까지 gradient가 전파됩니다.

ㄹ) 문제 유형에 맞는 "정답의 정의" 제공
어떤 손실 함수를 쓰느냐가 곧 "모델이 뭘 잘해야 좋은 모델인가"를 정의합니다.
    - 회귀(regression): MSE(평균제곱오차) — 예측값과 실제값의 거리를 최소화
    - 이진 분류: BCEWithLogitsLoss — Sigmoid 출력과 정답(0/1) 사이의 확률적 차이
    - 다중 분류: CrossEntropyLoss — Softmax로 얻은 클래스별 확률 분포와 정답 클래스 간의 차이(엔트로피 기반)

같은 모델 구조라도 손실 함수를 잘못 고르면(예: 분류 문제에 MSE 사용) 학습이 비효율적이거나 아예 이상한 방향으로 수렴할 수 있습니다.

2. 목표 함수(Objective Function)
목표 함수는 최적화 과정에서 "최대화" 또는 "최소화"하고자 하는 대상 함수를 가리키는 좀 더 넓은 개념입니다. 머신러닝/딥러닝 맥락에서는 손실 함수와 거의 같은 의미로 쓰이지만, 정확히는 손실 함수를 포함하는 상위 개념입니다.

ㄱ) 손실 함수와의 관계
    - 목표 함수(objective function): 최적화 문제 전반에서 "최적화하려는 함수"를 가리키는 일반 용어. 최소화할 수도, 최대화할 수도 있음.
    - 손실 함수(loss function): 목표 함수 중에서도 특히 "작을수록 좋은" 오차/비용을 나타내는 함수 — 즉, 최소화 대상인 목표 함수.
    - 비용 함수(cost function): 보통 손실 함수를 전체 데이터셋(또는 배치) 단위로 평균/합산한 것. 개별 샘플 단위면 loss, 전체 집계면 cost라고 구분하기도 하지만 실무에서는 거의 혼용됩니다.

목표 함수 (objective) ⊃ 손실 함수 (loss, 최소화용) / 보상 함수 (reward, 최대화용) 등

ㄴ) 딥러닝 학습에서의 역할
지도학습(supervised learning)에서는 보통 목표 함수 = 손실 함수(최소화)로 놓고, 학습 과정을 다음과 같이 정의합니다.

    학습 = 목표 함수(손실 함수)를 최소화하는 파라미터(가중치 θ)를 찾는 최적화 문제

ㄷ) 왜 "목표"라는 표현을 쓰는가
    - 강화학습(RL)에서는 "보상(reward)을 최대화"하는 것이 목표 함수인 경우가 많아, "손실을 최소화"라는 표현보다 "목표 함수를 최적화한다"는 표현이 더 일반적입니다.
    - 정규화 항(regularization term)이 추가된 경우, 순수 오차(loss) + 페널티(penalty) 형태로 목표 함수가 구성되기도 합니다. 예: 목표 함수 = 손실 + λ·정규화항 (L1/L2 규제 등)

3. 회귀 / 이진 분류 / 다중 분류 손실 함수
문제 유형에 따라 "무엇을 오차로 볼 것인가"가 다르기 때문에 서로 다른 손실 함수를 씁니다. 크게 세 가지로 나눠서 정리하겠습니다.

ㄱ) 회귀(Regression) — 연속값 예측
예측값이 연속적인 실수(가격, 온도, 좌표 등)일 때 사용합니다.

a. MSE (Mean Squared Error, 평균제곱오차) — 가장 대표적
    - 오차를 제곱하기 때문에 큰 오차에 더 큰 페널티를 줌 (이상치에 민감)
    - PyTorch: nn.MSELoss()

b. MAE (Mean Absolute Error, 평균절대오차)
    - 절대값이라 이상치에 덜 민감하지만, 0 근처에서 미분이 불연속(정확히는 미분 불가능 지점 존재)
    - PyTorch: nn.L1Loss()

c. Huber Loss — MSE와 MAE의 절충
    - 오차가 작으면 MSE처럼, 크면 MAE처럼 동작 → 이상치에 강건하면서도 미분 가능
    - PyTorch: nn.SmoothL1Loss()

ㄴ) 이진 분류(Binary Classification) — 두 클래스 중 하나
출력이 "0 또는 1일 확률"인 문제 (스팸/정상, 양성/음성 등).

Binary Cross Entropy (BCE)
    - 정답이 1인데 확률을 낮게 예측할수록, 정답이 0인데 확률을 높게 예측할수록 손실이 커짐 (로그 함수 특성상 확신에 찬 오답에 매우 큰 페널티)
    - PyTorch에서는 보통 nn.BCEWithLogitsLoss()를 씀 → 모델 출력(logit)에 Sigmoid + BCE를 한 번에 처리해서 수치적으로 더 안정적임 (별도로 Sigmoid를 적용한 뒤 nn.BCELoss()를 쓰는 것보다 권장됨)

ㄷ) 다중 분류(Multiclass Classification) — 셋 이상의 클래스 중 하나

Categorical Cross Entropy (CE)
    - 모델의 raw 출력(logits)에 Softmax를 적용해 클래스별 확률 분포로 만든 뒤, 정답 클래스의 확률만 뽑아 로그를 씌운 것
    - PyTorch: nn.CrossEntropyLoss() → 내부적으로 LogSoftmax + NLLLoss를 결합한 형태라, 모델의 마지막 레이어에 Softmax를 직접 넣지 않고 raw logits을 그대로 넣는 것이 정석 (역시 수치 안정성 때문)
    - 예측 시(추론 시)에는 argmax로 가장 확률 높은 클래스를 선택

4. 손실 함수 선택 체크리스트
손실 함수를 고를 때는 "출력이 무엇을 의미하는가"와 "정답 레이블의 형태가 무엇인가"를 먼저 확인하는 게 핵심입니다. 아래 순서대로 점검하면 됩니다.

Step 1. 예측 대상의 타입은 무엇인가?

질문                                              Yes →
출력이 연속적인 실수값인가? (가격, 온도, 좌표 등)     회귀 → MSE/MAE/Huber 계열
출력이 "둘 중 하나"인가? (참/거짓, 있음/없음)        이진 분류 → BCEWithLogitsLoss
출력이 "셋 이상 중 하나"인가? (상호 배타적 클래스)    다중 분류 → CrossEntropyLoss
출력이 "여러 개 동시에 해당 가능"한가? (멀티라벨)     다중 레이블 → BCEWithLogitsLoss (클래스별 독립적으로)

다중 분류(하나만 정답)와 다중 레이블(여러 개 동시 정답, 예: 태그 분류)을 헷갈리면 안 됨 — 전자는 CrossEntropyLoss, 후자는 BCEWithLogitsLoss를 클래스마다 적용.

Step 2. (회귀라면) 이상치(outlier)에 얼마나 민감해야 하는가?
    - 이상치를 강하게 억제하고 싶다 (큰 오차를 절대 용납 못함) → MSE (제곱이라 큰 오차에 민감)
    - 이상치에 영향을 덜 받고 싶다 (데이터에 노이즈나 튀는 값이 많음) → MAE
    - 둘의 장점을 절충하고 싶다 (대체로 안정적이되 이상치에도 어느 정도 강건) → Huber Loss

체크: "튀는 값(outlier)이 학습을 망치고 있는가?" → 그렇다면 MAE/Huber 고려

Step 3. (분류라면) 클래스 불균형(class imbalance)이 있는가?
    - 클래스 비율이 크게 치우쳐 있으면(예: 정상 99% vs 이상 1%) 기본 BCE/CrossEntropy만으로는 소수 클래스를 잘 못 맞출 수 있음
    - 대응 옵션:
        - pos_weight (BCEWithLogitsLoss) / weight (CrossEntropyLoss) 파라미터로 클래스별 가중치 부여
        - Focal Loss (극단적 불균형, 객체 탐지 등에서 자주 사용) 고려

체크: "정답 클래스 분포가 균등한가?" → 아니면 가중치 적용 여부 검토

Step 4. 모델 마지막 레이어에 활성화 함수를 직접 넣었는가?
    - PyTorch의 BCEWithLogitsLoss, CrossEntropyLoss는 Sigmoid/Softmax를 내부에 포함
    - 모델 출력에 이미 Sigmoid/Softmax를 적용했다면 → BCELoss, NLLLoss (logit 없는 버전) 사용해야 함
    - 가장 흔한 실수: 모델에 Softmax/Sigmoid를 넣고 나서 CrossEntropyLoss/BCEWithLogitsLoss를 또 씌우는 것 (이중 적용) → 수치 불안정 + 잘못된 gradient

체크: "activation을 손실 함수 안에서 처리하는가, 모델 안에서 처리하는가?" → 하나만 선택

Step 5. 정답 레이블의 자료형/shape이 손실 함수가 기대하는 형식과 맞는가?

손실 함수            정답 레이블 형식
MSELoss             예측과 동일 shape, float
BCEWithLogitsLoss   0.0/1.0 float, 예측과 동일 shape
CrossEntropyLoss    클래스 인덱스(long), shape은 예측보다 차원 하나 적음 (원-핫 아님)

연속값 예측?
 ├─ Yes → 이상치 민감도 확인 → MSE / MAE / Huber
 └─ No (분류)
     ├─ 클래스 하나만 정답 (상호 배타)?
     │    ├─ 2개 클래스 → BCEWithLogitsLoss
     │    └─ 3개 이상 → CrossEntropyLoss (+ class weight 필요 시)
     └─ 여러 클래스 동시 정답 가능 (멀티라벨) → BCEWithLogitsLoss (클래스별)

5. SGD, Adam과 learning rate
손실 함수로 "얼마나 틀렸는지"를 계산했다면, 이제 그 값을 최소화하도록 가중치를 실제로 업데이트하는 알고리즘이 옵티마이저(optimizer)입니다. SGD와 Adam은 가장 대표적인 옵티마이저이고, Learning Rate는 그 업데이트의 "보폭"을 결정하는 핵심 하이퍼파라미터입니다.

ㄱ) Learning Rate
    - 너무 크면: 최솟값을 지나쳐서 발산하거나 손실이 진동/폭주 (loss가 NaN이 되는 경우도 흔함)
    - 너무 작으면: 수렴은 하지만 학습이 매우 느리고, 지역 최솟값(local minimum)이나 평평한 구간(saddle point)에 갇히기 쉬움

실무에서는 보통 0.1 ~ 0.0001 사이 값에서 시작해 실험적으로 조정하며, learning rate scheduler(StepLR, CosineAnnealingLR 등)로 학습이 진행됨에 따라 점차 줄이는 방식도 흔히 씁니다.

ㄴ) SGD (Stochastic Gradient Descent)
    - 전체 데이터셋이 아니라 미니배치(mini-batch) 단위로 gradient를 계산해 업데이트 → "확률적(stochastic)"
    - 기본형은 단순히 gradient에 learning rate를 곱한 만큼 이동
    - Momentum을 추가한 버전이 실무에서 표준: 이전 업데이트 방향을 일부 반영해 관성처럼 누적 → 진동을 줄이고, 좁고 굽은 골짜기(ravine) 형태의 손실 지형에서 더 빠르게 수렴
    - PyTorch: torch.optim.SGD(params, lr=0.01, momentum=0.9)

특징: 구조가 단순하고 일반화 성능이 좋다고 알려져 있으나(특히 이미지 분류 등), learning rate 튜닝에 민감하고 수렴이 상대적으로 느림.

ㄷ) Adam (Adaptive Moment Estimation)
SGD의 두 가지 약점 — ① 모든 파라미터에 동일한 learning rate 적용, ② 수렴 속도 — 을 보완한 옵티마이저. 핵심 아이디어는 파라미터마다 다른 learning rate를 자동으로 적응(adapt)시키는 것이고, 이를 위해 두 가지 통계량을 추적합니다.
    - 1차 모멘트(m): gradient의 이동평균 (momentum과 유사 — 방향성)
    - 2차 모멘트(v): gradient 제곱의 이동평균 (그 파라미터의 최근 변화가 얼마나 컸는지 — 크기)
    - 최근에 gradient가 크게 요동친 파라미터는 → 업데이트 폭이 자동으로 작아짐 (안정적)
    - gradient가 꾸준히 작은 파라미터는 → 업데이트 폭이 상대적으로 커짐 (느린 파라미터를 더 밀어줌)
    - PyTorch: torch.optim.Adam(params, lr=0.001, betas=(0.9, 0.999))

특징: 하이퍼파라미터에 덜 민감하고 수렴이 빠름 → 실무/연구에서 기본값으로 가장 많이 쓰임. 다만 SGD+Momentum 대비 일반화 성능이 살짝 떨어진다는 보고도 있어, 최종 성능이 중요한 경우 SGD로 재학습하기도 함.

ㄹ) Momentum
Momentum은 경사하강법에 "관성(inertia)" 개념을 추가한 기법입니다. 이전 업데이트 방향을 기억해서 현재 업데이트에 반영함으로써, 순수 SGD의 두 가지 문제(진동, 느린 수렴)를 완화합니다.

a. 기본 아이디어
    - 일반 SGD는 매 스텝마다 오직 현재 gradient만 보고 업데이트합니다.
    - Momentum은 여기에 속도(velocity) 항을 추가해서, 과거 gradient들의 누적(지수이동평균과 유사)을 함께 반영합니다.

b. 비유
공이 경사면을 굴러 내려간다고 생각하면 됩니다. 일반 SGD는 매 순간 그 자리의 기울기만 보고 속도를 다시 정하는 것이고, Momentum은 이미 굴러가던 속도(관성)를 유지한 채 현재 기울기를 더해가는 것입니다.

c. Momentum이 해결하는 문제
    - 진동(oscillation) 감소: 손실 지형이 한쪽 방향으로는 가파르고 다른 방향으로는 완만한 골짜기(ravine) 모양일 때, 순수 SGD는 가파른 방향으로 지그재그 진동하면서 완만한 방향으로는 느리게 전진합니다.
        - 가파른 방향: 매 스텝 gradient 부호가 반대로 뒤집힘 → momentum 누적 시 서로 상쇄되어 진동이 줄어듦
        - 완만한 방향: gradient 부호가 계속 같음 → momentum이 누적되어 가속됨
      결과적으로 지그재그는 줄고, 일관된 방향으로는 더 빨리 나아갑니다.
    - 지역 최솟값/평평한 구간 탈출: 평평한 구간(gradient ≈ 0)이나 얕은 지역 최솟값에서도, 이미 쌓인 속도(관성) 덕분에 계속 밀고 나가 빠져나올 가능성이 높아집니다.
    - 수렴 속도 향상: 같은 방향으로 gradient가 반복되면 속도가 계속 커지므로, 평탄하지만 일관된 기울기를 가진 구간에서 학습이 빨라집니다.

d. Adam과의 관계
Adam의 1차 모멘트가 사실상 이 momentum과 동일한 개념입니다. Adam = Momentum(방향성, 1차 모멘트) + RMSProp(파라미터별 크기 조정, 2차 모멘트)의 결합이라고 볼 수 있습니다.

6. PyTorch 학습 Step 순서
지금까지 정리한 손실 함수, 옵티마이저(SGD/Adam), learning rate가 실제로 한 스텝(step) 안에서 어떤 순서로 맞물려 동작하는지를 정리하면 다음과 같습니다.

ㄱ) 표준 학습 루프 (한 배치당)

    for x, y in dataloader:
        optimizer.zero_grad()      # 1. 이전 gradient 초기화
        y_pred = model(x)          # 2. 순전파 (forward)
        loss = criterion(y_pred, y)  # 3. 손실 계산
        loss.backward()            # 4. 역전파 (backward)
        optimizer.step()           # 5. 파라미터 업데이트

ㄴ) 각 단계 설명

a. optimizer.zero_grad() — gradient 초기화
    - PyTorch는 .backward()를 호출할 때마다 gradient를 덮어쓰지 않고 누적(accumulate)합니다.
    - 이전 스텝에서 계산된 gradient가 남아있으면 현재 스텝의 gradient에 잘못 더해지므로, 매 스텝 시작 시 반드시 초기화해야 합니다.
    - 빠뜨리면: 여러 배치의 gradient가 계속 쌓여서 업데이트 방향이 왜곡됨 (흔한 버그 원인)

b. model(x) — 순전파(Forward pass)
    - 입력 x가 레이어들을 통과하며 예측값 y_pred를 계산
    - 이 과정에서 PyTorch의 autograd가 연산 그래프(computation graph)를 자동으로 기록 (나중에 backward 시 사용)

c. criterion(y_pred, y) — 손실 계산
    - 예측값과 정답을 비교해 손실값(스칼라)을 계산 (MSE/BCEWithLogitsLoss/CrossEntropyLoss 등)
    - 이 스칼라 값이 바로 backward의 출발점

d. loss.backward() — 역전파(Backward pass)
    - 손실값에서부터 연산 그래프를 거슬러 올라가며, 각 파라미터에 대한 gradient를 자동으로 계산 (chain rule 기반 자동미분, autograd)
    - 계산된 gradient는 각 파라미터의 .grad 속성에 저장됨 (아직 파라미터는 변하지 않음)

e. optimizer.step() — 파라미터 업데이트
    - .grad에 저장된 gradient와 learning rate, (SGD면 momentum / Adam이면 1·2차 모멘트) 등을 사용해 실제로 가중치를 업데이트
    - SGD/Adam의 업데이트 식이 바로 여기서 실행됨

1. q.shape = (8,), K.shape = (5, 8)일 때 q @ K.T의 Shape은?

q는 1차원 벡터 (8,) K.T는 (8, 5) 행렬

numpy에서 1차원 벡터와 2차원 행렬을 @로 곱하면,
q는 임시로 (1, 8)처럼 취급되어 행렬곱이 수행된 뒤 결과에서 다시 차원이 축소

(1, 8) @ (8, 5) → (1, 5)
앞쪽에 붙었던 1차원이 제거되어 최종 결과는 (5,)

즉 결과는 길이 5짜리 1차원 벡터이며, 이는 쿼리 q가 K의 5개 행(키) 각각과 내적(dot product)한 값들 — 어텐션 스코어(attention score) 5개를 담고 있는 벡터

2. Q.shape = (4, 8), K.shape = (4, 8)일 때 QKᵀ.shape은?

Q는 (4, 8) — 쿼리 4개, 각 8차원
K.T는 (8, 4) — K (4, 8)를 전치한 것
(4, 8) @ (8, 4) → (4, 4)

이 결과는 각 쿼리(4개) 대 각 키(4개)의 어텐션 스코어를 담은 정방 행렬입니다. 즉 (i, j) 원소는 i번째 쿼리와 j번째 키의 내적값이며, 시퀀스 길이가 4인 self-attention에서 나오는 전형적인 (seq_len, seq_len) 형태의 스코어 행렬

3. 배치 텐서 K의 마지막 두 축만 바꿀 때 K.T보다 np.swapaxes(K, -1, -2)가 안전한 이유

핵심 이유: .T는 "모든" 축의 순서를 뒤집지만, swapaxes(-1, -2)는 지정한 "두 축만" 바꾸기 때문입니다.

예를 들어 배치 텐서 K.shape = (B, seq_len, d_k) 같은 3차원(혹은 그 이상) 텐서를 생각해보면:

ㄱ) K.T의 동작
    - numpy에서 .T는 축 순서를 완전히 반대로 뒤집습니다: (B, seq_len, d_k) → (d_k, seq_len, B)
    - 배치 축(B)까지 마지막 축(d_k)과 뒤바뀌어버립니다
    - 즉 배치 차원이 사라지고 엉뚱한 위치로 이동 — 배치별로 독립적이어야 할 연산이 완전히 깨집니다

ㄴ) np.swapaxes(K, -1, -2)의 동작
    - 지정한 두 축(마지막, 마지막에서 두 번째)만 교환: (B, seq_len, d_k) → (B, d_k, seq_len)
    - 배치 축(B)은 그대로 첫 번째 자리에 유지됨
    - 각 배치 샘플 내부에서만 전치가 일어나므로 의도한 연산(각 배치별 QKᵀ)이 정확히 수행됨

방법                 2D 텐서            3D 배치 텐서 (B, seq, d)
.T                   정상적으로 전치     배치 축까지 뒤섞여버림 (버그)
swapaxes(-1, -2)     정상적으로 전치     배치 축은 유지, 마지막 두 축만 전치 (안전)

그래서 실무(PyTorch, 어텐션 구현 등)에서는 배치 차원이 있는 텐서를 다룰 때
.T 대신 swapaxes(-1, -2) (또는 transpose(-1, -2))를 관용적으로 사용합니다.
2D일 때는 결과가 같지만, 코드가 나중에 배치 차원이 추가된 입력을 받게 되어도 깨지지 않도록
애초에 안전한 방식을 쓰는 것

4. Shape이 (batch, query_len, key_len)인 Attention score에는 어느 축으로 Softmax를 적용해야 하나요?
마지막 축(axis=-1), 즉 key_len 축에 적용해야 합니다.

(batch, query_len, key_len) 형태에서 각 원소 score[b, i, j]는
"b번째 배치의 i번째 쿼리가 j번째 키에 대해 갖는 점수"입니다.

Softmax의 목적은 하나의 쿼리가 모든 키에 대해 갖는 점수를 확률분포(합=1)로 바꾸는 것입니다. 즉:
    - 고정된 (b, i) — 특정 배치의 특정 쿼리 — 에 대해
    - j(key_len)를 따라 나열된 값들의 합이 1이 되어야 함

그래서 axis=-1 (key_len 축)을 기준으로 softmax를 적용합니다.

    attn_weights = softmax(score, axis=-1)  # shape 그대로 (batch, query_len, key_len)

만약 축을 잘못 잡으면?
axis=-2(query_len 축)으로 잘못 적용하면, 하나의 키가 여러 쿼리에 걸쳐 정규화되어버립니다.
즉 "이 키가 어느 쿼리에게 더 중요한가"로 의미가 뒤바뀜.
우리가 원하는 건 "이 쿼리가 어느 키에 얼마나 주목할지"이므로, 반드시 키 축을 따라 합이 1이 되어야 합니다.

축                    의미                        Softmax 적용 여부
key_len (axis=-1)     하나의 쿼리가 보는 모든 키    ✅ 여기에 적용
query_len (axis=-2)   하나의 키가 보이는 모든 쿼리   ❌ 적용 안 함

이 결과로 나온 attn_weights[b, i, :]는 i번째 쿼리가 각 키에 얼마나 "주목(attention)"할지를 나타내는 확률분포가 됩니다.
이후 이 가중치를 Value(V)와 곱해 최종 어텐션 출력을 구합니다.

5. Causal Mask에서 미래 위치의 score을 셋팅하는 방법

채우는 값     Softmax 이후          의미
−∞ (정답)     해당 위치 확률 = 0     미래를 완전히 차단 ✅
+∞ (오답)     확률 독점 또는 NaN     오히려 미래에 집중하거나 계산 붕괴 ❌

6. Attention weight의 Shape이 (4, 4)이고 V의 Shape이 (4, 8)일 때 출력 Shape은 무엇인가요?

Attention weight: (4, 4) — (query_len, key_len)
V: (4, 8) — (key_len, d_v)

행렬곱: (4, 4) @ (4, 8) → (4, 8)
내부 차원 4(key_len)가 맞아떨어지며 소거되고, 남는 것은 (query_len=4, d_v=8)입니다.

입력이었던 Q, K, V 중 실제로 "정보"를 담아 출력으로 전달되는 건 V뿐이고,
Q와 K는 그 정보를 "어떻게 섞을지" 결정하는 가중치 계산에만 관여 합니다.

7. CrossEntropyLoss에 logits 대신 Softmax 확률을 미리 넣으면 왜 권장되지 않나요?

PyTorch의 CrossEntropyLoss는 내부적으로 LogSoftmax + NLLLoss를 자체적으로 수행하도록 설계되어 있어서,
입력으로 logits(정규화 전 원점수)를 기대합니다.
여기에 이미 softmax를 거친 확률을 넣으면 softmax를 두 번 적용하는 꼴이 되어 수학적으로 잘못된 결과가 나옵니다.

ㄱ) 이중 Softmax 문제

CrossEntropyLoss는 내부에서:

    loss = NLLLoss(LogSoftmax(input), target)

를 수행합니다.

즉 입력이 이미 softmax를 거친 확률이라면: softmax(softmax(x))이 되어버립니다.
Softmax를 두 번 적용하면 원래의 확률 분포가 한 번 더 "뭉개져서" 더 평평(smoothing)해지고, 실제로 모델이 학습하려던 손실 함수의 의미(정답 클래스의 log-확률을 최대화)와 전혀 다른 값이 계산됩니다.

ㄴ) 수치 안정성(Numerical Stability) 문제

PyTorch의 CrossEntropyLoss는 내부적으로 log-sum-exp trick을 사용해서 softmax와 log를 한번에 안정적으로 계산합니다 (LogSoftmax가 이를 구현).
    - logits를 그대로 넣으면: 큰 값이 있어도 log-sum-exp 트릭으로 overflow/underflow를 방지하며 안정적으로 계산됨
    - 이미 softmax를 거친 확률을 넣으면: 그 확률에 다시 log를 취하는 과정에서, 확률값이 0에 매우 가까울 경우 log(0) → -inf 문제가 발생할 위험이 커짐 (softmax 출력은 이론상 0에 수렴할 수 있음)

즉 "logits → softmax → log" 두 단계를 거치는 것보다 "logits → log-softmax"를
한 번에 안정적으로 계산하는 것이 수치적으로 훨씬 안전합니다.

ㄷ) Gradient 계산의 문제

CrossEntropyLoss의 backward pass는 logits를 기준으로 미분이 아주 깔끔하게 떨어지도록 설계되어 있습니다
(softmax + cross-entropy의 gradient는 단순히 예측확률 - 정답 원핫).

이미 확률을 넣어버리면 이 깔끔한 gradient 공식이 깨지고, 추가로 씌워진 softmax를 통과하는 gradient까지
역전파해야 해서 학습이 왜곡되거나 훨씬 불안정해집니다.

입력                     올바른 동작
Logits (정규화 전)        ✅ 권장 — 내부 LogSoftmax+NLLLoss가 정확하고 안정적으로 계산
Softmax 확률 (정규화 후)   ❌ 비권장 — 이중 softmax, log(0) 위험, gradient 왜곡

8. √d_k 스케일링과 Temperature의 목적

구분          √d_k 스케일링                        Temperature

적용 위치     Attention 메커니즘 내부 (QKᵀ 직후)      최종 출력 logits (주로 생성 단계)

√d_k 스케일링은 "모델이 애초에 제대로 학습되게 만들기 위한 구조적 장치"이고, Temperature는 "이미 학습된 모델의 출력을 사용 목적에 맞게 조절하는 후처리 제어 장치"입니다.

9. 미분값이 음수라는 것은 x가 증가할 때 함수값이 어떤 방향으로 변한다는 뜻인가요?
미분값이 음수라는 것은, x가 증가할 때 함수값 f(x)는 감소한다는 뜻입니다.

ㄱ) 직관적 이해
미분(도함수)은 특정 지점에서 함수의 순간 변화율(기울기)을 나타냅니다.
    - f′(x)>0 → x가 조금 증가할 때, f(x)도 증가 (그래프가 오른쪽 위로 향함, 우상향)
    - f′(x)<0 → x가 조금 증가할 때, f(x)는 감소 (그래프가 오른쪽 아래로 향함, 우하향)
    - f′(x)=0 → 그 지점에서 순간적으로 증가도 감소도 하지 않음 (극값 후보, 평평한 지점)

ㄴ) 딥러닝/최적화 관점에서의 의미
경사하강법(Gradient Descent)에서 이 성질이 핵심적으로 쓰입니다.
f′(x)<0이면 → −η·f′(x)는 양수 → x가 증가하는 방향으로 업데이트됨.
즉 "기울기가 음수인 곳"은 "x를 늘리면 손실(f)이 줄어드는 곳"이므로, 파라미터를 그 방향(양의 방향)으로 이동시켜 손실을 최소화.

10. 편미분을 계산할 때 나머지 변수는 어떻게 처리하나요?
편미분(partial derivative)을 계산할 때, 미분 대상이 아닌 나머지 변수들은 모두 "상수(constant)"로 취급합니다.

처리 대상                    취급 방식
미분하려는 변수 (예: x)       일반적인 변수처럼 미분 규칙 적용
나머지 모든 변수 (예: y,z)    상수로 취급 (계수 취급, 혹은 미분 시 0)

    - 어떤 항에 미분 대상 변수가 아예 없다면 → 그 항은 상수 항이므로 편미분 결과는 0
    - 어떤 항에 미분 대상 변수와 다른 변수가 곱해져 있다면 → 다른 변수는 계수처럼 그대로 남기고, 미분 대상 변수만 미분 규칙 적용

딥러닝에서의 의미:
신경망의 손실함수는 수많은 파라미터(가중치, 편향)의 함수입니다.
각 파라미터별로 독립적으로 구한 편미분들을 모아놓은 벡터가 바로 gradient(기울기 벡터) 입니다.

11. Gradient의 반대 방향으로 이동하는 이유는 무엇인가요?

Gradient(기울기)는 함수값이 가장 가파르게 "증가"하는 방향을 가리키기 때문에, 함수값을 최소화하려면 그 정반대 방향으로 이동해야 하기 때문입니다.

개념            설명
Gradient (∇f)   함수값이 가장 빠르게 증가하는 방향
−∇f             함수값이 가장 빠르게 감소하는 방향
목표            손실 함수를 최소화
결론            목표(최소화)와 반대되는 방향(증가)을 알려주는 gradient의, 그 반대 방향으로 이동해야 손실이 줄어듦

12. Gradient가 0에 가깝다고 반드시 좋은 최솟값이라고 말할 수 없는 이유는 무엇인가요?

Gradient가 0에 가깝다는 것은 "그 지점이 평평하다"는 사실만 알려줄 뿐, 그 평평한 지점이 전역 최솟값(global minimum)인지, 나쁜 지역 최솟값(local minimum)인지, 안장점(saddle point)인지, 혹은 그냥 매우 완만한 평지(plateau)인지는 전혀 구분해주지 못하기 때문입니다.

ㄱ) Gradient = 0은 "극값 후보"일 뿐, "최선의 값"이 아님

종류                          설명
전역 최솟값 (Global minimum)   정말로 함수 전체에서 가장 낮은 지점 — 우리가 원하는 것
지역 최솟값 (Local minimum)    주변보다는 낮지만, 더 멀리 가면 훨씬 낮은 곳이 존재
안장점 (Saddle point)         어떤 방향으로는 최솟값처럼 보이지만 다른 방향으로는 최댓값처럼 보이는 지점 (한쪽은 오목, 다른쪽은 볼록)
평지 (Plateau)                실제로 극값이 아닌데도 기울기가 매우 완만해서 거의 0에 가까운 넓은 구간

Gradient 값 하나만 보고는 이 네 가지를 구분할 수 없습니다 — 전부 "기울기 ≈ 0"이라는 동일한 신호를 냅니다.

ㄴ) 딥러닝에서 특히 중요한 이유: 고차원 공간의 특성

신경망은 파라미터가 수백만~수십억 개인 초고차원 함수입니다. 이런 고차원 공간에서는:
    - 안장점이 지역 최솟값보다 훨씬 흔하다는 것이 알려져 있습니다. 한 방향에서는 볼록(최솟값처럼), 다른 방향에서는 오목(최댓값처럼)인 지점이 무수히 많이 존재
    - 학습 중 loss가 정체되는 현상은 사실 "나쁜 지역 최솟값"보다는 안장점 근처의 매우 완만한 지역에 갇혀서 gradient가 작아지는 경우가 더 흔한 원인으로 지목됨

즉 "gradient ≈ 0"이라고 최적화가 끝났다고 착각하기 쉽지만, 실제로는 그냥 잠시 기울기가 작은 구간을 지나는 중일 수도 있음

ㄷ) 지역 최솟값의 함정

왼쪽의 "얕은 골짜기"에서도 gradient가 0에 가까워지므로 경사하강법이 멈출 수 있지만,
실제로 더 좋은(더 낮은 loss의) 지점이 다른 곳에 존재할 수 있습니다.
Gradient 값만으로는 "내가 지금 있는 골짜기가 가장 깊은 골짜기인지" 전혀 알 수 없습니다.

이런 이유로 딥러닝에서는:
    - Momentum, Adam 같은 optimizer가 사용됨 — 단순히 현재 gradient만 보지 않고 과거의 이동 방향(관성)을 유지해서 안장점이나 얕은 지역 최솟값을 관성으로 통과하도록 도움
    - 학습률 스케줄링, warm restart, 여러 초기값으로 재학습 등도 같은 문제(gradient=0이 최선이 아닐 수 있음)를 극복하기 위한 기법들
    - 단순히 "loss가 더 이상 안 줄어든다(gradient ≈ 0)"는 것을 "학습이 성공적으로 끝났다"고 성급히 판단하면 안 됨

Gradient ≈ 0인 지점     실제로는?
전역 최솟값처럼 보임      지역 최솟값일 수도 / 안장점일 수도 (더 위험 — 방향에 따라 다름) / 그냥 완만한 평지(정체 구간)일 수도

gradient가 0에 가깝다는 신호는 "기울기가 평평하다"는 국소적(local) 정보일 뿐이며, 함수의 전체적인 모양(global structure)에 대해서는 아무것도 말해주지 않기 때문에, 그 자체만으로 "좋은 최솟값을 찾았다"고 결론지을 수 없습니다.

13. y = f(g(x))의 dy/dx는 어떻게 계산하나요?

연쇄법칙(Chain Rule)을 사용해서 계산합니다.
"x가 조금 변하면 → 그로 인해 u(=g(x))가 얼마나 변하는지 → 그로 인해 y(=f(u))가 얼마나 변하는지"를 순서대로 곱해서 연결하는 것입니다. 마치 기어가 여러 개 맞물려 돌아가는 것처럼, 각 단계의 "변화 비율"을 곱하면 전체(x부터 y까지)의 변화 비율이 나옵니다.

딥러닝에서의 의미: Backpropagation
신경망은 여러 층(layer)이 겹겹이 합성된 함수입니다.
역전파(backpropagation)는 바로 이 연쇄법칙을 반복적으로 적용해서, 출력층의 loss로부터 각 층의 파라미터에 대한 gradient를 안쪽 층까지 순서대로(뒤에서 앞으로) 전파시키는 알고리즘입니다.

각 층에서 계산한 "국소적인 미분값"들을 체인처럼 곱해나가는 것이 연쇄법칙의 핵심이며, 이것이 딥러닝 학습(gradient descent + backpropagation)을 가능하게 하는 수학적 기반입니다.

14. 계산 그래프에서 Local Gradient와 Upstream Gradient는 어떤 관계인가요?

관계: Downstream Gradient = Local Gradient × Upstream Gradient — 즉 둘을 "곱해서" 다음 단계로 전달합니다. 이것이 바로 연쇄법칙을 계산 그래프 위에서 구현한 것입니다.

용어                  정의                                    계산 시점
Local Gradient        이 노드 하나만의 국소적 미분값            forward pass 때 이미 결정됨 (그 노드의 연산 규칙만 알면 됨)
Upstream Gradient     뒤쪽(출력 방향)에서 흘러 들어오는 gradient   backward pass 때 뒤 노드로부터 전달받음
Downstream Gradient   이 노드가 앞쪽(입력 방향)으로 흘려보낼 gradient   이 노드가 계산해서 앞으로 전달

Downstream Gradient = Local Gradient × Upstream Gradient이며, 이 곱셈 규칙이 모든 노드에서 반복되는 것이 곧 backpropagation입니다.

15. 한 변수에서 두 경로로 갈라졌다가 다시 합쳐지면 Gradient는 어떻게 처리하나요?

두 경로에서 흘러오는 gradient를 각각 계산한 뒤 더합니다.
다변수 연쇄법칙(Multivariable Chain Rule)
각 경로에서 (local × upstream)을 계산한 뒤, 그 결과들을 모두 더한 것이 x의 최종 gradient입니다.

16. 모델이 정답 클래스에 부여한 확률(p_true)이 점점 낮아질 때, Negative Log-Likelihood(NLL) 값은 어떻게 변하나요?

NLL = -log(p_true)이므로 p_true가 0에 가까워질수록 -log(p_true) 값은 점점 커집니다. 표에서도 확률 0.99일 때 손실이 약 0.01로 작지만, 확률 0.01일 때는 약 4.61로 크게 커지는 것을 확인할 수 있습니다.

1. 머신러닝과 딥러닝의 접근차이
머신러닝은 사람이 특징을 설계 하지만, 딥러닝은 모델이 데이터안에서 유용한 특징 표현을 스스로 학습한다.

2. 딥러닝 기본 코드 구조
딥러닝 학습은 데이터 -> 모델 -> 손실 -> 최적화 -> 평가 흐름으로 진행됩니다.
ㄱ) import : 필요한 라이브러리를 불러옵니다.
ㄴ) config / hyperparameter : batch size, learning rate, epoch 수를 정의합니다.
ㄷ) data / dataloader : X, y를 만들고 DataLoader를 구성합니다.
ㄹ) model : 입력을 예측값으로 바꾸는 신경망을 정의합니다.
ㅁ) loss function : 예측값과 정답의 차이를 계산하는 function을 정의합니다.
ㅂ) optimizer : parameter를 업데이트하는 방법을 정합니다.
ㅅ) train loop : 학습 데이터로 parameter를 업데이트합니다.
    - model.train() : 모델을 학습 모드로 전환합니다 (Dropout·BatchNorm이 학습 모드로 동작).
    - optimizer.zero_grad() : 이전 batch에서 계산된 gradient를 초기화합니다.
    - preds = model(batch_x) : 현재 batch에 대한 예측값을 만듭니다. forward
    - loss = loss_fn(preds, batch_y) : 예측값과 정답의 차이를 계산합니다.
    - loss.backward() : loss를 기준으로 gradient를 계산합니다.
    - optimizer.step() : gradient를 사용해 parameter를 업데이트합니다.
ㅇ) validation loop : 검증 데이터로 성능을 확인합니다.
ㅈ) logging : epoch별 loss와 metric을 저장합니다.
ㅊ) checkpoint : 학습된 모델을 파일로 저장합니다.


3. Tensor 생성과 dtype/shape 확인
딥러닝 모델은 숫자를 입력받고 숫자를 출력합니다.
이미지도 숫자, 텍스트도 숫자, 정답 라벨도 숫자로 바꿔서 모델에 넣습니다.
이때 PyTorch에서 숫자 데이터를 담는 기본 그릇이 **Tensor**입니다.

ㄱ) shape 
    - shape는 Tensor의 구조를 왼쪽에서 오른쪽으로 설명합니다.
    shape	                                    읽는 방법	                    예시
    torch.Size([])	                            값 하나	                        scalar
    torch.Size([3])	                            값 3개	                        vector
    torch.Size([2, 3])	                        2행 3열	                        matrix
    torch.Size([10, 4])	                    샘플 10개, 특성 4개	               tabular batch
    torch.Size([32, 3, 224, 224])	이미지 32장, 채널 3개, 높이 224, 너비 224	image batch

ㄴ) ndim
    - 차원수 
ㄷ) dtype
    - 값의 자료형 
ㄹ) device
    - Tensor가 저장된 장치(cpu, cuda:0)

4. Batch dimension
여러 개의 샘플(데이터)을 한 번에 묶어서 처리하기 위해 텐서의 맨 앞(보통 0번째)에 두는 차원입니다. "샘플이 몇 개인가"를 나타내는 축입니다.

딥러닝에서 한 샘플씩 처리하면 GPU 연산 효율이 매우 떨어집니다. GPU는 행렬 연산을 병렬로 처리하는 데 특화되어 있어서, 샘플을 여러 개 쌓아 한 번의 행렬곱으로 처리하는 게 훨씬 빠릅니다. 그래서 거의 모든 딥러닝 프레임워크가 "항상 batch 차원이 있다"고 가정하고 설계돼 있습니다.

데이터 종류	                일반적인 shape	                                      의미
표(정형) 데이터	        (batch, features)	                                       MLP/선형모델 입력
이미지	                (batch, channels, height, width)	                    CNN 입력
시퀀스(RNN 기본)	    (seq_len, batch, features)	                    batch_first=False 기본값
시퀀스(Transformer 등)	(batch, seq_len, features)	                        batch_first=True

5. unsqueeze / squeeze
squeeze와 unsqueeze는 텐서의 shape에서 크기가 1인 차원을 없애거나(squeeze) 새로 끼워넣는(unsqueeze) 함수입니다. 값 자체는 전혀 바뀌지 않고, 차원(축) 구조만 바뀝니다.

ㄱ) unsqueeze: 크기 1인 차원을 추가
x = torch.tensor([1, 2, 3])       # shape: (3,)
x.unsqueeze(0)                     # shape: (1, 3)  -> tensor([[1, 2, 3]])
x.unsqueeze(1)                     # shape: (3, 1)  -> tensor([[1], [2], [3]])

인자는 "몇 번째 위치에 새 차원을 끼워넣을지"입니다. 0이면 맨 앞, 1이면 두 번째 위치.

ㄴ) squeeze: 크기 1인 차원을 제거
y = torch.zeros(1, 3, 1)          # shape: (1, 3, 1)
y.squeeze()                        # shape: (3,)     -> 크기 1인 차원 전부 제거
y.squeeze(0)                       # shape: (3, 1)    -> 0번 차원만 제거
y.squeeze(2)                       # shape: (1, 3)    -> 2번 차원만 제거

인자 없이 쓰면 크기가 1인 차원을 전부 없애고, 인자를 주면 그 위치의 차원만 없앱니다 (그 위치가 1이 아니면 아무 일도 안 일어남).

ㄷ) 사용하는 이유

y = X @ true_w + 0.1 * torch.randn(200, 1)   # shape: (200, 1)
preds = model(batch_x)                        # shape: (batch, 1)

nn.Linear(16, 1)의 출력은 (batch, 1)처럼 항상 마지막에 크기 1인 차원이 남습니다. 이걸 스칼라처럼 다루고 싶을 때
preds.squeeze(-1)   # (batch, 1) -> (batch,)
로 없애줍니다. 반대로, 1차원 벡터를 모델에 넣거나 다른 텐서와 브로드캐스팅하려면

x_1d = torch.tensor([1.0, 2.0, 3.0])   # (3,)
x_1d.unsqueeze(0)                       # (1, 3)  배치 차원 추가 — "샘플 1개짜리 배치"로 취급
처럼 배치 차원을 끼워 넣어야 하는 경우가 많습니다.

ㄹ) shape 불일치로 인한 잘못된 브로드캐스팅
pred = torch.tensor([1.0, 2.0, 3.0])        # shape: (3,)
target = torch.tensor([[1.0], [2.0], [3.0]]) # shape: (3, 1)
pred - target   # shape: (3, 3) !! 의도치 않은 브로드캐스팅

이런 식으로 (3,)와 (3,1)을 빼면 브로드캐스팅 규칙 때문에 (3,3) 행렬이 나와버리는 흔한 버그가 있습니다. pred.unsqueeze(1)로 shape을 맞춰주면 의도한 대로 (3,1) 결과가 나옵니다. nn.MSELoss()에 입력/타깃 shape이 안 맞을 때 경고가 뜨는 것도 같은 이유입니다.

정리: squeeze = 불필요한 1차원 제거(예: 모델 출력 후 정리), unsqueeze = 필요한 1차원 추가(예: 배치/브로드캐스팅 맞추기)로 기억하시면 됩니다.

6. Broadcasting이란?
브로드캐스팅은 shape이 다른 두 텐서를 서로 복사하지 않고도 연산할 수 있게 자동으로 shape을 맞춰주는 규칙입니다. NumPy와 PyTorch가 동일한 규칙을 씁니다.

- 규칙 (뒤에서부터 차원을 비교)

두 텐서의 shape을 오른쪽(마지막 차원)부터 왼쪽으로 하나씩 비교하면서, 각 차원마다 다음 조건 중 하나를 만족해야 합니다.
    - 두 차원의 크기가 같다
    - 둘 중 하나가 1이다 (그러면 1인 쪽이 다른 쪽 크기만큼 복제된 것처럼 취급됨)
    - 둘 중 하나가 아예 존재하지 않는다 (차원 개수가 다른 경우, 짧은 쪽 앞에 1을 채운 것으로 간주)
이 세 조건 중 하나도 만족하지 못하는 차원이 있으면 에러가 납니다.

- 예시 1: 스칼라 연산 (가장 단순한 브로드캐스팅)
x = torch.tensor([1, 2, 3])   # (3,)
x + 10                         # (3,) + () -> (3,)  각 원소에 10을 더함

- 예시 2: 벡터 + 행렬
a = torch.ones(3, 4)      # (3, 4)
b = torch.tensor([1., 2., 3., 4.])  # (4,)
a + b   # (3, 4) + (4,)
        # b 앞에 1을 채워서 (1, 4)로 간주 -> 3번 복제되어 (3, 4)와 연산
결과는 a의 각 행마다 b를 더한 (3, 4).        

- 예시 3: 실수 케이스
pred = torch.tensor([1.0, 2.0, 3.0])          # (3,)
target = torch.tensor([[1.0], [2.0], [3.0]])   # (3, 1)
pred - target

뒤에서부터 비교:
    - 마지막 차원: 3 vs 1 → 1이니까 OK, 3으로 확장
    - 그다음 차원: 없음(pred는 1차원) vs 3 → 없는 쪽은 1로 채움 → 1 vs 3 → OK, 3으로 확장
결과 shape은 (3, 3). pred가 (1, 3)처럼, target이 (3, 1)처럼 확장되어 사실상 모든 pred와 모든 target의 조합을 계산해버립니다 (외적처럼 동작). 의도한 원소별 뺄셈이 아니게 됩니다 — 그래서 unsqueeze로 pred를 (3, 1)로 맞춰줘야 한다.

- 예시 4: 둘 다 확장되는 경우
a = torch.ones(3, 1)   # (3, 1)
b = torch.ones(1, 4)   # (1, 4)
(a + b).shape           # (3, 4)
양쪽 다 1인 차원이 있으면 서로 다른 방향으로 동시에 확장되어 (3, 4)가 됩니다.

- 요약
ㄱ) 비교는 오른쪽(마지막 차원)부터 시작
ㄴ)크기가 같거나, 둘 중 하나가 1이거나, 아예 없으면 OK
ㄷ)그 외에는 RuntimeError: size mismatch
ㄹ)딥러닝에서 흔한 실수는 (N,)과 (N, 1)을 헷갈려서 의도치 않게 (N, N)으로 확장되는 것 
loss 계산 전에 .shape을 항상 확인하는 습관이 중요합니다.

7. 손실함수
ㄱ)MSELoss : 회귀
    예측값과 정답의 차이를 제곱해서 평균낸 값입니다 (Mean Squared Error).
    - 정답이 연속적인 숫자(집값, 온도, 점수 예측 등)일 때 씁니다 — 앞서 다룬 선형회귀 예제가 바로 이 경우
    - 제곱을 쓰기 때문에 큰 오차에 더 강하게 벌점을 줌(이상치에 민감)
    - 출력값에 별도 제약이 없음(모델 마지막 레이어가 그냥 nn.Linear로 끝나도 됨)

ㄴ)BCEWithLogitsLoss : 이진 분류 | 다중 레이블
    "둘 중 하나"(예: 스팸/정상, 사기/정상)를 분류할 때 씁니다. Binary Cross Entropy(BCE)에 Sigmoid를 내부적으로 합쳐놓은 버전입니다.
    - 모델의 마지막 레이어는 확률로 변환하기 전의 raw 점수(logit)를 그대로 출력해야 합니다 — 즉 마지막에 nn.Sigmoid()를 직접 붙이면 안 됩니다
    - "Sigmoid + BCE"를 따로 하지 않고 하나로 합친 이유는 수치적으로 더 안정적이기 때문입니다(두 연산을 결합해서 계산하면  극단적인 logit 값에서 발생하는 오버플로/언더플로 문제를 피할 수 있음)
    - nn.BCELoss()도 있지만, 그건 모델이 이미 확률(0~1, sigmoid를 직접 적용한 값)을 출력했을 때만 쓰는 것 — 요즘은 BCEWithLogitsLoss를 쓰는 게 표준

ㄷ)CrossEntropyLoss : 다중 클래스 분류
    "셋 이상 중 하나"(예: 고양이/개/새, 숫자 0~9 분류)를 분류할 때 씁니다. Softmax + Negative Log Likelihood를 내부적으로 합쳐놓은 버전입니다.
    - 모델의 마지막 레이어는 클래스 개수만큼의 raw 점수(logit)를 출력해야 합니다 — 여기도 마지막에 nn.Softmax()를 직접 붙이면 안 됩니다(내부에서 이미 처리)
    - targets가 BCE처럼 0/1 float이 아니라 정수 클래스 인덱스(0, 1, 2, ...)라는 점이 shape/dtype 실수가 가장 잦은 부분
    - BCEWithLogitsLoss와 마찬가지로 Softmax를 따로 분리하지 않는 이유는 수치 안정성(log_softmax를 내부적으로 결합 계산) 때문입니다

BCEWithLogitsLoss와 CrossEntropyLoss는 둘 다 "활성화함수(sigmoid/softmax)를 loss 안에 숨겨놓았다"는 점이 같습니다. 그래서 모델은 항상 raw logit을 출력하게 설계하고, 확률이 실제로 필요한 추론 시점에만 별도로 sigmoid/softmax를 적용합니다.

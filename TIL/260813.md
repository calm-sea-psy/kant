1. 편향(Bias), 분산(Variance), 과소적합(Underfitting), 과적합(Overfitting)

ㄱ) 편향 (Bias)
모델이 너무 단순한 가정을 해서 실제 데이터의 패턴을 제대로 못 잡는 정도다.
    - 편향이 높다 = 모델이 지나치게 단순함 (예: 복잡한 곡선 데이터를 직선으로 예측)
    - 훈련 데이터조차 잘 못 맞춤

ㄴ) 분산 (Variance)
모델이 훈련 데이터의 미세한 변화·노이즈에 얼마나 민감하게 반응하는지다.
    - 분산이 높다 = 모델이 훈련 데이터 하나하나에 너무 민감함
    - 훈련 데이터를 조금만 바꿔도 예측 결과가 크게 달라짐
    - 훈련 데이터는 완벽히 맞추지만 새로운 데이터에서는 성능이 확 떨어짐

ㄷ) 과소적합 (Underfitting)
편향이 높을 때 발생하는 현상이다.
    - 모델이 너무 단순해서 데이터의 패턴 자체를 학습하지 못함
    - 훈련 데이터 성능도 나쁘고, 테스트 데이터 성능도 나쁨
    - 예: 비선형 데이터에 단순 선형회귀를 적용
해결책: 모델 복잡도 증가(더 많은 특성, 더 깊은 모델), 규제(regularization) 완화, 학습을 더 오래 시키기

ㄹ) 과적합 (Overfitting)
분산이 높을 때 발생하는 현상이다.
    - 모델이 너무 복잡해서 훈련 데이터의 노이즈까지 외워버림
    - 훈련 데이터 성능은 매우 좋지만, 테스트(새로운) 데이터 성능은 나쁨
    - 예: 데이터 포인트 100개에 10차 다항식을 억지로 맞추는 경우
해결책: 데이터 늘리기, 정규화/규제(L1, L2), 드롭아웃, 조기종료(early stopping), 모델 단순화, 교차검증

ㅁ) 편향-분산 트레이드오프 (Bias-Variance Tradeoff)
이 둘은 보통 반비례 관계다.

| 구분 | 모델 복잡도 낮음 | 모델 복잡도 높음 |
|---|---|---|
| 편향 | 높음 | 낮음 |
| 분산 | 낮음 | 높음 |
| 현상 | 과소적합 | 과적합 |

모델을 복잡하게 만들면 편향은 줄지만 분산이 커지고, 단순하게 만들면 분산은 줄지만 편향이 커져요.
머신러닝 모델링의 목표는 이 둘의 합(총 오차)이 최소가 되는 "적절한 지점"을 찾는 것

2. 기대 제곱 예측오차 = Bias^2 + Variance + sigma^2

Bias² : 여러 번 학습했을 때 평균 예측이 참값에서 얼마나 벗어나는가 (모델의 표현력 부족)
Variance : 훈련셋이 바뀔 때마다 예측이 얼마나 요동치는가 (모델의 데이터 민감도)
sigma^2 : 어떤 모델을 쓰든 절대 줄일 수 없는 오차 (data의 본질적 잡음)

과소적합 : Bias가 큰 상태
과적합 : Variance가 큰 상태

총 기대오차를 줄이려면 Bias²와 Variance의 합을 최소화해야 하고, 이 둘은 보통 모델 복잡도에 대해 반대 방향으로 움직인다.

3. 학습곡선(Learning Curve)의 높이·간격·끝부분 기울기
학습곡선은 보통 x축을 훈련 데이터 크기(또는 epoch), y축을 오차(loss)로 놓고, 훈련 오차 곡선과 검증(validation) 오차 곡선 두 개를 같이 그려서 본다.
이 곡선에서 세 가지 특징을 읽으면 편향/분산 문제를 진단할 수 있다.

ㄱ) 높이 (Height)
두 곡선이 결국 도달하는 절대적인 오차 수준이다.
    - 훈련 오차의 최종 높이가 목표 성능(사람 수준, 베이스라인 등)보다 여전히 높다 → 모델이 훈련 데이터조차 잘 못 맞추는 것 → 편향이 높다는 신호
    - 두 곡선이 모두 높은 위치에서 평평하게 붙어있으면 전형적인 과소적합 패턴

ㄴ) 간격 (Gap)
훈련 오차 곡선과 검증 오차 곡선 사이의 세로 거리다.
    - 간격이 크다 = 훈련 데이터에는 잘 맞지만 새 데이터(검증셋)에서는 성능이 뚝 떨어짐 → 분산이 높다는 신호 → 과적합
    - 간격이 작다(두 곡선이 거의 붙어있다) = 분산 문제는 적음. 이 경우 남은 문제는 높이(편향) 쪽을 봐야 함

ㄷ) 끝부분 기울기 (End-tail slope)
훈련 데이터 양을 계속 늘려갈 때, 곡선의 끝쪽(가장 많은 데이터를 썼을 때)이 아직 가파르게 움직이는지, 이미 평평(plateau)해졌는지를 보는 거다. "데이터를 더 모으면 도움이 될까?"에 대한 직접적인 답이다.
    - 검증 오차 곡선이 끝부분에서도 여전히 가파르게 감소 중 → 아직 수렴하지 않음 → 데이터를 더 모으면 성능이 개선될 여지가 큼
    - 끝부분 기울기가 거의 0(평평) → 이미 수렴해서 포화 상태 → 데이터를 더 모아도 소용없고, 모델 구조·특성·정규화를 바꿔야 함

| 관찰 패턴 | 진단 | 처방 |
|---|---|---|
| 높이 높음 + 간격 작음 + 끝기울기 평평 | 과소적합 (편향↑) | 모델 복잡도↑, 특성 추가, 규제 완화 |
| 높이 낮음 + 간격 큼 + 끝기울기 급함 | 과적합 (분산↑), 데이터 부족 | 데이터를 더 모으는 게 효과적 |
| 간격 큼 + 끝기울기 평평 | 과적합인데 데이터 추가 효과는 적음 | 정규화, 모델 단순화, 특성 선택 |
| 높이 낮음 + 간격 작음 | 이상적인 상태 | 현재 모델 유지 |

높이는 편향을, 간격은 분산을 보여주고, 끝부분 기울기는 "지금 이 시점에서 데이터를 더 모으는 것이 남은 오차를 줄이는 데 실제로 효과가 있을지"를 알려주는 지표다. 데이터 수집은 비용이 크기 때문에, 끝기울기를 확인하는 게 자원 배분 관점에서 특히 중요하다.

4. 검증곡선 (Validation Curve)

검증곡선은 학습곡선과 짝을 이루는 진단 도구인데, 축이 다르다.
    - 학습곡선: x축 = 훈련 데이터 크기, "데이터를 얼마나 더 모아야 하는가"를 진단
    - 검증곡선: x축 = 모델의 하이퍼파라미터(복잡도), "모델을 얼마나 복잡하게 해야 하는가"를 진단
y축은 동일하게 오차(또는 정확도 등 성능 지표)이고, 훈련 오차 곡선과 검증 오차 곡선 두 개를 하이퍼파라미터 값을 바꿔가며 그린다.

    오차
     │  검증 오차
     │     ╲                    ╱
     │      ╲                  ╱
     │       ╲___          ___╱
     │            ╲______╱
     │      훈련 오차 (계속 감소)
     │  ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
     └──────────────────────────→ 모델 복잡도
       단순                    복잡
      (과소적합)              (과적합)

훈련 오차: 모델이 복잡해질수록 거의 단조 감소 (더 복잡한 모델일수록 훈련 데이터를 더 잘 외울 수 있으므로)
검증 오차: 처음엔 감소하다가, 어느 지점을 지나면 다시 증가하는 U자형(또는 접시형) 곡선

| 구간 | 상태 | 특징 |
|---|---|---|
| 왼쪽 (복잡도 낮음) | 과소적합 | 훈련 오차, 검증 오차 둘 다 높음, 간격 작음 → 편향 문제 |
| 중간 (최적 지점) | 적절 | 검증 오차가 최소가 되는 지점 |
| 오른쪽 (복잡도 높음) | 과적합 | 훈련 오차는 계속 낮아지는데 검증 오차는 다시 올라감 → 간격이 벌어짐 → 분산 문제 |

ㄱ) 용도
    - 최적 하이퍼파라미터 선택: 검증 오차가 최소가 되는 지점(U자의 바닥)이 이론적으로 가장 좋은 복잡도
    - 과소/과적합 진단: 현재 설정된 하이퍼파라미터가 U자 곡선의 어느 쪽에 있는지 보고, 왼쪽이면 복잡도를 올리고 오른쪽이면 낮추는 식으로 조정 방향을 결정
    - 편향-분산 트레이드오프의 시각화: 이전에 설명한 Bias²+Variance+σ² 분해가 이 곡선 위에서 실제로 어떻게 나타나는지 눈으로 확인 가능 (왼쪽=Bias² 지배, 오른쪽=Variance 지배)

ㄴ) 학습곡선과의 관계
두 도구는 상호보완적이다.
    - 검증곡선으로 먼저 "지금 모델이 너무 단순한지 복잡한지"를 파악해서 적절한 복잡도를 고르고,
    - 그 다음 학습곡선으로 "이 복잡도에서 데이터를 더 모으면 도움이 되는지"를 확인하는 식으로 함께 쓴다.
즉 검증곡선은 "모델을 조정할지", 학습곡선은 "데이터를 더 모을지"를 결정하는 데 특화된 도구라고 정리할 수 있다.

5. Train/Validation 성능, Train-Valid Gap, Fold

ㄱ) Train 성능 vs Validation 성능
    - Train 성능: 모델이 학습에 직접 사용한 데이터에 대해 얼마나 잘 맞추는가
    - Validation 성능: 학습에 쓰지 않은, 모델이 "본 적 없는" 데이터에 대해 얼마나 잘 맞추는가
Train 성능은 모델의 학습 능력을 보여주고, Validation 성능은 모델의 일반화 능력을 보여준다.
우리가 실제로 관심 있는 건 결국 처음 보는 데이터(테스트/실전)에서의 성능이기 때문에, Validation 성능이 실질적인 판단 기준이 된다.

ㄴ) Train-Valid Gap
두 성능(또는 오차)의 차이다.

    Gap = Validation Error − Train Error

이건 앞서 설명한 분산(Variance)을 실제 데이터로 근사 측정한 값이라고 볼 수 있다.

| Gap 크기 | 해석 |
|---|---|
| Gap이 작음 (둘 다 성능 비슷) | 분산 문제는 적음. Train 성능 자체가 낮으면 → 편향(과소적합) 문제 |
| Gap이 큼 (Train ≫ Valid) | 분산이 큼 → 훈련 데이터에 과적합 |
| Gap이 거의 없고 둘 다 나쁨 | 과소적합 |
| Gap이 거의 없고 둘 다 좋음 | 이상적인 상태 |

ㄷ) Fold (k-겹 교차검증, k-fold Cross-Validation)
Fold는 데이터를 나눈 하나의 "조각(분할 단위)"을 말한다. 단순히 train/validation을 한 번만 나누면, 그 나누는 방식(운)에 따라 성능 추정치가 우연히 좋거나 나쁘게 나올 수 있다. 이 문제를 줄이기 위한 방법이 k-fold 교차검증이다.

절차:
    - 전체 데이터를 k개의 동일한 크기 조각(fold)으로 나눔 (보통 k=5 또는 10)
    - k번 반복: 그 중 1개 fold를 validation으로, 나머지 (k-1)개 fold를 train으로 사용해 모델을 학습·평가. 매번 다른 fold가 validation 역할을 함
    - k번의 validation 성능(또는 오차)을 평균내서 최종 성능 추정치로 사용

참고:
    - k값이 클수록: 각 fold의 train 크기가 커져서 편향은 줄지만, fold 간 겹치는 데이터가 많아져 fold별 결과의 상관이 커지고 계산 비용도 커짐
    - 극단적인 경우 k = 데이터 개수이면 LOOCV(Leave-One-Out CV)라고 부름
    - 분류 문제에서는 각 fold의 클래스 비율을 원본과 비슷하게 유지하는 Stratified k-fold를 많이 씀

6. Train AP vs Validation AP
    - Train AP: 학습에 사용한 데이터에 대해, 학습된 모델로 예측 → 정답과 비교해서 계산한 AP
    - Validation AP: 학습에 쓰지 않은 held-out 데이터에 대해 계산한 AP
    - Gap = Train AP − Validation AP

| Gap 패턴 | 해석 |
|---|---|
| Gap이 작고 둘 다 높음 | 이상적 — 일반화 잘 됨 |
| Gap이 작고 둘 다 낮음 | 과소적합(편향↑) — 모델/특성/학습량 부족 |
| Gap이 큼 (Train AP ≫ Val AP) | 과적합(분산↑) — 훈련 데이터 패턴/노이즈를 외움 |

객체 탐지에서 Gap이 크게 벌어지는 흔한 원인:
    - 훈련 데이터 양이 적음 / 특정 장면·객체 유형에 편중
    - 데이터 증강(augmentation) 부족
    - 모델 용량(파라미터 수)이 데이터에 비해 과함
    - 정규화(weight decay, dropout 등) 부족

7. 과적합/과소적합 대응 전략
"문제를 진단(고편향 후보 vs 고분산 후보)"하고 → "그에 맞는 처방(정규화, 조기 종료 등)을 적용"하는 흐름이다.

ㄱ) 고편향(High Bias) 후보
증상: Train 성능 자체가 낮음 (Train-Valid gap은 작음). 학습곡선/검증곡선에서 "높이"가 높은 상태 → 모델이 훈련 데이터조차 잘 설명 못함 → 과소적합

의미: 모델이 데이터의 실제 패턴을 표현할 능력(capacity) 자체가 부족한 상태다. 아무리 학습을 더 시켜도, 애초에 "그릴 수 있는 함수의 형태"가 데이터의 진짜 구조보다 단순하기 때문에 한계가 있음.

대응 방향: 모델의 표현력을 키우는 쪽
    - 모델 복잡도↑ (더 깊은 네트워크, 더 높은 차수의 다항식, 더 많은 트리)
    - 특성(feature) 추가 / 더 정교한 feature engineering
    - 규제 강도를 낮춤 (오히려 규제를 풀어줘야 함)
    - 학습을 더 오래/충분히 시킴 (학습이 덜 끝난 것도 편향처럼 보일 수 있음)

ㄴ) 고분산(High Variance) 후보
증상: Train 성능은 좋은데 Validation 성능이 크게 떨어짐 (gap이 큼). 학습곡선에서 "간격"이 크고, 검증곡선의 오른쪽(복잡도 높은 쪽)에 위치 → 과적합

의미: 모델이 데이터의 진짜 패턴뿐 아니라 훈련 데이터에만 있는 노이즈·우연한 패턴까지 외워버린 상태다. 훈련셋이 조금만 바뀌어도 예측이 크게 달라짐.

대응 방향: 모델을 제약하거나 데이터를 늘리는 쪽
    - 훈련 데이터 추가 (가장 근본적인 해결책, 학습곡선의 "끝기울기"가 가팔랐다면 특히 효과적)
    - 규제(regularization) 강화
    - 조기 종료(early stopping)
    - 모델 단순화, 드롭아웃, 데이터 증강(augmentation)
    - 앙상블(배깅 등)

ㄷ) 규제 (Regularization)
의미: 모델이 훈련 데이터를 "너무 잘" 맞추지 못하도록 손실 함수에 페널티를 추가해서, 파라미터가 과도하게 커지거나 복잡한 형태를 갖지 못하게 제약하는 기법이다.
핵심: 규제는 분산을 줄이는 대신 편향을 약간 늘리는 트레이드오프 조작이다. 그래서 이미 고편향 상태인 모델에 규제를 더 걸면 오히려 상황이 악화된다.

ㄹ) 조기 종료 (Early Stopping)
의미: 학습을 진행하면서 매 epoch마다 validation 성능을 함께 관찰하다가, validation 성능이 더 이상 좋아지지 않고 오히려 나빠지기 시작하는 시점에서 학습을 멈추는 기법이다.

    오차
     │  Validation Error
     │  ＼                    ╱  ← 다시 증가 (과적합 시작)
     │    ＼                ╱
     │      ＼____________╱
     │           ↑
     │      여기서 멈춤 (early stopping point)
     │  Training Error
     │  ＼＿＿＿＿＿＿＿＿＿＿＿＿＿＿ (계속 감소)
     └──────────────────────────→ epoch

    - 학습이 진행될수록 모델은 점점 더 복잡한 패턴(결국 노이즈까지)을 학습하게 되는데, 이는 암묵적으로 모델 복잡도를 늘리는 것과 같은 효과를 냄
    - 그래서 조기 종료는 사실상 "epoch 수를 규제 대상으로 삼는 규제 기법"이라고 볼 수 있다 (별도 penalty 항 없이도 분산을 억제)
    - 실무에서 가장 손쉽고 계산 비용이 적게 드는 과적합 방지 기법 중 하나

| 상황 | 진단 | 처방 |
|---|---|---|
| Train도 나쁨, gap 작음 | 고편향 (과소적합) | 모델 복잡도↑, 특성 추가, 규제 완화, 학습 더 |
| Train 좋음, gap 큼 | 고분산 (과적합) | 데이터 추가, 규제 강화, 조기 종료, 모델 단순화 |

8. 규제 L1(Lasso), L2(Ridge), ElasticNet
규제는 모델의 손실 함수에 파라미터 크기에 대한 페널티 항을 추가해서, 모델이 훈련 데이터를 "지나치게 정교하게" 맞추지 못하도록 제약하는 기법이다.

직관적으로, 파라미터(가중치) 값이 크면 클수록 모델이 입력의 작은 변화에도 출력을 크게 흔들 수 있다. 예를 들어 고차 다항식 회귀에서 과적합된 모델은 데이터 포인트 사이사이를 요동치며 지나가는데, 이때 계수들이 매우 큰 값을 갖게 된다.

이런 큰 계수들을 억제하면 곡선이 완만해지고, 훈련셋이 조금 바뀌어도 예측이 크게 흔들리지 않게 된다 — 즉 분산이 줄어든다. 대신 데이터를 완벽히는 못 맞추게 되니 편향은 약간 늘어나는 트레이드오프가 생긴다.

ㄱ) L1(Lasso)
    - 절댓값 합에 페널티 → 일부 계수를 정확히 0으로 만듦 (sparse solution)
    - 닫힌 형태 해가 없어서 좌표하강법(coordinate descent) 등 반복적 최적화로 풂
    - 결과적으로 자동 특성 선택 효과: 중요하지 않은 특성의 계수는 0이 되어 모델에서 사실상 제거됨
    - 상관관계가 높은 특성 그룹이 있으면, 그 중 하나만 남기고 나머지는 0으로 만드는 경향 (선택이 불안정할 수 있음)
    - 제약 영역이 마름모(다이아몬드) 모양 → 뾰족한 꼭짓점이 좌표축 위에 있고, 등고선이 이 꼭짓점에서 접할 확률이 높음 → 그 축의 계수가 정확히 0이 됨

ㄴ) L2(Ridge)
    - 파라미터 제곱합에 페널티를 부여 → 모든 계수를 고르게 축소시키되, 정확히 0으로 만들지는 않음
    - 특징: 닫힌 형태(closed-form) 해가 존재함
    - 수치적으로 안정적
    - 상관관계가 높은 특성들이 있으면, 그 계수들을 비슷한 크기로 나눠서 분담시키는 경향
    - 제약 영역이 원(구) 모양 → 손실함수 등고선이 원 경계 어디서든 접할 수 있고, 축 위에서 접할 특별한 이유가 없음 → 계수가 작아지긴 해도 0은 잘 안 됨

ㄷ) ElasticNet
    - L1과 L2를 가중 결합
    - Lasso는 특성 수 p가 샘플 수 n보다 많을 때(고차원) 최대 n개까지만 계수를 선택할 수 있다는 한계, 그리고 상관관계 높은 특성 그룹 중 하나만 임의로 선택해버리는 불안정성이 있음
    - L2 항을 섞어서, 상관관계 높은 특성들을 그룹으로 함께 선택(0으로 만들거나 살리거나)하면서도 L1의 sparsity 효과는 유지 → 두 방식의 장점을 절충

비교 정리

| 항목 | Ridge (L2) | Lasso (L1) | Elastic Net |
|---|---|---|---|
| 계수 축소 | 고르게 축소 | 일부 0으로 (sparse) | 절충 (그룹 sparsity) |
| 특성 선택 | 안 됨 | 자동으로 됨 | 됨 (그룹 단위) |
| 다중공선성 | 강건함 | 불안정할 수 있음 | 강건함 |
| 해 형태 | 닫힌 형태 존재 | 반복 최적화 필요 | 반복 최적화 필요 |
| 하이퍼파라미터 | lambda | lambda | lambda, alpha(L1 비율) |

    - 특성이 다 유의미하고, 다중공선성이 문제라면 → Ridge
    - 특성이 많고 그 중 일부만 진짜 중요할 것 같으며, 해석 가능한(단순한) 모델이 필요하다면 → Lasso
    - 특성 수가 샘플 수보다 많거나(고차원), 상관관계 높은 특성 그룹이 있는데도 sparsity가 필요하다면 → Elastic Net

scikit-learn 기준 Ridge, Lasso, ElasticNet(alpha=..., l1_ratio=...)로 제공되고, lambda(및 Elastic Net의 alpha)는 앞서 설명한 검증곡선 + k-fold 교차검증으로 튜닝하는 게 일반적

9. 하이퍼파라미터 alpha와 l1_ratio

ㄱ) alpha — 규제의 "세기"
규제를 얼마나 강하게 걸지를 결정하는 값이다. Ridge, Lasso, Elastic Net 셋 다 공통으로 갖는 하이퍼파라미터
    - lambda = 0 → 규제 없음 (원래 손실함수와 동일, 과적합 위험)
    - lambda가 커질수록 → 계수들이 점점 더 강하게 0쪽으로 눌림 (과소적합 위험)
    - 검증곡선의 x축이 바로 이 lambda (보통 로그스케일로 탐색: 0.001, 0.01, 0.1, 1, 10...)

ㄴ) l1_ratio — L1과 L2의 "배합 비율"
Elastic Net에서만 등장하는, L1과 L2를 얼마나 섞을지 정하는 값
    - l1_ratio = 1 → 순수 Lasso (L1만)
    - l1_ratio = 0 → 순수 Ridge (L2만)
    - l1_ratio = 0.5 → L1과 L2를 절반씩 섞음

Ridge나 Lasso 단독으로 쓸 때는 애초에 섞을 게 없으니 l1_ratio 자체가 필요 없다

| 구분 | alpha | l1_ratio |
|---|---|---|
| 의미 | 규제 전체 강도 | L1:L2 배합 비율 |
| 적용 대상 | Ridge, Lasso, Elastic Net 모두 | Elastic Net만 |
| 범위 | [0, ∞) | [0, 1] |
| 튜닝 방식 | 검증곡선(U자)에서 최소점 탐색 | 보통 alpha 함께 grid search |

직관적으로 비유하면, alpha는 "브레이크를 얼마나 세게 밟을지",
l1_ratio는 "그 브레이크가 앞바퀴(L1)와 뒷바퀴(L2) 중 어느 쪽에 더 실릴지"를 정하는 것과 비슷하다.

1. Fine-tuning

Fine-tuning(파인튜닝)은 이미 대규모 데이터로 사전학습된 모델을 내 목적에 맞는 소량의 데이터로 추가 학습시켜, 모델의 가중치 자체를 바꾸는 작업이다. 프롬프트나 RAG가 모델에 주는 입력을 바꾸는 방식이라면, 파인튜닝은 모델 자체를 바꾸는 방식이다.

사전학습과 원리는 같고, 데이터가 훨씬 적고 학습률이 낮다는 점이 다르다. 이미 배운 언어 능력은 유지한 채 특정 방향으로만 조정하기 위해서다.

ㄱ) 주요 방식

    - Full fine-tuning: 모든 가중치를 업데이트한다. 효과는 크지만 GPU 메모리와 비용이 많이 들고, 기존 지식을 잃는 문제(catastrophic forgetting)가 생기기 쉽다.
    - LoRA: 원본 가중치는 고정하고, 옆에 붙인 작은 저랭크 행렬(어댑터)만 학습한다. 학습 파라미터가 전체의 1% 미만이라 가볍고, 어댑터 파일만 교체하면 용도를 바꿀 수 있다. 현재 사실상 표준이다.
    - QLoRA: 모델을 4bit로 양자화해 올린 뒤 LoRA를 적용한다. 소비자용 GPU에서도 수십억 파라미터 모델을 튜닝할 수 있다.
    - PEFT(Parameter-Efficient Fine-Tuning) : LoRA와 QLoRA처럼 일부 파라미터만 학습하는 방식

ㄴ) 프롬프트, RAG와 파인튜닝의 차이점

| 상황 | 적합한 방법 |
|---|---|
| 최신 정보나 사내 문서 같은 지식이 필요함 | RAG |
| 지시만 잘 주면 해결됨 | 프롬프트 엔지니어링 |
| 말투, 출력 형식, 특정 작업 패턴을 일관되게 만들어야 함 | 파인튜닝 |
| 작은 모델로 큰 모델 수준의 특정 작업 성능이 필요함 | 파인튜닝 |
| 프롬프트가 너무 길어 비용과 지연이 문제임 | 파인튜닝 |

파인튜닝은 지식을 넣는 수단으로는 약하고, 행동 방식을 바꾸는 수단으로 강하다. 사실 정보를 파인튜닝으로 주입하면 부정확하게 기억하거나 환각이 늘기 쉬워서, 지식은 RAG로 넣고 형식과 스타일은 파인튜닝으로 맞추는 조합이 일반적이다.

ㄷ) 주의할점

    - 데이터 품질: 결과를 가장 크게 좌우한다. 일관된 고품질 예시 수백 개가 지저분한 수만 개보다 낫다.
    - 과적합: 데이터가 적으면 학습 데이터를 외워버려 일반화 성능이 떨어진다.
    - 평가 체계: 튜닝 전후를 같은 기준으로 비교할 평가 세트가 없으면 좋아졌는지 알 수 없다.
    - 유지보수: base model이 바뀌면 다시 학습해야 한다.

2. SFT

SFT(Supervised Fine-Tuning, 지도 미세조정)는 "이 입력에는 이렇게 답하라"는 정답 쌍을 보여주고 그대로 따라 하도록 학습시키는 방식이다. 파인튜닝 중 가장 기본이고, 보통 파인튜닝이라고 하면 SFT를 가리킨다.

ㄱ) 학습 데이터

입력과 정답 출력의 쌍으로 구성한다. LLM에서는 대개 대화 형식이다.

    {"messages": [
        {"role": "user", "content": "배송이 3일째 안 와요"},
        {"role": "assistant", "content": "불편을 드려 죄송합니다. 주문번호를 알려주시면 바로 확인하겠습니다."}
    ]}

이 데이터에 모델의 chat template을 적용해 하나의 토큰 시퀀스로 만든 뒤 학습한다. 템플릿이 추론 때와 다르면 성능이 크게 떨어지므로 반드시 같은 것을 써야 한다.

ㄴ) 학습 원리

목적 함수는 사전학습과 똑같은 다음 토큰 예측(cross-entropy loss)이다. 차이는 두 가지다.

    - 데이터: 사전학습은 정답이 따로 없는 일반 텍스트를 쓰고, SFT는 사람이 만들거나 검수한 입력과 정답 쌍을 쓴다.
    - loss 계산 범위: 보통 assistant 응답 부분에만 loss를 건다. 질문 토큰은 label을 -100으로 마스킹해 제외한다. 모델이 배울 것은 질문을 만드는 법이 아니라 답하는 법이기 때문이다.

    [user: 배송이 안 와요] [assistant: 불편을 드려 죄송합니다...]
    └── loss 계산 안 함 ──┘ └────── 여기만 loss 계산 ──────┘

ㄷ) LLM 학습 과정에서의 위치

사전학습 → SFT → 선호도 정렬(RLHF, DPO 등)

    - 사전학습만 끝난 base model은 문장을 이어 쓸 뿐이라, 질문을 받으면 답 대신 질문을 계속 이어 쓰기도 한다.
    - SFT를 거치면 지시를 받아 답하는 형식을 익힌다. 이 단계를 instruction tuning이라고도 부르며, base model과 instruct/chat model의 차이가 여기서 생긴다.
    - 그 뒤의 RLHF나 DPO는 정답을 주는 대신 "A가 B보다 낫다"는 선호 신호로 품질을 다듬는다.

SFT는 full fine-tuning과 LoRA 중 무엇으로 하든 SFT다. SFT는 무엇을 신호로 학습하느냐의 구분이고, LoRA는 어떤 파라미터를 업데이트하느냐의 구분이어서 서로 다른 축이다.

ㄹ) 한계

    - 모방까지만 학습한다: 정답 데이터의 품질이 모델의 상한이고, 데이터에 있는 오류와 편향도 그대로 배운다.
    - 정답이 하나로 고정된다: 좋은 답이 여러 개일 수 있는 문제에서도 데이터에 있는 표현 하나만 정답으로 취급한다.
    - 하지 말아야 할 것을 가르치기 어렵다: 좋은 예시만 보여주는 방식이라 나쁜 답을 피하게 하는 신호가 약하다. 이 부분을 선호도 기반 학습이 보완한다.(DPO, RLHF)
    - 모르는 것을 답하게 가르치면 환각이 늘어난다: 모델이 갖고 있지 않은 지식을 정답으로 학습시키면, 근거 없이도 자신 있게 답하는 습관을 배운다.

3. 선호도 기반 학습

RLHF와 DPO가 선호도 기반 학습의 대표적인 두 방식이다. 둘 다 정답을 주지 않고 "이 답이 저 답보다 낫다"는 비교 신호로 학습한다.

ㄱ) SFT와 차이

| 구분 | SFT | 선호도 기반 학습 |
|---|---|---|
| 데이터 | 질문 + 정답 | 질문 + 더 나은 답 + 덜 나은 답 |
| 신호 | 이렇게 답하라 | 이쪽이 저쪽보다 낫다 |
| 나쁜 답에 대한 학습 | 없음 | 있음 |

a. SFT의 한계 보완 방법

    - 하지 말아야 할 것: 덜 나은 답이 데이터에 명시적으로 들어 있어, 그쪽 확률을 낮추는 신호가 생긴다.
    - 정답이 하나로 고정되는 문제: 특정 문장을 따라 하는 것이 아니라 상대적인 우열을 배우므로, 표현이 달라도 좋은 답이면 된다.
    - 모방의 상한: 좋은 답을 직접 쓰기는 어려워도 둘 중 나은 것을 고르기는 쉽다. 그래서 작성자의 실력을 넘어서는 방향으로도 모델을 유도할 수 있다.

ㄴ) RLHF(Reinforcement Learning from Human Feedback)

a. 사람이 모델의 답변 쌍을 비교해 선호 데이터를 만든다.
b. 이 데이터로 답변에 점수를 매기는 보상 모델(reward model)을 따로 학습한다.
c. 보상 모델의 점수가 높아지도록 강화학습(주로 PPO)으로 LLM을 업데이트한다. 이때 원래 모델에서 너무 멀어지지 않도록 KL 페널티를 건다.

효과는 좋지만 모델을 두 개 다뤄야 하고 강화학습이 불안정해 튜닝이 까다롭다.

ㄷ) DPO(Direct Preference Optimization)

보상 모델과 강화학습 단계를 없애고, 선호 데이터로 LLM을 직접 학습한다.

    {"prompt": "배송이 3일째 안 와요",
    "chosen": "불편을 드려 죄송합니다. 주문번호를 알려주시면 바로 확인하겠습니다.",
    "rejected": "배송은 택배사에 문의하세요."}

loss는 chosen의 확률을 높이고 rejected의 확률을 낮추는 방향으로 설계되어 있고, 기준이 되는 원래 모델(frozen reference)에서 크게 벗어나지 않도록 하는 항이 들어 있다. 학습 절차가 SFT와 거의 같아서 안정적이고 구현이 쉽다. 개인이나 소규모 팀이 선호도 학습을 할 때는 대부분 DPO나 그 변형(ORPO, KTO 등)을 쓴다.

두 방식 모두 SFT를 대체하지 않고 SFT 다음에 적용한다. SFT로 답하는 형식과 기본 능력을 먼저 만들고, 선호도 학습으로 품질, 말투, 안전성 같은 세부를 다듬는다. SFT를 거치지 않은 모델은 비교할 만한 답변 자체를 만들지 못하기 때문이다.

a. 선호 데이터 만드는 방법

    - 같은 질문에 모델이 여러 답을 생성하게 하고, 사람이나 더 강한 LLM이 순위를 매긴다.
    - 모델의 원래 답을 rejected로, 사람이 고친 답을 chosen으로 쓴다. 서비스 운영 로그가 있으면 이 방식으로 데이터가 자연스럽게 쌓인다.
    - 공개 선호 데이터셋(UltraFeedback 등)을 쓴다.

b. 주의할 점

    - 의도하지 않은 차이를 학습한다. chosen이 항상 더 길면 모델은 품질 대신 "길게 쓰기"를 배운다. 두 답은 가르치려는 차이 외에는 비슷해야 한다.
    - loss가 내려가도 품질이 떨어질 수 있다. margin만 벌어지면 되므로 chosen의 확률도 함께 떨어지는 경우가 있다. 학습 지표 외에 실제 생성 결과를 반드시 평가해야 한다.
    - 너무 쉬운 쌍은 효과가 없다. rejected가 명백히 엉망이면 모델이 이미 구분하고 있어 배울 것이 없다. 미묘하게 나쁜 답이 좋은 학습 재료다.
    - 과적합이 빠르다. 보통 1~3 epoch 안에서 끝낸다.

c. 변형

    - KTO: 쌍이 없어도 된다. 답변마다 좋음/나쁨 라벨만 있으면 학습한다.
    - ORPO: SFT와 선호도 학습을 한 번에 하고, reference 모델이 필요 없다.
    - IPO, SimPO: DPO의 과적합이나 길이 편향을 줄이도록 loss를 수정한 방식이다.

4. LoRA 와 QLoRA

LoRA와 QLoRA는 어떤 파라미터를 업데이트하느냐에 관한 기법이다.

ㄱ) LoRA (Low-Rank Adaptation)

원본 가중치는 고정하고, 옆에 작은 행렬 두 개를 붙여 그것만 학습한다.

                    ┌─────────────┐
        입력 x ──┬──│ W (고정)     │──┬── 출력
                │  └─────────────┘  │
                │  ┌───┐   ┌───┐    │ (더하기)
                └──│ A │──│ B │───┘
                    └───┘   └───┘
                학습함   학습함

원래 계산이 y = Wx라면 LoRA를 붙인 계산은 y = Wx + BAx다. 가중치의 변화량 ΔW를 통째로 학습하지 않고 B × A라는 두 행렬의 곱으로 대신한다.

a. 파라미터가 줄어드는 이유

W가 4096×4096 행렬이면 파라미터는 약 1,677만 개다. rank r=16이면 A는 16×4096, B는 4096×16이므로 합쳐서 약 13만 개이고, 원본의 0.8% 수준이다.

이렇게 줄여도 되는 근거는 파인튜닝에서 일어나는 가중치 변화가 실제로는 저차원(low-rank)이라는 관찰이다. 사전학습된 모델을 특정 작업에 맞출 때는 가중치 전체를 바꿀 필요가 없고 몇 개 방향으로만 조정하면 충분하다는 것이다.

b. 초기화

B는 0으로, A는 무작위 값으로 시작한다. 처음에는 BA = 0이므로 원본 모델과 출력이 같고, 학습이 진행되면서 조금씩 달라진다.

c. 주요 설정

    - r (rank): 어댑터의 크기다. 보통 8~64를 쓰며, 클수록 표현력이 커지지만 파라미터와 과적합 위험도 늘어난다.
    - lora_alpha: 어댑터 출력에 곱하는 배율로, 실제로는 alpha / r이 곱해진다. r과 같거나 2배로 두는 경우가 많다.
    - target_modules: 어댑터를 붙일 레이어다. 원 논문은 attention의 일부(q, v)에만 붙였고, 요즘은 모든 linear 레이어에 붙이는 설정이 흔하다.
    - lora_dropout: 과적합 방지용이다.

d. 장점

    - 원본 가중치의 gradient와 optimizer 상태를 저장하지 않아 학습 메모리가 크게 줄어든다.
    - 결과물이 어댑터 파일(수십~수백 MB)뿐이라, base model 하나에 용도별 어댑터를 바꿔 끼울 수 있다.
    - 학습 후 W + BA로 합치면(merge) 추론 속도가 원본과 같다.
    - 원본이 고정되어 있어 기존 능력을 잃는 문제가 덜하다.

ㄴ) QLoRA (Quantized LoRA)

LoRA를 써도 base model은 메모리에 올려야 하고, 여기서 메모리를 가장 많이 쓴다. QLoRA는 base model을 4bit로 양자화해서 올리고 그 위에 LoRA를 붙인다.

    base model: 4bit로 압축, 고정
    LoRA 어댑터: 16bit 정밀도 그대로 학습

a. 구성 요소

    - NF4 양자화: 신경망 가중치가 정규분포에 가깝다는 점을 이용해, 4bit로 표현할 16개 값을 그 분포에 맞게 배치한다. 균등하게 나누는 방식보다 정보 손실이 적다.
    - Double quantization: 양자화에 쓰는 상수들도 한 번 더 양자화해 메모리를 추가로 줄인다.
    - 계산은 16bit로: 저장은 4bit로 하고, 연산할 때는 그때그때 16bit로 풀어서 계산한다.

b. 메모리 비교 (8B 모델 기준, 대략적인 값)

| 방식 | 모델 가중치 메모리 |
|---|---|
| Full fine-tuning | 가중치 + gradient + optimizer 상태로 수십 GB 이상 |
| LoRA (16bit) | 약 16GB + 어댑터 학습분 |
| QLoRA (4bit) | 약 5~6GB + 어댑터 학습분 |

실제 사용량은 여기에 시퀀스 길이와 배치 크기에 따른 activation 메모리가 더해진다.

c. 단점

    - 연산마다 4bit에서 16bit로 푸는 과정이 있어 학습 속도가 LoRA보다 느리다.
    - 양자화로 약간의 품질 손실이 있다. 원 논문은 16bit 파인튜닝과 거의 같은 성능을 보고했지만 작업에 따라 차이가 날 수 있다.
    - merge가 번거롭다. 보통 원본 정밀도의 base model에 어댑터를 합친 뒤 다시 양자화하며, 이때 학습 환경과 미세한 차이가 생긴다.

ㄷ) 선택 기준

    - 메모리가 충분하면 LoRA가 더 빠르고 양자화 손실이 없다.
    - 모델이 GPU 메모리에 16bit로 올라가지 않으면 QLoRA를 쓴다.
    - 작은 모델을 LoRA로 튜닝할지 큰 모델을 QLoRA로 튜닝할지 고민될 때는, 대체로 큰 모델을 QLoRA로 튜닝하는 쪽이 결과가 좋다. 다만 작업에 따라 다르므로 직접 비교 평가해서 결정해야 한다.

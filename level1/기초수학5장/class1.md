필수 1 : 딥러닝 코드에 나오는 숫자 뭉치 읽기

모델 코드를 인계받은 담당자가 (32, 10, 512) 같은 숫자를 만납니다. 이 숫자를 읽지 못하면 데이터가 어떤 구조로 흐르는지 전혀 파악할 수 없습니다. 차원 수에 따라 대상을 벡터·행렬·텐서로 구분하고, 자주 쓰이는 표기 두 가지를 해석해 봅니다.

문제 1-1 : 벡터·행렬·텐서의 shape 읽기

**요구 사항**

1. 1차원 배열, 2차원 배열, 3차원 배열을 각각 만들고 `shape`, `ndim`, `size`를 출력합니다.
2. 각 대상이 벡터·행렬·텐서 중 무엇인지, 각 축이 무엇을 의미할 수 있는지 적습니다.
3. `(32, 10, 512)` 크기의 배열을 만들고, 세 축을 각각 `batch`, `seq_len`, `hidden_dim`으로 해석해 문장으로 설명합니다.
4. `x[0]`, `x[0, 0]`을 인덱싱했을 때의 shape을 **예측한 뒤** 실행해 확인합니다.

문제 1-2 : 이미지 텐서 (batch, channel, height, width) 해석하기

**요구 사항**

1. 배치 16장, RGB 3채널, 224×224 크기의 이미지 텐서를 만들고 shape을 확인합니다.
2. 흑백 이미지 배치(채널 1)도 만들어 shape을 비교합니다.
3. 이미지 한 장(`images[0]`), 한 장의 한 채널(`images[0, 0]`)의 shape을 확인합니다.
4. 같은 데이터를 TensorFlow 관례인 `(batch, height, width, channel)`로 바꾸고 shape을 확인합니다.
5. 두 표기 방식의 차이를 표로 정리하고, 축 순서를 잘못 넣으면 어떤 문제가 생길지 한 문장으로 작성합니다.

필수 2 : 길이가 제각각인 고객 이력을 하나의 텐서로 묶기

이커머스 추천 모델팀은 고객별 구매 이력을 시퀀스 모델에 입력하려 합니다. 그런데 고객마다 구매 건수가 달라 그대로는 하나의 배열로 묶이지 않습니다. 실무 표준인 (batch, seq_len, hidden_dim) 형태로 만들려면 길이를 맞추고 임베딩을 적용해야 합니다.

문제 2-1 : padding으로 시퀀스 길이 맞추기

**요구 사항**

1. 고객별 시퀀스 길이를 출력해 서로 다름을 확인합니다.
2. 길이가 다른 시퀀스를 다음 3단계로 확인합니다. ① 그대로 `np.array()`로 묶으면 `ValueError`가 발생함을 확인 → ② `dtype=object`를 명시하면 오류는 사라지지만 여전히 2차원 배열이 아니라 1차원 object 배열임을 확인 → ③ 그래서 padding이 필요하다는 결론을 적습니다.
3. 상품 코드를 1부터 시작하는 정수 ID로 인코딩합니다. (0은 padding 전용)
4. `max_len`을 데이터의 실제 최대 길이로 계산해 길이를 맞추고, 뒤쪽을 0으로 채운 `encoded` 배열을 만듭니다. (`max_len = 10` 처럼 고정값을 쓰면 어떤 고객도 채우지 못하는 padding 전용 열이 남아 낭비됩니다)
5. 실제 토큰과 padding을 구분하는 `mask` 배열도 함께 만듭니다.
6. `encoded`와 `mask`의 shape을 확인하고, mask가 왜 필요한지 한 문장으로 설명합니다.

문제 2-2 : 임베딩으로 3차원 텐서 만들기

**요구 사항**

1. `(상품 수 + 1) × hidden_dim` 크기의 임베딩 테이블 `E`를 난수로 만들고, 0번 행(padding)은 0으로 채웁니다.
2. `E[encoded]`로 임베딩을 적용하고 결과 shape을 **먼저 예측한 뒤** 확인합니다.
3. 결과 텐서의 세 축이 각각 무엇인지 설명합니다.
4. padding 위치의 임베딩 벡터가 모두 0인지 확인합니다.
5. `hidden_dim`을 16에서 32로 바꾸면 shape이 어떻게 변할지 예측한 뒤 실행해 확인합니다.

심화 1 : 실행하기 전에 연산 가능 여부 판단하기

모델을 조립하다 보면 ValueError: operands could not be broadcast together 같은 오류를 자주 만납니다. shape을 먼저 비교하는 습관을 들이면 실행 전에 대부분 걸러낼 수 있습니다. 어떤 조합이 되고 안 되는지 직접 확인합니다.

문제 3-1 : shape 조합별 연산 가능 여부 확인하기

**요구 사항**

1. `a = (32, 10, 512)`, `b = (32, 10, 512)`, `c = (32, 5, 512)`, `d = (512,)` 배열을 만듭니다.
2. `a + b`, `a + c`, `a + d` 각각에 대해 **실행 전에 가능 여부를 예측**하고 적습니다.
3. `try/except`로 세 연산을 실행해 결과 shape 또는 오류 메시지를 출력합니다.
4. 예측과 실행 결과를 표로 비교합니다.
5. `a + c`를 가능하게 하려면 어떤 처리가 필요한지 한 문장으로 적습니다.
6. 두 텐서의 shape을 뒤쪽 축부터 비교하는 규칙을 정리합니다.

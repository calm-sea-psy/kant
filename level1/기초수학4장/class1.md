필수 1 : 정사각형이 아닌 행렬도 분해하기

데이터 플랫폼팀은 고객 60명 × 상품 40개 구매량 행렬을 다뤄야 합니다. 3장에서 배운 고유분해는 정사각행렬에만 쓸 수 있어 이 행렬에는 적용할 수 없습니다. 어떤 모양의 행렬이든 분해할 수 있는 SVD를 적용해, 행렬을 "고객 쪽 축 × 중요도 × 상품 쪽 축"으로 나눠 봅니다.

문제 1-1 : SVD를 적용하고 각 행렬의 shape 해석하기

**요구 사항**

1. `np.linalg.svd(M, full_matrices=False)`로 `U`, `S`, `Vt`를 구합니다.
2. `M`, `U`, `S`, `Vt`의 shape을 출력하고 각각이 무엇을 담고 있는지 설명합니다.
3. `full_matrices=True`로도 분해해 shape이 어떻게 달라지는지 비교합니다.
4. `S`가 내림차순으로 정렬되어 있는지 확인하고 상위 5개 특이값을 출력합니다.
5. `S`가 1차원 배열로 반환되는 이유를 한 문장으로 설명합니다.

문제 1-2 : 직교성 확인과 원본 복원하기

**요구 사항**

1. `U.T @ U`와 `Vt @ Vt.T`가 각각 단위행렬인지 확인합니다.
2. `np.diag(S)`로 Σ를 만들고 `U @ Σ @ Vt`를 계산합니다. 이때 **복원은 반드시 `full_matrices=False`로 얻은 `U`, `S`, `Vt`로 합니다.** 문제 1-1의 전체형 결과(`Uf`, `Sf`, `Vtf`)를 쓰면 `Uf`는 (60, 60), `np.diag(Sf)`는 (40, 40)이 되어 행렬곱 shape이 맞지 않아 오류가 납니다.
3. 복원 결과와 원본 `M`의 차이(프로베니우스 노름)를 계산합니다.
4. 상대 오차(`복원 오차 / 원본 노름`)도 함께 계산합니다.
5. 모든 특이값을 사용했을 때 오차가 사실상 0인 이유를 한 문장으로 설명합니다.

필수 2 : 특이값은 어디에서 오는가

특이값이 그냥 주어지는 숫자가 아니라 AᵀA의 고유값에서 나온다는 점을 확인하면, 3장의 고유분해와 4장의 SVD가 하나의 이야기로 연결됩니다. 또한 이 행렬에 고유분해를 직접 시도해 보면 왜 SVD가 필요한지 분명해집니다.

문제 2-1 : 특이값과 AᵀA 고유값의 관계 확인하기

**요구 사항**

1. `MᵀM`을 계산하고 대칭행렬인지 확인합니다.
2. `np.linalg.eigvalsh(MᵀM)`로 고유값을 구하고 내림차순으로 정렬합니다.
3. 고유값에 제곱근을 취한 값과 특이값 `S`를 비교합니다.
4. 상위 5개에 대해 두 값을 표로 나란히 출력하고 최대 차이를 계산합니다.
5. 음수 반올림 오차가 생길 수 있으므로 제곱근을 취하기 전 `np.clip(..., 0, None)`을 적용하는 이유를 설명합니다.
6. 실데이터 `M`은 `MᵀM`의 최소 고유값도 충분히 큰 양수여서, clip이 있으나 없으나 결과가 같습니다. clip이 진짜로 필요해지는 상황을 직접 만들어 봅니다. **랭크가 부족한 행렬** `R = C @ P`(`C`는 60×5, `P`는 5×40이므로 `rank(R) ≤ 5`)를 만들고, `RᵀR`의 고유값을 구해 **음수 고유값이 몇 개 나오는지** 세어 봅니다.
7. 그 고유값에 clip 없이 `np.sqrt`를 바로 적용해 `nan`이 몇 개 생기는지 확인하고, clip을 적용한 결과와 비교합니다.

문제 2-2 : 고유분해와 SVD의 적용 범위 비교하기

**요구 사항**

1. 직사각행렬 `M`에 `np.linalg.eig`를 직접 시도하고 어떤 오류가 나는지 확인합니다.
2. 같은 `M`에 SVD를 적용해 정상적으로 분해되는지 확인합니다.
3. 정사각이지만 대각화가 불가능한 `B = [[1, 1], [0, 1]]`에 대해 SVD를 적용해 특이값을 확인합니다.
4. 고유분해와 SVD의 차이를 적용 대상 / 결과 벡터의 직교성 / 수치 안정성 관점에서 표로 정리합니다.
5. 어떤 상황에서 SVD를 선택해야 하는지 한 문장으로 작성합니다.

심화 1 : 상위 몇 개만 남겨도 원본을 설명할 수 있을까

고객-상품 행렬을 그대로 저장하고 다루면 용량과 계산 비용이 큽니다. 특이값이 내림차순이라는 점을 이용해 상위 k개만 남기면 저장 공간을 크게 줄일 수 있습니다. 어느 정도까지 줄여도 원본을 충분히 설명하는지 오차와 보존 에너지로 확인합니다.

문제 3-1 : 저랭크 근사의 오차와 정보 보존량 계산하기

**요구 사항**

1. `k = 1, 2, 5, 10, 20`에 대해 `M_k = U[:, :k] @ diag(S[:k]) @ Vt[:k, :]`를 계산합니다.
2. 각 `k`에 대해 다음을 계산해 표로 정리합니다.
    - 복원 오차 `||M - M_k||`
    - 상대 오차 `||M - M_k|| / ||M||`
    - 보존 에너지 `sum(S[:k]²) / sum(S²)`
    - 저장에 필요한 원소 수 `k * (행 + 열 + 1)`와 원본 원소 수 대비 비율
3. `k`에 따른 보존 에너지 곡선을 그립니다.
4. 보존 에너지가 90%를 넘는 최소 `k`를 찾습니다.
5. `M_k`의 rank가 실제로 `k`인지 확인합니다.
6. 어느 정도의 정보 손실까지 허용할지 결정할 때 고려할 점을 2~3문장으로 작성합니다.

### 1. 지도학습(Supervised Learning)이란

입력과 정답(레이블)이 짝지어진 데이터로 학습해서, 새로운 입력에 대한 정답을 예측하는 함수를 만드는 방식입니다. 크게 회귀와 분류 두 가지 문제 유형으로 나뉩니다.

#### 1-1. 회귀(Regression): 연속값 예측

입력 변수와 연속적인 출력 변수 사이의 관계를 학습하는 기법입니다. 분류가 "어느 범주에 속하는가"를 묻는다면, 회귀는 "값이 얼마인가"를 묻습니다. 예를 들어 면적·방 개수·위치 같은 정보로 집값(연속값)을 예측하는 문제가 대표적입니다.

학습은 실제값과 예측값의 차이를 줄이는 방향으로 파라미터를 조정하는 방식으로 이루어지며, 가장 흔히 쓰이는 손실 지표는 평균제곱오차입니다.

대표 알고리즘으로는 선형회귀(가장 단순하고 해석이 쉬움), 다항회귀(비선형 관계를 다항식으로 표현), 릿지/라쏘 회귀(정규화로 과적합 방지), 결정트리 회귀(비선형·구간별 예측), 랜덤포레스트·그래디언트부스팅 회귀(여러 트리를 앙상블해 성능 우수), 신경망 회귀(복잡한 비선형 관계 학습)가 있습니다.

평가는 오차 제곱 평균(또는 그 제곱근), 오차 절댓값 평균(이상치에 덜 민감), 결정계수(모델이 데이터의 분산을 얼마나 설명하는지, 1에 가까울수록 좋음) 등을 사용합니다.

#### 1-2. 분류(Classification): 범주 예측

입력을 미리 정의된 범주 중 하나로 매핑하는 기법입니다. 회귀가 연속값을 예측한다면 분류는 이산적인 카테고리를 예측합니다. 이메일을 스팸/정상으로 나누거나, 손글씨 숫자를 0~9 중 하나로 분류하는 문제가 대표적입니다.

분류 문제는 두 클래스 중 하나를 고르는 이진 분류, 셋 이상의 클래스 중 하나만 고르는 다중 클래스 분류, 하나의 샘플이 여러 클래스에 동시에 속할 수 있는 다중 레이블 분류로 나뉩니다.

회귀의 평균제곱오차 대신, 분류에는 주로 교차 엔트로피 손실을 사용합니다. 대표 알고리즘으로는 로지스틱 회귀(단순하고 해석 쉬움), KNN(가까운 이웃들의 다수결), 결정트리(규칙 기반), SVM(마진을 최대화하는 경계 탐색), 랜덤포레스트·그래디언트부스팅(여러 트리 앙상블), 나이브 베이즈(조건부 확률 기반, 텍스트 분류에 강함), 신경망(복잡한 비선형 경계 학습)이 있습니다.

분류의 평가는 회귀처럼 "얼마나 틀렸나"가 아니라 "맞았나 틀렸나"를 다양한 관점에서 봅니다. 실제 양성인데 양성으로 맞힌 경우, 실제 음성인데 양성으로 잘못 예측한 경우, 실제 양성인데 음성으로 잘못 예측한 경우, 실제 음성인데 음성으로 맞힌 경우 네 가지 조합을 정리한 혼동행렬이 기본 도구입니다. 이를 바탕으로 전체 중 맞춘 비율(정확도, 클래스 불균형 시 왜곡될 수 있음), 양성이라 예측한 것 중 실제 양성 비율(정밀도), 실제 양성 중 맞게 예측한 비율(재현율), 정밀도와 재현율의 조화평균(F1), 임계값을 바꿔가며 그린 곡선의 아래 면적(ROC-AUC) 등을 계산합니다. 암 진단처럼 놓치면 안 되는 경우는 재현율을, 스팸 필터처럼 정상 메일을 잘못 걸러내면 안 되는 경우는 정밀도를 중시합니다.

정상 거래가 99%, 사기 거래가 1%인 경우처럼 클래스 비율이 크게 치우친 상황에서는 정확도만 보면 오해하기 쉽습니다. 이런 클래스 불균형에는 오버샘플링(SMOTE)이나 언더샘플링, 클래스 가중치 조정, F1·AUC 같은 다른 지표 활용으로 대응합니다.

### 2. 비지도학습(Unsupervised Learning)이란

레이블 없는 데이터에서 숨겨진 구조나 패턴을 스스로 찾아내는 방식입니다. 목표는 데이터의 분포, 군집, 구조를 파악하는 것입니다.

#### 2-1. 군집화(Clustering): 비슷한 데이터끼리 묶기

레이블 없는 데이터에서 유사한 데이터끼리 그룹으로 묶는 기법입니다. 지도학습처럼 "정답"이 없으므로, 데이터 자체의 거리나 밀도, 분포 구조를 기준으로 그룹을 스스로 발견합니다. 고객의 구매 패턴으로 비슷한 소비 성향의 고객군을 자동으로 나누는 문제가 대표적입니다.

핵심은 결국 "거리(또는 유사도)를 어떻게 정의하느냐"의 문제이며, 대표 알고리즘으로는 K-means(분할 기반), 계층적 군집화, DBSCAN(밀도 기반), GMM(확률 기반)이 있습니다.

군집의 개수를 정하는 방법으로는, 군집 개수에 따른 군집 내 응집도를 그래프로 그려 급격히 완만해지는 지점을 찾는 엘보우 기법이나, 각 데이터가 자기 군집과 얼마나 가깝고 다른 군집과는 얼마나 먼지를 측정하는 실루엣 계수가 있습니다.

비지도학습은 정답 레이블이 없어 평가가 애매합니다. 레이블 없이 평가하는 내부 지표(실루엣 계수, Davies-Bouldin Index 등)와, 정답 레이블이 있을 때만 쓸 수 있는 외부 지표(ARI, NMI 등)로 나뉩니다.

#### 2-2. 차원 축소(Dimensionality Reduction): 특징 수 줄이기

데이터의 특징 개수(차원)를 줄이면서 원래 정보를 최대한 보존하는 기법입니다. 목적은 시각화, 계산량 감소, 노이즈 제거, 그리고 차원이 늘어날수록 데이터 간 거리가 모두 비슷해지고 필요한 데이터 양이 폭발적으로 늘어나는 "차원의 저주" 완화입니다.

대표 알고리즘으로는 PCA(선형, 압축·노이즈 제거에 강하고 새 데이터에도 적용 가능하며 해석 가능성이 높음), t-SNE(비선형, 시각화 전용이며 새 데이터 적용이 어렵고 해석 가능성 낮음), UMAP(비선형, 시각화와 압축 모두 가능), 오토인코더(비선형, 압축·특징 추출용)가 있습니다.

전처리 단계에서 군집화나 분류 전에 PCA로 노이즈와 다중공선성을 제거해 모델 성능을 높이거나, 고차원 데이터를 2~3차원으로 축소해 t-SNE·UMAP으로 시각화하는 데 활용됩니다.

#### 2-3. 이상치 탐지(Anomaly Detection)

전체 데이터의 정상적인 패턴에서 크게 벗어난 데이터를 찾아내는 기법입니다. 지도학습으로도 가능하지만, 실무에서는 이상 사례가 극히 드물고 레이블도 없는 경우가 많아 비지도학습으로 접근하는 경우가 많습니다. 신용카드 이상 거래 탐지, 설비 고장 예측, 네트워크 침입 탐지 등이 대표적입니다.

이상치 탐지가 어려운 이유는 정상 데이터가 99% 이상인 극심한 클래스 불균형, 무엇이 "이상"인지 사전에 정의하기 어려운 레이블 부족, 시간에 따라 정상 패턴 자체가 바뀔 수 있다는 점(개념 변화) 때문입니다.

접근 방식은 통계 기반, 거리·밀도 기반, 트리 기반(Isolation Forest), 확률 기반(GMM), 재구성 기반(오토인코더·PCA), One-Class SVM 등으로 나뉩니다.

레이블이 없으면 사람이 직접 검증하거나 도메인 지식으로 판단해야 하고, 레이블이 일부 있다면 극심한 불균형 상황에서는 정확도보다 Precision-Recall 곡선이 더 유용합니다. 놓치는 이상치를 최소화할지(재현율 중시), 오탐을 최소화할지(정밀도 중시)의 트레이드오프가 특히 중요합니다.

#### 2-4. 밀도 추정(Density Estimation)

관측된 데이터가 따르는 확률분포 자체를 추정하는 기법입니다. 군집화·이상치 탐지·차원 축소가 데이터의 "구조"를 요약한다면, 밀도 추정은 데이터가 어디에 얼마나 밀집해 있는지를 확률 함수 형태로 직접 모델링합니다. 사실 GMM 기반 군집화나 재구성 오차 기반 이상치 탐지도 결국 밀도를 명시적 또는 암묵적으로 추정하는 것입니다.

접근 방식은 분포의 형태를 가정하고 소수의 파라미터로 표현하는 모수적 방법(예: GMM)과, 분포 형태를 가정하지 않고 데이터 자체를 그대로 활용하는 비모수적 방법(예: 커널 밀도 추정)으로 나뉩니다. 모수적 방법은 대용량에 유리하지만 가정과 실제 분포가 다르면 왜곡되고, 비모수적 방법은 유연하지만 데이터가 많아질수록 느려지고 고차원에서 취약합니다.

### 3. 데이터 분리: train / valid / test

모델이 학습에 쓴 데이터로 자기 성능을 스스로 평가하면, 답을 미리 보고 시험을 치르는 것과 같습니다. 실제로는 처음 보는 데이터에서 잘 작동해야 하므로, 학습에 쓰지 않은 데이터로 성능을 확인해야 합니다. 그래서 데이터를 학습용·검증용·테스트용으로 나누어, 모델이 처음 보는 데이터에 얼마나 잘 일반화되는지를 정직하게 측정합니다.

### 4. 선형모델: 선형회귀와 로지스틱회귀

지도학습의 가장 기본이 되는 두 모델로, 입력을 선형으로 결합한다는 공통점이 있고 목적(회귀 vs 분류)에 따라 출력을 어떻게 변환하느냐만 다릅니다. 선형회귀는 선형결합을 그대로 출력해 연속값을 예측하고, 손실로는 평균제곱오차를 씁니다. 로지스틱회귀는 선형결합을 확률(0~1)로 변환해 분류에 사용하며, 손실로는 교차 엔트로피를 씁니다. 같은 뼈대 위에 출력 변환과 손실 함수만 다르게 얹은 형제 모델이라 할 수 있습니다.

두 모델 모두 특징과 출력의 관계가 선형이라 해석이 쉽고, 경사하강법으로 학습 가능하며 손실 함수가 볼록해서 전역 최적해가 보장됩니다. 과적합 방지를 위해 L1(라쏘)/L2(릿지) 정규화를 흔히 추가합니다. 다만 비선형 관계는 잘 표현하지 못한다는 한계가 있어, 다항 특징 추가나 커널 기법, 트리·신경망 모델로 확장합니다.

데이터가 상대적으로 적고 해석 가능성이 중요할 때 우선 시도하며, 복잡한 모델의 베이스라인으로도 자주 쓰입니다.

### 5. KNN: 거리 기반 예측

새로운 데이터를 예측할 때, 학습 데이터 중 가장 가까운 k개의 이웃을 찾아 그들의 값으로 예측하는 알고리즘입니다. 별도의 학습(파라미터 추정) 과정 없이 예측 시점에 전체 학습 데이터를 그대로 사용해 계산하기 때문에 "게으른 학습"이라 불리며, 분류와 회귀 양쪽에 모두 사용됩니다.

분류에서는 k개 이웃의 다수결로 클래스를 결정하고, 회귀에서는 k개 이웃 값의 평균(또는 거리 가중 평균)으로 예측합니다. 거리를 재는 방식으로는 가장 흔한 유클리드 거리, 격자형 이동을 가정해 이상치에 덜 민감한 맨해튼 거리, 이 둘의 일반형인 민코프스키 거리, 텍스트나 고차원 희소 데이터에 적합한 코사인 유사도 등이 있습니다.

k 값이 작으면 노이즈에 민감해 결정 경계가 복잡해지고 과적합(분산이 큼) 위험이 커지며, k 값이 크면 여러 이웃을 평균내 경계가 매끄러워지는 대신 다른 클래스의 영향까지 받아 과소적합(편향이 큼) 위험이 커집니다. 보통 교차검증으로 여러 k를 시도해 최적값을 선택합니다.

KNN은 거리 기반이므로 전처리가 특히 중요합니다. 특징들의 단위나 범위가 다르면 값이 큰 특징이 거리 계산을 지배해버리기 때문에 표준화나 정규화가 거의 필수입니다. 또한 차원이 높아질수록 모든 점 사이의 거리가 비슷해져 "가까운 이웃"이라는 개념 자체가 희미해지는 차원의 저주 문제도 있어, 차원 축소를 먼저 적용하는 경우가 많습니다.

예측할 때마다 전체 학습 데이터와 거리를 계산해야 하므로 데이터가 많으면 예측이 느려진다는 단점이 있고, 이를 보완하기 위해 KD-Tree, Ball Tree, 근사 최근접 이웃 같은 가속 구조를 사용합니다.

### 6. 결정트리(Decision Tree): 규칙 기반 분할

데이터를 "만약~라면" 형태의 규칙으로 반복 분할해 예측하는 모델로, 스무고개처럼 질문을 던지며 답을 좁혀갑니다. 분류와 회귀 모두 가능합니다.

트리는 전체 데이터를 나타내는 루트 노드, 특정 특징에 대한 분할 조건을 담은 내부 노드, 조건의 참/거짓에 따라 나뉘는 가지, 최종 예측값을 담은 리프 노드로 구성됩니다.

매 노드마다 데이터를 가장 "잘" 나누는 특징과 기준값을 탐욕적으로 선택합니다. "잘 나눈다"는 것은 분할 후 각 자식 노드가 최대한 순수해지는(한 범주로 쏠리는) 것을 의미하며, 이 과정을 반복해 정지 조건(최대 깊이 도달, 노드 내 샘플 수 부족, 더 이상 순도 개선이 없음 등)에 도달하면 리프 노드로 확정합니다.

트리를 끝까지 키우면 학습 데이터에 완벽히 맞춰져 극심한 과적합이 발생합니다. 이를 막기 위해 트리 생성 중 조건으로 조기에 멈추는 사전 가지치기(최대 깊이 제한, 분할·리프 최소 샘플 수 제한 등)와, 일단 트리를 완전히 키운 뒤 검증 성능이 떨어지지 않는 선에서 불필요한 가지를 제거하는 사후 가지치기를 사용합니다.

결정트리는 해석이 매우 쉽고(규칙을 그대로 시각화·설명 가능), 특징 스케일링이 불필요하며(거리 기반이 아니므로 KNN과 대조적), 수치형·범주형 데이터를 모두 처리할 수 있고, 특징 간 상호작용을 자동으로 포착하며, 특징 중요도를 계산할 수 있다는 장점이 있습니다. 반면 과적합되기 쉽고, 데이터가 조금만 바뀌어도 트리 구조가 크게 바뀌는 불안정성(분산이 큼)이 있으며, 결정 경계가 축에 평행한 계단 형태로 제한된다는 단점이 있습니다.

결정트리는 분산이 크다는 근본적 약점이 있어, 이를 보완하기 위해 여러 트리를 결합하는 앙상블 기법(랜덤포레스트, 그래디언트부스팅)으로 발전합니다.

### 7. 비지도학습 대표주자: K-means와 PCA

K-means(군집화)와 PCA(차원 축소)는 비지도학습의 양대 축을 대표하는 알고리즘입니다. 목적은 다르지만 둘 다 "데이터를 더 단순한 형태로 요약한다"는 공통점이 있습니다.

**K-means**는 레이블 없는 데이터를 지정된 개수의 그룹(군집)으로 나누는 알고리즘입니다. 각 군집은 하나의 중심점으로 대표됩니다. 중심을 무작위로 초기화한 뒤, 각 데이터를 가장 가까운 중심에 배정하고, 각 군집에 속한 데이터들의 평균으로 중심을 다시 계산하는 과정을 중심이 더 이상 변하지 않을 때까지 반복합니다. 군집 개수는 미리 정해야 하며 엘보우 기법이나 실루엣 계수로 결정하고, 유클리드 거리 기반이라 스케일링이 필수입니다.

**PCA**는 고차원 데이터를 정보 손실을 최소화하며 저차원으로 압축하는 방법으로, 데이터의 분산이 가장 큰 방향(축)을 순서대로 찾아 그 축들로 데이터를 투영합니다. 데이터를 평균 0으로 중심화한 뒤 공분산행렬을 계산하고, 그 고유값 분해에서 고유값이 큰 순서대로 고유벡터(주성분)를 골라 상위 몇 개에 투영합니다. 선형 변환이라 계산이 빠르고 해석이 가능하며, 고유벡터들이 서로 직교해 주성분들끼리 독립적인 정보를 담게 됩니다. 다만 비선형 구조는 왜곡될 수 있어 이런 경우 t-SNE·UMAP·오토인코더가 대안이 됩니다.

고차원 데이터를 K-means로 바로 군집화하면 차원의 저주 때문에 거리 계산이 무의미해지는 경우가 많습니다. 그래서 실무에서는 PCA로 먼저 차원을 축소한 뒤(예: 1000차원을 20차원으로), 그 축소된 공간에서 K-means를 수행하고, 필요하면 2~3차원까지 추가로 축소해 결과를 시각화하는 순서로 함께 사용합니다. PCA는 "연속적인 선형 부분공간"으로, K-means는 "이산적인 점들의 집합"으로 데이터를 근사한다는 점에서, 같은 압축 철학의 두 극단이라 볼 수 있습니다.

### 8. 모델을 어떻게 고를까: 선택 기준

**1단계: 문제 유형 확정.** 레이블(정답)이 있으면 지도학습(회귀 또는 분류), 없으면 비지도학습(군집화·차원 축소·이상치 탐지·밀도 추정)입니다. 예측 대상이 연속값이면 회귀, 범주면 분류입니다.

**2단계: 선택 기준들**

- **데이터 규모**: 데이터가 적으면(수백~수천 건) 선형모델·KNN·결정트리처럼 단순한 모델을, 데이터가 많으면(수만 건 이상) 랜덤포레스트·그래디언트부스팅·신경망처럼 복잡한 모델을 고려합니다.
- **해석 가능성 vs 성능**: 금융 심사나 의료 진단처럼 의사결정 근거를 설명해야 하는 경우는 선형모델·단일 결정트리가 유리하고, 추천이나 이미지 인식처럼 성능이 최우선인 경우는 랜덤포레스트·그래디언트부스팅·신경망이 유리합니다.
- **선형성/비선형성**: 관계가 대체로 선형이면 선형모델로 충분하고, 복잡한 비선형·상호작용 관계라면 트리 기반 앙상블·KNN·신경망을 고려합니다.
- **특징 스케일 민감도**: 거리 기반 모델(KNN, K-means, PCA)은 스케일링이 필수지만, 트리 기반 모델은 분할 기준이 순서만 보므로 스케일링이 불필요합니다.
- **계산 비용/속도**: KNN은 학습은 빠르지만 예측이 느리고, 선형모델·트리 기반은 학습은 오래 걸릴 수 있지만 예측이 빠릅니다.
- **클래스 불균형**: 극심한 불균형은 일반 분류보다 이상치 탐지 관점으로 접근하거나 클래스 가중치·리샘플링을 병행합니다.
- **차원 수**: 특징이 매우 많고 상관관계가 크면 먼저 차원 축소로 정리한 뒤 모델링하고, 차원이 높고 희소한 데이터(텍스트 등)에는 정규화가 강한 선형모델이 의외로 강력합니다.

**3단계: 실전 워크플로우.** 가장 단순한 모델(회귀는 선형회귀, 분류는 로지스틱회귀)로 성능 기준선을 확보한 뒤, 결정트리 → 랜덤포레스트·그래디언트부스팅 순으로 비선형 모델로 개선을 시도합니다. 교차검증으로 일반화 성능을 확인하면서 편향-분산 트레이드오프를 점검합니다. 학습 성능은 높은데 검증 성능이 낮다면 과적합(분산이 큼)이므로 정규화·가지치기·데이터 증강을, 둘 다 낮다면 과소적합(편향이 큼)이므로 더 복잡한 모델이나 특징 추가를 시도합니다. 마지막으로 하이퍼파라미터 탐색과 여러 모델의 앙상블로 성능을 다듬습니다.

### 1. 부트스트랩(Bootstrap)

원본 데이터셋에서 복원추출(같은 것을 다시 뽑을 수 있도록 허용하는 추출)로 같은 크기의 새로운 데이터셋을 여러 개 만드는 통계 기법입니다. 원래는 모집단 전체를 알 수 없을 때, 가진 표본만으로 추정치의 불확실성을 근사하기 위해 통계학에서 고안된 방법입니다.

원본 데이터가 n개 있을 때, 그중에서 무작위로 하나씩 n번 뽑되 뽑은 것을 다시 넣고 뽑습니다. 그 결과 어떤 데이터는 여러 번 뽑히고, 어떤 데이터는 한 번도 뽑히지 않습니다. 평균적으로 원본 데이터의 약 63.2%만 각 부트스트랩 샘플에 포함되고, 나머지 약 36.8%는 빠지는데, 이 빠진 데이터를 OOB(Out-Of-Bag) 샘플이라 부르며 별도의 검증셋 없이 모델 성능을 평가하는 데 활용할 수 있습니다.

부트스트랩이 유용한 이유는, 데이터가 하나뿐이어도 여러 개의 "가상의 다른 데이터셋"을 만들어낼 수 있어 추정치의 신뢰구간을 계산하거나 모델의 불안정성을 줄이는 데 활용할 수 있기 때문입니다.

### 2. 배깅(Bagging, Bootstrap Aggregating)

부트스트랩으로 만든 여러 데이터셋 각각에 모델을 학습시킨 뒤, 그 예측을 집계해 최종 예측을 만드는 앙상블 기법입니다. 원본 데이터에서 부트스트랩으로 여러 개의 데이터셋을 만들고, 각각으로 독립적으로 모델(주로 결정트리)을 학습시킨 뒤, 예측 시 회귀는 평균을, 분류는 다수결을 취합니다.

배깅이 효과 있는 이유는 분산 감소에 있습니다. 단일 결정트리는 분산이 매우 커서 데이터가 조금만 바뀌어도 트리 구조가 확 달라지는데, 여러 개의 서로 다른 트리를 평균 내면 개별 모델의 노이즈가 상쇄되어 전체 분산이 줄어듭니다. 반면 편향은 크게 변하지 않으므로, 배깅은 편향-분산 트레이드오프에서 분산만 선택적으로 줄이는 기법이라 할 수 있습니다. 그래서 분산이 큰(불안정한) 모델일수록 배깅 효과가 크고, 원래 안정적인 선형회귀 같은 모델에는 배깅을 적용해도 효과가 미미합니다.

### 3. 랜덤포레스트의 두 가지 무작위성

랜덤포레스트라는 이름 자체가 이 이중 무작위화에서 나온 것입니다.

**무작위성 ① 데이터 샘플링(배깅)**: 원본 데이터에서 복원추출로 여러 데이터셋을 만들어 각 트리가 서로 다른 데이터를 학습합니다. 하지만 이것만으로는 부족한데, 부트스트랩 데이터셋들이 원본과 63% 이상 겹치다 보니 하나의 강력한 특징이 있으면 대부분의 트리가 그 특징으로 첫 분할을 해버려 트리들이 여전히 서로 비슷해질 수 있습니다.

**무작위성 ② 특징 샘플링**: 각 노드에서 분할을 결정할 때, 전체 특징 중 무작위로 뽑은 일부만 후보로 검토합니다. 매 분할마다 사용 가능한 특징을 제한하면, 강한 특징이 없을 때 다른 특징들도 분할에 참여할 기회를 얻어 트리들이 서로 다른 구조로 자랍니다.

데이터 샘플링만으로는 트리 간 다양성이 확보되지만 강한 특징 때문에 여전히 트리들이 유사해지는 반면, 특징 샘플링까지 함께 적용하면 데이터도 다르고 분할 후보 특징도 달라 트리 간 상관관계가 최소화되어 분산 감소가 극대화됩니다. 분산 감소 효과가 이상적으로 성립하려면 트리들이 서로 독립적(상관관계 낮음)이어야 하는데, 데이터 샘플링만으론 이 독립성이 부족하고 특징 샘플링을 더해야 실질적인 독립성에 가까워집니다.

단일 결정트리에서는 가지치기로 과적합을 막아야 했지만, 랜덤포레스트에서는 오히려 개별 트리를 깊게(과적합 상태로) 키우는 것이 전략입니다. 어차피 이중 무작위성으로 다양화된 트리들을 평균 내면서 분산이 상쇄되기 때문입니다.

**랜덤포레스트가 강해지기 위한 두 조건**: 각 트리는 개별적으로 충분히 정확해야 하고(강도, 낮은 편향), 트리들끼리는 서로 최대한 달라야 합니다. 두 무작위성은 두 번째 조건을 위한 장치이고, 트리를 깊게 키우는 것은 첫 번째 조건을 지키기 위한 선택이며, 이 둘 사이의 균형이 하이퍼파라미터 튜닝의 본질입니다.

### 4. OOB Score

각 트리는 부트스트랩으로 만든 데이터셋으로 학습되는데, 평균 약 63.2%만 포함되고 나머지 약 36.8%는 그 트리 학습에 전혀 쓰이지 않습니다. 이 "안 쓰인" 데이터를 OOB 샘플이라 부릅니다.

계산 방식은, 각 데이터 포인트에 대해 그 포인트를 학습에 쓰지 않은 트리들(평균적으로 전체의 약 36.8%)만 모아서 예측하고, 이를 모든 데이터 포인트에 대해 반복해 실제값과 비교하는 것입니다. 이렇게 하면 별도의 검증셋이나 교차검증 없이도 학습에 쓰지 않은 데이터로 검증한 것과 동일한 효과를 얻을 수 있어, 데이터가 적을 때 특히 유용합니다. 다만 트리 개수가 적으면 OOB 샘플이 부족해 추정이 불안정할 수 있고, 시계열처럼 데이터 간 독립성이 깨진 경우엔 부트스트랩 자체가 부적절해 OOB 신뢰도도 낮아집니다.

### 5. 두 가지 특징 중요도: MDI와 Permutation Importance

**MDI(Mean Decrease in Impurity, 불순도 감소 기반)**: 각 트리에서 특정 특징이 분할에 쓰일 때마다 그로 인한 불순도 감소량을 기록하고, 해당 특징이 관여한 모든 분할의 감소량을 담당 샘플 비율로 가중 합산한 뒤 전체 트리에 대해 평균합니다. 학습 과정에서 이미 나온 값을 재활용하므로 계산이 빠르고, scikit-learn이 기본 제공하는 특징 중요도가 바로 이것입니다. 다만 고유값 개수가 많은 특징일수록 우연히 좋은 분할을 찾을 기회가 많아 과대평가되는 편향이 있고(순수 노이즈인 ID 같은 변수도 값이 다양하다는 이유만으로 중요도가 높게 나올 수 있음), 학습 데이터 자체의 불순도 감소를 측정하는 것이라 일반화 성능과 괴리될 수 있습니다.

**Permutation Importance(순열 기반)**: "이 특징이 정말 중요하다면 값을 무작위로 뒤섞었을 때 성능이 크게 떨어져야 한다"는 직관에 기반합니다. 기준 성능을 측정한 뒤, 특정 특징의 값만 무작위로 섞어 다시 예측하고 성능 하락폭을 봅니다. 하락폭이 클수록 그 특징이 중요합니다. 실제 예측 성능에 미치는 영향을 직접 측정하므로 더 신뢰할 수 있고, 카디널리티 편향이 없으며, 어떤 모델에도 적용 가능합니다. 다만 계산 비용이 크고, 서로 강하게 상관된 특징이 있으면 하나를 섞어도 다른 하나가 비슷한 정보를 담고 있어 둘 다 과소평가될 수 있습니다.

### 6. 부스팅(Boosting)

배깅이 병렬로 독립적인 트리를 평균 내 분산을 줄이는 전략이라면, 부스팅은 순차적으로 약한 모델을 개선해나가며 편향을 줄이는 전략입니다. 개별로는 성능이 그저 그런 약한 학습기(주로 얕은 결정트리)를 순차적으로 학습시키되, 각 모델이 이전 모델이 잘 못 맞춘 부분을 집중적으로 보완하도록 하고, 최종 예측은 모든 모델의 가중 합으로 만듭니다.

**AdaBoost**는 이전 모델이 틀린 샘플에 가중치를 부여해, 다음 모델이 그 샘플에 더 신경 쓰도록 만드는 방식입니다. 마치 오답노트를 계속 갱신하며 공부하는 것과 비슷합니다.

**Gradient Boosting**은 더 일반화된 관점으로, 모델 자체를 손실이 줄어드는 방향(경사 방향)으로 갱신합니다. 손실이 평균제곱오차라면 그 경사가 곧 잔차이므로 "잔차를 학습"하는 것과 동일해지고, 손실 함수를 바꾸면 분류나 이상치에 강건한 회귀 등 다양한 문제에 적용할 수 있어 AdaBoost보다 훨씬 유연한 프레임워크입니다.

랜덤포레스트(배깅 계열)는 개별 트리를 깊게 키워 낮은 편향·높은 분산 상태로 만든 뒤 평균으로 분산을 상쇄하는 전략인 반면, 부스팅은 얕고 약한 트리들을 높은 편향·낮은 분산 상태로 두고 순차적으로 편향을 줄여나가는 전략입니다. 배깅은 트리 개수를 늘려도 과적합이 잘 늘지 않지만, 부스팅은 모델을 계속 더할수록 학습 데이터에 점점 더 맞춰져 과적합 위험이 존재합니다. 이에 대응하기 위해 학습률을 낮추거나, 개별 트리를 얕게 유지하거나(최대 깊이 제한), 조기 종료를 쓰거나, 정규화 항을 튜닝합니다.

이미지·텍스트 등 비정형 데이터는 딥러닝이 강세지만, 테이블 형태의 정형 데이터에서는 지금도 XGBoost·LightGBM 계열이 신경망보다 우수한 성능을 내는 경우가 많습니다.

배깅은 같은 표현력을 가진 모델들을 평균 내므로 흔들림(분산)만 줄일 뿐 모델이 원래 가진 체계적 오차(편향)는 그대로 남습니다. 부스팅은 이전 모델이 놓친 잔차를 다음 모델이 계속 더해가며 채우는 구조라, 앙상블 전체의 표현력이 라운드를 거듭할수록 커지고 이것이 편향을 점진적으로 줄이는 근본 원리입니다. 다만 매 라운드가 이전 라운드에 의존하는 순차적 구조이므로, 학습 데이터의 작은 변화가 초기 트리부터 전체 사슬에 영향을 미쳐 뒤로 갈수록 증폭될 수 있어 분산이 커지는 위험도 함께 따라옵니다.

### 7. XGBoost · LightGBM · CatBoost 비교

셋 다 Gradient Boosting의 구현체지만, 트리를 어떻게 키우는지, 분할을 어떻게 찾는지, 범주형 변수를 어떻게 다루는지에서 철학이 갈립니다.

**XGBoost**는 손실 함수를 2차 근사(뉴턴 방법)로 더 정확하게 최소화하고, 트리 복잡도에 대한 명시적인 정규화 항을 목적함수에 포함시켜 과적합을 억제합니다. 같은 깊이의 모든 노드를 동시에 분할하는 레벨 단위 성장 방식을 쓰며, 결측값을 만나면 학습 중 어느 방향으로 보낼지 자동으로 최적 방향을 결정합니다. 정확도가 높고 안정성이 검증되어 있지만, 레벨 단위 성장 특성상 LightGBM보다 느리고 메모리를 더 씁니다.

**LightGBM**은 속도와 메모리 효율에 초점을 맞춰, 손실 감소가 가장 큰 리프 하나만 골라 분할하는 리프 단위 성장 방식을 씁니다. 같은 리프 수 기준으로 레벨 단위보다 손실을 더 빠르게 줄이지만, 깊이 제한 없이 두면 한쪽으로만 깊어져 과적합 위험이 커서 반드시 제어가 필요합니다. 연속값을 구간으로 이산화해 분할 탐색을 빠르게 하는 히스토그램 기반 분할, 이미 잘 맞추는 샘플은 일부만 남기고 잘 못 맞추는 샘플은 그대로 두는 샘플링 기법, 거의 겹치지 않는 희소 특징들을 하나로 묶는 기법 등으로 속도를 최적화합니다. XGBoost보다 훨씬 빠르고 메모리를 적게 쓰지만, 소규모 데이터에서는 과적합되기 쉬워 튜닝에 민감합니다.

**CatBoost**는 범주형 변수 처리에 특화되어 있습니다. XGBoost·LightGBM은 범주형 변수를 사용자가 수치로 미리 변환해야 하지만, CatBoost는 데이터를 무작위 순서로 배열한 뒤 각 샘플 이전에 등장한 데이터만으로 평균을 계산하는 방식으로 범주형 변수를 자동 인코딩해 타겟 정보가 자기 자신의 인코딩에 섞여드는 누수를 방지합니다. 이 순서를 두고 학습하는 방식을 부스팅 전체에도 적용해(Ordered Boosting), 일반 Gradient Boosting에서도 존재하는 미묘한 타겟 누수 문제까지 방지해 과적합에 더 강건합니다. 같은 깊이의 모든 노드가 동일한 분할 조건을 쓰는 대칭 트리 구조라 균형이 잡히고 예측 속도가 빠르지만, 유연성은 XGBoost·LightGBM보다 낮을 수 있습니다. 범주형 변수가 많은 데이터에 최상이고 하이퍼파라미터 튜닝 없이도 준수한 성능을 내지만, 학습 속도가 LightGBM보다 느릴 수 있습니다.

실무에서는 범주형 변수가 많고 빠르게 좋은 결과를 원하면 CatBoost, 데이터가 매우 크고 속도·메모리가 중요하면 LightGBM, 검증된 안정성과 정교한 정규화 제어가 필요하면 XGBoost를 고려하되, 셋 다 시도해보고 교차검증으로 비교하는 것이 일반적입니다. 셋 다 잔차·그래디언트를 순차적으로 보완하는 같은 뼈대 위에 있으며, 차이는 트리를 키우는 방식과 범주형 변수 처리라는 공학적 최적화 지점에 있습니다.

### 8. 학습률 · 반복 수 · Early Stopping

부스팅의 과적합 위험에 대응하는 세 가지 핵심 하이퍼파라미터는 서로 얽혀 있어 하나만 떼어놓고 튜닝할 수 없는 삼각관계입니다.

**학습률**은 새로 학습된 트리의 기여분을 얼마나 반영할지 조절하는 값입니다. 학습률이 크면 몇 번의 반복만으로도 학습 데이터에 급격히 맞춰져 빠르게 과적합되고, 학습률을 작게 하면 한 트리가 실수해도 전체 예측에 미치는 영향이 작아 더 매끄럽고 안정적인 학습 경로를 만듭니다.

**반복 수(부스팅 라운드 수)**는 배깅과 결정적으로 다릅니다. 배깅·랜덤포레스트는 트리를 늘려도 과적합이 거의 늘지 않아 "많을수록 안정적, 계산 비용만 증가"하는 반면, 부스팅은 트리를 늘릴수록 학습 데이터에 점점 더 정교하게 맞춰져 어느 지점을 넘으면 검증 성능이 오히려 나빠지는 명확한 과적합 지점이 존재합니다. 학습 손실은 반복할수록 계속 감소하지만, 검증 손실은 어느 지점까지 감소하다가 다시 늘어나며, 이 반등이 시작되는 지점이 최적 반복 수입니다.

**Early Stopping**은 매 반복마다 별도의 검증셋 성능을 함께 측정하다가, 검증 성능이 일정 횟수 동안 개선되지 않으면 학습을 중단하고 검증 성능이 가장 좋았던 시점의 모델을 최종 모델로 채택하는 방법입니다. 반복 수를 직접 튜닝할 필요가 없어지고 학습 시간도 절약되며, 사실상 모델이 너무 복잡해지기 전에 학습을 멈추는 정규화의 한 형태이기도 합니다.

권장 워크플로우는 학습률을 작게 고정하고, 반복 수 상한을 매우 크게 설정해두고, Early Stopping을 활성화해 검증셋 기준으로 알아서 최적 지점에서 멈추게 한 뒤, 나머지 하이퍼파라미터(트리 깊이, 리프 수, 정규화 항 등)를 교차검증으로 튜닝하는 것입니다.

### 9. 공정한 모델 비교를 위한 네 가지 통제 조건

여러 모델(또는 여러 알고리즘)을 비교할 때, 모델 자체가 아닌 다른 요인이 성능 차이를 만들지 않도록 통제해야 할 네 가지 조건이 있습니다.

**같은 Fold(동일한 교차검증 분할)**: 모델마다 다른 시드로 데이터를 나누면, 성능 차이가 모델 차이인지 우연히 쉬운 분할을 받았기 때문인지 구분할 수 없습니다. 비교 대상 모델 전체에 완전히 동일한 분할을 고정해서 적용해야 합니다.

**전처리 경계(Preprocessing Boundary)**: 스케일링, 결측치 대체, 인코딩 같은 전처리를 학습/검증 분할 전 전체 데이터에 미리 적용하면 검증 데이터의 정보가 학습 과정에 스며들어 검증 성능이 실제보다 부풀려집니다. 전처리 파라미터를 계산(fit)하는 시점과 적용(transform)하는 시점 사이에 명확한 경계를 그어, 학습 부분에서만 fit하고 양쪽 모두에 transform해야 합니다. 비교 대상 모델들이 같은 전처리 경계를 지키는지 확인해야 순수하게 알고리즘 차이만 비교할 수 있습니다.

**같은 평가지표**: 평가 지표는 정확도, 정밀도, 재현율, F1, ROC-AUC, AP 등 여러 가지가 있고 어떤 지표를 쓰느냐에 따라 "더 나은 모델"의 순위가 바뀔 수 있습니다. 특히 클래스 불균형 상황에서는 정확도는 왜곡되기 쉽고 ROC-AUC도 다수 클래스에 유리하게 낙관적으로 보일 수 있습니다. 서로 다른 지표로 평가한 모델들을 비교하는 것은 애초에 다른 잣대로 잰 것이라 성립하지 않습니다.

**같은 계산 조건**: 서로 다른 라이브러리는 처리 속도가 크게 다를 수 있어, 같은 시간을 준다면 더 빠른 쪽이 더 많은 하이퍼파라미터 탐색이나 부스팅 라운드를 돌릴 기회를 얻습니다. 이 경우 성능 차이가 알고리즘의 본질적 우월함이 아니라 단지 더 많이 탐색해봤기 때문일 수 있습니다. 같은 트리 개수·라운드 수, 같은 하이퍼파라미터 탐색 횟수, 같은 하드웨어·병렬화 수준, 같은 랜덤 시드를 맞춰야 순수한 알고리즘 비교가 됩니다.

네 조건 모두 "모델 외의 다른 변수를 고정해서, 성능 차이의 원인을 모델 자체로 좁히자"는 하나의 원칙에서 나옵니다. 이를 고정하지 않은 상태에서 "모델 A가 B보다 좋다"고 결론 내리면, 실제로는 모델의 우월함이 아니라 실험 설계 자체의 편향을 관측한 것일 수 있습니다.

### 10. 세 가지 특징 중요도: MDI · Permutation · SHAP

"어떤 특징이 예측에 얼마나 기여하는가"라는 같은 질문에 답하지만, 어느 수준에서 어떤 원리로 답하는지가 다릅니다.

**MDI**와 **Permutation Importance**는 위에서 설명한 대로, 각각 학습 과정의 불순도 감소량과 순열 이후 성능 하락폭으로 "이 특징이 전체적으로 얼마나 중요한가"라는 전역적 질문에 답합니다.

**SHAP(SHapley Additive exPlanations)**은 한 걸음 더 나아가 "이 특정 샘플의 이 예측값에, 이 특징이 정확히 얼마를 기여했는가"라는 개별 예측 단위의 질문에 답합니다. 협력 게임이론에서 여러 참가자가 함께 만든 보상을 각자의 기여도에 따라 공정하게 나누는 방법(섀플리 값)을 특징 기여도 분배에 적용한 것입니다. 예를 들어 집값 예측에서 "역세권 여부"의 SHAP 값이 특정 크기의 양수라면, 다른 특징들이 이미 고려된 상태에서 역세권이라는 정보를 추가로 알려줬을 때 예측 가격이 그만큼 올라간다는 의미입니다.

섀플리 값은 게임이론에서 다음 네 가지 성질을 동시에 만족하는 유일한 배분 방법으로 증명되어 있습니다.

- **효율성**: 모든 특징의 기여도 합은 전체 예측값에서 기준값을 뺀 것과 같음
- **대칭성**: 두 특징이 항상 동일한 기여를 한다면 같은 값을 받음
- **더미**: 예측에 전혀 영향 없는 특징은 0을 받음
- **가산성**: 여러 모델을 합친 앙상블의 기여도는 각 모델 기여도의 합과 같음

MDI나 Permutation Importance는 이런 공리적 보장이 없는 휴리스틱인 반면, SHAP은 "이렇게 나누는 것이 수학적으로 유일하게 공정하다"는 근거를 가집니다. 빠르게 대략적인 감을 잡고 싶다면 MDI(카디널리티 편향에 주의하며), 모델과 무관하게 신뢰할 수 있는 전역 중요도가 필요하다면 Permutation Importance, 개별 예측의 근거를 설명해야 하거나 영향의 방향성까지 알아야 한다면 SHAP을 사용합니다. 셋 중 하나만 정답인 것이 아니라, MDI로 빠르게 스크리닝하고 Permutation으로 신뢰도를 검증한 뒤 SHAP으로 개별 사례를 설명하는 식으로 단계적으로 함께 쓰는 경우가 많습니다.

### 11. TreeSHAP: 전역 해석과 지역 해석

정확한 섀플리 값을 계산하려면 원래 모든 특징 조합을 다 검토해야 해서 특징이 많으면 사실상 불가능합니다. 모델과 무관하게 쓸 수 있는 근사법(Kernel SHAP)은 샘플링으로 근사하지만 느리고 오차가 있습니다.

**TreeSHAP**은 결정트리의 구조(분할 조건, 리프값)를 직접 활용해 정확한 섀플리 값을 빠르게 계산하는 방법입니다. 트리를 따라 내려가는 경로마다 특정 특징의 값을 "알 때"와 "모를 때"의 기댓값 차이를 재귀적으로 추적하는 방식이며, 랜덤포레스트나 XGBoost·LightGBM·CatBoost 같은 트리 앙상블에도 그대로 확장됩니다(각 트리의 SHAP 값을 더하면 되는데, 이는 섀플리 값의 가산성 성질 덕분입니다).

**지역 해석(Local Interpretation)**은 하나의 개별 샘플에 대해, 각 특징이 그 샘플의 예측값을 전체 평균(기준선)에서 얼마나 밀어 올리거나 내렸는지 계산합니다. "기준선에서 최종 예측까지 어떤 특징이 얼마나 밀고 당겼는지"를 누적으로 보여주므로, 특정 개별 사례를 왜 이렇게 예측했는지 설명할 수 있습니다. 개별 의사결정 설명(왜 이 대출은 거절됐는가), 이상 사례 디버깅(모델이 이상하게 예측한 샘플의 원인 추적) 등에 활용됩니다.

**전역 해석(Global Interpretation)**은 MDI·Permutation과 근본적으로 다른 방향에서 얻어집니다. MDI·Permutation은 처음부터 전역 지표로만 계산되어 개별 샘플 단위로 분해가 안 되지만, SHAP은 개별 샘플 단위의 지역 해석을 먼저 계산한 뒤 이를 모든 샘플에 대해 집계해서 전역 해석을 얻습니다. 즉 "전역은 지역의 평균"이라는 구조입니다. 모든 샘플에서 특징별 기여도 크기(절댓값)를 평균하면 카디널리티 편향 없는 특징 중요도 순위를 얻을 수 있고, 각 특징마다 모든 샘플의 SHAP 값을 점으로 흩뿌려 표시하면 "높은 값일 때 예측을 올리는지 내리는지"까지 한눈에 파악할 수 있으며, 특정 특징의 실제 값과 SHAP 값의 관계를 산점도로 그리면 특징과 예측 사이의 비선형 관계를 시각적으로 드러낼 수 있습니다.

MDI·Permutation은 전체적으로 어떤 특징이 중요한지는 알려주지만 특정 개별 사례를 설명할 수 없는 반면, TreeSHAP은 지역 해석이라는 더 세밀한 단위에서 출발해 일관된 수학적 원리로 전역 해석까지 자연스럽게 이어진다는 점이 가장 큰 강점입니다.

#### 11-1. RAG 품질 예측 모델의 SHAP 시각화 3종

검색된 문서와 질의의 유사도, 청크 개수, 컨텍스트 길이 등의 특징으로 RAG(검색 증강 생성) 답변 품질을 예측하는 트리 모델에 TreeSHAP을 적용하는 예시로 세 가지 시각화의 관계를 정리할 수 있습니다.

**Bar Plot**은 각 특징의 SHAP 값 절댓값을 평균해 막대그래프로 그린, 가장 압축된 전역 요약입니다. 방향성 정보는 없이(품질을 올리는지 내리는지는 안 보임) 어떤 특징이 중요한지만 빠르게 보여주며, 발표 자료나 경영진 보고처럼 핵심만 빠르게 전달할 때 사용합니다.

**Beeswarm Plot**은 각 특징마다 모든 샘플의 SHAP 값을 점으로 흩뿌리고, 점 색깔로 그 샘플의 실제 특징값 크기를 표시합니다. 예를 들어 검색 유사도가 높은 샘플(점)들이 SHAP 값이 양수인 쪽에 몰려 있다면, 검색 유사도가 높을수록 품질이 올라간다는 일관된 패턴을 확인할 수 있습니다. 순위뿐 아니라 방향성과 샘플별 분포까지 보여주므로, 모델이 왜 그렇게 작동하는지 도메인 지식과 대조해 검증하거나 특징 엔지니어링 아이디어를 얻을 때 유용합니다.

**Waterfall Plot**은 특정 샘플 하나에 대해, 기준선(평균 예측)에서 시작해 각 특징이 얼마씩 더하고 뺐는지를 누적으로 보여주어 최종 예측값에 도달하는 과정을 분해합니다. 예를 들어 검색 유사도는 높았지만 1위와 2위 검색 결과의 점수 차이가 작아 모델이 확신하지 못했고, 컨텍스트가 길어서 오히려 품질이 깎였다는 식의 개별 사례 스토리를 읽을 수 있습니다. 특정 응답이 이상하게 나쁘거나 좋을 때 원인을 진단하거나, 여러 실패 사례의 Waterfall을 모아 반복되는 주요 원인을 발견하는 데 사용합니다.

세 시각화는 "Bar(가장 압축된 요약, 뭐가 중요한가) → Beeswarm(전역 패턴과 방향성, 왜 어느 방향으로) → Waterfall(샘플 하나의 완전한 분해, 이 사례는 정확히 왜)"로 이어지는 확대 관계에 있습니다. Bar로 큰 그림을 파악하고, Beeswarm으로 방향성과 패턴을 검증한 뒤, Waterfall로 특정 실패·성공 사례를 진단하는 순서가 자연스럽습니다. 셋은 같은 SHAP 값을 압축의 정도만 달리해 바라보는 하나의 연속된 해석 도구입니다.


## 편향-분산과 규제

### 1. 편향, 분산, 과소적합, 과적합

> 참고 · 딥러닝 모델에서의 과적합 대응은 [딥러닝 · 52. Overfitting과 Underfitting](3-딥러닝.md#52-overfitting과-underfitting-mlp-학습-관점), [딥러닝 · 55. Early Stopping](3-딥러닝.md#55-early-stopping)

**편향(Bias)**은 모델이 너무 단순한 가정을 해서 실제 데이터의 패턴을 제대로 못 잡는 정도입니다. 편향이 높다는 것은 모델이 지나치게 단순하다는 뜻이며(예: 복잡한 곡선 데이터를 직선으로 예측), 이 경우 훈련 데이터조차 잘 맞추지 못합니다.

**분산(Variance)**은 모델이 훈련 데이터의 미세한 변화나 노이즈에 얼마나 민감하게 반응하는지입니다. 분산이 높다는 것은 모델이 훈련 데이터 하나하나에 너무 민감하다는 뜻이며, 훈련 데이터를 조금만 바꿔도 예측 결과가 크게 달라집니다. 이 경우 훈련 데이터는 완벽히 맞추지만 새로운 데이터에서는 성능이 확 떨어집니다.

**과소적합(Underfitting)**은 편향이 높을 때 발생하는 현상으로, 모델이 너무 단순해서 데이터의 패턴 자체를 학습하지 못해 훈련 성능도, 테스트 성능도 모두 나쁩니다(예: 비선형 데이터에 단순 선형회귀를 적용). 해결책은 모델 복잡도를 높이거나(특성 추가, 더 깊은 모델), 규제를 완화하거나, 학습을 더 오래 시키는 것입니다.

**과적합(Overfitting)**은 분산이 높을 때 발생하는 현상으로, 모델이 너무 복잡해서 훈련 데이터의 노이즈까지 외워버려 훈련 성능은 매우 좋지만 테스트 성능은 나쁩니다(예: 데이터 포인트가 적은데 매우 고차원의 다항식을 억지로 맞추는 경우). 해결책은 데이터를 늘리거나, 규제(L1, L2)를 적용하거나, 드롭아웃·조기종료를 쓰거나, 모델을 단순화하거나, 교차검증을 활용하는 것입니다.

**편향-분산 트레이드오프**: 편향과 분산은 보통 반비례 관계입니다. 모델 복잡도가 낮으면 편향은 높고 분산은 낮아(과소적합) 지고, 복잡도가 높으면 편향은 낮고 분산은 높아(과적합)집니다. 모델을 복잡하게 만들면 편향은 줄지만 분산이 커지고, 단순하게 만들면 분산은 줄지만 편향이 커집니다. 머신러닝 모델링의 목표는 이 둘의 합(총 오차)이 최소가 되는 적절한 지점을 찾는 것입니다.

### 2. 기대 예측오차의 세 가지 구성요소

모델의 기대 예측오차는 편향에서 비롯된 오차, 분산에서 비롯된 오차, 그리고 어떤 모델을 쓰든 절대 줄일 수 없는 데이터 자체의 본질적인 잡음, 이렇게 세 부분으로 나누어 이해할 수 있습니다.

- **편향 요소**: 여러 번 학습했을 때 평균 예측이 참값에서 얼마나 벗어나는가(모델의 표현력 부족)
- **분산 요소**: 훈련셋이 바뀔 때마다 예측이 얼마나 요동치는가(모델의 데이터 민감도)
- **본질적 잡음**: 어떤 모델을 쓰든 절대 줄일 수 없는, 데이터 자체가 가진 오차

과소적합은 편향 요소가 큰 상태, 과적합은 분산 요소가 큰 상태입니다. 총 기대오차를 줄이려면 편향과 분산 요소의 합을 최소화해야 하고, 이 둘은 보통 모델 복잡도에 대해 반대 방향으로 움직입니다.

### 3. 학습곡선(Learning Curve)

학습곡선은 가로축을 훈련 데이터 크기(또는 epoch), 세로축을 오차(손실)로 놓고, 훈련 오차 곡선과 검증 오차 곡선을 함께 그려서 봅니다. 이 곡선에서 세 가지 특징을 읽으면 편향·분산 문제를 진단할 수 있습니다.

- **높이(Height)**: 두 곡선이 결국 도달하는 절대적인 오차 수준. 훈련 오차의 최종 높이가 여전히 높다면, 모델이 훈련 데이터조차 잘 못 맞추는 것이므로 편향이 높다는 신호입니다. 두 곡선이 모두 높은 위치에서 평평하게 붙어 있으면 전형적인 과소적합 패턴입니다.
- **간격(Gap)**: 훈련 오차와 검증 오차 사이의 세로 거리. 간격이 크면 훈련 데이터에는 잘 맞지만 새 데이터에서는 성능이 뚝 떨어진다는 뜻이므로 분산이 높다는(과적합) 신호입니다. 간격이 작으면 분산 문제는 적다는 뜻이며, 이 경우 남은 문제는 높이(편향) 쪽을 봐야 합니다.
- **끝부분 기울기(End-tail Slope)**: 훈련 데이터 양을 계속 늘려갈 때, 곡선의 끝쪽이 아직 가파르게 움직이는지 이미 평평해졌는지를 봅니다. 검증 오차 곡선이 끝부분에서도 여전히 가파르게 감소 중이라면 아직 수렴하지 않은 것이라 데이터를 더 모으면 성능이 개선될 여지가 큽니다. 끝부분 기울기가 거의 평평하다면 이미 수렴해 포화 상태이므로, 데이터를 더 모아도 소용없고 모델 구조·특성·정규화를 바꿔야 합니다.

높이는 편향을, 간격은 분산을, 끝부분 기울기는 "지금 시점에서 데이터를 더 모으는 것이 실제로 효과가 있을지"를 알려주는 지표입니다. 데이터 수집은 비용이 크기 때문에, 끝기울기 확인은 자원 배분 관점에서 특히 중요합니다.

### 4. 검증곡선(Validation Curve)

검증곡선은 학습곡선과 짝을 이루는 진단 도구이지만 가로축이 다릅니다. 학습곡선의 가로축이 "훈련 데이터 크기"로 "데이터를 얼마나 더 모아야 하는가"를 진단한다면, 검증곡선의 가로축은 "모델의 하이퍼파라미터(복잡도)"로 "모델을 얼마나 복잡하게 해야 하는가"를 진단합니다.

훈련 오차는 모델이 복잡해질수록 거의 계속 감소하는 경향을 보입니다(더 복잡한 모델일수록 훈련 데이터를 더 잘 외울 수 있으므로). 반면 검증 오차는 처음엔 감소하다가 어느 지점을 지나면 다시 증가하는 U자형 곡선을 그립니다.

- **왼쪽(복잡도 낮음)**: 훈련 오차, 검증 오차 둘 다 높고 간격은 작음 → 과소적합(편향 문제)
- **중간(최적 지점)**: 검증 오차가 최소가 되는 지점 → 적절
- **오른쪽(복잡도 높음)**: 훈련 오차는 계속 낮아지지만 검증 오차는 다시 올라가 간격이 벌어짐 → 과적합(분산 문제)

검증곡선의 U자 바닥이 이론적으로 가장 좋은 복잡도이며, 현재 설정이 U자 곡선의 어느 쪽에 있는지 보고 왼쪽이면 복잡도를 올리고 오른쪽이면 낮추는 식으로 조정 방향을 정합니다.

검증곡선으로 먼저 "지금 모델이 너무 단순한지 복잡한지"를 파악해 적절한 복잡도를 고르고, 그다음 학습곡선으로 "이 복잡도에서 데이터를 더 모으면 도움이 되는지"를 확인하는 식으로 두 도구를 상호보완적으로 함께 씁니다. 즉 검증곡선은 "모델을 조정할지"를, 학습곡선은 "데이터를 더 모을지"를 결정하는 데 특화된 도구입니다.

### 5. Train/Validation 성능과 Train-Valid Gap, Fold

**Train 성능**은 모델이 학습에 직접 사용한 데이터에 대해 얼마나 잘 맞추는가를, **Validation 성능**은 학습에 쓰지 않은 데이터에 대해 얼마나 잘 맞추는가를 보여줍니다. Train 성능은 모델의 학습 능력을, Validation 성능은 모델의 일반화 능력을 나타내며, 실제로 관심 있는 것은 처음 보는 데이터에서의 성능이므로 Validation 성능이 실질적인 판단 기준이 됩니다.

**Train-Valid Gap**은 두 성능(또는 오차)의 차이로, 분산을 실제 데이터로 근사 측정한 값이라 볼 수 있습니다. Gap이 작고 둘 다 성능이 비슷하면 분산 문제는 적으며 Train 성능 자체가 낮으면 편향(과소적합) 문제, Gap이 크면(Train이 Valid보다 훨씬 좋으면) 분산이 큰 과적합, Gap이 거의 없고 둘 다 나쁘면 과소적합, Gap이 거의 없고 둘 다 좋으면 이상적인 상태입니다.

**Fold**는 데이터를 나눈 하나의 분할 단위입니다. 단순히 train/validation을 한 번만 나누면 그 나누는 방식(운)에 따라 성능 추정치가 우연히 좋거나 나쁘게 나올 수 있는데, 이 문제를 줄이기 위한 방법이 k-fold 교차검증입니다. 전체 데이터를 k개의 동일한 크기 조각으로 나눈 뒤, 매번 1개 fold를 validation으로, 나머지를 train으로 써서 학습·평가하는 과정을 k번 반복하고 이 k번의 결과를 평균 내어 최종 성능 추정치로 삼습니다. k 값이 클수록 각 fold의 train 크기가 커져 편향은 줄지만, fold 간 겹치는 데이터가 많아져 fold별 결과의 상관이 커지고 계산 비용도 커집니다. 극단적으로 fold 개수를 데이터 개수만큼 두면 LOOCV(Leave-One-Out CV)라 부르며, 분류 문제에서는 각 fold의 클래스 비율을 원본과 비슷하게 유지하는 방식(Stratified k-fold)을 많이 씁니다.

### 6. Train AP vs Validation AP

Train AP는 학습에 사용한 데이터에 대해 계산한 평균 정밀도(AP)이고, Validation AP는 학습에 쓰지 않은 held-out 데이터에 대해 계산한 값입니다. 둘의 차이(Gap)가 작고 둘 다 높으면 일반화가 잘 된 이상적인 상태, 작고 둘 다 낮으면 편향이 높은 과소적합(모델·특성·학습량 부족), Gap이 크면(Train이 Validation보다 훨씬 높으면) 분산이 큰 과적합(훈련 데이터의 패턴이나 노이즈를 외운 상태)입니다.

객체 탐지 문제에서 이 Gap이 크게 벌어지는 흔한 원인으로는 훈련 데이터 양이 적거나 특정 장면·객체 유형에 편중된 경우, 데이터 증강 부족, 데이터에 비해 과한 모델 용량, 정규화(가중치 감쇠, 드롭아웃 등) 부족이 있습니다.

### 7. 과적합·과소적합 대응 전략

문제를 고편향 후보인지 고분산 후보인지 진단한 뒤, 그에 맞는 처방을 적용하는 흐름입니다.

**고편향(High Bias) 후보**: Train 성능 자체가 낮고 Train-Valid gap은 작습니다. 학습곡선·검증곡선에서 "높이"가 높은 상태로, 모델이 훈련 데이터조차 잘 설명하지 못하는 과소적합입니다. 이는 모델이 데이터의 실제 패턴을 표현할 능력 자체가 부족한 상태로, 아무리 학습을 더 시켜도 "그릴 수 있는 함수의 형태"가 데이터의 진짜 구조보다 단순하기 때문에 한계가 있습니다. 대응 방향은 모델의 표현력을 키우는 쪽으로, 모델 복잡도를 높이거나(더 깊은 네트워크, 더 많은 트리), 특성을 추가하거나, 규제 강도를 오히려 낮추거나, 학습을 더 오래 시키는 것입니다.

**고분산(High Variance) 후보**: Train 성능은 좋은데 Validation 성능이 크게 떨어져 gap이 큽니다. 학습곡선에서 "간격"이 크고, 검증곡선의 복잡도 높은 쪽에 위치한 과적합입니다. 이는 모델이 데이터의 진짜 패턴뿐 아니라 훈련 데이터에만 있는 노이즈나 우연한 패턴까지 외워버린 상태로, 훈련셋이 조금만 바뀌어도 예측이 크게 달라집니다. 대응 방향은 모델을 제약하거나 데이터를 늘리는 쪽으로, 훈련 데이터를 추가하거나(가장 근본적인 해결책), 규제를 강화하거나, 조기 종료를 쓰거나, 모델을 단순화·드롭아웃·데이터 증강을 적용하거나, 앙상블(배깅 등)을 활용하는 것입니다.

**규제(Regularization)**는 모델이 훈련 데이터를 "너무 잘" 맞추지 못하도록 손실 함수에 페널티를 추가해, 파라미터가 과도하게 커지거나 복잡한 형태를 갖지 못하게 제약하는 기법입니다. 규제는 분산을 줄이는 대신 편향을 약간 늘리는 트레이드오프 조작이므로, 이미 고편향 상태인 모델에 규제를 더 걸면 오히려 상황이 악화됩니다.

**조기 종료(Early Stopping)**는 학습을 진행하면서 매 epoch마다 validation 성능을 함께 관찰하다가, validation 성능이 더 이상 좋아지지 않고 오히려 나빠지기 시작하는 시점에서 학습을 멈추는 기법입니다. 학습이 진행될수록 모델은 점점 더 복잡한 패턴(결국 노이즈까지)을 학습하게 되는데, 이는 암묵적으로 모델 복잡도를 늘리는 것과 같은 효과를 냅니다. 그래서 조기 종료는 사실상 "epoch 수를 규제 대상으로 삼는 규제 기법"이라 볼 수 있으며, 별도의 페널티 항 없이도 분산을 억제할 수 있는, 실무에서 가장 손쉽고 계산 비용이 적게 드는 과적합 방지 기법 중 하나입니다.

### 8. 규제: L1(Lasso), L2(Ridge), ElasticNet

규제는 모델의 손실 함수에 파라미터 크기에 대한 페널티 항을 추가해, 모델이 훈련 데이터를 지나치게 정교하게 맞추지 못하도록 제약하는 기법입니다.

직관적으로, 파라미터(가중치) 값이 클수록 모델이 입력의 작은 변화에도 출력을 크게 흔들 수 있습니다. 예를 들어 고차 다항식 회귀에서 과적합된 모델은 데이터 포인트 사이사이를 요동치며 지나가는데, 이때 계수들이 매우 큰 값을 갖게 됩니다. 이런 큰 계수들을 억제하면 곡선이 완만해지고, 훈련셋이 조금 바뀌어도 예측이 크게 흔들리지 않게 되어 분산이 줄어듭니다. 대신 데이터를 완벽히는 못 맞추게 되니 편향은 약간 늘어나는 트레이드오프가 생깁니다.

**L1(Lasso)**은 계수들의 절댓값 합에 페널티를 주어, 일부 계수를 정확히 0으로 만듭니다(성긴 해). 반복적인 최적화 방법으로 풀어야 하며, 결과적으로 중요하지 않은 특성의 계수를 0으로 만들어 사실상 모델에서 제거하는 자동 특성 선택 효과가 있습니다. 다만 상관관계가 높은 특성 그룹이 있으면 그중 하나만 남기고 나머지는 0으로 만드는 경향이 있어 선택이 불안정할 수 있습니다.

**L2(Ridge)**는 파라미터 제곱합에 페널티를 부여해, 모든 계수를 고르게 축소시키되 정확히 0으로 만들지는 않습니다. 계산이 닫힌 형태(공식으로 한 번에 계산 가능)로 존재해 수치적으로 안정적입니다. 상관관계가 높은 특성들이 있으면 그 계수들을 비슷한 크기로 나눠 분담시키는 경향이 있습니다.

**ElasticNet**은 L1과 L2를 가중 결합한 방식입니다. Lasso는 특성 수가 샘플 수보다 많은 고차원 상황에서 선택할 수 있는 계수 개수에 한계가 있고, 상관관계 높은 특성 그룹 중 하나만 임의로 선택해버리는 불안정성이 있습니다. ElasticNet은 L2 항을 섞어 상관관계 높은 특성들을 그룹으로 함께 선택(0으로 만들거나 살리거나)하면서도 L1의 성긴 해 효과는 유지해, 두 방식의 장점을 절충합니다.

정리하면, 계수 축소 방식은 Ridge가 고르게, Lasso가 일부를 0으로, ElasticNet이 그룹 단위로 절충합니다. 특성 선택 효과는 Ridge는 없고, Lasso는 자동으로 있으며, ElasticNet은 그룹 단위로 있습니다. 다중공선성(특성 간 강한 상관관계)에는 Ridge와 ElasticNet이 강건하고 Lasso는 불안정할 수 있습니다. 계산 방식은 Ridge만 공식으로 한 번에 풀리고, Lasso와 ElasticNet은 반복 최적화가 필요합니다.

특성이 다 유의미하고 다중공선성이 문제라면 Ridge를, 특성이 많고 그중 일부만 진짜 중요할 것 같으며 해석 가능한(단순한) 모델이 필요하다면 Lasso를, 특성 수가 샘플 수보다 많거나 상관관계 높은 특성 그룹이 있는데도 성긴 해가 필요하다면 ElasticNet을 선택합니다. 규제 강도는 앞서 설명한 검증곡선과 k-fold 교차검증으로 튜닝하는 것이 일반적입니다.

### 9. 하이퍼파라미터: 규제 강도와 L1·L2 배합 비율

**규제의 세기를 정하는 하이퍼파라미터**는 규제를 얼마나 강하게 걸지를 결정하며, Ridge·Lasso·ElasticNet 셋 다 공통으로 갖습니다. 이 값이 0이면 규제가 없는 것과 같아(원래 손실함수와 동일) 과적합 위험이 있고, 값이 커질수록 계수들이 점점 더 강하게 0쪽으로 눌려 과소적합 위험이 커집니다. 검증곡선의 가로축이 바로 이 값이며, 보통 로그 스케일(0.001, 0.01, 0.1, 1, 10 등)로 탐색합니다.

**L1과 L2의 배합 비율을 정하는 하이퍼파라미터**는 ElasticNet에서만 등장하며, 값이 1에 가까울수록 순수 Lasso(L1만)에, 0에 가까울수록 순수 Ridge(L2만)에 가까워지고, 중간값이면 둘을 절반씩 섞은 형태가 됩니다. Ridge나 Lasso를 단독으로 쓸 때는 애초에 섞을 것이 없으므로 이 배합 비율 자체가 필요 없습니다.

두 하이퍼파라미터의 의미를 비유하면, 규제 세기는 "브레이크를 얼마나 세게 밟을지"에 해당하고, 배합 비율은 "그 브레이크가 앞바퀴(L1)와 뒷바퀴(L2) 중 어느 쪽에 더 실릴지"를 정하는 것과 비슷합니다. 규제 세기는 Ridge·Lasso·ElasticNet 모두에 적용되고 보통 검증곡선(U자)에서 최소점을 탐색해 정하는 반면, 배합 비율은 ElasticNet에만 적용되고 보통 규제 세기와 함께 그리드 탐색으로 정합니다.

### 1. 클래스 불균형(Class Imbalance)

분류 문제에서 각 클래스(레이블)에 속하는 데이터 개수가 크게 차이 나는 상황을 말합니다. 예를 들어 사기 탐지 데이터에서 정상 거래가 대부분이고 사기 거래는 극소수(전체의 1% 수준)인 경우가 대표적입니다.

이런 상황에서는 모델이 무조건 다수 클래스(정상)로만 예측해도 정확도가 매우 높게 나올 수 있어, 정확도만으로는 모델 성능을 제대로 평가할 수 없습니다. 그래서 정밀도, 재현율, F1-score, AUC 같은 지표를 함께 봐야 합니다.

### 2. 혼동행렬(Confusion Matrix)의 4요소

이진 분류에서 "양성"(예: 사기, 질병 있음)을 기준으로 예측 결과를 네 가지로 나눕니다.

- **TP(True Positive)**: 실제로 양성인데 양성으로 맞게 예측한 경우 (예: 사기인데 사기로 잡음)
- **FP(False Positive)**: 실제로는 음성인데 양성으로 잘못 예측한 경우 (예: 정상인데 사기로 오탐)
- **FN(False Negative)**: 실제로 양성인데 음성으로 잘못 예측한 경우 (예: 사기인데 놓침)
- **TN(True Negative)**: 실제로 음성인데 음성으로 맞게 예측한 경우 (예: 정상을 정상으로 맞춤)

### 3. 양성률(Positive Rate)

문맥에 따라 두 가지로 쓰입니다.

- **실제 양성 비율(prevalence)**: 전체 데이터 중 실제로 양성 클래스인 데이터의 비율. 클래스 불균형이 심할수록 이 값은 매우 작아집니다.
- **예측 양성 비율**: 모델이 양성이라고 예측한 데이터의 비율.

여기서 파생되는 대표적인 지표들은 다음과 같습니다.

- **재현율(Recall)**: 실제 양성 중에서 모델이 얼마나 잘 잡아냈는지의 비율
- **정밀도(Precision)**: 양성이라고 예측한 것 중에서 실제로 양성이었던 것의 비율
- **위양성률(FPR)**: 실제 음성 중에서 모델이 잘못 양성으로 예측한 것의 비율

클래스 불균형 상황에서는 재현율·정밀도·F1을 정확도보다 우선해서 봐야, 모델이 소수 클래스(보통 더 중요한 클래스, 예: 사기·질병)를 얼마나 잘 잡아내는지 제대로 파악할 수 있습니다.

### 4. F1-score

정밀도와 재현율의 조화평균입니다. 산술평균 대신 조화평균을 쓰는 이유는, 정밀도와 재현율 중 어느 하나라도 낮으면 F1도 크게 낮아지도록 만들기 위해서입니다.

예를 들어 정밀도가 완벽한데 재현율이 0이라면(즉 양성을 하나도 못 잡아낸 쓸모없는 모델이라면), 산술평균으로는 꽤 괜찮은 점수가 나오지만 조화평균으로 계산한 F1은 0에 가깝게 나와 모델이 쓸모없다는 사실을 정확히 반영합니다. 즉 정밀도와 재현율 중 어느 한쪽만 극단적으로 잘해도 점수가 부풀려지지 않게 막아줍니다.

불균형 데이터에서는 정확도가 왜곡되기 쉽고, 정밀도와 재현율은 서로 트레이드오프 관계(하나를 올리면 다른 하나가 내려가는 경향)에 있는 경우가 많습니다. 임계값을 낮추면 양성 예측이 늘어나 재현율은 오르고 정밀도는 내려가며, 임계값을 높이면 반대 현상이 나타납니다. F1은 이 둘을 한 숫자로 균형 있게 요약해주기 때문에, 모델을 비교하거나 최적 임계값을 고를 때 자주 쓰입니다.

### 5. ROC-AUC와 AP(Average Precision)

둘 다 분류 임계값을 하나로 고정하지 않고, 임계값을 처음부터 끝까지 쭉 바꿔가면서 모델 성능을 종합적으로 평가하는 지표입니다.

**ROC-AUC**: 임계값을 바꿔가며 위양성률과 재현율(진짜 양성 비율)을 각각 좌표로 찍어 이은 곡선(ROC 곡선) 아래의 면적입니다. 완전히 무작위로 예측하는 수준부터 완벽하게 분류하는 수준까지의 사이 값을 가지며, 직관적으로는 "무작위로 양성 샘플 하나와 음성 샘플 하나를 뽑았을 때, 모델이 양성 샘플에 더 높은 점수를 줄 확률"로 해석할 수 있습니다.

위양성률의 분모는 실제 음성 샘플 전체의 개수입니다. 음성이 압도적으로 많은 불균형 데이터에서는, 오탐(FP)이 꽤 늘어나도 분모가 워낙 커서 위양성률 자체는 거의 변하지 않습니다. 그 결과 ROC-AUC가 실제보다 낙관적으로 좋게 나오는 경향이 있다는 함정이 있습니다.

**AP(Average Precision)**: 임계값을 바꿔가며 재현율과 정밀도를 좌표로 찍어 이은 곡선(PR 곡선) 아래의 면적입니다. 정밀도의 분모는 모델이 양성이라고 예측한 것들의 개수입니다. 음성이 아무리 많아도 오탐이 조금만 늘어도 이 분모 대비 비중이 크게 잡혀 정밀도가 민감하게 반응하므로, 소수 클래스(양성)를 잘 맞추는지를 훨씬 엄격하게 반영합니다.

정리하면, ROC-AUC는 분모에 다수 클래스(TN)가 포함되어 클래스 불균형 시 과대평가되기 쉬운 반면, AP는 다수 클래스가 분모에 포함되지 않아 더 현실적인 평가를 제공합니다. 그래서 클래스가 비교적 균형 잡힌 경우에는 ROC-AUC가, 사기 탐지·질병 진단처럼 불균형이 심하고 소수 클래스가 중요한 경우에는 AP가 더 적합합니다.

### 6. 임계값(Threshold)

대부분의 분류 모델은 "양성이다/음성이다"를 직접 뱉지 않고, "이 샘플이 양성일 확률(또는 점수)"을 연속적인 숫자로 출력합니다. 이 연속적인 확률값을 양성과 음성이라는 이산적인 클래스로 변환하기 위해 기준선을 긋는데, 그 기준값이 임계값입니다. 확률이 임계값 이상이면 양성으로, 미만이면 음성으로 분류합니다.

같은 모델, 같은 확률 출력이라도 임계값을 어디에 긋느냐에 따라 TP·FP·FN·TN이 전부 달라집니다. 임계값을 낮추면 더 많은 샘플이 양성으로 분류되어 놓치는 경우(FN)는 줄지만 오탐(FP)은 늘어나 재현율이 오르고 정밀도는 내려갑니다. 반대로 임계값을 높이면 확실한 것만 양성으로 분류해 오탐은 줄지만 애매한 것을 놓쳐(FN 증가) 정밀도가 오르고 재현율은 내려갑니다.

임계값을 극단에서 반대쪽 극단까지 미끄러뜨리면서, 그때마다 계산되는 위양성률·재현율 쌍 또는 재현율·정밀도 쌍을 좌표에 이어 그린 것이 각각 ROC 곡선, PR 곡선입니다. 즉 이 곡선들은 특정 임계값 하나를 정하지 않고 모든 임계값에서의 성능을 한번에 보여주므로, 임계값 선택과 무관하게 모델 자체의 판별력을 비교할 수 있게 해줍니다.

### 7. SMOTE (Synthetic Minority Over-sampling Technique)

클래스 불균형 문제를 데이터 단계에서 완화하는 대표적인 오버샘플링 기법입니다. 소수 클래스의 샘플 수를 인위적으로 늘려 다수 클래스와 비율을 맞춰줍니다.

가장 단순한 오버샘플링 방법인 단순 복제는 소수 클래스 샘플을 그냥 복사해서 늘리는 것인데, 이 경우 완전히 똑같은 데이터가 여러 번 등장해 모델이 과적합되기 쉽고 새로운 정보는 전혀 추가되지 않는다는 문제가 있습니다.

SMOTE는 단순 복제 대신, 기존 소수 클래스 샘플들 사이를 보간해 새로운 합성 샘플을 만듭니다. 소수 클래스 샘플 하나를 고르고, 그 샘플과 가까운 이웃 중 같은 소수 클래스인 샘플 하나를 무작위로 골라, 두 샘플을 잇는 선분 위의 임의의 한 점을 새로운 합성 샘플로 생성합니다. 이 과정을 원하는 비율이 될 때까지 반복합니다. 이렇게 하면 단순 복제보다 훨씬 다양성 있는 소수 클래스 데이터를 만들 수 있어 과적합을 완화하고, 모델이 소수 클래스의 결정 경계를 더 폭넓게 학습하도록 돕습니다.

다만 다음과 같은 주의사항이 있습니다.

- 소수 클래스 샘플 중 이상치이거나 다수 클래스 영역에 섞여 있는 샘플 사이를 보간하면, 오히려 다수 클래스 영역에 잘못된 소수 클래스 합성 샘플이 생길 수 있습니다.
- 고차원 데이터에서는 이웃 기반 보간이 덜 의미 있어질 수 있습니다(차원의 저주).
- 반드시 학습(train) 데이터에만 적용해야 합니다. 검증·테스트 데이터에 SMOTE를 적용하면 합성 샘플의 정보가 원본 샘플에서 새어 나가 성능이 부풀려집니다.
- 교차검증을 쓸 때도, fold를 나눈 뒤 학습 fold 안에서만 SMOTE를 적용해야 합니다.

대안으로는 다수 클래스를 줄이는 언더샘플링(정보 손실 위험이 있음)이나, 데이터를 건드리지 않고 손실함수에서 소수 클래스에 더 큰 가중치를 주는 클래스 가중치 조정(SMOTE와 함께 쓰기도 함)이 있습니다.

### 8. 봉인 테스트(Sealed Test) 원칙

머신러닝 모델 개발 시, 테스트 데이터를 마지막 최종 평가 전까지 절대 들여다보지도, 사용하지도 않고 봉인해서 따로 떼어놓는다는 원칙입니다. 데이터 유출을 막기 위한 핵심 원칙 중 하나입니다.

모델 개발 과정은 보통 전처리, 학습, 성능 확인, 하이퍼파라미터 조정, 다시 학습이라는 반복 루프를 거칩니다. 이 반복 루프에서 테스트 데이터로 성능을 확인하면서 조정을 하면, 개발자가 의식하지 못하는 사이에 모델(또는 개발자의 선택)이 테스트 데이터에 맞춰지게 됩니다. 이러면 테스트 데이터는 더 이상 "한 번도 못 본 데이터"가 아니게 되어, 실제 운영 환경(진짜 처음 보는 데이터)에서는 성능이 뚝 떨어지는 낙관적 편향이 생깁니다.

데이터는 학습 데이터(모델 파라미터를 직접 학습), 검증 데이터(하이퍼파라미터 튜닝·모델 선택·조기 종료 판단에 사용), 테스트 데이터(오직 마지막에 딱 한 번만 최종 성능 확인)로 나누어, 학습·검증 데이터는 개발 중 자유롭고 반복적으로 쓰지만 테스트 데이터는 튜닝이 전부 끝나고 모델이 확정된 뒤 정말 마지막에 딱 한 번만 열어봅니다.

실무에서 흔히 이 원칙이 깨지는 경우로는 다음이 있습니다.

- 테스트 성능을 보고 하이퍼파라미터를 다시 조정하는 경우 (사실상 테스트가 검증처럼 쓰여 봉인이 깨짐)
- 정규화, 결측치 대체, SMOTE 같은 전처리를 전체 데이터에 먼저 적용한 뒤 학습/테스트로 분할하는 경우 (테스트의 통계 정보가 학습 과정에 스며듦)
- 특성 선택을 전체 데이터로 한 뒤 분할하는 경우 (마찬가지로 정보 유출)
- 여러 모델을 테스트 데이터로 비교해서 그중 제일 좋은 것을 최종 선택하는 경우 (테스트가 모델 선택 기준으로 쓰인 것이므로 봉인 위반)
- 교차검증을 쓸 때도 fold 분할 전에 전처리·오버샘플링을 하는 경우
- 시계열 데이터를 무작위로 분할하는 경우 (미래 데이터가 학습에 섞여 들어가 미래 정보를 미리 학습하는 시간 유출)

### 9. 배포 후 새로 만날 "단위" 기준으로 분할하기

봉인 테스트 원칙의 핵심은 "테스트 데이터가 진짜 처음 보는 데이터여야 한다"는 것이지만, "처음 보는 데이터"가 정확히 무엇을 의미하는지는 문제마다 다릅니다. 이를 정하는 것이 바로 데이터를 나누는 단위를 선택하는 문제입니다. 핵심 질문은 "모델을 배포하고 나면, 실제 운영 환경에서는 어떤 새로운 것을 만나게 되는가?"입니다.

- **행(row) 단위로 무작위 분할하는 것은 흔히 저지르는 실수**입니다. 예를 들어 사용자별 거래 로그를 거래 건별로 무작위 분할하면, 같은 사용자의 데이터가 학습과 테스트 양쪽에 다 들어가게 됩니다. 그런데 배포 후 실제로 만나는 상황은 대개 "한 번도 본 적 없는 새로운 사용자"이므로, 이렇게 분할하면 신규 사용자에 대한 실제 성능보다 낙관적으로 평가됩니다.
- **올바른 단위는 사용자(그룹) 단위 분할**입니다. 일부 사용자 전체를 학습에, 나머지 사용자 전체를 테스트에 배정해, 테스트에 포함된 사용자는 학습에서 단 한 건도 등장하지 않도록 합니다.
- **배포 후 만나는 새로움이 미래 시점의 데이터라면(대부분의 실무 상황이 그렇습니다), 시간순 분할**이 맞습니다. 과거 데이터를 학습에, 미래 데이터를 테스트에 배정해야 하며, 무작위로 섞어서 분할하면 미래 데이터가 학습에 섞여 들어가 미래 정보를 미리 학습하는 문제가 생깁니다.
- 신약 효과를 새로운 환자에게 적용할 모델이라면 환자 단위로, 특정 병원에서 학습해 다른 병원에 배포할 모델이라면 병원 단위로 분할해야 합니다.

정리하면, 완전히 새로운 사용자·고객·환자·기기를 만나는 경우는 그룹 단위 분할이, 미래 시점의 데이터를 만나는 경우는 시간 단위 분할이, 새로운 지역·매장·기관을 만나는 경우는 해당 단위의 그룹 분할이, 정말로 독립적인 개별 관측치를 만나는 경우는 단순 무작위 분할도 무방합니다. "테스트 데이터를 어떤 단위로 나눌지"는 통계적 선택이 아니라 "배포 후 모델이 실제로 마주칠 새로움이 무엇인가"에 대한 답이어야 하며, 이 매칭이 틀리면 테스트 성능이 아무리 좋아도 실제 운영에서는 재현되지 않습니다.

### 10. 교차검증 분할 방식 4종 비교

모두 데이터를 여러 개의 조각(fold)으로 나눠서 번갈아가며 학습/검증으로 쓰는 k-fold 교차검증의 변형입니다.

**기본형(KFold)**: 데이터를 순서대로(또는 무작위로 섞은 뒤) 여러 등분으로 나눠, 매 라운드마다 한 조각을 검증으로, 나머지를 학습으로 사용합니다. 클래스 비율이나 그룹을 전혀 고려하지 않으므로, 불균형 데이터라면 어떤 조각에는 소수 클래스가 거의 없을 수 있고, 같은 사용자의 데이터가 학습·검증에 섞여 들어갈 수 있는 leakage 위험이 있습니다.

**클래스 비율 유지형(StratifiedKFold)**: 각 조각을 나눌 때 클래스 비율이 원본 데이터와 동일하게 유지되도록 층화해서 분할합니다. 불균형 데이터에서는 사실상 필수적인데, 그렇지 않으면 특정 조각에 소수 클래스가 거의 안 들어가 그 조각의 평가가 불안정하거나 왜곡될 수 있기 때문입니다.

**그룹 단위 분리형(GroupKFold)**: 같은 그룹(예: 같은 사용자, 같은 환자)의 데이터가 학습과 검증에 절대 동시에 들어가지 않도록 그룹 단위로 조각을 나눕니다. "배포 후 새로운 사용자를 만난다"는 상황을 재현하는 방식입니다. 클래스 비율은 신경 쓰지 않고 오직 그룹이 겹치지 않는 것만 보장하므로, 그룹별 클래스 비율이 원래 들쭉날쭉하다면 조각을 나누는 과정에서 어떤 조각은 양성 비율이 확 낮아지거나 높아질 수 있다는 한계가 있습니다.

**그룹+클래스 결합형(StratifiedGroupKFold)**: 그룹은 겹치지 않게 분리하면서 동시에 각 조각의 클래스 비율도 최대한 원본과 비슷하게 유지하려고 시도하는 방식으로, 그룹 단위 분리와 클래스 균형을 동시에 만족시키려는 절충안입니다. 완벽하게 둘 다 만족시키긴 어렵기 때문에 최대한 비슷하게 맞추는 근사적인 방법을 씁니다. 사용자 단위로 그룹핑해야 하고 동시에 클래스 비율이 매우 불균형한 경우(예: 사기 탐지)에 가장 이상적입니다.

### 11. TimeSeriesSplit

시계열 데이터는 무작위 셔플 기반의 k-fold류 분할을 쓰면 안 됩니다. 미래 데이터가 학습에 섞여 들어가 모델이 미래 정보를 미리 보고 학습하는 시간 유출이 발생하기 때문입니다. TimeSeriesSplit은 항상 과거로 학습하고 미래로 검증하도록 설계된 분할 방식입니다.

데이터를 시간 순서대로 여러 등분한 뒤, 매 라운드마다 학습 구간이 점점 확장되면서 그 바로 다음 구간을 검증으로 씁니다. 즉 학습 구간은 항상 검증 구간보다 과거 시점이고, 라운드가 진행될수록 학습 데이터 양이 누적되며 늘어나, 실제 운영에서 시간이 지나며 데이터가 쌓이는 상황과 동일한 구조를 만듭니다.

주요 설정으로는 몇 라운드로 나눌지, 학습 구간이 무한정 커지지 않도록 최대 크기를 제한할지(오래된 데이터가 최신 패턴과 안 맞을 때 유용한 방식), 각 검증 구간의 크기를 얼마로 고정할지, 그리고 학습 구간의 끝과 검증 구간의 시작 사이에 공백을 둘지가 있습니다. 이 공백은 예측 시점과 실제 라벨이 확정되는 시점 사이에 지연이 있는 경우(예: "30일 후 이탈 여부"라는 라벨은 30일이 지나야 확정됨) 정보 유출을 막기 위해 사용합니다.

학습 구간을 계속 누적해서 키우는 방식(전체 데이터를 최대한 다 활용)과, 항상 일정 크기의 최근 구간만 학습에 사용하는 방식(오래된 패턴이 최신 트렌드와 다를 때 더 현실적) 중에서 선택할 수 있습니다.

시계열 데이터에서 검증 구간을 딱 한 구간만 떼어 평가하면 그 시기(계절성, 이벤트 등)의 특성에 운 좋게 또는 나쁘게 걸릴 수 있어 평가가 불안정한데, 여러 시점에서 반복 검증함으로써 모델이 다양한 시간대에 걸쳐 일관되게 잘 작동하는지 확인할 수 있습니다.

주의할 점으로는, 최종 테스트 구간(봉인 구간)은 별도로 가장 마지막 시점을 떼어놓고 그 이전 구간 안에서만 TimeSeriesSplit을 하이퍼파라미터 튜닝용 검증으로 사용해야 한다는 것, 전처리 통계량도 각 조각의 학습 구간 안에서만 계산해야 한다는 것, 그룹(예: 여러 매장의 시계열)과 시간이 동시에 존재하는 데이터라면 기본 TimeSeriesSplit만으로는 부족해 그룹별로 따로 시간 분할을 적용하거나 커스텀 로직이 필요할 수 있다는 것이 있습니다.

### 12. 데이터 유출(Leakage)의 다섯 가지 유형

지금까지 설명한 봉인 테스트, 분할 방식, SMOTE 관련 주의사항들은 사실 모두 데이터 유출이라는 하나의 큰 개념의 서로 다른 측면입니다.

**분할 누수(Split Leakage)**: 어떤 단위로 학습·테스트를 나눠야 하는지를 잘못 정해서, 같은 정보가 양쪽에 동시에 들어가는 경우입니다. 같은 사용자의 거래가 학습·테스트에 흩어져 들어가거나, 미래 데이터가 학습에 섞여 들어가는 경우가 해당합니다. 배포 후 마주칠 새로움의 단위에 맞춰 그룹 분할이나 시간 분할을 사용해 해결합니다.

**전처리 누수(Preprocessing Leakage)**: 정규화, 결측치 대체, 특성 선택 같은 전처리의 통계량을 학습·테스트 분할 전에 전체 데이터로 계산해서, 테스트 데이터의 정보가 학습 과정에 스며드는 경우입니다. 전처리 파라미터는 학습 데이터로만 계산(fit)하고, 테스트 데이터에는 그 파라미터를 적용(transform)만 해야 합니다. 교차검증을 쓸 때도 각 조각의 학습 구간 안에서만 계산해야 합니다.

**Target·미래 누수(Target/Future Leakage)**: 예측 시점에는 아직 알 수 없어야 할 정보(미래 정보 또는 예측 대상과 인과적으로 얽힌 정보)가 입력 특성으로 들어가는 경우입니다. 가장 치명적이고 발견하기 어려운 누수 유형입니다. 예를 들어 "환자 퇴원 여부"를 예측하는데 "퇴원 후 처방된 약" 정보가 특성에 포함되어 있다면 사실상 정답이 특성에 숨어 있는 것이고, 라벨이 확정되는 시점 이전 특성에 그 이후 발생한 이벤트 정보가 섞여 들어가는 경우, 집계 특성(예: 고객의 평균 구매액)을 만들 때 미래 시점의 구매 데이터까지 포함해 계산하는 경우도 이에 해당합니다. 해결책은 "이 특성이 실제 예측 시점에 정말로 확보 가능한 정보인가"를 특성 하나하나 검증하는 것입니다.

**리샘플링 누수(Resampling Leakage)**: 오버샘플링·언더샘플링을 학습·테스트 분할 전(또는 교차검증의 조각 분할 전)에 전체 데이터에 적용하는 경우입니다. SMOTE가 테스트 샘플을 참고해 만든 합성 데이터가 학습에 들어갈 수 있고, 테스트 안에도 인위적으로 생성된 샘플이 섞여 평가 자체가 왜곡됩니다. 테스트 데이터는 실제 운영에서 만나는 원본 분포(불균형)를 그대로 반영해야 하므로 리샘플링해서는 안 되며, 리샘플링은 반드시 학습 데이터에만 적용해야 합니다.

**선택 누수(Selection Leakage)**: 모델·하이퍼파라미터·특성을 "선택"하는 과정에서 테스트 성능을 참고하는 경우입니다. 여러 모델을 학습시킨 뒤 테스트 점수를 보고 그중 제일 좋은 것을 최종 채택하면 테스트가 사실상 모델 선택 기준(검증)으로 쓰인 것이고, 특성 선택을 전체 데이터 기준으로 하고 나서 분할하는 것도 일종의 선택 누수입니다. 모델 선택·하이퍼파라미터 튜닝·특성 선택은 전부 검증 데이터(또는 교차검증)로만 하고, 테스트 데이터는 정말 마지막에 확정된 파이프라인 전체를 딱 한 번 통과시켜 성능만 확인해야 합니다.

**올바른 파이프라인 순서**를 정리하면, 전체 데이터를 배포 후 만날 단위에 맞는 방식으로 분할해 학습·테스트를 봉인한 뒤, 학습 데이터 안에서 전처리 통계량을 계산하고(테스트에는 적용만), 리샘플링도 학습에만 적용하며, 특성 선택과 하이퍼파라미터 튜닝은 교차검증·검증 데이터로만 수행하고, 마지막으로 확정된 모델을 봉인된 테스트에 딱 한 번 적용해 최종 성능을 확인합니다.

다섯 유형 모두 본질은 하나입니다. "모델이 실제 운영에서는 절대 접근할 수 없는 정보를, 개발 과정 어딘가에서 몰래 참고했는가?"라는 질문을 파이프라인의 매 단계(분할, 전처리, 특성, 리샘플링, 모델 선택)마다 던져보는 것이 누수를 막는 가장 확실한 방법입니다.

### 13. scikit-learn Pipeline과 누수 방지

앞서 정리한 다섯 가지 누수 중 상당수는 개발자가 매번 "전처리는 학습 데이터에만 적용해야지"라고 스스로 기억해야 하는 수동 규칙이었습니다. Pipeline은 이걸 사람이 기억하지 않아도 구조적으로 강제해주는 도구입니다.

**Pipeline이란**: 여러 변환 단계와 마지막 모델을 하나의 객체로 묶어서, 학습을 호출하면 내부적으로 각 단계를 순서대로 실행해주는 sklearn 도구입니다.

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('clf', LogisticRegression())
])

pipe.fit(X_train, y_train)      # scaler.fit_transform(X_train) → clf.fit(...)
pipe.predict(X_test)            # scaler.transform(X_test) → clf.predict(...)  ← fit 아님, transform만!
```

핵심은 학습을 호출하면 내부의 모든 변환 단계가 오직 그 호출에 넘긴 데이터에만 맞춰지고(fit), 이후 예측이나 변환을 호출할 때는 그 맞춰진 규칙을 적용만(transform) 할 뿐 다시 맞춰지지 않는다는 것입니다.

**Pipeline이 구조적으로 막아주는 누수**

- **전처리 누수**: Pipeline을 교차검증에 통째로 넣으면, 각 조각마다 전처리 단계가 그 조각의 학습 부분에만 맞춰지고 검증 부분은 적용만 됩니다. Pipeline 없이 수동으로 하면 흔히 "전체 데이터에 전처리를 먼저 맞추고 교차검증을 시작"하는 실수를 저지르기 쉬운데, Pipeline은 이를 원천적으로 막아줍니다.
- **리샘플링 누수**: imblearn 라이브러리가 제공하는 SMOTE 대응 Pipeline을 쓰면, SMOTE도 매 조각의 학습 부분에만 적용되고 검증·테스트에는 적용되지 않습니다.

- **선택 누수(부분적으로)**: 하이퍼파라미터 탐색 도구에 Pipeline을 통째로 넣으면, 탐색 중인 각 후보 조합이 내부 교차검증의 학습 조각으로만 학습되고 검증 조각으로 평가됩니다. 최종적으로 봉인된 테스트 데이터에는 손도 안 대게 코드를 짤 수 있어, 튜닝 중에 실수로 테스트를 참고하는 실수를 줄여줍니다.

**Pipeline이 자동으로 못 잡는 누수**: Pipeline은 "학습이 학습 데이터에만 적용되는가"라는 기계적인 순서 문제만 해결해줄 뿐, 그 이상의 논리적·의미적 문제는 전혀 못 잡습니다.

- **Target·미래 누수**: 특성 자체에 이미 미래 정보나 정답 정보가 숨어 들어가 있으면, Pipeline이 아무리 정직하게 fit·transform을 나눠도 소용이 없습니다. 이는 도메인 지식으로 특성 하나하나를 검토해야만 발견할 수 있습니다.
- **분할 누수(단위 선택 오류)**: Pipeline은 교차검증의 각 조각이 어떻게 나뉘는지는 관여하지 않고, 분할 방식이 넘겨준 조각을 그대로 신뢰합니다. 잘못된 분할 방식을 골라 같은 사용자가 학습·검증에 섞여도 Pipeline 입장에서는 정상적인 두 개의 다른 데이터셋으로만 보입니다. 분할 방식 선택은 사람이 "배포 후 무엇을 새로 만나는가"를 판단해서 골라야 하는 영역입니다.
- **외부에서 만든 특성의 누수**: 별도의 데이터베이스 조인이나 배치 작업 등 Pipeline 바깥에서 미리 만들어진 특성 테이블에 이미 누수가 있다면, Pipeline이 그 데이터를 받은 시점엔 이미 늦습니다.
- **라벨 자체의 정의 오류**: 예측 대상(y)을 정의하는 로직 자체가 미래 시점 정보를 써서 만들어졌다면, 이는 Pipeline이 다루는 입력 변환과는 완전히 별개의 문제라 감지할 수 없습니다.

정리하면, Pipeline은 전처리 누수·리샘플링 누수·부분적인 선택 누수는 구조적으로 막아주지만, 분할 누수·target/미래 누수·외부 특성 테이블의 누수는 여전히 사람이 직접 판단하고 검증해야 합니다. Pipeline은 "fit은 학습 데이터에만, transform은 항상"이라는 기계적 규율을 강제해서 절차적 누수를 없애주지만, "이 특성이나 라벨이 애초에 의미상 미래 정보를 담고 있는가"라는 질문에는 답해주지 않습니다.

### 14. 하이퍼파라미터 탐색: GridSearchCV와 RandomizedSearchCV

봉인 테스트 원칙(8절)에 따르면 하이퍼파라미터 튜닝은 검증 데이터(또는 교차검증)로만 해야 합니다. GridSearchCV와 RandomizedSearchCV는 이 튜닝 과정을 교차검증과 결합해 자동화해주는 도구입니다.

**GridSearchCV**는 지정한 하이퍼파라미터 후보값들의 모든 조합을 하나씩 다 시도하고, 각 조합마다 교차검증으로 성능을 평가해 가장 좋은 조합을 고릅니다. 후보 범위 안에서는 최적해를 놓치지 않는다는 장점이 있지만, 조합 수가 파라미터 개수와 값 범위에 따라 폭발적으로 늘어나 느려집니다.

**RandomizedSearchCV**는 전체 조합을 다 보지 않고, 지정한 분포나 범위에서 무작위로 정해진 횟수(`n_iter`)만큼만 샘플링해서 시도합니다. 연속형 분포를 지정할 수 있어 탐색 공간이 그리드보다 유연하고, 시도 횟수를 직접 제어할 수 있어 파라미터가 많거나 범위가 넓을 때 유리합니다. 다만 운이 나쁘면 최적 조합을 못 찾을 수 있다는 확률적 한계가 있습니다.

실무에서는 먼저 RandomizedSearchCV로 대략적인 좋은 영역을 찾은 뒤, 그 근처 범위로 GridSearchCV를 좁혀 정밀 탐색하는 2단계 방식이 흔히 쓰입니다. 두 도구 모두 13절의 Pipeline을 그대로 받을 수 있어서, 전처리·리샘플링까지 포함한 파이프라인 전체를 한 번에 튜닝하면서도 각 후보 조합의 평가가 교차검증의 학습 조각에서만 이루어지도록 구조적으로 보장됩니다.


### 15. ColumnTransformer: 컬럼별 전처리 결합

실제 데이터는 수치형과 범주형 컬럼이 섞여 있는 경우가 대부분인데, 수치형엔 스케일링을, 범주형엔 인코딩을 적용해야 합니다. ColumnTransformer는 지정한 컬럼 그룹마다 서로 다른 변환기를 적용하고, 그 결과를 가로로 이어붙여 하나의 행렬로 합쳐주는 도구입니다.

지정하지 않은 컬럼은 기본적으로 결과에서 빠지며(`remainder='passthrough'`로 유지 가능), 각 튜플은 (이름, 변환기, 적용할 컬럼목록) 형태입니다. 13절의 Pipeline과 결합하면 "컬럼별 전처리 → 리샘플링 → 모델"이 하나의 객체로 묶이고, 이 전체가 14절의 GridSearchCV·RandomizedSearchCV에도 그대로 들어갈 수 있습니다.

### 16. 다양한 Sampler: 오버샘플링·언더샘플링·결합

7절에서 다룬 SMOTE 외에도 imbalanced-learn 라이브러리는 여러 종류의 sampler를 제공합니다. 모두 리샘플링 누수를 피하려면 13절의 imblearn Pipeline 안에서, 학습 데이터에만 적용해야 한다는 원칙은 동일합니다.

**오버샘플링(소수 클래스를 늘림)**
- `RandomOverSampler`: 소수 클래스 샘플을 단순 복제. SMOTE보다 다양성이 떨어져 과적합 위험이 큼
- `SMOTE`: 소수 클래스 샘플 사이를 보간해 합성 샘플 생성 (7절 참고)
- `ADASYN`: SMOTE와 비슷하지만, 분류가 어려운(결정 경계에 가까운) 소수 샘플 주변에 더 많이 생성해 어려운 영역을 집중적으로 보강
- `BorderlineSMOTE`: 결정 경계 근처의 소수 샘플 위주로만 보간

**언더샘플링(다수 클래스를 줄임)**
- `RandomUnderSampler`: 다수 클래스 샘플을 무작위로 제거. 데이터가 줄어 학습은 빨라지지만 다수 클래스의 유용한 정보를 버릴 위험이 있음
- `TomekLinks`: 서로 다른 클래스인데 가장 가까운 이웃 쌍(경계에 애매하게 걸친 샘플)을 제거해 결정 경계를 명확히 함
- `EditedNearestNeighbours(ENN)`: 이웃 대부분이 다른 클래스인 샘플을 제거하는 노이즈 제거 방식
- `NearMiss`: 소수 클래스와 가까운 다수 클래스 샘플만 선택적으로 남김

**결합(오버+언더)**
- `SMOTEENN`: SMOTE로 늘린 뒤 ENN으로 노이즈성 샘플 정리
- `SMOTETomek`: SMOTE로 늘린 뒤 TomekLinks로 경계 정리

노이즈가 많은 데이터에서 SMOTE만 쓰면 합성 샘플이 오히려 경계를 흐릴 수 있는데, 언더샘플링을 뒤에 붙여 정리하는 결합 방식이 이를 보완합니다. `sampling_strategy` 파라미터로 목표 비율을 조정할 수 있고(`'auto'`는 소수=다수가 되도록, 숫자를 주면 그 비율로), 어떤 sampler가 최선인지는 데이터마다 달라 14절의 GridSearchCV·RandomizedSearchCV로 sampler 종류와 파라미터까지 함께 튜닝하기도 합니다.

### 17. 학습된 파이프라인의 저장과 재현성 검증

> 참고 · 딥러닝 체크포인트는 [딥러닝 · 48. state_dict와 checkpoint](3-딥러닝.md#48-state_dict와-checkpoint) · Hugging Face 모델은 [LLM · 12. 저장·재로드와 재현성 메타데이터](4-LLM.md#12-저장재로드와-재현성-메타데이터)

모델 개발의 마지막 단계는 확정된 파이프라인을 실제로 배포 가능한 형태로 저장하고, 저장·로드 과정에서 예측 결과가 달라지지 않는지 확인하는 것입니다.

**최종 성능 확인**: 8절의 봉인 테스트 원칙에 따라, 튜닝이 전부 끝난 뒤 마지막에 딱 한 번 봉인된 test set으로 성능을 확인합니다. 불균형 데이터에서는 5절에서 다룬 AP(Average Precision)를 최종 지표로 흔히 씁니다.

**새 요청 예측**: `best_model`은 15절의 ColumnTransformer 전처리, 16절의 sampler, classifier가 하나로 합쳐진 파이프라인 전체이므로, 원본 raw 데이터를 그대로 넣으면 내부에서 전처리 → classifier 순으로 자동 처리됩니다. sampler는 학습(`fit`) 시에만 작동하고 예측(`predict`) 시에는 적용되지 않으므로, 예측 결과가 인위적으로 왜곡되지 않습니다.

**저장과 재로드**: `joblib`으로 파이프라인 객체 전체(학습된 파라미터 포함)를 파일로 저장해두면, 나중에 재학습 없이 그대로 불러와 재사용할 수 있습니다.

**동일성 검증**: 저장 전 예측값과 reload 후 예측값이 정확히 같은지 비교해, 직렬화 과정에서 아무것도 깨지지 않았음을 확인합니다. 이 검증을 통과해야 학습 시 확인한 AP 점수와 예측 결과가 실제 배포 환경에서도 그대로 재현된다는 것이 보장됩니다.

### 18. TPE (Tree-structured Parzen Estimator)

Optuna가 기본으로 쓰는 하이퍼파라미터 탐색 알고리즘입니다. 14절의 GridSearchCV·RandomizedSearchCV는 둘 다 "지금까지의 결과를 전혀 참고하지 않고" 후보를 고릅니다(그리드는 정해진 모든 조합을, 랜덤은 무작위로). 그래서 이미 성능이 안 좋았던 영역 근처를 계속 낭비적으로 탐색할 수 있습니다. TPE는 반대로 "지금까지 좋았던 시도들은 어떤 패턴이었는가"를 학습해서, 다음 후보를 그 패턴에 가깝게 뽑는 베이지안 최적화 계열 방법입니다.

**핵심 아이디어**: 일반적인 베이지안 최적화(Gaussian Process 기반)는 "하이퍼파라미터가 주어졌을 때 성능이 어떨지"를 직접 모델링하는데, TPE는 이를 뒤집어 접근합니다.

1. 지금까지 시도한 하이퍼파라미터 조합들을 성능 기준으로 정렬합니다.
2. 상위 일정 비율(예: 상위 25%)을 "좋은 그룹", 나머지를 "나쁜 그룹"으로 나눕니다.
3. 각 그룹의 하이퍼파라미터 분포를 커널 밀도 추정(Parzen window)으로 별도 추정합니다 — 좋은 그룹의 분포를 `l(x)`, 나쁜 그룹의 분포를 `g(x)`라 부릅니다. 이름의 "Parzen Estimator"가 여기서 나옵니다.
4. 다음 시도할 후보는 `l(x)/g(x)` 비율이 큰 지점, 즉 나쁜 그룹보다 좋은 그룹에 훨씬 더 흔했던 조합을 고릅니다. (통계적으로 Expected Improvement를 최대화하는 것과 동치임이 알려져 있습니다.)
5. 그 지점에서 실제로 평가해 관측값에 추가하고 1~4를 반복합니다.

**왜 "Tree-structured"인가**: 하이퍼파라미터들이 서로 조건부 관계를 가질 때가 많습니다(예: optimizer가 Adam이면 beta1·beta2를 튜닝하지만 SGD면 momentum을 튜닝). 이런 탐색 공간은 평평한 격자가 아니라 트리 구조를 이루는데, TPE는 각 파라미터의 밀도를 독립적으로(트리를 따라가며) 추정하므로 이런 조건부·계층적 공간을 자연스럽게 다룰 수 있습니다. Gaussian Process 기반 베이지안 최적화는 이런 비정형 공간을 다루기 어렵습니다.

탐색 공간을 정의하면, TPE가 매 trial마다 이전 결과를 참고해 다음 후보를 제안합니다. 초반 몇 번은 관측치가 부족해 무작위 탐색과 비슷하게 동작하다가, 시도가 쌓일수록 점점 유망한 영역으로 수렴합니다.

| | GridSearchCV | RandomizedSearchCV | Optuna(TPE) |
|---|---|---|---|
| 다음 후보 선정 | 전체 격자 순회 | 무작위 | 과거 결과 기반 추정 |
| 과거 결과 활용 | 안 함 | 안 함 | 함 |
| 조건부 하이퍼파라미터 | 다루기 번거로움 | 다루기 번거로움 | 자연스럽게 지원 |
